## 三、三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
|---|---|---|---|
| 话题 Topic | 发布-订阅（publisher-subscriber） |信息只由pub到sub单向传递，持续发布，无应答 |持续上报足球的位置，准确定位足球的实时位置 |
| 服务 Service |请求-应答（request-response） |server持续监听client请求，client发布request，server接收并通过一系列操作向client反馈response。要一次请求和一次应答全部完成才算结束通信。在反馈过程中客户端会被阻塞，直到反馈结束。反馈的只有最终结果，没有进程。适合一次性操作。 |重置机器人位姿，单次触发视觉识别 |
| 动作 Action | 目标-反馈-结果（goal-feedback-result）|与service的区别是反馈完成前客户端不会被堵塞，能进行其他进程，并且能够反馈整个任务进程和当前状态，客户端能通过发送cancel指令随时取消任务进程。适合长时间的，着重进程的操作 | 实时战术调整转变，向目标运动过程反馈实时位置|

**我实际用到的服务调用**：`ros2 service call /clear std_srvs/srv/Empty`是清屏操作，只需要完成一次即可，因此选择service作通信方式。我在完成任务中选择的通信方式是topic，因为在定位操作中我需要不断定位乌龟和小球，不断更新位置信息才能更准确地控制方向，因此选择topic作为通信方式

## 四、差速三公式

- `v = (vL + vR) / 2` → 左轮和右轮的平均速度，表示机器人向前或向后沿着直线移动的平移速度。
- `ω = (vR − vL) / L` → 左右轮速度之差除以轮间距，表示机器人转弯或者在原地转圈的旋转速度，这个值的正负表示转弯的方向，为正向左转，为负向右转。
- `r = v / ω` → 平移速度除以旋转速度，表示机器人在转弯过程中圆弧运动路径的半径。
