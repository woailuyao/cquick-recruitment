# Week2 通信与运动控制
## 任务1：自定义BallPos消息，发布三个球坐标
做了什么：新建ROS2功能包，自定义BallPos消息（id、x、y），写发布、订阅节点，先以2Hz发送球坐标，后改成5Hz观察变化。
遇到的问题：卡在`member_of_group`近两小时，自定义消息编译一直报错。
解决：查阅资料，在package.xml补上该标签；同时养成新开终端先source的习惯，给脚本添加执行权限、补全CMakeLists安装配置。

## 任务2：订阅球坐标，控制小乌龟依次前往1→2→3
做了什么：订阅球坐标，集齐三点后闭环控制乌龟，先对准角度再前进，距离小于0.5判定到达，依次跑完三个目标。
遇到的问题1：启动顺序错误，导航先运行，一直等待球数据，乌龟不动。
解决：按顺序启动：仿真→清轨迹服务→发布节点→导航节点。
遇到的问题2：初始速度太大，乌龟冲点，误差超标。
解决：降低最大线速度，速度随距离衰减，保证误差≤0.5。
用到的服务：`ros2 service call /clear std_srvs/srv/Empty`

## 任务3：串口与总线舵机理论学习
做了什么：学习串口参数8‑N‑1，理解波特率乱码、半双工、共地、电平匹配；读懂众灵舵机指令，编写两条控制指令。
遇到的问题：一开始不理解回环测试的作用。
解决：弄懂TX、RX短接自发自收，用来检测串口通路；本周无硬件，回环测试留到下周实操。
要点：舵机转动前PULR恢复扭力，断电前PULK卸力。

## ROS2三种通信方式对比
| 通信方式 | 模型 | 特点 | 足球机器人典型场景 |
| ---- | ---- | ---- | ---- |
| 话题 Topic | 发布‑订阅，多对多 | 单向持续数据流，不关心接收方 | 视觉上报球位置，下发速度指令 |
| 服务 Service | 请求‑响应，一对一 | 一问一答，同步等待回复 | 查询机器人状态、切换模式（任务2用到/clear） |
| 动作 Action | 目标‑反馈‑结果 | 长任务，支持反馈、中途取消 | 导航移动，可随时停止 |

## 差速底盘公式
线速度：$v=\frac{v_L+v_R}{2}$
角速度：$\omega=\frac{v_R-v_L}{L}$
转弯半径：$r=\frac{v}{\omega}$
