# 03 串口与总线舵机笔记

## 串口四个参数

不同于 I2C、SPI 这种有时钟线的总线，串口（UART）通信**没有时钟线**。因此必须实现约定四个参数以同步。四个里只要有一个对不上，接收到的就不是原来的数据。

**1. 波特率（Baud Rate）**

每秒传多少bit。比如 115200 表示每秒传 115200 个 bit。
波特率本质上是在规定"每一位持续多长时间"。115200 波特率下，一个 bit 的时长是 `1/115200 ≈ 8.68 微秒`。收发双方必须用同一个波特率，不然连"一位到底多长"都没共识，后面全乱。

**2. 数据位（Data Bits）**

即"一帧里用**几个格子**装数据"——这是收发双方**事先约定好的固定值**。常见 5、6、7、8 位，我们固定用 8。因为一个 ASCII 字符正好 8 位，所以 8 位数据位就能完整表达一个字符。

如果这个参数设错，收发双方的"格子数"没对齐：发 8 位、收 7 位，收方读满 7 位就以为这帧结束，第 8 位被当成停止位或下一帧的起始位；发 7 位、收 8 位，收方多读 1 位，把停止位也当数据读进去。两种情况都会乱码。

**3. 停止位（Stop Bits）**

一帧结束的标志。在数据位后面跟 1 位高电平，告诉接收方"这一帧发完了"。

**4. 校验位（Parity）**

最简单的查错手段。可选无（None/N）、奇校验（Odd/O）、偶校验（Even/E）。

发送方根据数据位上的数值，按一定方式算出一个值写入校验位发过去。接收方对收到数据帧的数据位进行同样的计算，如果得出的校验位不相等就说明传输中出了错。

注意它只能**发现**错误、不能**纠正**错误，所以我们这种对可靠性要求不高的场景默认用"无校验"。

我们这套默认组合写作 **8-N-1**：8 数据位、无校验、1 停止位。以此为例，发送一个字符 'A'：
```
┌ 起始位 ┐   ┌──────── 数据位(8位) ────────────┐   ┌ 停止位 ┐
│   0    │  │ b0  b1  b2  b3  b4  b5  b6  b7 │  │   1    │
```
## 单线半双工

总线舵机这类设备，收发共用**一根**信号线（TX/RX 合在一根上）。同一时刻信号只能往一个方向传，此为**半双工**。

由此产生了两个现象：

- **回显**：因为TX/RX 合在一根线上，**自己由TX发出去的数据，自己也会由RX线收到**。
- **不能同时“说话”**：这是**电平冲突**造成的。数字信号只有高、低两个状态，一根线任一时刻只能呈现一个电平。如果两个设备同时发，两个输出会在线上打架，电压变成一个不确定值。所以同一条总线上**同一时刻只能有一个设备在发**，其他设备都在收。

## 共地

串口靠"线上的电平是高还是低"来区分 0 和 1，而"高""低"是**相对于参考点（GND）**来说的。如果两个设备不共地，各自的地电位可能差好几伏，A 发出一个自己认为 3.3V 的高电平，B 拿自己的地一量可能变成 -1V，根本判断不了是 0 还是 1。所以只接 TX/RX 不接地，收不到数据是必然的。

## 电平不匹配

电流从高电势流向地电势。因此若5V 设备的 TX 直接接到 3.3V 设备的 RX 上，低压侧会烧掉。所以要么加电平转换电路，要么先确认 3.3V 那侧本身兼容 5V 输入（很多芯片引脚标"5V tolerant"才行）。

## 波特率不一致的原理

由前文：串口通信没有时钟线，接收方如何知道一位从哪开始、到哪结束？

答案是靠**起始位**。串口空闲时线保持高电平，要发数据前，发方先把线拉低一个 bit 的时长，这就是起始位（Start bit）。接收方一直在盯着这根线，一旦检测到"从高到低"这个下降沿，就知道"开始收数据了"。

但起始位只解决了"什么时候开始"这个问题。开始之后，每个数据位在哪一时刻去采样，就完全靠波特率来推算。收发双方约定好一个波特率，接收方从起始位的下降沿开始，每隔 `1/波特率` 秒采一次样，读那个时刻线上的电平是 0 还是 1。

现在假设**发方按 115200 发，收方按 9600 采**：

- 发方眼里，一个 bit 是 8.68μs；
- 收方眼里，一个 bit 是约 104μs，是发方的 12 倍长。

结果就是：收方在它以为的"第一个数据位"采样时，发方其实已经发出去十几个 bit 了。采样点根本不在正确的 bit 上。更糟的是这个错位会**累积**——越往后，采样点偏离得越远，读出来的 0/1 从一开始就是乱的，到后面更是面目全非。

## 回环测试

**状态：未做，下周补做。**

**预期**：发送区发出去的信息（如：`hello`），接收区会**原样**显示（`hello`）。因为 TX 和 RX 被短接了，数据从 TX 脚出去，直接绕回 RX 脚接收到。

## 总线舵机指令逐字拆解
```
#001P1500T1000!
```
这一条的意思是：让 1 号舵机转到 PWM 为 1500 的位置，用时 1000 毫秒。我把它拆成七段：

| 片段 | 含义 |
| --- | --- |
| `#` | 帧头，告诉接收方"一条指令开始了" |
| `001` | 目标舵机的 ID，固定 3 位。`001` 就是 1 号舵机 |
| `P` | 表示"下面要写的是PWM 值" |
| `1500` | PWM 值，固定 4 位。范围 500–2500，表示舵机的对应位置。`1500` 是中立位 |
| `T` | 表示"下面要写的是时间" |
| `1000` | 舵机从上个位置达到本目标位置所用的时间，固定 4 位，单位毫秒 |
| `!` | 帧尾，告诉接收方"指令结束" |

### 自己写两条指令

1. 让 1 号舵机转到中立、用 1.5 秒：
```
#001P1500T1500!
```

2. 让 3 号舵机卸力：
```
#003PULK!
```
