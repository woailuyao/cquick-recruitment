# 03 串口与总线舵机笔记

## 1. 串口四参数

| 参数 | 我的理解 | 常见值 |
| ---- | ---- | ---- |
| 波特率 | 每秒传多少个 bit，通信双方必须设成一样 | 115200、9600 |
| 数据位 | 一个字符实际用几位表示 | 8 |
| 停止位 | 一帧结束的高电平标志，告诉对方"这段完了" | 1 |
| 校验位 | 数据位加一个奇/偶校验，用来发现传输出错 | 无（N） |

默认组合叫 **8-N-1**：8 位数据、无校验、1 位停止位。

**波特率不一致会怎样**：收到的是一堆乱码，而且往往"能收到东西"但内容全错。原因见第 3 节。

## 2. 回环测试

**未做，计划下周拿到舵机后补做。**（本周没买 CH340，也没去实验室）

我的预期：把 USB 转 TTL 模块的 TX 和 RX 用杜邦线短接，电脑串口助手发什么，同一个串口助手就会原样收到什么——因为数据从 TX 出去、绕一圈从 RX 回来。如果波特率两边一致（比如都 115200），收到的字符和发出的一模一样；故意把接收端波特率改成 9600，收到的就该是乱码，这正好可以验证第 3 节说的原理。

## 3. 波特率不一致的原理（我自己复述一遍）

串口线上没有时钟线，接收端只能靠约定好的节拍去采样。发送端按 115200 bit/s 的节奏把每个 bit 摆上线（一个 bit 约 8.68 微秒）；接收端也按自己的时钟数"这段电平持续了多久"来还原 bit。如果接收端以为节拍是 9600 bit/s，它量出来的"一个 bit"比实际的宽 12 倍——它会把连续 12 个真实的 bit 揉成 1 个来解，解出来的字节和发出去的完全对不上，表现就是乱码。

这就好比两个人传纸条约好"每秒翻一页"，一方每秒翻 12 页、另一方每秒翻 1 页，看到的"第 N 页内容"完全错位。所以**波特率不一致不是设备坏了，是采样节拍对不上**。

## 4. 总线舵机指令逐字拆解

`#001P1500T1000!` 拆成七段：

| 段 | 内容 | 含义 |
| ---- | ---- | ---- |
| `#` | 起始符 | 一条指令的开关 |
| `001` | ID，固定 3 位 | 发给 1 号舵机（1 号要写 001，不是 1） |
| `P` | 位置段关键字 | 后面跟 PWM 值 |
| `1500` | PWM，固定 4 位，范围 500–2500 | 1500 是中立位 |
| `T` | 时间段关键字 | 后面跟运动时间 |
| `1000` | 时间，固定 4 位，单位 ms | 用 1000 ms 平滑转到位，不是瞬间跳 |
| `!` | 结束符 | 一条指令到此为止 |

自己写的两条：

- 让 1 号舵机转到中立位（1500）、用 1.5 秒：`#001P1500T1500!`
- 让 3 号舵机卸力：`#003PULK!`

补充两个容易忘的点（写给自己）：**要舵机动之前必须先发 `#xxxPULR!` 恢复扭力**，否则发了角度指令它也纹丝不动；**断电前必须 `#xxxPULK!` 卸力**，不然舵机一直顶着力会发热堵转。另外所有舵机挂同一条串口总线、靠 ID 区分，指令是单线半双工——同一时刻总线上只能有一个设备说话。
