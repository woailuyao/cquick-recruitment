# 串口基础与总线舵机串口模式 · 学习笔记

## 一、串口四参数

| 参数 | 我的理解 | 常见值 |
|---|---|---|
| 波特率 | 通信双方约好每秒传多少个位，各自靠自己的定时器数位来对齐，所以两边必须一致。115200 就是每秒 115200 个位，算下来每一位大约 8.68 微秒。 | 115200、9600 |
| 数据位 | 一个字符占几位。8 位刚好一个字节，传中文或者二进制都要 8 位。 | 8 |
| 停止位 | 一帧末尾的一段高电平，表示这个字符结束，顺便给对方留一点处理时间。 | 1 |
| 校验位 | 在数据后面再加一位，让 1 的个数保持奇数（奇校验）或偶数（偶校验），只能发现单个位错了，纠正不了。 | 无（N） |

默认组合写作 `8-N-1`，也就是 8 位数据、无校验、1 位停止位。加上起始位那 1 位，发一个字节一共是 10 个位时间，所以 115200 的时候每秒实际能传的字节大约只有 115200 ÷ 10 ≈ 11520 个。

**波特率不一致会怎样**：接收方会按自己的节奏去切分电平，采样位置全错，收到的是完全错误的内容，并不是完全读不到。

## 二、回环测试（已做）

- **怎么接线**：把 CH340 模块上的 TXD 和 RXD 用一根杜邦线短接，让它自己发、自己收。GND 不用接——TX 和 RX 是同一块板子上的，本来就共地。一开始我以为要接三根线，后来查了资料才明白回环只需要这一根短接线。
- **发了什么**：16 个字节的 `#001P1500T1000!`，波特率 115200，8-N-1。
- **收到什么**：一模一样的内容，程序里打印出来的判断是 `一致: True`。
- **现象截图**：`03_回环测试.png`。

中途遇到两个问题，记一下：

1. 插上模块之后 `/dev/ttyUSB0` 一直不存在。`sudo dmesg | tail` 看到 `ch341-uart converter now attached to ttyUSB0`，紧接着又出现 `now disconnected`，中间夹着一行提到 `brltty`。查了才知道 Ubuntu 自带一个盲文终端服务 brltty，会把串口设备抢走。执行 `sudo systemctl mask brltty-udev.service` 之后再拔插一次，`/dev/ttyUSB0` 才稳定出现。
2. 脚本里 `import serial` 报 `ModuleNotFoundError: No module named 'serial'`，装 `sudo apt install python3-serial` 就好了。

## 三、波特率不一致为什么会乱码

**现象**：收到的东西和发出去的对不上，看上去是一堆随机字符。

**接收方是怎么读的**：串口没有时钟线，接收方只能靠电平变化自己找节奏。它看到电平从高掉到低，就认为起始位来了；然后等 1.5 个"位时间"去采第一位（这样正好落在这一位的中间），之后每隔 1 个"位时间"再采一次，连采 8 次，最后还要检查停止位是不是高电平。

**问题出在"位时间"是怎么来的**：这 1 个位时间，是接收方按自己设置的波特率算出来的。发送方按 115200 发（每位 8.68 微秒），接收方却按 9600 收（每位约 104 微秒）：起始沿到来后，接收方要等 1.5 × 104 ≈ 156 微秒才去采第一位，而这段时间里发送方已经把十几个位发完了。它采到的第一位其实是发送方后面的某个位，后面每次采样继续按自己的慢节奏走，越采越偏。

**为什么不是"完全收不到"**：电平还在跳，接收方每次都能采到某个电平值，所以它总会"凑"出一个字节，只是内容是错的。

**另外一点（我理解是这样，还没实测）**：单口回环时，发送和接收用的是同一个串口、同一个设置，两边永远一致，所以波特率改成别的值应该也照样能通。要造出"不一致"，必须有两个独立的串口（比如两个 CH340，或者用 socat 虚拟出一对串口）。所以"改波特率就乱码"这个说法，只在两个设备之间才成立。

## 四、总线舵机的串口指令

拿 `#001P1500T1000!` 逐段拆：

| 段 | 含义 | 说明 |
|---|---|---|
| `#` | 起始符 | 告诉舵机指令从这儿开始，用来对齐帧 |
| `001` | 舵机 ID | 固定 3 位，1 号舵机就写 001 |
| `P` | 位置指令 | 表示接下来要给 PWM 值。另外 `PID` 是读 ID、`PRAD` 是读位置、`PULR`/`PULK` 是上力/卸力 |
| `1500` | PWM 值 | 固定 4 位，范围 500–2500，对应传统舵机脉宽 0.5–2.5 ms（周期 20 ms）。1500 是中立位，约 90° |
| `T` | 时间标识 | 表示后面跟的是运动用时 |
| `1000` | 用时 | 固定 4 位，单位是毫秒。舵机用这 1000 ms 平滑转过去，而不是瞬间跳过去 |
| `!` | 结束符 | 告诉舵机这条指令结束了，可以执行 |

**为什么全都用固定位数、中间不加逗号**：单片机解析最省事，直接按位置切片就行，不用写字符串分割；而且传的是 ASCII，调试的时候直接就能看懂。

**我自己写的两条指令**：

- `#001P1500T1500!` —— 让 1 号舵机用 1500 毫秒（也就是 1.5 秒）转到 PWM 1500 的中立位。
- `#003PULK!` —— 让 3 号舵机卸力。这条没有 P 和 T，因为它不需要转到哪个位置、也不需要时间。

**其他常用指令**（看懂即可）：

| 功能 | 指令 | 说明 |
|---|---|---|
| 读 ID | `#001PID!` | 问它"你是几号"，上电第一件事就是这个 |
| 读位置 | `#001PRAD!` | 读回当前 PWM 值，验证它到底动没动 |
| 恢复扭力 | `#001PULR!` | 重新上力。卸力状态下写角度它是不动的，所以写角度之前必须先发这个 |
| 卸力 | `#001PULK!` | 松开电机，断电之前必须发，否则一直顶着力会发热 |

**通信参数**：波特率 115200，供电 5–8.4V。

## 五、三个必须搞懂的点

1. **单线半双工**：总线舵机为了省线把所有舵机挂在一条数据线上，收发都用这一根，所以叫单线；同一时刻只允许一个设备工作，所以叫半双工。普通 UART 有 TX 和 RX 两根线，可以一边发一边收，是全双工。如果两个设备同时驱动这一根线，一个想拉高、一个想拉低，就是短路，会烧 IO。
2. **共地**：电压是相对量，两块板子如果只连了信号线、没连 GND，它们各自的 GND 之间可能有电位差，那么同一个高电平在对方看来电压就不一样，判断必然出错。所以接线顺序是先接 GND 再接信号线。
3. **电平不匹配**：3.3V 器件的输入脚通常只能承受 VDD 再加一点点，5V 直接灌进去会通过内部钳位二极管形成大电流，时间长了就烧。反过来 3.3V 输出接到 5V 输入一般不会烧，但可能被判成低电平，通信不稳定。解决办法是用电平转换芯片，或者确认器件本身是不是宽压兼容——这个要看手册，不能想当然。
