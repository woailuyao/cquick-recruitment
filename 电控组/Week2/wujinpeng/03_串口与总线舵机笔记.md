## 一、串口四个参数

串口（UART）是两根线一收一发地传数据。要让两边对得上，必须约定四件事：

| 参数 | 是什么 | 常见值 | 我的理解 |
|---|---|---|---|
| **波特率** | 每秒传多少位（bit/s） | 115200、9600 | 说话的**语速**。一秒吐多少个高低电平，双方必须一样 |
| **数据位** | 一个字符用几位表示 | 8 | 一个字节拆成 8 位，从最低位开始一位一位发 |
| **停止位** | 一帧的结尾标志 | 1 | 说完一个字节，拉高电平一小段时间，告诉对方「这个字结束了」 |
| **校验位** | 简单查错 | 无（N） | 可选。奇校验/偶校验让「1 的个数」符合约定，收错了能发现 |

四个参数默认的组合写法是 **8-N-1**：8 位数据、无校验、1 位停止位。舵机手册里写的通信参数就是 **115200, 8-N-1**。

### 波特率不一致会怎样、为什么

**现象**：收到的全是乱码（`烫烫烫`、`�`、一堆问号），或者干脆一个字节都收不对。设备本身没坏。

**为什么**：
串口没有时钟线，双方靠**事先约好的时间间隔**去采样。约定 9600 就是「每一位持续 1/9600 ≈ 104 μs」，
约定 115200 就是「每一位持续 1/115200 ≈ 8.7 μs」。

发送方按 8.7 μs 一位吐，接收方却按 104 μs 一位去读——它在第 1 位的位置上读到的可能是第 4 位、第 12 位的电平，
**采样点全错位了**，读出来的 0/1 组合自然是一堆垃圾。而且错位会累积，越往后越离谱。

一句话：**波特率不是「快慢」的区别，是「节拍」的区别。节拍对不上，听到的就是噪音。**

## 二、回环测试（Loopback）

**本周未做，计划下周拿到舵机后补做。**

没做的原因：手头没有 CH340 这种 USB 转 TTL 模块。按细则，回环不影响本周成绩，下周统一补。

### 我预期会看到什么

回环就是把 TX 和 RX 用一根杜邦线短接：**自己发出去的东西，原封不动被自己收回来**。

我会用 `minicom`（或 `screen`）打开 `/dev/ttyUSB0`，参数设成 115200 8-N-1，然后敲键盘：

- 敲 `abc` → 屏幕上应该立刻出现 `abc`（本地的回显 + 从线上收回来的各一份，所以可能会看到 `aabbcc`）
- 敲 `#001P1500T1000!` → 同样原样回来

如果**什么都没回来**，说明线没接对或者串口选错了；如果回来的是**乱码**，说明波特率设错了（比如设备是 9600 我开成 115200）。
所以回环测试的真正价值不是「验证串口能用」，而是**在没有舵机的情况下，先把「线、端口、波特率」这三件事排干净**——
这样下周接上舵机，出问题时就能确定不是串口本身的问题。

## 三、波特率不一致的原理（讲给自己听版）

想象两个人用旗语通信，约定「我每秒挥一次旗，你每秒看一次」。结果我实际每秒挥两次，
你按每秒一次去记录，就会把「举-放-举-放」记成「举-举」，信息全乱。

串口就是这个逻辑：
1. 起始位（一个低电平）到来，接收方**从这一位开始计时**；
2. 之后每隔「一位的时间」采样一次，连续采 8 次得到一个字节；
3. 只要两边「一位的时间」不一样，第 n 次采样的位置就会越偏越远；
4. 偏到半个位宽以上，采到的电平就翻个个儿，0 变 1。

所以波特率误差在 **2%~3% 以内**通常还能勉强通信（采样点还没偏出安全区），超过就容易整帧报错。
这也是为什么晶振不准的板子通信会「时好时坏」——不是玄学，是采样点漂移。

另外三个必须记住的硬件前提：

1. **单线半双工**（总线舵机）：收发共用一根信号线，自己发出去的数据自己也会「听到」。
   所以同一条总线上**不能两个设备同时说话**，得排队。
2. **共地（GND 必须连）**：两个设备判断「高/低」靠的是电压差，而电压是相对于各自的地来说的。
   不共地，两边对「0V」的理解都不一样，收到的电平就无从判断——**只接 TX/RX 不接地，收不到数据是必然的**。
3. **电平不匹配**：5V 的单片机直接连 3.3V 的器件，3.3V 那侧会被 5V 顶穿。要么加电平转换，要么确认器件本身兼容 5V。

## 四、舵机指令逐字拆解

众灵总线舵机的指令是 **ASCII 字符串**，`#` 开头、`!` 结尾，所有舵机挂在同一条串口总线上，靠 **ID** 区分。

拿 `#001P1500T1000!` 举例，一共 16 个字符，拆成七段：

| 段 | 内容 | 含义 |
|---|---|---|
| `#` | 起始符 | 告诉总线「一条新指令开始了」 |
| `001` | 舵机 ID，**固定 3 位** | 1 号舵机。位数不足要补 0，不能写 `1` |
| `P` | 功能码 | **P** = Position，写角度（位置） |
| `1500` | PWM 值，**固定 4 位**，范围 500–2500 | 1500 是**中立位**（舵机行程的中间）。比 1500 小往一边转，比 1500 大往另一边转 |
| `T` | 功能码 | **T** = Time，指定用多长时间转到位 |
| `1000` | 时间，**固定 4 位**，单位 **ms** | 用 1000 ms（1 秒）**平滑**转到位，不是瞬间跳过去 |
| `!` | 结束符 | 告诉总线「这条指令完了，可以执行了」 |

几个容易忽略的点：
- **位数是硬性的**：ID 必须 3 位、PWM 必须 4 位、时间必须 4 位，少一位大概率不认；
- **`T` 的意义是「限速」**：舵机内部会自己规划一条轨迹，用 1000 ms 走完。如果直接给 `T0` 或者给很小的时间，舵机会猛地窜过去，电流冲击大、齿轮也容易坏；
- **PWM 500–2500 对应的是角度范围**，1500 在正中间。不同型号舵机这个范围可能略有差别，写超过量程的值可能被忽略或顶到限位。

### 自己写两条指令

**① 让 1 号舵机转到中立位，用 1.5 秒**

1.5 秒 = 1500 ms → 时间字段写 `1500`
中立位 PWM = 1500 → `1500`
ID 1 → `001`

```
#001P1500T1500!
```

**② 让 3 号舵机卸力**

卸力的功能码是 `PULK`，不需要 PWM 和时间参数
ID 3 → `003`

```
#003PULK!
```

顺带记一下完整的使用顺序（下周实操按这个走，顺序不能乱）：

```
读 ID（#001PID!）→ 恢复扭力（#001PULR!）→ 写角度（#001P1500T1000!）
→ 读位置（#001PRAD!）→ 卸力（#001PULK!）
```

不先 `PULR` 就写角度，舵机会**纹丝不动**；断电前不 `PULK`，舵机会一直顶着力发热烧掉。

## 五、我还没搞懂的问题

重新 PULR 之后，它认的是**丢掉之前记的那个位置**，还是**当前实际停在哪**？如果是前者，舵机会不会突然「弹回去」？
如果是后者，那我是不是每次 PULR 之后都得先 `PRAD` 读一次位置，再决定写什么角度？

**2. 一条指令 16 字节，115200 波特率下传输只要 1.4 ms 左右，但 `T` 是 1000 ms——发指令会不会被「卡住」？**

那如果我在 1000 ms 内连着发 100 条不同的角度，舵机是**每条都执行一点**（看起来一顿一顿），
还是**只认最后一条**？总线是半双工的，多舵机同时回数据时会不会撞车？

**3. PWM 500–2500，那写 `#001P3000T1000!` 会怎样？**

我担心的是：程序算出来的角度超出了量程却没人报错，舵机顶在限位上一直使劲——这和堵转是一样会烧的。

**4. 单线半双工「自己发的自己也能听到」，那主控发的指令会不会被自己当成舵机的回应收回来？**
如果是这样，读 `PRAD` 的时候怎么区分「我刚刚发出去的那串字符」和「舵机真正回的数据」？
是不是靠「发送时先关掉接收」这种硬件层面的处理？
