节点是负责单一特定的功能的“电路元件”，话题是将节点联系起来的“导线”，消息是节点通过话题传输的内容（“电子”），而发布者订阅者是节点对于某个话题的具体身份（这个想不到比喻词了。原谅我。）
话题像一种频道，在这个频道中有人负责发布消息，不管谁收，有没有人收；有人负责接收别人发出的消息，不管谁发的，发布者订阅者不知道对方的存在（异步），并且一个话题中可以有多个发布者和订阅者
而服务是同步的，一对一的，服务端只有一个，客户端可以有多个，并且是调用一次响应一次，有点像你点外卖，所有人都可以点这一家的外卖（多个客户端），你点一个他做一个，大家的外卖就按顺序来做这样
动作包含三个部分，客户端发送任务，执行过程中有持续的反馈，任务完成后会返回最终结果，其实也挺像点外卖的，你下了单之后，平台会给你反馈商家正在出餐，骑手前往取餐等等，然后最后外卖到了告诉你外卖放哪里了这样，但是动作可以中途终止外卖你点了不能退奥（doge)
# 任务2 ： 订阅三个球的坐标并走过去
很显然这个导航的代码也是ds生成的（我并没有理直气壮只是有点没招了。能看懂代码和能打出来完全是两码事，正在努力学习中...对不己...）
角度差过大的时候，不给线速度，只给角速度，让乌龟先把方向转过来再前进；角度对准了之后再给线速度，此时会给一点点角速度对方向进行微调，然后线速度也不是固定的，会根据距离目标点的位置进行调整，越近越小，防止冲过头了；先对准再走一方面是为了减小误差，另一方面是因为两点之间直线最短，不先对准就会走出一段圆弧，就绕远路了
线速度公式是指小车的线速度是左右轮速度的平均值，角速度公式是指，如果左右轮速度不一致，会有一边跑得快使小车产生偏转，速度差除以两轮之间的距离得到角速度，而转弯半径公式是小车的线速度除以角速度，线速度越大或者角速度越小，小车的转弯半径就越大，如果两侧轮子速度一致则小车直线运动，不发生偏转，没有角速度和转弯半径一说
