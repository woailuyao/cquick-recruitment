# 串口与总线舵机笔记

## 串口的几个基本参数

之前学 STM32 的时候用过串口，主要是用串口助手发数据，让板载 LED 亮灭。这次主要补一下通信参数和总线舵机的指令。

常见的串口设置是 `115200，8-N-1`。115200 是波特率，8 是数据位，N 表示不加校验位，1 表示一个停止位。

波特率：决定发数据的节奏。普通 UART 里可以理解为每秒传多少位，发送端和接收端要设成一致。
数据位：真正装数据的部分，常用 8 位，也就是一个字节。
校验位：用来发现一部分传输错误，常用的有奇校验、偶校验和无校验。
停止位：表示这一帧传完了，常用一个停止位。

8-N-1 还要算上一个起始位，所以传一个数据字节实际要用 10 位。115200 波特率并不是一秒能传 115200 个字节，连续发送时理论上约是 11520 个数据字节。

在 STM32 标准库里，对应下面几项：

USART_InitStructure.USART_BaudRate = 115200;
USART_InitStructure.USART_WordLength = USART_WordLength_8b;
USART_InitStructure.USART_Parity = USART_Parity_No;
USART_InitStructure.USART_StopBits = USART_StopBits_1;

我之前写 LED 控制程序时，用的是 `byteRcvd == '0'`。这里接收的是字符 `0`，对应 ASCII 码 `0x30`，不能在串口助手里用 HEX 发 `00` 来代替。

另外，之前配置 PB6 和 PB7 时，我改完 PB6 的结构体参数，没有马上调用 `GPIO_Init`，就又改成了 PB7 的参数。最后只初始化了一次，PB6 的配置就没有真正写进去。还有一次下载完一直没反应，折腾了一会儿才发现忘了复位。

## 接线和单线半双工

普通串口的 TX 是发送，RX 是接收，两边交叉接，还要共地。之前 USART1 做了重映射，所以 USB 转串口模块的 RX 接 PB6，TX 接 PB7，GND 接 GND。用这组引脚的前提是程序里已经打开相关时钟，并配置了重映射。

总线舵机用的单线半双工，收和发共用一根通信线，需要轮流发送。主机发完指令，再切换到接收，等舵机回复。如果两个设备同时发送，就可能互相干扰。有些电路还会收到自己发出去的数据，所以接收区有内容，也要判断是不是自己的回显。

共地是为了让两边判断电平时有同一个参考点。5 V 信号接到 3.3 V 器件前，要查这个引脚能不能承受，不能承受就要做电平转换。舵机供电电压和串口信号电平也要分清。

## 回环测试

回环测试的实际结果还需要补充，之前做的串口控制 LED 实验不能直接算成 TX、RX 短接回环。

测试时把 USB 转串口模块自身的 TX 和 RX 短接，打开对应串口，关闭软件本地回显，再发送一段内容，例如 `hello123`。正常情况下接收区应该收到相同的内容。断开短接线后再发一次，应该不再收到这些数据，这样能排除本地回显造成的误判。

如果这次没有做，就如实记录未做，并计划后续补做；做了就补上接线、发送和接收的内容，以及带姓名、时间的截图。

## 波特率不一致为什么会乱码

串口接收端检测到起始位后，会按自己设置的节拍去读后面的数据。比如发送端用 115200，一位大约持续 8.68 微秒；接收端却设成 9600，认为一位大约有 104.17 微秒。等接收端准备读下一位时，发送端可能已经发过去很多位了，读出来的数据自然不对，就可能乱码、报帧错误，或者收不到有效数据。所以串口不正常时，要先核对两边的参数。波特率存在一点偏差不一定马上出错，但不能超过接收端能容忍的范围。

## 舵机指令怎么读

这次学的是考核资料里众灵总线舵机的串口模式。多个舵机接在同一条总线上，通过 ID 区分要控制哪一个。资料给出的波特率是 115200，供电范围是 5–8.4 V，实际接线前还要核对手上的型号。
以这条指令为例：
```text
#001P1500T1000!
```
| 内容 | 意思 |
| --- | --- |
| `#` | 一条指令的开始 |
| `001` | 1 号舵机，ID 固定写三位 |
| `P` | 后面跟目标位置 |
| `1500` | 位置参数，固定四位，1500 表示中位 |
| `T` | 后面跟运动时间 |
| `1000` | 用时 1000 毫秒，也就是 1 秒，固定写四位 |
| `!` | 指令结束 |
整条指令就是让 1 号舵机用 1 秒转到中位。位置参数范围是 500–2500，不能把 1500 当成角度，具体怎么换算要看舵机型号。

让 1 号舵机用 1.5 秒转到中位：
#001P1500T1500！

让 3 号舵机卸力：
#003PULK!

另外几条需要认识的指令：
| 指令 | 作用 |
| --- | --- |
| `#001PID!` | 查询 ID |
| `#001PRAD!` | 读取当前位置参数 |
| `#001PULR!` | 恢复扭力 |
| `#001PULK!` | 卸力 |

资料要求运动前先恢复扭力，结束操作时注意卸力。这些指令都是 ASCII 字符串，用程序发送时，要把字符串里的字符依次发出去。比如字符 `0` 发的是 `0x30`，不是数值 0，这和之前串口控制 LED 时的字符判断是相通的。

## 学定时器时踩过的两个坑

### 函数写了，为什么还提示找不到？

之前在 STM32 工程里，我声明和调用的是 `App_TIM1_Init()`，下面定义时却写成了 `App_TIM_Init()`，少了一个 `1`。Keil 报了 `L6218E: Undefined symbol`。

当时的问题是函数名没对上。编译时看到了声明，但链接时找不到同名的函数实现。后来把声明、调用和定义的名字统一，链接错误就解决了。以后遇到这种错误，先对照函数名，不要一上来就怀疑定时器参数配错了。

### 创建了定时器，回调就会自己执行吗？

这个是学 ROS 2 定时器时理解错的地方。我当时以为不写 `rclpy.spin(node)`，回调和控制循环也会执行一次，只是不能一直执行。

实际上，`create_timer()` 是把周期和函数注册进去，正常运行时还需要执行器调度回调。我们写的程序通过 `rclpy.spin(node)` 来处理这些事件。只创建定时器，不运行执行器，不能指望回调先自动执行一次。

这里也让我发现自己之前只看得懂单段代码，却没弄清楚整个程序是谁在调用谁。STM32 的硬件定时器中断和 ROS 2 定时器回调也不能直接当成同一种实现。

接下来还想弄清楚：ROS 2 设成每 0.1 秒调用一次，如果回调本身执行超过 0.1 秒，后面的调用会怎么安排？
