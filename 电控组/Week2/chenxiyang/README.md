**【五个词解释】
- **节点（Node）**：一个执行具体任务的程序（比如负责控制乌龟的、负责发球坐标的）。
- **话题（Topic）**：节点之间传递数据的通道
- **消息（Message）**：在话题上传输的具体数据格式（比如包含了 id, x, y 的数据结构）。
- **发布者（Publisher）**：字面意思，发布消息的节点
- **订阅者（Subscriber）**：字面意思，从发布者那接收消息的节点，可以是我们的“turtlesim”
- **两个节点靠什么对上号？**：靠**完全一致的话题名称**（比如 `/ball_pos`）和**一致的消息类型**（比如 `BallPos`）。所以任务1里强调发布者和订阅者前面的话题名要一字不差

## 三种通信方式对比
| 通信方式 | 模型 | 特点 | 足球机器人典型场景 |
| --- | --- | --- | --- |
| 话题 Topic | 发布/订阅，多对多 | 单向、持续流、不管对方在不在 | 视觉持续广播球位置；战术广播速度指令 |
| 服务 Service | 请求/响应，一对一 | 同步、有返回值、调一次答一次 | 「现在比分多少」 |
| 动作 Action | 目标/反馈/结果 | 长任务、报进度、可取消 | 「走到点 (1,1)」并中途报进度 |

- **实现思路**：写了 `go_to_balls.py`，订阅 `/turtle1/pose` 和 `ball_pos`。采用闭环控制，越接近目标速度越小。
- **控制逻辑**：
  - 算出了目标方位角和当前乌龟朝向的差值。
  - 代码里的 `angular.z` 是用来控制转弯（原地转圈调整方位）的，`linear.x` 是用来控制前进的。
  - **先对准再走的原因**：如果不先对准方向直接往前走，就会跑偏绕大远路，甚至撞墙。所以先原地转圈调整方位，对准了再一边往前走一边微调。
