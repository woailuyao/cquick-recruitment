## 一、串口四参数

串口通信是**异步**的 —— 收发双方之间只有一根数据线，没有时钟线来告诉对方「这一位现在该采了」。所以双方必须提前约定好一套**帧格式**，这四个参数就是这套约定：

| 参数 | 含义 | 常见值 | 我们舵机用的 |
|---|---|---|---|
| **波特率** | 每秒传输多少位（bit/s）。它不是"每秒多少字节"，一个字节约占 10 位（含起止位） | 9600 / 115200 | **115200** |
| **数据位** | 一个字符用几位表示。8 位正好对应一个字节 | 7 / 8 | **8** |
| **停止位** | 一帧结束的标志，用高电平维持一段时间 | 1 / 2 | **1** |
| **校验位** | 简单的查错位（奇/偶/无） | 无(N) / 奇 / 偶 | **无(N)** |

四个参数合起来写成 **115200-8-N-1**，这是最容易背的记法。

### 波特率不一致会发生什么

**收到的是一堆乱码**（或者干脆报 framing error）。

最关键的一点：**这不是设备坏了**。很多人第一次遇到乱码就以为线接错了、舵机烧了，其实只是采样节拍对不上。所以调串口的第一件事永远应该是「两边波特率是不是一样」，而不是先怀疑硬件。

为什么会乱码，见第三节。

## 三、为什么波特率不一致会收到乱码

这一节我按"能讲给别人听"的标准写。

### 1. 串口靠"时间"而不是"时钟线"来对齐

SPI、I2C 这类总线有专门的时钟线（SCL），每一位什么时候采由时钟决定，很稳。
UART **没有时钟线**，只有一根 TX 一根 RX。接收方怎么知道每一位的边界在哪？

答案是：**靠起始位**。

一帧的格式是这样（以 8-N-1 为例，一共 10 位）：

```
空闲(高) ── 起始位(低) ── D0 D1 D2 D3 D4 D5 D6 D7 ── 停止位(高) ── 空闲(高)
              ↑
         接收方检测到这个下降沿，开始计时
```

平时线是高电平（空闲）。发送方要发数据时，先把线**拉低一位的时间**作为起始位。接收方一旦检测到这个下降沿，就启动自己的内部计时器，然后按照**双方约定的波特率**，每隔「一位的时间」去线上采一次。

关键就在这句：**接收方完全依赖自己这边的计时器来数位**。它并不知道发送方实际是什么节奏。

### 2. 误差会累积，不会自我纠正

设发送方一位的持续时间是 `T_send`，接收方一位的持续时间是 `T_recv`。

假设接收方的时钟**偏快**（`T_recv < T_send`），那么它每采一位，采样点就比实际位置**往前挪一点**。挪的量是逐位累积的：

```
第 n 位的采样偏移 ≈ n × (T_send − T_recv)
```

一开始偏移很小，采到的还是对的；越往后偏得越多。**当偏移超过半个位宽时，采样点就跨到位边界上了** —— 这时候采到的 0/1 跟原来完全无关，读出来就是乱码。

举个具体数字：一帧 10 位。如果两边波特率相差 5%，到第 10 位时已经累积了 `10 × 5% = 0.5` 个位宽 —— **正好卡在会出错的临界点**。所以实际工程里要求两边的时钟误差通常控制在 2%~3% 以内。

这也解释了一个现象：**误差小的时候，收到的往往是"前面几个字节对、后面开始错"**，而不是全错。

### 3. 还会触发 framing error

除了数据位采错，停止位也会出问题。停止位规定必须是**高电平**。如果接收方因为节拍不对，在"它以为是停止位"的时刻采到低电平，就会判定 **framing error（帧错误）**，直接把这帧丢掉。

所以波特率严重不匹配时，现象往往是：**要么收不到任何字节，要么收到一堆 0x00 / 0xFF / 奇怪的符号**。

### 4. 一句话总结

> 串口是"按时间数位"的通信方式，双方各自用自己的时钟去采样。波特率不一致 → 每采一位就多偏一点 → 累积到半个位宽后开始采错 → 数据位和停止位全错 → 乱码或帧错误。**这不是硬件故障，是节拍没对齐。**

## 四、舵机指令逐字拆解

总线舵机的特点是：**所有舵机挂在同一条串口总线上，靠 ID 区分**，而不是每个舵机拉一根 PWM 信号线。指令是 **ASCII 字符串**，`#` 开头、`!` 结尾。

### 逐字拆 `#001P1500T1000!`

| 段 | 内容 | 说明 |
|---|---|---|
| `#` | 帧头 | 告诉舵机「一条指令从这里开始」。舵机看到 `#` 才开始解析，前面的杂波会被忽略 |
| `001` | 舵机 ID | **固定 3 位**，不足补零。`001` = 1 号舵机。位宽固定是为了让解析器能准确切分字段 |
| `P` | 功能码 | `P` = Position，表示接下来要**写位置**。这是最常用的功能码 |
| `1500` | PWM 值 | **固定 4 位**，范围 **500–2500**。**1500 = 中立位**（舵机的中点是 1500，不是 0）。数值对应舵机内部的目标角度 |
| `T` | 功能码 | `T` = Time，表示接下来是**运动时间** |
| `1000` | 时间值 | **固定 4 位**，单位是 **毫秒**。1000 ms = 1 秒。意思是「用 1 秒平滑转到 1500」，**不是瞬间跳过去** |
| `!` | 帧尾 | 告诉舵机「这条指令到此结束，可以执行了」 |

### 两条自己写的指令

**① 让 1 号舵机转到中立位，用 1.5 秒**

```
#001P1500T1500!
```

拆解：`#` + `001`（1号） + `P` + `1500`（中立位） + `T` + `1500`（1500 ms = 1.5 秒） + `!`

**② 让 3 号舵机卸力**

```
#003PULK!
```

拆解：`#` + `003`（3号） + `PULK`（卸载扭力） + `!`
注意 **卸力指令没有 PWM 和 T 字段**，因为它不需要转到某个角度，只是把输出关掉。

### 顺带记下的指令（下周要用）

| 功能 | 指令 | 什么时候用 |
|---|---|---|
| 读 ID | `#001PID!` | 上电第一步，先确认总线上有谁 |
| 恢复扭力 | `#001PULR!` | **写角度之前必须先发这个**，否则舵机没力、纹丝不动 |
| 读位置 | `#001PRAD!` | 确认它到底转到位没有 |
| 卸力 | `#001PULK!` | 下电前必发，防止堵转发热烧舵机 |

所以下周的标准流程是：

```
读 ID → 恢复扭力 → 写角度 → 读位置 → 卸力
```

## 五、我还没搞懂的问题

**问题 1：为什么 `PULR`（恢复扭力）之后，舵机会"丢掉"之前的位置？**

我的困惑是：舵机卸力（`PULK`）之后，内部并没有断电，控制器还在。那么它的编码器 / 位置寄存器应该一直记着当前角度才对。为什么恢复扭力后写一个新角度，它是从**当前位置**平滑过去的，而不是从"上电时的那个位置"？是卸力期间位置寄存器被重置了，还是它一直在跟踪、只是没有输出力矩？

**问题 2：同一条总线上多个舵机，回包会不会"撞车"？**

指令里带 ID，所以发指令不会冲突。但**读操作**（`PID` / `PRAD`）是所有舵机都能收到这条广播的 —— 如果总线上有 6 个舵机，它们会不会同时回包，导致电平冲突？手册里没写清楚，我怀疑是"只有 ID 匹配的那个才回"，但不确定。下周实测一下：接两个舵机，发 `#001PID!`，看会不会收到两个回包。

**问题 3：`T` 这一段是"线性插值"还是"舵机内部规划曲线"？**

`T1000` 是让舵机在 1 秒内匀速转过去，还是内部有个加减速曲线？这决定了写轨迹的时候要不要自己做插值。下周用 `PRAD` 连续读位置就能画出实际曲线，到时候就知道了。
