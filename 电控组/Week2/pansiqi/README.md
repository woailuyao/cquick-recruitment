## 三、三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
|---|---|---|---|
| 话题 Topic | 发布/订阅，多对多 | 单向、持续流、不管对方在不在 | 视觉持续广播球位置；决策持续广播速度指令；本周的 `ball_pos` 和 `/turtle1/pose` |
| 服务 Service | 请求/响应，一对一 | 同步、有返回值、调一次答一次 | 「现在比分多少」「切到防守模式」；任务 2 开始前清屏的 `/clear` |
| 动作 Action | 目标/反馈/结果 | 长任务、报进度、可取消 | 「走到点 (2,3)」→ 过程中不断回报进度，可以中途取消或改目标 |

**我实际用到的服务调用**：任务 2 开始前的 `ros2 service call /clear std_srvs/srv/Empty`。它是服务而不是话题，因为：清屏这件事**只需要做一次**、而且我**需要知道它到底清没清**（命令返回了响应才算完成）。如果用话题来做，就得发布一条消息、然后自己猜对方收到没有——清屏结果没法验证。这跟 `ball_pos` 那种「一直发、没人听也无所谓」的场景正好相反。

## 四、差速三公式

- `v = (vL + vR) / 2` → 整车平移速度就是左右两个轮子速度的平均值。两轮同速时 v 等于轮速；两轮一快一慢时，车身中心仍然只按平均值前进，多出来的那部分速度差全部转成转动。
- `ω = (vR − vL) / L` → 角速度来自两轮的**速度差**：右轮比左轮快多少、快多少除轮距，就转多快。两轮同速 ω = 0，走直线；反转时转得最猛。这是差速底盘能转弯的根本原因。
- `r = v / ω` → 转弯半径。ω 越小弯越大，ω = 0 时 r 是无穷大，也就是直线；ω 固定、v 越大则走的圆越大。想原地转就把 v 设成 0（此时 r = 0，绕自身中心转）。

对应到 `Twist` 的用法：直行 `linear.x = v, angular.z = 0`；原地转 `linear.x = 0, angular.z ≠ 0`；画弧两者都非 0。

## 五、踩过的坑 & 怎么解决的

1. **`colcon build` 报 `The install base 'install' is not a directory`** → 我发现命令是在 `~/ros2_ws/src` 目录下跑的，`colcon` 会在当前目录找 `install/` → `cd ~/ros2_ws` 回到工作空间根目录重新 build，一次就过（`01_colcon_build.png` 里报错和成功在同一张图，刻意留了证据）。
2. **编译报一堆 `rosidl` 相关的错** → 就是细则预告的那个坑：`package.xml` 少了 `<member_of_group>rosidl_interface_packages</member_of_group>`。补上这行、连同 `rosidl_default_generators`（buildtool_depend）和 `rosidl_default_runtime`（exec_depend）一起配齐后才通过。
3. **`ros2 run` 报 `No executable found`** → 两个原因叠加：① 脚本没加可执行权限；② `CMakeLists.txt` 里没用 `install(PROGRAMS ...)` 把脚本装进 `lib/<包名>`。`chmod +x scripts/*.py` + 补 install 段 + 重新 build 后解决。
4. **乌龟转向时绕远路** → 目标方位角和当前朝向直接相减会算出 340° 这种值（明明转 -20° 就行）。用 `atan2(sin(Δ), cos(Δ))` 把角度差归一化到 [-π, π]，保证永远走最短转向。
5. **乌龟到点后不停下来、在附近打转** → 只有到点判定没有速度收敛：线速度不随距离衰减就会一直冲。加上「越近越慢」+ 限速 0.8 之后轨迹才干净（见第二节的原因说明）。
