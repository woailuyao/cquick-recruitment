## 1. 串口四参数

**串口**就是把一个字节拆成8位，在一根线上按时间顺序发出去。没有时钟线，所以收发双方
必须**事先约好速度**，这个速度就是波特率。

| 参数 | 含义 | 常用值 |
| --- | --- | --- |
| 波特率 | 每秒传多少位（bit/s），双方必须一致 | 115200、9600 |
| 数据位 | 一个字符用几位，8 位正好对应 ASCII 表里的一个字符 | 8 |
| 停止位 | 一帧的结尾标志，电平拉高 | 1 |
| 校验位 | 简单查错（奇/偶/无） | 无（N） |

写作 **8-N-1**。除此之外还有**起始位**用来说明开始传输了。

## 2. 回环测试

**接线**：CH340 USB 转 TTL 模块，用一根杜邦线把 **TX 和 RX 直接短接**，不接 VCC，
GND 是同一块板本来就共地。

**环境**：设备在 Windows 主机上，用 Serial Assistant 打开 **COM9**，参数 **9600 / 8 位 / 1 停止位 / 无校验 / 无流控**。

**操作与现象**：

- 发送 `xuyuhan` → 接收区原样返回 `xuyuhan`
- 发送 `123456` → 原样返回 `123456`
- 发送 `徐宇涵` → 原样返回 `徐宇涵`

**结论**：发送什么就收到什么，说明 USB 转串口的驱动、端口、TX/RX 通路都正常。


## 3. 波特率不一致的原理

每一位占用的时间是 `1 / 波特率`：

- 115200 → 1 位约 **8.7 微秒**
- 9600 → 1 位约 **104 微秒**

接收方靠起始位那个下降沿对齐，然后按自己的节拍，**在每个位的正中间采样**一次。

如果两边波特率不同，接收方的采样点就会出现错位：开始还在位中间，几十微秒后就偏到了
位边界甚至邻位上，于是 0 被读成 1、1 被读成 0。所以表现出来的是一整串乱码。

## 4. 总线舵机指令逐字拆解

总线舵机不用单独的信号线，**所有舵机挂在同一条串口总线上，靠 ID 区分**。指令是 ASCII 字符串，
`#` 开头 `!` 结尾。通信参数：波特率 115200，PWM 范围 500–2500，**1500 是中立位**。

以 `#001P1500T1000!` 为例，拆成七段：

| 段 | 含义 | 规则 |
| --- | --- | --- |
| `#` | 指令起始符 | 固定 |
| `001` | 舵机 ID | 固定 3 位，1 号写 001 |
| `P` | 位置指令标识 | 后面跟 PWM 值 |
| `1500` | PWM 值 | 固定 4 位，500–2500，1500 = 中立 |
| `T` | 时间指令标识 | 后面跟毫秒数 |
| `1000` | 转动时间 | 固定 4 位，单位 ms，舵机在这段时间内平滑转到位 |
| `!` | 指令结束符 | 固定 |

整句含义：**让 1 号舵机用 1000 毫秒平滑转到 PWM 1500（中立位）**。

**自己推的两条**：

- 1 号舵机转到中立位、用 1.5 秒：`#001P1500T1500!`
- 3 号舵机卸力：`#003PULK!`

其他常用指令：

| 指令 | 作用 |
| --- | --- |
| `#001PID!` | 读 ID，确认总线上有谁 |
| `#001PRAD!` | 读回当前 PWM 位置 |
| `#001PULR!` | 恢复扭力（要它动之前必须先发） |
| `#001PULK!` | 卸力（断电前必须发） |


## 5. 我还没搞懂的问题

**同一根总线上，如果两个舵机同时回数据会怎样？协议靠什么避免？**

我目前的猜测：单线半双工只有一根线，同时说话就是电平打架，接收方会收到叠加的毛刺，帧直接废掉，
严重时两个输出对顶还会有大电流。所以协议应该靠“点名”——控制器发带 ID 的指令，只有对应 ID 的
舵机才回应，其他保持沉默。
