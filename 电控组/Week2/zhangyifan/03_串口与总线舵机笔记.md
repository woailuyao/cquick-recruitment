# 串口与总线舵机笔记
## 一、串口四个参数

串口传数据没有时钟线，双方靠"约定好的速度"对时间，所以叫异步通信。

| 参数 | 我理解的 | 常见值 |
|---|---|---|
| 波特率 | 每秒传多少位（bit），类比人说话一定时间内能讲多少个字 | 115200 / 9600 |
| 数据位 | 一个字符用几位表示，类比一句话由几个字构成 | 8 |
| 停止位 | 一帧结束时拉高，表示发完了 | 1 |
| 校验位 | 简单查错 | 无（N）|

四个参数合起来写成 8-N-1：8 个数据位、无校验、1 个停止位。

一帧的完整结构：空闲（高电平）→ 起始位（低）→ 8 个数据位 → 停止位（高）→ 空闲。
起始位的作用是告诉对方"我要开始发了"，接收方靠它对齐节奏。

## 二、三个硬件常识

1. 必须共地：两个设备要靠在同一个"零伏"参考点上判断高低电平。只接 TX/RX 不接 GND，收不到数据是必然的。
2. 电平要匹配：5V 和 3.3V 的设备不能直接连，会烧掉 3.3V 那一侧，要么加电平转换，要么确认器件兼容。
3. 单线半双工：总线舵机所有设备挂在同一条信号线上，自己发出去的数据自己也会"听到"，所以同一时刻只能有一个设备说话，靠 ID 区分是谁的。

## 三、回环测试

没做。计划下周拿到舵机后再补做。
预期现象：把 TX 和 RX 用一根线短接，发送的字符会原样回显；如果波特率设错，回显会是乱码。

## 四、波特率不一致为什么会乱码

串口是"按时间采样"的：接收方每隔 1/波特率 秒去读一次线是高还是低。
双方波特率不一样，采样点会越来越偏，最后采到位与位中间，甚至采到隔壁位，
本来该读成 0100 0001（字母 A），结果读成了别的组合，显示出来就是乱码。

打个比方：两个人用不同语速数数，一个数得快、一个听得慢，两个人就无法互相理解了。

一般允许 2%~3% 的误差，超过就一定错。所以这不是设备坏了，是双方的节拍对不上。

## 五、舵机指令逐字拆

指令：#001P1500T1000!

| 段 | 含义 | 规则 |
|---|---|---|
| # | 帧起始 | 固定 |
| 001 | 舵机 ID | 固定 3 位 |
| P | 位置控制指令 | 让舵机转到指定位置 |
| 1500 | PWM 值 | 固定 4 位，范围 500–2500，1500 是中立位 |
| T | 时间参数 | 后面跟用时 |
| 1000 | 用时 1000ms | 固定 4 位，舵机用这段时间平滑转过去，不是瞬间跳 |
| ! | 帧结束 | 固定 |

另外几条：
- #001PID!  读 ID
- #001PRAD! 读当前位置
- #001PULR! 恢复扭力（要它动之前必须先发）
- #001PULK! 卸力（下电前必发，防止堵转发热烧舵机）

我自己写两条：
- 1 号舵机转到中立、用 1.5 秒：#001P1500T1500!
- 3 号舵机卸力：#003PULK!
