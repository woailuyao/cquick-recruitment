## 任务 1：自定义消息 + 发布/订阅

我定义了 BallPos 消息（int32 id、float32 x、float32 y），用 ament_cmake 包编译，
写了一个发布者每 0.5 秒发三颗球（坐标 2.0/3.0、5.5/8.0、9.0/4.0），
另一个订阅者接收并打印。
改参数观察：把发布频率从 0.5 秒（2 Hz）改成 0.2 秒（5 Hz）后，
订阅端的打印密度明显变高，约是原来的 2.5 倍；说明两端的频率是一致的，
只是发送节奏变快了。验证完已改回 0.5 秒。

踩过的坑：
- ros2 run 报 No executable found：CMakeLists.txt 少了 install(PROGRAMS ...)，
  脚本没被装进 lib/<包名>/ 目录。
- 接着报 Exec format error：脚本第一行缺了 #!/usr/bin/env python3，
  系统不知道该用什么程序执行它。

## 任务 2：订阅球坐标，依次导航

写了一个 nav_balls 节点：用字典按 id 收齐三颗球，同时订阅 /turtle1/pose 拿实时位姿，
用闭环控制让乌龟依次走到 (2,3)、(5.5,8)、(9,4)。

控制逻辑：
- 算出到目标的距离和方位角差；
- 角度差大于 0.3 弧度时先原地转，对准了再走；
- 线速度跟距离挂钩（越近越慢），避免冲过头；
- 距离小于 0.3 判定到达，打日志并切下一个点。

实际结果：三个点误差分别是 0.28、0.30、0.28，均小于 0.5。

踩过的坑：CMakeLists 加了安装项但忘了保存文件，编译报
"file INSTALL cannot find nav_balls.py"——编译失败原因永远在输出最后几行。

## 三种通信方式对比

| 方式 | 模型 | 特点 | 足球机器人里的用法 |
|---|---|---|---|
| 话题 | 发布/订阅，多对多 | 单向、持续流、不管对方在不在 | 视觉持续广播球坐标 |
| 服务 | 请求/响应，一对一 | 同步、有返回值、调一次答一次 | 清屏、查比分、切模式 |
| 动作 | 目标/反馈/结果 | 长任务、能报进度、可取消 | 走到指定点 |

任务 1 用的是话题。任务 2 开头那条清屏命令
`ros2 service call /clear std_srvs/srv/Empty` 是一次服务调用——
它必须有回应、调一次就结束，这是服务和话题最直观的差别。

## 差速三公式

- 线速度：v = (vL + vR) / 2
- 角速度：ω = (vR − vL) / L
- 转弯半径：r = v / ω

ω = 0 走直线；ω 越小弯越大；两轮反向就是原地转。
