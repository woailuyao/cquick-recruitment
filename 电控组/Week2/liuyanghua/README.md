## 三、三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
|---|---|---|---|
| 话题 Topic | 发布-订阅（所有数据） | 可以任何一方随时发送，所有节点立即接收，且可以持续发布 | |
| 服务 Service | 客户端请求-服务端返回（request/response） | 一对一联系，请求需要等待服务端响应再继续 | |
| 动作 Action | 设置目标-持续反馈-结果（goal/result/feedback） | 适合长任务，不阻塞进程，中途持续反馈进度，中途可以取消，任务的请求和取消都需要服务端同意 | |

**我实际用到的服务调用**：<`ros2 service call /clear std_srvs/srv/Empty`：向turtlesim节点发送请求，等待节点响应，然后完成请求(清屏)；服务需要等待，有别于话题的实时性。除此之外，似乎改变参数也是类似服务的方式，我改变节点发布频率也是需要等待响应>

## 四、差速三公式

- `v = (vL + vR) / 2` → <如果两轮速度一致，则v就是轮速，如果不一致，机器人以弧线轨迹前进，v就是内环与外环线速度的平均值，即机身作为中心，其运行轨迹是两轮连线中点划过的轨迹，从而线速度就是内外环线速度的平均>
- `ω = (vR − vL) / L` → <显然，两轮反着转会让机器人转起来，转速相同那就总体v=|vR|=|vL|，根据ω=v/L得出角速度(此处L为直径，L=2R)，如果转动方向相同以及转速绝对值不同，机器人以弧线轨迹前进，也可以推导出公式。但是此处正负的定义需要谨慎>
- `r = v / ω` → <高中公式，此处r是运动半径，实际控制情况是线速度与角速度决定转弯半径>
