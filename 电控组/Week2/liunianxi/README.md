## 三、三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
|---|---|---|---|
| 话题 Topic | 发布 / 订阅，单向、多对多 | 像 Scratch 里的「广播」：负责单向地对多方发布消息，发的人不管有没有人在听 | 视觉节点持续广播球的位置；战术节点持续广播速度指令 |
| 服务 Service | 请求 / 响应，一对一 | 一对一，而且必须收到应答才算完成，调一次答一次 | 「现在比分多少」「切到防守模式」，还有我任务 2 开头的 `/clear` |
| 动作 Action | 目标 / 反馈 / 结果 | 给机器人发的连续命令，跑的过程中能报进度，出问题可以随时叫停 | 「走到 (1,1)」这种要跑几秒的活，中途能看进度、能取消 |

**我实际用到的服务调用**：任务 2 开始前的 `ros2 service call /clear std_srvs/srv/Empty`。因为 service 是「一问一答」式的通信方式，必须有应答才能结束；如果换成 topic 就没有「完成」这个反馈，我就不知道它到底清没清屏，所以 `/clear` 必须是服务。

## 四、差速三公式

- `v = (vL + vR) / 2` → 粗略可理解为物理里的**线速度**：决定车整体跑多快，两个轮子的速度取平均。
- `ω = (vR − vL) / L` → 就是**角速度**：决定转弯快慢，看两轮的速度差再除以轮距，差越大转得越急。
- `r = v / ω` → 就是**转弯半径**：决定转弯的轨迹，`ω` 越小弯越大，`ω = 0` 就是直线。
