# 串口基础 + 总线舵机串口模式 · 学习笔记

> 第 2 周任务 3。这周不发舵机，所以重点是「搞懂、看懂」：串口四参数、回环、波特率、舵机指令格式。

## 1. 串口四参数

串口一次只走一根线传一个 bit，所以双方得先约好「怎么读这些 bit」，这就是四参数：

| 参数 | 是什么 | 常见值 | 不一致会怎样 |
|---|---|---|---|
| 波特率 | 每秒传多少位（bit/s） | 115200、9600 | 直接乱码（下面单独说） |
| 数据位 | 一个字符用几位表示 | 8 | 位对不齐，字符被截断/多读 |
| 停止位 | 一帧结束时拉高的那一位 | 1 | 帧边界判断错位，越读越乱 |
| 校验位 | 简单的查错位（奇/偶/无） | 无（N） | 校验方式不同，接收端把好数据判成坏数据 |

常见的默认组合写出来就是 **8-N-1**：8 个数据位、无校验、1 个停止位。实际画出来的波形是「1 个起始位（低）+ 8 个数据位 + 1 个停止位（高）」，一帧 10 个 bit 时间。

## 2. 回环测试

我**没有做**回环测试——手上没有 CH340 模块，舵机下周才发，实验室的 24 路控制器我也还没摸到。

**计划**：下周拿到舵机（或先借个 CH340），把模块的 TX 和 RX 用一根杜邦线短接，然后用串口助手发 `hello`，预期能在接收区原样看到 `hello`，而且波特率改成 9600 之后看到的是乱码。

**我认为回环通了会看到的现象**：发什么收什么、字数一致；如果加个十六进制显示，`hello` 会显示成 `68 65 6C 6C 6F`；如果把波特率改成和发送端不一样，收到的就是一串 `烫烫烫` 似的乱码或干脆收不到。

## 3. 波特率不一致为什么是乱码

波特率描述的是「每一位持续多长时间」：115200 时一个 bit 约 8.68 µs。

接收端并不知道发送端什么时候开始发，它靠**起始位**下降沿对齐，然后按自己的节拍每隔一个 bit 时间采样一次。如果两边波特率不一样，采样点就会一点点偏移：开始几位还能采到对的电平，越往后偏得越多，到第 5、6 位的时候采样点可能正好落在电平跳变的地方，采出 0 或 1 全凭运气——于是同一个字节被读成完全不同的值，看起来就是乱码。

所以这不是「设备坏了」，而是**采样节拍对不上**。波特率偏差在 2%~3% 以内一般还能用（UART 允许一定容差），超了就必乱。

## 4. 总线舵机指令逐字拆解

总线上所有舵机挂在一根线上，靠 **ID** 区分谁听谁的。指令是 ASCII 字符串，`#` 开头、`!` 结尾。

### `#001P1500T1000!` 拆成七段

| 段 | 含义 |
|---|---|
| `#` | 指令起始符，告诉舵机「一句话开始了」 |
| `001` | 舵机 ID，固定 3 位，这里指 1 号舵机 |
| `P` | 功能码，P = 控制位置（PWM） |
| `1500` | 目标 PWM，固定 4 位，范围 500–2500，1500 是中立位 |
| `T` | 功能码，T = 时间（Time） |
| `1000` | 转动时间，固定 4 位，单位 ms，表示用 1000 ms 平滑转到位（不是瞬间跳过去） |
| `!` | 指令结束符 |

所以这条指令的意思是：**让 1 号舵机在 1000 ms 内平滑转到 PWM 1500（中立位）**。

### 自己写两条

- 让 1 号舵机用 1.5 秒转到中立位：`#001P1500T1500!`
- 让 3 号舵机卸力：`#003PULK!`

（按手册，要让舵机动之前得先发 `#003PULR!` 恢复扭力；断电前发 `PULK` 卸力，防止堵转发热烧掉。）
