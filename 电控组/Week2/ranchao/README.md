- 到达情况：

| 球编号 | 目标坐标 | 实际到达坐标 | 误差 |
|---|---|---|---|
| 1 | (2.0, 3.0) | (2.00, 3.00) | 0.013 |
| 2 | (5.5, 8.0) | (5.48, 7.95) | 0.000 |
| 3 | (9.0, 4.0) | (9.00, 4.00) | 0.001 |

- 关键参数：到点阈值 `ARRIVE_TOL = 0.1`、允许前进的角度残差 `ANGLE_TOL = 0.15 rad`、最大角速度 `TURN_SPEED = 1.2`、最大线速度 `MOVE_SPEED = 1.2`、控制循环 10 Hz
- 为什么这样调：
  - 细则只要求误差 ≤ 0.5，我把阈值收到 0.1，留够余量，实际跑出来三个点误差都在 0.02 以内。
  - 一开始只想「朝目标直接走」，结果乌龟会侧着滑过去甚至原地打转。加了 `ANGLE_TOL` 之后逻辑变成「偏差大就原地转、对准了才前进」，轨迹一下子就直了。
  - 速度不是恒定的：`linear.x = MOVE_SPEED * max(0.3, 1 - |角度偏差|)`，越接近目标、偏差越小，走得越慢，避免冲过头。

## 三、三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
|---|---|---|---|
| 话题 Topic | 发布/订阅，多对多 | 单向、持续流、不管对方在不在听 | 视觉节点以固定频率广播球的位置；战术节点持续广播目标速度指令 |
| 服务 Service | 请求/响应，一对一 | 同步、有返回值、调一次答一次就结束 | 开赛前查询「现在是红方还是蓝方」；中途请求「切换到防守模式」 |
| 动作 Action | 目标/反馈/结果 | 适合长任务，过程中不断报进度，可以中途取消 | 「走到 (1.5, 2.0) 这个点」——走的过程中报进度，发现球跑了可以取消重来 |

我实际用到的服务调用：任务 2 开始前的 `ros2 service call /clear std_srvs/srv/Empty`。

它是一次标准服务调用，不是话题：我发出请求后，终端立刻返回 `response: std_srvs.srv.Empty_Response()`，**一问一答就结束**，不会持续输出的数据流。如果是话题，我会看到一直刷新的消息，除非服务端专门再发一条，否则不会给我回应。这也正好说明为什么「清屏」这种「做一次就完事、需要确认做没做」的动作用服务比用话题合适。

## 四、差速三公式

- `v = (vL + vR) / 2` → 线速度是左右轮速的平均值。两轮都往前 1 m/s，车就往正前方走；一轮 1 一轮 0，车的实际前进速度只有 0.5 m/s。
- `ω = (vR − vL) / L` → 角速度是左右轮速之差除以轮距。轮子不差速（vL = vR）时 ω = 0，走直线；左轮慢右轮快，ω 为正，向左转；差得越多转得越急。
- `r = v / ω` → 转弯半径 = 线速度 ÷ 角速度。同样的速度下 ω 越小（转得越慢），画出来的弧越大；ω 趋近 0 时半径趋于无穷，也就是直线。

写代码时对应的就是：`cmd_vel.linear.x` 控制 v，`cmd_vel.angular.z` 控制 ω。想让乌龟原地转，就把 linear.x 给 0、angular.z 给非零；想直着走，就是 linear.x 非零、angular.z 给 0。

## 五、踩过的坑 & 怎么解决的

1. 编译时报一大堆 `rosidl` 相关错误，说找不到消息类型
   → 第一反应是以为 `CMakeLists.txt` 写错了，反复改 `rosidl_generate_interfaces`。后来在报错里搜关键词发现提示「找不到接口组」
   → 最后是 `package.xml` 里少了一行 `<member_of_group>rosidl_interface_packages</member_of_group>`。补上这一行，重新 `colcon build` 立刻通过。原来消息包不只是「有 msg 文件」就行，还得向系统声明自己属于接口包分组。

2. `ros2 run` 报 `No executable found`
   → 以为包没编译成功，反复 `colcon build` 都正常
   → 查了才知道是 `CMakeLists.txt` 里少了 `install(PROGRAMS scripts/xxx.py DESTINATION lib/${PROJECT_NAME})`，脚本没被安装进包的 `lib` 目录，`ros2 run` 自然找不到。顺便还发现脚本得先 `chmod +x` 才有执行权限。

3. 复制代码后 `if __name__ == '__main__'` 不生效，脚本一跑就退出
   → 现象很怪：程序退出码是 0，看起来「成功」了，但什么都没干
   → 排查发现代码块里的双下划线在划选复制时被聊天界面加了隐藏字符，`__main__` 变成了 `_&#8203;main_`，判断永远为假
   → 后来改成用代码块右上角的复制按钮而不是鼠标划选，问题就没了。这让我知道了程序「没报错」不代表「跑对了」。

4. `git pull` 报 `Failed to connect to github.com:443`
   → 一开始以为是 Git 配置或者账号问题，查了远程地址、查了凭据都没问题
   → 实测发现是本地代理软件没有正常运行，所有流量都堵在那里；直连 GitHub 也不通
   → 把代理软件重新打开后 `git pull` 直接就通了。

5. `git pull` 突然弹出一个全是 `~` 的界面，敲什么都退不出去
   → 吓了一下，以为把仓库搞坏了
   → 后来知道那是 vim 编辑器，git 在让我确认合并信息。按 `Esc` 再敲 `:wq`， 回车就正常退出了。
