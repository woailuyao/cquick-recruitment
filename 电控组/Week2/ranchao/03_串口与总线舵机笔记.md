# 03 · 串口与总线舵机学习笔记

> 第 2 周任务 3。本周没有舵机实物，这份笔记只做一件事：把串口和总线舵机的通信搞清楚、看懂指令。

## 一、串口四个参数

串口通信是两个设备之间「一个电平一个电平地传数据」，要能对上话，双方必须约定同一套规则。这套规则就是四个参数。

### 1. 波特率（Baud Rate）

**每秒传多少个「位」（bit）**。常见值 9600、115200。

我们用的是 **115200**，也就是每秒传 115200 个 bit。按一个字节 10 bit 算（1 起始位 + 8 数据位 + 1 停止位），大约每秒 11520 个字节，每个字节大约 87 微秒。

**波特率不一致会怎样：收到一堆乱码。**

为什么会乱码，我按自己的理解复述一遍：

串口线上没有「时钟线」告诉接收方「这个电平该采了」，双方全靠各自数时间。发送方按自己的波特率决定每个 bit 持续多久，接收方按自己设定的波特率去「每隔多久看一眼」线上的电平。

比如发送方用 115200（每 bit 约 8.68 微秒），我却把接收方设成 9600（每 bit 约 104 微秒）。接收方一个 bit 的时间，发送方已经发了 12 个 bit 了。接收方每「看一眼」，看到的其实是发送方第 12 个位上的电平，拼起来的字节和原始数据完全是两回事。数据没错、线也没坏，只是**采样的节拍对不上**。所以乱码不是设备故障，是「节拍问题」。

### 2. 数据位（Data Bits）

**一个字符用几位来表示**。常见值 8。

8 位正好是一个字节，能表示 0~255，ASCII 字符全都能装下。用 7 位也行（只能装 0~127），但发了中文、或者值超过 127 的数据就废了。所以基本都用 8。

### 3. 停止位（Stop Bits）

**一帧的结尾标志**。常见值 1。

一帧数据传完，线上要保持一段时间的高电平，告诉接收方「这一帧结束了，准备接下一帧」。用 1 位就够，够接收方反应过来的时间。

### 4. 校验位（Parity）

**最简单的查错方式**。常见值：无（N）。

它的原理是：发送前统计一下 8 个数据位里「1」的个数是奇数还是偶数，把这个信息（0 或 1）作为第 9 位一起发出去。接收方自己再数一遍，对不上就知道传输过程中有 bit 被干扰翻了。

我们用的舵机是**无校验（N）**——因为舵机指令本身以 `#` 开头、`!` 结尾，格式很明显，错了很容易看出来，而且现场线缆短、干扰小，省一个位还能传快一点。

### 默认组合：8-N-1

四个参数合起来的标准写法就是 **8-N-1**：8 个数据位、无校验、1 个停止位。这是绝大多数设备的默认设置，也是我们舵机的设置。

## 二、回环测试

**未做。** 手里没有 CH340 这个 USB 转 TTL 模块，这周也没去实验室借舵机控制器。计划下周拿到舵机后补做。

**我认为回环通了会看到什么：**

回环的做法是把模块自己的 TX（发送）和 RX（接收）用一根杜邦线短接起来，这样就等于「自己发给自己」。

- 如果用一个串口助手软件（比如 Windows 上的 XCOM、SSCOM），设置 115200 / 8-N-1，在发送框输入 `#001P1500T1000!` 点发送，**接收框里应该原样出现这串字符**；
- 如果波特率设错了（比如接收端设 9600、发送端 115200），接收框里会是一堆看不懂的符号或者问号；
- 如果 GND 没接好，接收框大概率是**空的**，因为两边没有共同的电压参考点，判断不了什么是高电平。

所以回环测试其实一次能把三件事验掉：波特率对不对、接线通不通、GND 有没有共地。

## 三、各个设备的地必须连通（GND）

这一条我单独写，因为细则里点了名，而且我很可能在这里翻车。

两个设备通信，本质是「用电压判断 0 还是 1」。比如 3.3V 算高、0V 算低。但「3.3V」是相对于**谁**而言的？相对于各自的 GND。

如果两个设备的 GND 没有连在一起，A 设备说的「3.3V」是相对于 A 的地，B 设备量到的电压是相对于 B 的地。两个地之间可能有几伏的电位差，B 看到 A 的「高电平」可能变成 5V，也可能变成 0V，判断全乱。

**现象就是：只接了 TX 和 RX，数据一条都收不到；把 GND 也连上，立刻通了。**

所以接线第一位永远是 **TX → RX、RX → TX、GND → GND**。注意 TX 和 RX 要**交叉**接（我的发送接你的接收）。

另外细则还提到**电平不匹配**：5V 的设备直连 3.3V 的设备会烧掉 3.3V 那一侧的引脚。舵机控制器和串口模块的电压等级要先确认，不确定就加电平转换模块。

## 四、总线舵机串口指令逐字拆解

总线舵机和普通舵机最大的区别：**普通舵机每根信号线只控制一个舵机（靠 PWM 脉宽），总线舵机是所有舵机挂在同一根串口线上，用 ID 区分是谁。**

指令是 ASCII 字符串，`#` 开头、`!` 结尾。

### 逐字拆 `#001P1500T1000!`

| 段 | 内容 | 含义 |
|---|---|---|
| `#` | 井号 | 指令起始符。告诉舵机「一条指令从这里开始」，用来和上一条指令分隔。 |
| `001` | 舵机 ID | 指定**哪个**舵机执行。固定 **3 位**，所以 1 号要写 `001` 不是 `1`。总线上几十个舵机靠这一段区分。 |
| `P` | 命令字 | 表示这次要做的是「设定位置（Position）」。不同的字母代表不同功能：`P` 写位置、`PID` 读 ID、`PRAD` 读位置、`PULR` 恢复扭力、`PULK` 卸力。 |
| `1500` | PWM 值 | 舵机转到的目标位置。固定 **4 位**，范围 **500–2500**，其中 **1500 是中立位**（大概在舵机行程的正中间）。500 和 2500 分别是两个方向的极限。 |
| `T` | 时间命令字 | 表示后面跟的是「用时（Time）」。 |
| `1000` | 时间值 | 走完这段角度用多久，单位 **毫秒**。1000 = 1 秒。舵机会在这 1 秒里平滑地转过去，**不是瞬间跳过去**——这一点很重要，瞬间大角度跳转会冲击齿轮。 |
| `!` | 感叹号 | 指令结束符。舵机看到它才开始执行，没有它指令不生效。 |

整句读下来就是：**「1 号舵机，请用 1000 毫秒的时间，平滑地转到 PWM 1500（中立位）。」**

### 自己写两条

**① 让 1 号舵机转到中立位，用 1.5 秒**

1.5 秒 = 1500 毫秒，所以时间是 `1500`。

```
#001P1500T1500!
```

**② 让 3 号舵机卸力**

卸力是 `PULK`，不需要位置和时间参数。3 号 ID 写成 `003`。

```
#003PULK!
```

### 顺带记住的安全顺序

舵机上电后不是立刻有力气的，要发 `PULR` 恢复扭力它才「硬」起来；下电前一定要发 `PULK` 卸力，不然舵机会一直顶着力，堵转发烫，长期会烧。所以实际用的时候是个固定流程：**读 ID → 恢复扭力 → 写角度 → 读位置 → 卸力**。

## 五、我还没想明白的问题

**问题一：为什么发 `PULR` 恢复扭力之后，舵机的位置会「丢」或者跳一下？**

手册里说要它动之前必须先发 `PULR`，但我不太理解这个机制的物理过程。卸力（`PULK`）的时候舵机是没有阻力的，我可以用手随便扳它的转轴。这时候舵机内部到底还记不记得自己在哪？如果我扳了一圈再恢复扭力，它是回到原来的位置，还是从当前这个被我扳到的位置继续？

我猜可能是：卸力时电机断电但编码器还在计数，位置信息还能记住；恢复扭力后它会朝它记录的位置回去。但这只是猜的，下周拿到实物我想试一下——卸力后用手扳一下，再发 PULR，看它动不动、动多少。

**问题二：同一根总线上如果两个舵机 ID 设成一样了会怎么样？**

因为所有舵机共用一条线，指令靠 ID 区分。如果我不小心把两个舵机的 ID 都设成 001，发 `#001P1500T1000!` 的时候，是两个都会动，还是会冲突、谁都收不对？如果是两个都动，那在拼装前怎么避免这个问题——是不是每个舵机上电前都要单独接、单独设 ID？

这两个问题下周实操时应该能自己找到答案。
