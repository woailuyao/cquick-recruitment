## 三、三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
|---|---|---|---|
| **话题 Topic** | 发布/订阅，多对多 | 单向、持续流、不管对方在不在 | 视觉节点持续广播球位置；战术节点持续广播速度指令 |
| **服务 Service** | 请求/响应，一对一 | 同步、有返回值、调一次答一次 | 「现在比分多少」「切到防守模式」 |
| **动作 Action** | 目标/反馈/结果 | 长任务、能报进度、可中途取消 | 「走到点 (1,1)」→ 过程报进度，走错可取消 |

**我实际用到的服务调用**：任务 2 开始前本该先执行
`ros2 service call /clear std_srvs/srv/Empty` 清屏。这条命令是典型的**服务**而不是话题：它必须有一个回应，而且调一次就结束，不会像 `/ball_pos` 那样一直发。

**我自己的理解**：话题像广播电台，发的人不知道有几个人在听；服务像打 110，得有人接、接完就挂；动作像点了外卖，中间还能看骑手到哪了、也能取消。

## 四、差速三公式

- `v = (vL + vR) / 2` —— 左右轮速取平均就是车体前进的线速度。两轮同速直行时 v 就等于轮速；一快一慢时取中间值。
- `ω = (vR − vL) / L` —— 左右轮速之差除以轮距 L，就是车体转多快。右轮快 → ω 为正 → 左转（逆时针）；两轮同速 → ω = 0 → 走直线。
- `r = v / ω` —— 转弯半径。ω 越小弯越大；ω 趋于 0 时 r 趋于无穷，就是直线。

## 五、踩过的坑 & 怎么解决的

1. **`ros2 run ball_comm ball_publisher` 报 `No executable found`。**
   我以为是包没编译好，查了 `install` 目录，脚本其实已经装进去了。
   最后发现是**文件名带 `.py`**：`ros2 run` 找的是 `lib/ball_comm/` 下的**文件名**，所以命令必须写成 `ball_publisher.py`。
   教训：报错说的是「找不到可执行文件」，不是「包不存在」，这两件事要分开查。

2. **`ros2 pkg create` 建包建到了错误的位置。**
   我在终端粘贴命令时，第一行被粘进了 `[200~` 这个控制符，导致 `mkdir ~/ros2_ws/src` 没执行成功，后面的 `cd` 也失败，包就建到了 `/home/zeng/ball_comm`。
   解决：`mv ~/ball_comm ~/ros2_ws/src/` 移回去。
   教训：粘贴后先看一眼命令行的第一个字符对不对。

3. **`~/ros2_ws` 根本不存在。**
   第 1 周只跑了 `/opt/ros` 里现成的节点，从没建过工作空间，所以细则前置准备第 3 条必须补做，否则 `colcon build` 无处可编。

4. **改发布频率。**
   把 `create_timer(0.5` 改成 `create_timer(0.2`，重新 `colcon build` 后，订阅端从每秒 6 条变成每秒 15 条（3 个球 × 5 Hz）。改完必须重新 build，因为脚本是被 install 过去的副本，改源码不重编不会生效。

5. **`package.xml` 的 `member_of_group` 那行**（细则 FAQ Q3 提到的头号坑）。
   我一开始就照细则把它写上了，所以没踩到，但看报错就知道了：少了它 `colcon build` 会甩一堆 `rosidl` 不开头的错，光看报错找不到原因。
