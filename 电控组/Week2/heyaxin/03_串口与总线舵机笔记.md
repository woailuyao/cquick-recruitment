## 一、串口四参数

| 参数  | 我的理解                                | 常见值           |
| --- | ---------------------------------------- | ------------- |
| 波特率 | 每秒传输多少位，代表传输速度，双方要统一                   | 115200 / 9600 |
| 数据位 | 一个字符里真正用来传有效数据的比特数量                    | 8             |
| 停止位 | 一帧数据结束的标记，告诉对方一组数据传完了，留给接收端时间准备接收下一组数据 | 1             |
| 校验位 | 简单查错用的附加比特，用来判断传输中有没有出错，只能查错，不能纠错      | 无（N）          |

**默认组合**：8-N-1（一个字节 8 位数据、无校验、1 位停止）

**波特率不一致会怎样？为什么？**

会怎样：双方按照自己的节拍发送和接收指令，结果是乱码，指令无法执行。

为什么：串口属于异步通信。收发双方通过波特率确定数据传输速度，如果收发端比特率不一致，则传出的数据与收到的数据会有偏移，接收端解析出来的是乱码，无法识别指令。比如接收端为 9600，它接收 1 bit 的时间是 1/9600 ≈ 104.17 μs；发送端若为 115200，发送 1 bit 的时间是 1/115200 ≈ 8.68 μs。接收端接收数据的速度比发送端慢得多，采样点会一路偏移，可能跳过某些 bit，0 被读成 1、1 被读成 0，最终结果乱码。

## 三、波特率不一致的原理

**要求：讲到自己能脱稿复述给别人听。**

1. 串口是异步通信，没有时钟线来同步收发，双方约定好「每一位持续多久」；
2. 这个时长由波特率决定：115200 → 每位约 8.68 μs；9600 → 每位约 104 μs；
3. 接收方在起始位下降沿（电压从高变低）开始，接收端检测到这个下降沿就启动自己的计时器，按自己的节拍每过一位时间采样一次；
4. 一旦两端节拍不同，计时速度不一样，采到的点会逐渐偏离位的中心，越往后错得越多；高位是这一帧里比较晚才采的样，所以高位数据先错；
5. 结果就是整帧解码错误，屏幕上显示乱码，舵机无法识别指令。

## 四、舵机指令逐字拆解

### 4.1 拆 `#001P1500T1000!`

| 段 | 内容     | 含义                      |
| - | ------ | ---------------------------- |
| 1 | `#`    | 一帧指令的起始                    |
| 2 | `001`  | 舵机 ID，固定 3 位，代表 1 号舵机           |
| 3 | `P`    | 位置控制指令                     |
| 4 | `1500` | PWM 位置值（500–2500，1500 为中立位置） |
| 5 | `T`    | 时间参数                       |
| 6 | `1000` | 平滑转动耗时，四位，单位 ms             |
| 7 | `!`    | 指令结束                       |

**字段规则**：ID 3 位、PWM 4 位（500–2500，1500 为中立）、时间 4 位单位 ms、波特率 115200、供电 5–8.4 V。

### 4.2 自己写两条指令

| 要求                               | 我写的指令               |
| -------------------------------- | ------------------- |
| 让 **1 号**舵机转到**中立位**、用 **1.5 秒** | `#001P1500T1500!`   |
| 让 **3 号**舵机**卸力**                | `#003PULK!`         |

> 备注：时间是 4 位、单位 ms，所以「1.5 秒」要写成 `1500`，不能写 `1.5`；卸力指令的功能码是 `PULK`，必须写全 4 个大写字母，末尾是英文半角 `!`。
