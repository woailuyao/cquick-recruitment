## 任务 2：订阅三个球坐标，依次走过去

写了个导航节点，同时订阅 `/ball_pos` 和 `/turtle1/pose`，用字典按 id 收齐三个球后才开始动，
按 1→2→3 顺序走。用的是闭环：每 0.1 秒算一次距离和方位差，方位差大就先原地转，
对准了再边走边微调，越接近目标速度越小，防止冲过头。每个点到达时打印实际坐标和误差。

实测误差 0.13 / 0.13 / 0.14，一次跑成。

## 三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人场景 |
| --- | --- | --- | --- |
| 话题 Topic | 发布/订阅，多对多 | 单向、持续流、不管对方在不在 | 视觉持续广播球位置、战术广播速度指令 |
| 服务 Service | 请求/响应，一对一 | 同步、有返回值、调一次答一次 | 查当前比分、切换防守模式 |
| 动作 Action | 目标/反馈/结果 | 长任务、可报进度、可取消 | 让机器人走到指定点，可中途取消 |

我在任务 2 里实际用到的服务调用：

```bash
ros2 service call /clear std_srvs/srv/Empty
```

清空乌龟已画的轨迹，让现场干净——它必须有回应、只调一次就结束，这就是服务和话题最直观的差别。

## 差速底盘三个公式

- 线速度：`v = (vL + vR) / 2`
- 角速度：`ω = (vR - vL) / L`
- 转弯半径：`r = v / ω`

线速度一定时，角速度越小转弯半径就会越大
