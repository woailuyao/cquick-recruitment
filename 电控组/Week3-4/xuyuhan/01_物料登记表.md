## 五、安全区间实测（对应 `01_安全区间实测.png`）

**方法**：单向逼近法 —— 从 1500 出发，每步 100 个单位向外走，每步等 3 秒后连读两次 `PRAD`，
两次一致且与目标偏差 >30 即判定「顶到机械限位」。

| 目标 | 读回 | 偏差 | 判定 |
| --- | --- | --- | --- |
| 1400 | 1405 | +5 | ok |
| 1300 | 1308 | +8 | ok |
| 1200 | 1207 | +7 | ok |
| 1100 | 1105 | +5 | ok |
| 1000 | 1007 | +7 | ok |
| **900** | **1007** | **+107** | **❌ 顶住（读回卡死不再跟随）** |

向上方向 1600~2100 全程偏差 ≤7，未探到机械边界，按厂家电气上限 2100 封顶。

**结论**：

```yaml
pwm_min: 1050     # 物理下止点约 1007，留 43 余量
pwm_max: 2050     # 电气上限 2100，留 50 余量
```

## 八、能脱稿讲清的三件事

**① 为什么必须先发 `PULR`？**
舵机内部有扭力开关，上电默认为卸力状态时只回数据不出力，位置根本不动。`PULR` 是恢复力矩输出，相当于松开刹车。

**② 为什么指令要 `!` 结尾？**
串口是字节流，没有"包"的概念，控制器必须靠明确的帧结束符判断一条指令发完了。`#` 是帧起始、`!` 是帧结束，一问一答靠这两个符号把流切开。

**③ 波特率错了会看到什么？**
收到乱码。两边对"一位多久"理解不一致，采样点全部错位，把 0 读成 1。表现为"收到数据但全是垃圾"，或者干脆收不到。
