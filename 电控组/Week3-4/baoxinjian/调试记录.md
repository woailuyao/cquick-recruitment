# 调试记录（Week 3-4 电控组考核 · 鲍鑫剑）

> 时间跨度：2026-11-12 ~ 2026-11-20
> 环境：VMware Ubuntu 22.04 + ROS2 Humble，USB 转 TTL（CH340）→ LES24-UC 24 路控制板 → 幻岚总线舵机

## 1. 舵机出厂 ID 与文档不符（重要发现）

- **现象**：按考核文档协议（ID 1~254）扫描 ID 1~24，全部无应答；仅收到 `#000P!` 应答，一度误判为控制板故障。
- **排查**：万用表测执行口电源针 0.28V、信号针 3.27V → 怀疑供电；换件对照测试（借同学板子/舵机/电池交叉验证）确认舵机、电池、串口链均正常。
- **根因**：组员实战情报——该批舵机**出厂默认 ID 为 000**，文档声明的 1~254 范围与实物不符，而扫描脚本从 1 开始，恰好错过 000。
- **解决**：扫描范围改为 0~24；`#000PID!`/`#000PRAD!` 全部正常应答。
- **教训**：文档声明的取值范围要与实物核对；扫描永远从 0 开始。已将 4 个舵机逐一标定登记（PRAD 均 ≈1500）。

## 2. USB 转 TTL 频繁掉线（Errno 5 / Errno 2，一晚 5 次）

- **现象**：串口操作中报 `termios.error (5, 'Input/output error')`，或设备直接从 `/dev/ttyUSB*` 消失（`No such file or directory`）。
- **排查**：`ls /dev/ttyUSB*` 发现掉线重连后**设备编号会变化**（ttyUSB0 ↔ ttyUSB1）。
- **解决**：物理拔插重置 + 先 `ls` 确认当前编号再以对应 port 启动驱动；长期方案为 udev 规则固定别名 `/dev/cquick_servo`（见加分项）。
- **教训**：设备编号不是稳定标识，脚本里应使用 udev 别名。

## 3. 重启 launch 后出现"多个 action server 抢 goal"

- **现象**：`ros2 action send_goal` 出现黄字警告 `There may be more than one action server for the action '/move_servo'`，goal 被旧实例接走后 ABORTED（`串口异常`）。
- **根因**：串口失败后反复重启 launch，launch 主进程被杀但 `servo_driver` 子进程残留，多个实例并存。
- **解决**：`pkill -f servo.launch.py; pkill -f servo_driver` 后用 `pgrep -af servo_driver` 确认清零，再启动唯一实例。
- **教训**：重启 launch ≠ 重启了节点；杀进程后必须验证。

## 4. bag 录制三连坑

1. **后台录制被挂起**：`ros2 bag record ... &` 启动后 bash 显示 `Stopped`（后台进程试图读终端被 SIGTTIN 冻结），目录都没建。→ 加 `< /dev/null` 重定向 stdin 解决。
2. **pkill 硬杀导致 metadata 丢失**：`pkill -f "ros2 bag record"` 强杀后 `ros2 bag info` 报 `Could not find metadata`。→ 改用前台终端运行、Ctrl+C 正常退出，metadata 正常写盘。
3. **bag 回放舵机不动**：action 路径下驱动直接写串口，不经过 `/servo/command` 话题，录到的 bag 只有 `/servo/state` 回显。→ 改用 `ros2 topic pub --once /servo/command ...` 驱动动作重录，bag 中含真指令后 `bag play` 可完整复现动作。

## 5. 取消测试"舵机不动"的误解

- **现象**：取消测试发 `{pwm: 1700, duration_ms: 10000}`，Ctrl+C 后舵机"没动"。
- **分析**：`duration_ms` 既是 goal 时长也作为舵机 T 参数下发——10 秒走完 1500→1700 仅 18°，每秒 1.8°，1~2 秒时打断肉眼不可见；且取消分支会立即回 1500，视觉上等于没动。
- **解决**：改用大行程短时长（2100/5000 或 1200/8000），取消动作清晰可见。
- **教训**：演示类动作要按"肉眼可见"设计行程和速度，而不是只看协议数值。

## 7. 舵机堵转保护锁死（11/20 00:50）
- 现象：goal 到位校验失败，PRAD 冻结不变（1694），正反两个方向都不动，ABORTED；发 PULK 卸力后手转无反应
- 排查：PRAD 仍能读回 → 通信活着、只是电机不执行 → 判定堵转保护锁死
- 修复：**拔电池 XT30 断电 5 秒复位** → PULR 恢复扭力 → 恢复正常
- 根因：在舵臂上贴了纸质标签后阻力变大，**快速动作（T800，0.8s 甩 290 步）触发堵转**，反复堵转导致保护锁死
- 规则：贴标签/带负载时所有动作 duration_ms ≥ 2000（慢速）；听到持续嗡嗡硬顶立即停指令并断电复位
- 经验：到位校验（PRAD 读回 + ±30 阈值 + ABORTED）在这里立功——若驱动不校验，堵转会被当成"成功"，故障无从发现

## 8. 9 号舵机机械卡死，换新件重分 ID（11/20 11:25）

- **现象**：整机装配阶段，9 号舵机保持力矩锁死（持续嗡嗡响、转不动）。发 `#009PULK!` / `#009PULR!` 均无法卸力；`#009PRAD!` 仍正常应答（1493）→ 排除堵转保护冻结。
- **排查**：断电后输出轴依然转不动 → 保持力矩已随断电释放，卡死来自机械层面，判定舵机内部齿轮故障。
- **处理**：
  1. 拆下故障舵机，领备件单独接串口板（出厂 ID 000）
  2. `#000PID009!` 重分配 ID → 回 `#009P!OK!`
  3. `#009P1500T2000!` 归中位 → `#009PRAD!` 读回 1506，验证 ID 生效 + 中位正确
  4. 带电保持状态下装舵臂，换装入机，串联回总线
- **教训**：
  - 「嗡嗡响 + 转不动」先分辨三态：PULK 可卸 = 保持力矩；断电才松 = 堵转保护锁死；断电仍死硬 = 机械/齿轮故障，指令救不了，直接换件
  - 换新舵机的完整流程 = 扫出厂 ID → 重分 ID → 归中 → 带电装臂 → 回总线点名，缺一步整机就少一只关节

## 9. 7 号舵机机械卡死，换件（11/20 11:45）

- **现象**：装配阶段 7 号转不动；`#007PRAD!` 正常应答（1505，无堵转冻结），发 PULK 后仍死硬；**断电状态下输出轴也转不动** → 与 9 号同款机械/齿轮故障。
- **处理**：坏件 `#007PID000!` 还原出厂 ID 后退役贴标；备件出厂 000 → `#000PID007!` 重分 ID → 归中 1500 → 带电装臂 → 换装入机。
- **注意**：两只不同舵机先后出现同类机械卡死，概率异常。后续装配逐只检查孔位对齐、螺丝是否顶壳、舵盘是否蹭机架——若为装配应力，换件治标不治本。

## 10. 控制板上电自动执行动作，总线被垄断（11/20 20:00，未结案）

- **现象**：整机装配后上电，所有舵机（含单挂的备件）持续向同一方向猛转；不接电脑也转；板上三个按键无效；期间 VM 发送的文字指令（`#001PRAD!`）与 LSC 协议停止指令（`55 55 02 07`，9600/115200 双波特率）均无应答——总线被板子的动作输出垄断。
- **排查（排除法）**：
  1. 换舵机/换位置/换口 → 同样疯转 → 排除舵机与链条
  2. 拔掉 USB-TTL 上电 → 仍转 → 排除转接头
  3. 同类板（幻尔 LSC-24 / 众灵 24 路）有「脱机运行」机制：上位机点「启用」后动作组存入 Flash，**每次上电自动执行**——症状完全吻合，判定为脱机运行被启用（具体触发者待查：中午测试仍正常，晚间发作，期间板子被多次挪动装配）
- **未完成的验证**：电池电压（欠压致 MCU 紊乱为次级嫌疑）
- **解除路径**：需上位机软件 → 脱机工作页面 → 「禁用」→ 板子断电重启；或问同学借板先恢复今晚进度
- **教训**：
  - 控制板 MCU 不是透明管道，它有自己的 Flash 与自动行为——「上电疯转」优先查板子自带功能，而不是舵机
  - 排除法顺序：换件（舵机）→ 换口 → 拔 USB → 单挂复现，每步锁定一个嫌疑，4 步定位到板子
  - 带电接线/手持装配是安全事故隐患：舵机上电自行动作曾把手卷向关节，此后固定「断电接线 → 手撤 → 上电」流程

## 【结案更正 11/21 00:53】第 10 条根因修正

- **真实根因**：**装配时未按中位装舵臂**。总线舵机上电后会自动回到记忆的保持位置——舵臂装偏的关节，上电瞬间全体「归位」，表现即「往一个方向猛转/卷起」。板子本身无故障，脱机运行的怀疑不成立。
- **修复**：全部舵机拆下，先归中 1500，再带电按中位装舵臂，重新装配 → 整机装配完成，上电行为正常。
- **最终规则**：**总线舵机的装配永远在「通电归中 → 带电装臂」之后进行**；任何上电瞬间的剧烈动作，第一怀疑对象是「当前位置 ≠ 记忆位置」，而不是舵机坏了。

## 11. 整机五关节冻死 → 判「舵机坏」→ 复测全部翻案（11/21 00:54 ~ 02:24）

- **现象**：整机动作组首跑，中间高度五关节（左 3/5/7、右 2/6）全部 FAIL，踝/髋正常；断电复位无效。
- **初判（后被推翻）**：逐只拆下单独上电测试，5/7 冻结（PRAD 不动），判「内部齿轮损坏」；2「单向能动」判「单向损伤」；拟换 3 只新舵机。
- **翻案**：02:24 对三只「故障件」串联复测（带姓名戳取证脚本），**2/5/7 全部双向恢复动作**。而装机冻过的 3/6 拆下后本来就双向正常。
- **修正结论**：无一只是「死舵机」。冻死 = **堵转保护锁死**——装配应力/结构阻力使中间高度关节带载较劲，舵机进入堵转保护（PRAD 冻结、指令不理），断电静置后自行解除。7 号曾拆下仍冻结，是堵转锁死状态跨断电延续、静置后解除所致。
- **真正要修的是结构**：中间高度关节的装配应力（贯穿螺栓过紧/连杆过死点/孔位应力）才是根因。舵机本体在空载下均正常，是否带载可靠待结构修复后验证。
- **教训**：
  - 「PRAD 冻结」≠ 舵机坏：先断电静置 5 分钟再复测，堵转锁死可自行解除
  - 判死必须「空载 + 断电掰 + 通电双向动作」三证据齐备，缺一不可
  - 整机关节连续冻结且集中在同一结构高度时，优先怀疑装配应力，而不是连环坏件
- **补拍复现（11/21 06:26~06:32）**：旧 5/7（当初判「齿轮损坏」）台架复测 ±100 双向全部到位（1430/1587、1414/1572），翻案实锤落图；旧 6 号 ±200 双向到位坐实「空载正常、带载出力不足」退役定性，并还原出厂 ID 000（#000P1509! 应答）贴标退役。证据：`03_故障舵机复测翻案_补拍.jpg`。过程插曲：USB 接触不良两次断串口（device disconnected），换口重插 + 断线重连容错脚本跑通。

## 12. 「冻结」真相分层：站立负载 + 关节静摩擦（11/21 01:30 ~ 03:20）

- **现象分层**：整机站立时 ±100 摆幅下 2/3/5/6 冻结；平躺（卸载）后 5/3 立即痊愈；2/6 仍冻；±200 大摆幅下 2/6 能动但欠位 30~50 步；松开 2 号贯穿螺栓后 ±100 即恢复正常。
- **两层根因**：
  1. **站立负载**：舵机驱动力矩与位置误差成正比，小误差力矩不足以克服「整机重量 + 结构摩擦 + 静摩擦」——放倒即可验证/规避
  2. **关节静摩擦过大**（仅 2/6）：贯穿螺栓过紧，±100 误差力矩撕不开静摩擦，±200 才能动——松螺栓根治，2 号松完立愈，6 号待修
- **解决**：调试动作组时垫空腿或放倒验证关节本身；装配时贯穿螺栓以「踝/髋关节手感」为基准；动作组设计尽量顺着重力方向。
- **附带落地**：udev 规则 `/dev/cquick_servo` 别名（CH340 1a86:7523）——设备编号漂移（ttyUSB0↔1）后驱动重开别名即可，无需改端口；但**掉线后驱动仍需重启**以重开句柄（Errno 5）。
