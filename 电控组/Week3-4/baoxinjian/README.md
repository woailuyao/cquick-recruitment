## 二、代码结构

- `cquick_servo_interfaces`：`action/MoveServo.action`（id / pwm / duration_ms → progress / final_pwm / success）
- `cquick_servo`：
  - `servo_driver.py` —— 串口驱动节点（参数声明与校验、Action Server、到位校验 ±30、取消回中位）
  - `sequence_player.py` —— 动作组播放器（读 yaml → 顺序下发 → 等 result 再发下一个）

  - `config/actions/test_single.yaml / stand_up.yaml / wave.yaml`

## 三、调试记录摘要（详见 `调试记录.md`）

1. USB-TTL 反复掉线（Errno 5）→ 设备编号变化 → 拔插重置后用 `ls /dev/ttyUSB*` 确认再启动
2. 旧驱动进程残留 → 多 Action Server 抢 goal → `pkill -f servo_driver` + `pgrep` 确认清零
3. bag record 后台运行被 shell 挂起 → 前台录制 + Ctrl+C 正常退出写 metadata
4. action 路径不经 /servo/command → bag 回放无动作 → 改用 topic pub 驱动 command 话题重录
5. **舵机堵转保护锁死**：贴标签后舵臂阻力变大 + 快速动作（T800）→ PRAD 冻结 → 拔电池断电 5 秒复位；规则：带负载时 duration_ms ≥ 2000
6. 总线舵机实际出厂 ID 为 **000**（文档示例 1~254），扫描必须从 0 开始
7. 「上电疯转」根因 = 装配未按中位装舵臂（舵机上电自动归位）；装配铁律 = 通电归中 → 带电装臂
8. 「舵机判死」翻案：PRAD 冻结 ≠ 舵机坏（堵转保护锁存可自行释放）；整机站立时关节冻结分两层——站立负载（放倒即愈）+ 贯穿螺栓过紧致静摩擦过大（松螺栓立愈）；判死须「空载 + 断电掰 + 通电双向动作」三证据齐备
9. **串口漂移根治**：CH340 设备号在 ttyUSB0/1 间反复漂移（掉线 7+ 次）→ udev 规则按 idVendor/idProduct 固定别名 `/dev/cquick_servo`，驱动与脚本端口参数一次写死不再跟改
10. **PULK 无回显 ≠ 失败**：该固件动作/卸力指令一律静默，仅查询指令回话；卸力生效的正确判定法 = 卸力后下发动指令观察关节无响应（有力矩必动），配合 PRAD 回显证明总线存活
