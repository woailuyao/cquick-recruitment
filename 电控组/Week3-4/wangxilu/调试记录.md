## 调试记录

| 想做什么 | 现象 | 我的怀疑 | 怎么验证的 | 结论 |
|---------|------|---------|-----------|------|
| 用Python脚本发指令让舵机转 | 脚本发 `#001PID!` 无任何回显，舵机不动 | ID不对 / TTL模块坏 / 指令格式错 | 换新的TTL模块；用串口助手手动发；短接RX/TX做回环 | 旧TTL模块坏了，换新模块后回环正常。但舵机仍不回 |
| 确认舵机实际ID | 发 `#001PID!` 没反应，但 `#255PID!` 有回显 `#003PID!` | 这批舵机ID不是1，是出厂默认的3 | 用 `#255PID!` 广播查询 | 实际ID=3。后续所有指令改成 `#003...` |
| 发运动指令 `#003P1500T1000!` | 舵机仍不动 | 没发PULR恢复扭力 / 指令带`\r\n`多余 | 先补发 `#003PULR!`，再去掉脚本里的 `\r\n` | 众灵协议**不要任何换行**。`write(cmd.encode())` 即可。`#003PULR!` + `#003P1500T1000!` 后舵机**转了** |
| 启动 servo_driver 节点 | `ros2 node list` 崩溃；节点列表里有重复的 servo_driver；发 goal 报 "Ignoring unexpected goal response" | 之前开的节点没 kill 干净，ROS图脏了 | `pkill -f servo_driver`；`ros2 daemon stop && ros2 daemon start` | 每次重开节点前必须 `pkill` 清残留，否则 ActionServer 会收到不属于自己的响应 |
| source 环境 | `source install/setup/bash` 报没有那个文件 | 路径记错了 | 看报错，改回 `source install/setup.bash` | install 目录下是 `setup.bash`，不是 `setup/bash` |
| `ros2 param set pwm_max 1600` 后发 goal pwm=1700 | 返回 successful，但 1700 仍然被执行，舵机转了 | 代码里读的是 `__init__` 存的 `self.pwm_max` 副本，set 之后没变 | 在 `goal_callback` 里加 `self.get_logger().info` 打印 `get_parameter().value` | **参数必须用 `self.get_parameter('xxx').value` 实时读**，不能抄进 `self.xxx` 就不管了 |
| 按 `Ctrl+C` 取消 goal | 没反应，舵机继续转到完 | `time.sleep()` 把 executor 单线程卡死了，cancel 回调进不来 | 把 `executor.spin()` 换成 `MultiThreadedExecutor()`；ActionServer 加 `ReentrantCallbackGroup` | 两条都要做：MultiThreadedExecutor + ReentrantCallbackGroup。取消立即生效 |
| 给 `pwm_max` 设 100000，看是否被拒 | 返回 successful，舵机准备执行 | 没注册 `add_on_set_parameters_callback`，或者回调没处理这个参数 | 在 `__init__` 里补 `self.add_on_set_parameters_callback(self.on_set_parameters)`；回调里对 pwm_min/pwm_max 做范围校验和交叉校验 | 回调必须 `return SetParametersResult(successful=False, reason=...)` 才会真拒。Humble 不会自动帮你拦 |
| 交叉校验：set pwm_min=2500 而 pwm_max=2100 | 应该被拒，但担心逻辑写反 | 手动触发 | `ros2 param set /servo_driver pwm_min 2500` | 返回 `pwm_min=2500 必须小于 pwm_max=2100`。交叉校验生效 |
| 改 pwm_max=1600 后 action 发 1800 | `Goal was rejected` | 参数校验和 action 校验两条链路都通了 | 再 `set pwm_max=2100`，发 1800，`Goal accepted` | 两条链路独立但数据同源（都读参数服务器），验证通过 |
| grep 自检代码有没有硬编码 | 第一次 grep 路径错了，在 `~/cquick_ws` 根目录搜文件名，报 "没有那个文件" | 文件在 `src/.../cquick_servo/` 下面 | `cd` 进正确目录再跑 `grep -rn "ttyUSB\|115200\|/dev/" servo_driver.py move_client.py` | 逻辑代码零硬编码。`declare_parameter` 默认值和校验白名单不算硬编码，评审问就这么答 |
| `ros2 param list` 崩溃，xmlrpc Fault | daemon 缓存有脏数据，之前多个实例的节点信息混在里面 | 清理 daemon | `ros2 daemon stop && ros2 daemon start` | 清 daemon 是 ROS2 调试三板斧之一：stop → start → 重试 |

### 经验总结

1. **舵机不动先查三件事**：PULR发了没 / ID对不对 / 有没有多余的`\r\n`。众灵这批不回查询，靠广播`#255PID!`扫ID
2. **节点残留是幽灵**：ROS2 的 ActionServer 如果上一个进程没死透，新的会收到旧响应。`pkill -f servo_driver` 是起手式
3. **`get_parameter` 要实时读**：`ros2 param set` 只改参数服务器的值，代码里存了副本就永远读不到新值
4. **取消靠多线程**：`time.sleep` 在单线程 executor 里会堵死所有回调。MultiThreadedExecutor 是必须的
5. **`add_on_set_parameters_callback` 是真门卫**：`ros2 param set` 返回 successful 不代表值生效了，回调返回 `False` 才会拒
6. **交叉校验要读当前值**：校验 `min < max` 时，如果只改 min，要用 `get_parameter('max').value` 读当前的 max
7. **daemon 脏数据会传染**：节点异常退出后，`ros2 node list` / `ros2 param list` 可能崩。stop+start 是标准恢复流程
8. **grep 搜硬编码要进对目录**：在 workspace 根目录搜文件名会报 "没有那个文件"，要么给完整相对路径，要么 cd 进去

## 踩坑总表

| 问题 | 现象 | 根因 | 解决 |
|------|------|------|------|
| setup.py entry_points 漏逗号 | `ros2 run` 报 No executable found，ls 发现缝合怪文件名 | Python 字符串字面量自动拼接 | 两行 console_scripts 之间加逗号 |
| action 分隔符全角 | `InvalidActionSpecification` | 中文输入法敲了 `——` 而不是 `---` | 用英文输入法重打 |
| BRLTTY 抢 CH340 | `ls /dev/ttyUSB*` 时有时无 | Ubuntu 盲文驱动占用 | `sudo apt remove brltty` |
| 舵机 ID 不是 1 | 发 `#001PID!` 无反应 | 出厂默认 ID=3 | `#255PID!` 广播查询 |
| 指令带 `\r\n` | 舵机完全不理 | 众灵协议不要换行 | `write(cmd.encode())` 即可 |
| TTL 模块坏 | 回环有乱码后彻底无声 | 硬件损坏 | 换新模块 |
| 参数改了不生效 | `set` 成功但 goal 仍按旧值执行 | 代码存了 `self.pwm_max` 副本 | 改成 `self.get_parameter('pwm_max').value` 实时读 |
| 取消无反应 | `Ctrl+C` 后舵机继续转 | 单线程 executor 被 sleep 占满 | MultiThreadedExecutor + ReentrantCallbackGroup |
| 多个 servo_driver 实例 | "Ignoring unexpected goal response" | 旧进程没 kill | `pkill -f servo_driver` |
| source 路径错 | `install/setup/bash` 找不到 | 记错文件名 | `install/setup.bash` |
| daemon 脏数据 | `ros2 node list` / `param list` 崩溃 | 异常退出留下坏缓存 | `ros2 daemon stop && start` |
