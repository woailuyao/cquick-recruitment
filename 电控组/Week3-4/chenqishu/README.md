# 第 3、4 周作业 · 电控组 · 陈琦姝

这两周挺折腾的。

本来以为就是接线、发指令、舵机转，结果光「让它转」就卡了一整个下午。中间踩的坑都
在 [`调试记录.md`](./调试记录.md) 里，这里挑几个印象最深的写。

先说一下我这台机器的情况，因为后面所有数字都是按它来的。

---

## 一、硬件

十个舵机，众灵 ZP20D，20 公斤厘米。板子是学长给的那个 24 路控制板，板载 USB 串口。
电池是 2S 锂电，我上电前用万用表量了一下，6.79 V。另一次量到 6.87，反正都在 5 到
8.4 之间，可以接。

腿是打印件，右腿从脚往上是 1 2 3 4 5，左腿从胯往下是 6 7 8 9 0。这个编号看着有点
怪（左腿是从上往下数的），我一开始记混过，后来在纸上画了一遍才记住。

### 编号是改过的

舵机出厂全是 0 号。第一次三个一起接上去的时候，有一个一直嗡嗡响还发热，我吓得直接
把电池拔了。后来问学长才知道是编号冲突，两个都叫 0 号，一条指令它们一起执行，所以
打架。

改法是：一次只接一个，在电脑上开众灵那个 Zide，发 `#000PID001!`，看到回 `#OK!` 就
说明改好了，再发 `#001PID!` 确认。第二个改成 2 号。剩下的不动，本来就叫 0。

改完我把编号写在小纸条上，贴在每个舵机壳子侧面。因为装进结构以后就看不见了，之后再
想认哪个是几号，只能靠这个纸条。

### 关节是怎么分的

这个是蹲下去量的。我把腿摆成蹲下的姿势，把十个数全读出来，跟站立时的 1500 一比，谁
动得多谁就是主力。

| 关节 | 右腿 | 左腿 | 蹲下变了多少 |
|---|---|---|---|
| 脚 | 1 | 0 | 5 / 1 |
| 膝下 | 2 | 9 | 304 / 275 |
| 膝 | 3 | 8 | 634 / 542 |
| 胯下 | 4 | 7 | 255 / 264 |
| 胯 | 5 | 6 | 4 / 21 |

膝盖那两个（3 和 8）动得最多，一看就是主力。4 和 7 各动了两百多，是蹲下去以后被顶得
偏了，得补回来，所以后来写动作的时候把它们单独拎出来，叫「躯干补偿」。

这里有个坑：左右是反的。右膝弯是数字变小（1500 到 866），左膝弯是数字变大（1500 到
2042）。我第一次写 yaml 两边写成一样了，跑起来一条腿往上翘，看着特别滑稽。改了才好。

## 二、接线

线一共就三根：

橙色的（有的舵机是白的）是信号，红的接正极，棕的（有的黑的）接地。电池出来一个
绿色接线柱，红进黑出，别接反。

我在这上面卡过一次：只接了信号没接地，扫了半天一个舵机都没有，我还以为板子坏了，
差点去找学长。学长说你把 GND 接上再试。接上就好了。

还有电池上那个白色的三根线的小插头，那是充电用的平衡头，任何时候都不要往板子上插。

## 三、代码

两个包：

```
src/
├── cquick_servo_interfaces/    只放接口，ament_cmake
│   ├── msg/ServoCommand.msg
│   └── action/MoveServo.action
└── cquick_servo/               ament_python
    ├── servo_driver.py         Action Server，管串口
    ├── move_client.py          一次发一条
    ├── sequence_player.py      读 yaml 跑动作组
    ├── launch/servo.launch.py
    └── config/
        ├── servo_params.yaml
        └── actions/*.yaml
```

数据大概是这么走的：我在终端敲一个 goal 出去，`servo_driver` 收到先判断 pwm 和编号对
不对，不对就拒掉。对了就先把文字拼成 `#000P1500T1000!` 这种格式，从串口发出去。发的
同时往 `/servo/command` 也发一份，那份是专门给 bag 录的。

跑动作组的时候不是我在敲，是 `sequence_player` 读 yaml，把里面每个 step 展开成几条
goal，发出去，等这一批的 result 都回来了，再发下一步。

## 四、参数

| 参数 | 值 | 说明 |
|---|---|---|
| `port` | `/dev/ttyUSB0` | 但这东西经常变成 `ttyUSB1`，见踩坑第四条 |
| `baudrate` | 115200 | 手册写的。我试过 9600，全是乱码 |
| `pwm_min` | 800 | 手册说电气上 500~2500 都行，但我蹲到底的时候 3 号要 866，写 900 就被拒了，只能往下放 |
| `pwm_max` | 2100 | 蹲下时 8 号要 2042，再大结构就顶住了 |
| `default_duration_ms` | 800 | 一般行程走完的时间 |
| `servo_ids` | 0 到 9 | 一共十个 |
| `startup_reset` | true | 每次启动先回中间，这样姿势一致好复查 |
| `sim` | false | 真机。之前没硬件的时候我拿 true 测过逻辑 |

参数是能边跑边改的，不用重启。因为代码里每次执行都是重新读一遍参数，不是初始化时存
在变量里。

## 五、Action 接口

**Goal**

- `id` 是舵机编号，得在 `servo_ids` 里面
- `pwm` 是想去的位子，得在 800~2100 之间
- `duration_ms` 是用多久走过去。填 0 就用默认的 800

**Feedback**，一秒钟发二十次左右

- `current_pwm` 是当前大概在哪。这个不是读回来的，是从起点到目标线性算出来的
- `progress` 是 0 到 1 的进度

**Result**

- `success` 成没成
- `final_pwm` 是最后用 `PRAD` 读回来的真实位置
- `message` 会说原因，`ok` 是好的，`canceled` 是被取消了，`not_reached` 是没走到，
  还有 `ok_no_prad` 是命令发成功了但没读回来

为什么 result 里要读一遍再报：因为舵机可能被结构调整卡住，你以为走到了其实没到。读一
遍，差 30 以内才算成。

## 六、怎么跑起来

```bash
ros2 launch cquick_servo servo.launch.py
```

起来以后看这一行：

```
[servo_driver]: 串口已打开：/dev/ttyUSB0 @ 115200 8-N-1
```

这句话很重要。如果它说的是「打不开串口」，后面照样会刷一堆 `TX ->`，看着像在发，其实
一条都没发出去，舵机一动不动。我第一次被这个骗了十几分钟。

端口不对可以现改：

```bash
ros2 launch cquick_servo servo.launch.py port:=/dev/ttyUSB1
```

单发一条：

```bash
ros2 action send_goal /move_servo cquick_servo_interfaces/action/MoveServo \
  "{id: 0, pwm: 1700, duration_ms: 1000}" --feedback
```

跑动作组：

```bash
ros2 run cquick_servo sequence_player --ros-args \
  -p action_file:=$(ros2 pkg prefix cquick_servo)/share/cquick_servo/config/actions/squat_repeat.yaml
```

## 七、800 和 2100 是怎么试出来的

手册上写 500~2500，我一直以为直接用这个范围就行。后来发现不行。

那个范围是电气上的，意思是「舵机不给烧了」。但装在结构上就不一样了：转到某个角度，
打印件会顶住，舵机还在使劲，转又转不过去，就嗡嗡响，摸上去很快就热。这就是堵转，久
了线圈就烧了。

我的试法是笨办法：先回 1500，然后一次改 50 往两边试，1450、1400、1350……听到嗡嗡
就往回退 50，那个位置就是这一边的极限。

试完发现蹲下的时候 3 号要 866，8 号要 2042，所以最后把范围放到 800 到 2100。现在跑
squat 和 step 都不会响。

## 八、改参数

我录了一段，节点一直没重启，就改了一下上限，行为立刻变了。

```
$ ros2 param get /servo_driver pwm_max
Integer value is: 2100

$ ros2 action send_goal ... pwm 1700
Goal finished with status: SUCCEEDED

$ ros2 param set /servo_driver pwm_max 1600
Set parameter successful

$ ros2 action send_goal ... pwm 1700
Goal was rejected

$ ros2 param set /servo_driver pwm_max 100000
Setting parameter failed: pwm_max 必须在 500~2500 之间，收到 100000

$ ros2 param set /servo_driver pwm_max 2100
Set parameter successful
```

第四步那行 `Goal was rejected` 是我最想放的一段。东西一直在跑，参数一改，同样一条
goal 就被拒了，说明它是真的每次都在读参数。

最后那个 100000 被拦住，是因为我注册了一个检查参数的回调，超范围直接不认。

## 九、bag

```bash
ros2 bag record /servo/command /servo/state -o ~/servo_bag2/run1
```

我只录了这两个话题，没敢用 `-a` 全录，全录会带进去一堆没用的东西，文件还大。

```bash
$ ros2 bag info ~/servo_bag2/run1
Messages: 6
Topic: /servo/command | Count: 3
Topic: /servo/state   | Count: 3
```

回放的时候我什么都没敲，舵机自己把刚才那套动作又做了一遍。当时挺有成就感的。

能做到是因为 `/servo/command` 那条路和 Action 走的是同一个发送函数，录的时候走一遍，
放的时候还是走那一遍，所以一模一样。

不过第一次录的时候 `/servo/command` 是 0 条，我明明看到 `/servo/state` 有数。查了半天
才发现在代码里创建了发布器，但从来没 publish 过。补了一行 `.publish` 之后才有三条。

## 十、装配

顺序是这样的：

先把十个舵机都标定到 1500，一个一个接，一个一个发 `#00xP1500T1000!`，等它真的转到
中间再拔。这一步不能省，后面全靠它。

然后贴编号纸条，装进打印件。装的时候要看轴的方向，装反了关节就是反着转。

再装舵臂。**这一步一定要断电**，而且舵机还得保持在中位。因为舵臂装上去的那个角度，
就是这个关节的机械零点。装歪了，以后发 1500 它不站直，而且十个舵机歪得还不一样，软
件没法统一补。我装的时候对了好几次才把舵臂的孔和打印件上的基准线对上。

接着固定板卡、固定电池，最后走线。线要贴着内侧走，用扎带固定，关键是**不能穿过会转
动的地方**。

### 装配时出的三个问题

**第一个，0 号舵机扫不到。**

十个全接上以后，`scan` 只有 1 到 9，0 号一直不出来。我一开始以为那个舵机坏了，单独接
上去 `ping 0`，有回显。又以为是扫描间隔太短，从 0.35 秒加到 1.5 秒，还是不行。

换了板子上另一个通道以后，单独 ping 稳定了，但十个一起扫还是偶尔漏掉。我猜它挂在串联
总线的最后面，连续发十条指令的时候，它的应答回得晚，被下一条指令前的清空缓冲给冲掉
了。所以最后交的证据是两张图：一张扫 1 到 9，一张单独 ping 0。

**第二个，线差点被磨断。**

0 号在脚上，第一版走线是从关节外面绕的，手转关节的时候能感觉到线被拉紧了。后来改成
从内侧走，留了一点余量，用扎带固定在打印件上，转到底也不绷了。

**第三个，单腿抬起来的时候底座会翘。**

这个是写 step.yaml 之后才发现的。抬右脚的时候只有左腿在撑，底座会翘起来一点。目前还
没想好怎么办，先凑合着。

## 十一、动作组

一套动作就是一个 yaml，放在 `config/actions/` 下面。写起来长这样：

```yaml
motion_name: squat_repeat
repeat: 3

steps:
  - name: 蹲下
    duration_ms: 1000
    moves:
      - {id: 2, pwm: 1196}
      - {id: 3, pwm: 866}
      - {id: 8, pwm: 2042}
      - {id: 9, pwm: 1775}

  - name: 保持蹲姿1秒
    hold_ms: 1000
    moves: []
```

写的时候只有两条规矩要记住。

一条是，**同一个 step 里的关节是一起发的**，所以它们会同时动。想同时动就写一起。

另一条是，**step 和 step 之间要等 result 回来**才发下一条。这个不是我 sleep 出来的，
是播放器里等结果。我一开始图省事想过用 sleep，算着 1 秒应该走完了就发下一步，后来发
现只要有一个舵机慢一点，后面全乱套，连跑三遍长得都不一样。改成等 result 就稳了。

`hold_ms` 那个是「这个姿势保持多久」，它是动作本身的一部分，跟同步没关系，别混。

我写了三套：

- `squat.yaml`，站起来到蹲下去再站起来，膝盖分两段走。因为一次从 1500 跳到 866 太猛
- `squat_repeat.yaml`，蹲下、停一秒、站起，重复三遍
- `step.yaml`，左右交替抬脚，重复两遍

换动作就改一个参数：

```bash
ros2 run cquick_servo sequence_player --ros-args \
  -p action_file:=$(ros2 pkg prefix cquick_servo)/share/cquick_servo/config/actions/step.yaml
```

python 一行都没改。

为什么非要拆成好几个 step，不只是为了好看。一是物理上有先后，膝盖得先弯下去，躯干再
补偿，同时动结构会互相别着。二是电流，十个舵机同时猛动的那一下电流很大，板子电压会
掉，然后 USB 就掉线了。

## 十二、踩过的坑

完整的十条在 [`调试记录.md`](./调试记录.md)。这里挑四个最折腾的。

### 一、十个舵机不是一起动，是一节一节动

写动作组第一次跑的时候，我盯着看，发现腿是 1、2、3 这样一节一节动的，先右腿后左腿，
完全不是「蹲下」的样子。

我一开始以为是 `sequence_player` 发得太慢，加了打印看，确实是十个 goal 连着发出去
的，发得很快。那问题就在服务端。

翻了 `servo_driver.py`，看到 `MultiThreadedExecutor(num_threads=4)`。

问题就在这。一个 goal 在执行的时候是占着一个线程的，执行里面还有 sleep。十个 goal 只
给了四个线程，所以只能四个四个跑，剩下的排队等前面的跑完。排队的顺序就是编号顺序，
所以看起来先右腿后左腿。

改成按舵机数量动态分配：

```python
n_servo = len(list(node.get_parameter('servo_ids').value))
n_threads = max(8, n_servo + 6)
executor = MultiThreadedExecutor(num_threads=n_threads)
```

日志里出现 `executor 线程数 = 16` 之后，十个关节才真的同时动。这个坑我觉得最值，因为
它不在我写的那部分代码里，是藏在库的用法里。

### 二、十个 PRAD 一起查，总线上撞车

修好线程之后跑三遍，看着是挺好的，但日志里有黄字：

```
id=2 没到位: not_reached: 目标 1500 实际 0 差 1500
id=8 没到位: not_reached: 目标 149 实际 1351 差 1202
```

实际 0，就是根本没读到。

我想了一下，十个 goal 差不多同时结束，那就是十个线程同时发 `PRAD` 去问位置，舵机的
应答全挤在一条线上，谁都没读到完整的。

这一版我先绕过去了：读不到就报 `ok_no_prad`，不判成失败，因为动作其实是做了的。彻底
修要把「写命令」和「读应答」放在同一把锁里，一个一个来，这个还没做。

### 三、USB 一天掉了八次

这个最气人。`/dev/ttyUSB0` 时有时无，`ls` 的时候还有，下一条命令就没了，报
`No such file or directory`。后来发现编号还在 `ttyUSB0` 和 `ttyUSB1` 之间跳。

我 `ls -l` 看了一眼，minor 号从 `188, 0` 变成 `188, 11`，说明它已经重连了十一次。

我一开始以为是虚拟机的问题，把虚拟机重启了，好了一会儿又掉。后来换到机身后面的
USB 口，上电顺序也改成先插 USB 再上电池，才稳定下来。我怀疑是舵机那一下大电流把
USB 冲掉了，加上之前一直用扩展坞，供电本来就不稳。

现在我的习惯是：每次操作前先 `ls /dev/ttyUSB*` 看一眼是几号，命令里就用实际的号，
不再默认是 0。这东西真的会因为重连改号。

### 四、创建了发布器，但从来没 publish

第一次录 bag，`ros2 bag info` 里 `/servo/state` 有三条，`/servo/command` 是零条。回放
的时候驱动一点反应都没有。

我在代码里搜 `cmd_pub`，只搜到创建那一行，没有 `.publish`。补上之后 Count 从 0 变 3。

## 十三、下电

顺序不能反：

1. 先卸力，十个舵机都发 `#00xPULK!`
2. 再断动力，拔电池
3. 最后关机，`sudo shutdown now`

**为什么先卸力**，因为舵机在卸力之前一直在通电流保持位置。这时候如果被结构顶着，电流
全变成热，几分钟就能把线圈烧了。我现在的习惯是卸完力用手推一下腿，能自由转才说明真
的卸掉了。

**为什么先断动力**，如果先关电脑、舵机还带着电并且顶着力矩，突然断电结构会掉下来，也
可能打火。

**为什么不能直接拔电源**，文件系统会坏，下次开不了机。

四条红线，我抄在纸上了：

1. 不许带电插拔舵机线
2. 不许反接电源
3. 电池鼓包立刻停用
4. 不许让舵机硬顶结构

第三条我是真的有点怕，之前那个舵机嗡嗡发热的时候我一直在旁边守着，怕它鼓起来。
