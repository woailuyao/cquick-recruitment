## 二、ID 扫描证据

2026-11-17 使用以下命令扫描当前整机：

```bash
python3 ~/servo_tools/scan_id.py --port /dev/ttyUSB0 --min-id 1 --max-id 10
```

实际扫描结果为 `001、002、003、004、005、006、007、008、009、010` 全部在线，见 `03_ID扫描.png`。

**改 ID 的安全规则：一次只接一台。**多台出厂 ID 都为 `000` 时曾同时回包并出现撞号乱动；逐台改成唯一 ID 后才恢复正常。不能把多台同 ID 舵机接在总线上直接批量改号。

## 四、标定说明

1. **电气中位与机械标准位不同**：协议中位是 1500；整机 YAML 的 1500 会叠加每个关节自己的 offset。
2. **标定顺序**：先 `PULR` 上力，慢速转到中位并用 `PRAD` 回读，再安装舵臂和连杆。
3. **为什么慢速**：标定关注准确停位而非速度，慢速可减小超调和回弹。
4. **为什么每台都要标定**：舵盘齿位和舵臂安装角度存在个体差异，不能只标一台后套用到全部关节。
5. **拆换后必须重测**：换舵机、拆舵臂、改变连杆或齿位后，旧 offset 不再自动有效。
6. **恢复姿态的方法**：使用 ROS2 驱动或 `sequence_player` 播放回标准位 YAML；旧 `center_all.py`、`wiggle.py` 等原始串口工具不带 offset，不能用来恢复当前机械标准姿态。

## 五、串口与接线方式

| 通道 | 协议 | 用途 |
|---|---|---|
| 板载 USB-C | HID（Windows 不产生 COM 口） | 众灵上位机改 ID、标定 |
| `RX1/TX1/GND` 排针 + USB-TTL | UART 115200 8-N-1，产生 `/dev/ttyUSB0` | ROS2 驱动 |

接线时 TX↔RX 交叉、GND 共地，**USB-TTL 的 5V 悬空不接**。控制板由电池供电，不能把两路电源并接互灌。

**回包格式实测**：

```text
#001PRAD!  →  #001P1504!      带位置值
#001PID!   →  #001P!          只回 ID 确认，不带位置值
```

因此 `PID` 用于扫描在线，`PRAD` 用于读位置；驱动解析需兼容不同回包形式，不能把 `PID` 当作位置读取命令。
