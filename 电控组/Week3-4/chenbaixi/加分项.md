## 1 · udev 固定设备名（+2）

**问题**：同时插着 USB 转 TTL 和其他 USB 设备时，`/dev/ttyUSB0` 会变成 `/dev/ttyUSB1`，
`port` 参数一换代码就跑不起来（别人机器上更是必挂）。这是真问题，不是花活。

**规则**：`/etc/udev/rules.d/99-cq-servo.rules`

```
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", SYMLINK+="cq_servo", MODE="0666", GROUP="dialout"
```

生效并验证：

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
ls -l /dev/cq_servo        # -> /dev/ttyUSB0
```

**代码侧**：`servo_driver.py` 的 `port` 参数**默认值已改为 `/dev/cq_servo`**，
`config/servo_params.yaml` 同步。没装规则的机器显式传参即可：

```bash
ros2 launch cquick_servo servo.launch.py port:=/dev/ttyUSB0
```

> `1a86:7523` 是 CH340 的 VID:PID。CP2102 是 `10c4:ea60`，换芯片时改这一行。

## 2 · PRAD 闭环校验（+3）

**做法**：动作执行完自动发 `#NNNPRAD!` 读回真实位置，与目标比对；
差值超过 `prad_tolerance`（默认 30）判定未到位，**自动重发一次**并打日志。

```python
tol = int(self.p('prad_tolerance'))
final = self._read_pwm(sid)

if self.p('prad_retry') and (final is None or abs(final - target) > tol):
    self.get_logger().warn('未到位（读回 %s vs 目标 %d），重发一次' % (final, target))
    self._send(build_move_cmd(sid, target, max(period_ms, 200)))
    time.sleep(max(period_ms, 200) / 1000.0)
    final = self._read_pwm(sid)
    self.get_logger().info('重发后读回 %s' % final)
```

**真实日志**（`02_断线重连.png` 左半屏）：

```
[WARN] [servo_driver]: 未到位（读回 1460 vs 目标 1500），重发一次
[WARN] [servo_driver]: 重发后读回 1492          <- 重发后到位
[INFO] [servo_driver]: 完成 id=0 result=ok
```

## 3 · 安全看门狗（+3）· 心跳版

**做法**：驱动订阅外部发来的 `/servo/heartbeat`；超过 `watchdog_timeout_ms`
（默认 1000 ms）没收到心跳，就**给所有舵机发 `#NNNPULK!` 卸力**、打 **ERROR** 日志，
并把 `_tripped` 置真**锁死** —— 之后 `goal_callback` 一律 `REJECT`，**不会自己乱动**；
必须外部执行 `ros2 param set /servo_driver watchdog_reset true` 才恢复。

```python
def _on_heartbeat(self, msg):
    self._last_heartbeat = time.monotonic()

def _watchdog(self):
    if not bool(self.p('watchdog_enable')):
        return                                  # 关闭时走旧「指令超时」兼容逻辑
    if self._tripped:
        if bool(self.p('watchdog_reset')):       # 外部确认恢复
            self._tripped = False
            self._last_heartbeat = time.monotonic()
            self.get_logger().warn('看门狗已复位（外部确认），恢复接受指令')
        return
    lim = int(self.p('watchdog_timeout_ms')) / 1000.0
    if time.monotonic() - self._last_heartbeat > lim:
        self.get_logger().error(
            '看门狗触发：%.1f 秒未收到 /servo/heartbeat 心跳，全部舵机 PULK 卸力；'
            '此后拒绝新指令，需 ros2 param set /servo_driver watchdog_reset true 恢复' % lim)
        self.unload_all()
        self._tripped = True
```

`goal_cb` 里拦截：

```python
if self._tripped:
    self.get_logger().error('看门狗已触发（舵机已卸力），拒绝新 goal；需外部确认恢复')
    return GoalResponse.REJECT
```

**演示步骤**：

```bash
# 终端 A
ros2 run cquick_servo servo_driver --ros-args -p port:=/dev/ttyUSB0 -p watchdog_enable:=true

# 终端 B：模拟上位机心跳
ros2 topic pub -r 5 /servo/heartbeat cquick_servo_interfaces/msg/ServoCommand "{id: 0, pwm: 0, duration_ms: 0}"

# 停掉终端 B -> 1 秒后 ERROR + 全部舵机卸力
# 再发 goal    -> Goal was rejected（锁死生效）
ros2 param set /servo_driver watchdog_reset true     # -> 恢复
```

**设计说明**：心跳话题必须**独立**于 `/servo/state`。
若直接订阅驱动自己发的 `/servo/state`，会形成「自己发自己收」，看门狗永远不会触发。

## 4 · 串口掉线自动重连（+3）

**做法**：`_send()` 捕获串口异常 → 关闭句柄、标记断开 →
下次发送时按 2 秒限频尝试 `_open_serial()`，成功后打「串口已恢复」。

```python
def _try_reopen(self):
    now = time.monotonic()
    if now - self._last_reopen_try < 2.0:      # 限频，避免刷屏
        return False
    self._last_reopen_try = now
    self.get_logger().warn('尝试重新打开串口…')
    self._open_serial()
    if self.ser is not None:
        self.get_logger().info('串口已恢复')
        return True
    return False
```

## 6 · 动作组抢占（+4）· 未实现

细则要求：动作组正在跑时来了新 goal，能打断并从**当前位置**平滑接上
（不跳变、不先回中位再切）。

**本版未实现**，原因如实说明：
桌面阶段只有一个 Action Server 跑单条 goal，
没有常驻的动作组进程，「抢占」场景无法构造与验证。
计划与任务 3 整机动作组一起在第 5 周补：

1. `goal_callback` 里检测已有活跃 goal → 主动 `cancel` 它
2. 记录 cancel 时刻的 PRAD 作为新 goal 起点
3. 用新 goal 的 `duration_ms` 从当前点平滑过渡（不先回中位）
