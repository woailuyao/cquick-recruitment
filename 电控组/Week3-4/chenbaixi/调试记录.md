## 三条最关键的

### ① 出厂 ID 是 0，不是 1

**现象**：`#001PID!` 在 8 种波特率、ID 1~255 全部无回包，模块 RX 灯从不闪。

**排查路径**：
1. 回环测试（TxD-RxD 短接）→ 能收到自己发的数据 ⇒ 模块与线材排除
2. 量 TX1 空闲电平 3.25 V ⇒ 引脚是活的
3. 全波特率 × 全 ID 扫描 ⇒ 依旧零回包
4. 队长提示出厂默认 ID = 000
5. `#000PID!` → `b'#000P!'`；`#000PRAD!` → `b'#000P1504!'`

**结论**：出厂 ID 为 0。教训：遇到「完全无应答」，别只怀疑物理链路，
也要确认「默认 ID 是不是非 1」；且用 PRAD 扫比 PID 扫可靠（PID 回包可能不含 ID）。

### ② PRAD 读不到 —— 读取顺序错了

```python
# 错误：发送后清缓冲，把回包丢了
ser.write(cmd)
ser.reset_input_buffer()
data = ser.read(64)

# 正确
ser.reset_input_buffer()      # 发送前清空
ser.write(cmd); ser.flush()
# 轮询读到 '!' 结尾或超时
```

### ③ Ctrl+C 不等于取消 goal

`ros2 action send_goal --feedback` 按 `Ctrl+C` 只杀客户端进程，**不发 cancel 请求**，
服务端 goal 会继续执行完。正确做法是客户端显式 `cancel_goal_async()`；
服务端需 `MultiThreadedExecutor` + `ReentrantCallbackGroup` + 循环内小步 sleep
并每轮查 `is_cancel_requested`，否则 cancel 回调进不来。
