# 安全区间 · pwm_min / pwm_max 的来历

> 当前值：**900 – 2100**，中位 1500，到位容差 ±30。
> 一句话：**这三个数不是一个东西** —— 协议域、结构行程、机械死点，混着讲一定被问穿。

---

## 一、先把三个区间分开

| 区间 | 数值 | 谁定的 | 作用 | 超了会怎样 |
|---|---|---|---|---|
| **协议 / 参数域** | `500 – 2500` | 代码常量 `PARAM_ABSOLUTE_MIN / MAX` | 拦住"把参数改成 100000"这类手滑 | `ros2 param set` 被拒，值不变 |
| **结构安全行程** | `900 – 2100` | `config/servo_params.yaml` ← **答辩要讲的就是这个** | 实际允许的动作范围 | goal 被 `goal_callback` **REJECT**，舵机不动 |
| **机械死点** | 实测，应比 900/2100 更宽 | 结构件本身 | 物理兜底 | 撞上去还发力 = 堵转 → 发热 → 烧舵机 |

关键差别：**前两个是软件约束，第三个是物理事实**。软件限位写错了，物理死点不会拦你，只会冒烟。

---

## 二、为什么中位是 1500

- 舵机协议定义 **PWM 1500 = 中立位**，这是绝对值，不随参数变；
- 900 和 2100 关于 1500 对称：`1500 − 900 = 600`，`2100 − 1500 = 600`；
- 代码里中位不是写死的，是 `(pwm_min + pwm_max) // 2` 算出来的 —— 所以改限位，启动回中的目标跟着变，不会出现"限位改了、回中还在旧位置"。

> 这也是为什么 yaml 里改 `pwm_min` 要顺手看一眼 `pwm_max`：两个值一歪，中位就偏，所有动作都偏。

---

## 三、为什么是 900–2100，不是 500–2500

1. **500–2500 只是"参数可以是这个数"，不是"结构能转到这个位置"**。它存在的意义是防止 `param set` 把参数改坏，不是给动作留余量。
2. 装好舵臂和连杆之后，两端在某个角度会**顶到结构**。900/2100 就是"顶到之前"的位置，各留了一段余量。
3. 判定容差 ±30 意味着：目标 2100 时，读到 2070 也算到位 —— 所以真正的边界比 2100 还要再往里一点。
4. 越界不是"转不动"这么简单：**顶着限位继续发力就是堵转**，电流上去、热量上来，三分钟能把舵机烧穿。所以宁可窄，不可宽。

---

## 四、怎么试出来（可复现，逐步手动）

> 前提：舵机已装舵臂、**没装整机连杆**（空载），人能听到声音、手能马上断电。
> 一次只动一个方向，一次只改 50。

**步骤**

1. 上电，先发 `#000PULR!` 恢复扭力（不发这条，后面全白做）；
2. 回 1500，静置 3 秒 —— **有嗡鸣说明结构已经顶住了**，先解决装配，别急着往下试；
3. 从 1500 开始，每步 **+50**（1550 → 1600 → …），每步停 1.5–2 秒，听声音、看结构有没有变形；
4. 第一次出现**持续嗡鸣 / 结构明显顶死**，记下这个位置，这就是该方向的**死点**；
5. **退回 50**（或 100，看你敢留多少）作为安全边界；
6. 反方向重复（1450 → 1400 → …）；
7. 两个边界取整到 50 的倍数，写进 yaml。

**半自动脚本**（每步等回车，人控制节奏，不要一次跑到底）

```python
import serial, time

ser = serial.Serial('/dev/ttyUSB0', 115200, timeout=0.05)

def send(text):
    ser.write((text + '\r\n').encode())
    time.sleep(0.05)

send('#000PULR!')          # 恢复扭力
for pwm in range(1500, 2251, 50):
    input(f'下一步 {pwm}，手放电源上，按回车发送 > ')
    send(f'#000P{pwm}T600!')
    time.sleep(1.5)        # 这 1.5 秒专心听
```

听到嗡鸣：`Ctrl-C` 停脚本 → 发 `#000PULK!` 卸力（或直接断电），别让它继续顶着。

**记录表（把实测值填进来，这份就是答辩证据）**

|---|---|---|---|
| 正向（1500 → 大） | ______ | ______ | `pwm_max: ______` |
| 反向（1500 → 小） | ______ | ______ | `pwm_min: ______` |

> ⚠️ 当前 yaml 里是 **900 / 2100**。如果你的调试记录里没有这一轮实测，就别在答辩时说"这是试出来的"—— 评委会问"试到多少开始响的"，答不上来比说"按经验取的保守值"更扣分。**现在补一次最快**：空载、每步 50、十分钟能测完。

## 五、代码里这三个数怎么用的

| 位置 | 用途 | 依据 |
|---|---|---|
| `_goal_callback` | `pwm_min <= pwm <= pwm_max` 不满足就 **REJECT** | 拒绝发生在动作开始前，不会"动一半才发现越界" |
| `_read_position` | 回显取数时用 `[pwm_min-100, pwm_max+100]` 过滤杂数 | 串口回显里混着 ID、温度等数字，靠这个带把位置挑出来 |
| `_get_center_pwm` | `(pwm_min + pwm_max) // 2` | 中位不硬编码，跟限位联动 |
| `_on_parameters_set` | `500 <= 值 <= 2500` 且 `pwm_min < pwm_max` | 拦非法改参，两种错都拒 |
| `_on_command_replay` | bag 回放的 pwm 用 `min(max(...))` 夹到区间内 | 回放也不许越界 |

## 六、答辩三问

**Q1：安全区间是多少？**
> 900 到 2100，中位 1500，两边各 600。这是**结构行程**，不是舵机的能力上限。

**Q2：怎么试出来的？**
> 空载，从 1500 每 50 往外走，听到持续嗡鸣就退回 50 留余量，两个方向各测一次。（配上第三节那张记录表）

**Q3：为什么不用 500–2500？**
> 500–2500 是参数保护域，防止误改参数；真按它跑，两端会顶住结构堵转。软件限位必须比机械死点更窄，才有余量。

**追问：改了限位会怎样？**
> `ros2 param set pwm_max 1900` 当帧生效，下一条 goal 就按新值判。但**结构没变** —— 软件限位改宽了，物理上照样会撞，所以改宽要慎重，改窄安全。
