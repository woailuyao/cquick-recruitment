# 参数表 · servo_driver（7 个，全部来自 yaml）

> 一句话：**7 个参数只在 yaml 给值，代码里只声明类型**；除 `baudrate` 要重启外，其余都能 `ros2 param set` **当帧生效**。
> 最外层 key 必须等于节点名 `servo_driver` —— 写错一个参数都不加载，而且**不报错**。

---

## 一、总表

| 参数 | 类型 | 默认值 | 为什么是这个默认值 | 运行时可改 |
|---|---|---|---|---|
| `port` | string | `/dev/ttyUSB0` | CH340 在本机**实测枚举为 0**。插拔或重启会漂到 1，所以这个 0 只是"当前值"、不是契约 —— 启动后必须看日志里有没有「串口已打开」 | 是（下次开串口生效） |
| `baudrate` | int | `115200` | 厂家协议固定 **115200 8-N-1**。9600 / 19200 / 38400 / 57600 实测全不转；白名单外的值直接拒 | 否（改要重启） |
| `pwm_min` | int | `900` | 结构行程的安全下限，留了余量。撞到限位还继续发力就是堵转，三分钟能烧穿舵机 | 是（当帧生效） |
| `pwm_max` | int | `2100` | 上限同理。1500 是中立位，900–2100 就是 **±600 的对称行程** | 是（当帧生效） |
| `default_duration_ms` | int | `800` | 当初填 800 是图快，但**实测偏短**：舵机还没走到位就被判超时（ABORTED）。建议改 **1500**（实测 1500 最稳） | 是 |
| `servo_ids` | int[] | `[0,1,2,3,4,5,6]` | 实测本舵机 ID = **000**（考核文档写"从 1 开始"，实际不是），列 0 才能兼容；1–6 留给整机 6 个舵机 | 是 |
| `startup_reset` | bool | `true` | 上电先回中位，保证每次启动姿态一致。否则会带着上次停下的角度上电，结构可能已经顶住 | 是 |

---

## 二、两条铁律

1. **代码里不写默认值**。`declare_parameter('port', Parameter.Type.STRING)` 只声明类型；值必须来自 yaml，取不到直接 `RuntimeError`。
   —— 写成 `declare_parameter('port', '/dev/ttyUSB0')` 等于设备名仍然硬编码，yaml 改不动。
2. **yaml 的 key 必须是 `/servo_driver`**（等于节点名）。写成 `/servo_driver_node` 或漏了前导 `/`，参数一个都不加载，日志里也不报错，只会表现得"参数没生效"。

---

## 三、怎么改、怎么验证（现场六步）

```bash
# ① 看全部参数
ros2 param list /servo_driver

# ② 改前记一下
ros2 param get /servo_driver pwm_max

# ③ 当帧生效：不用重启、不用改 yaml
ros2 param set /servo_driver pwm_max 1900

# ④ 立刻验证：同一条命令再发 goal，越界判定应该跟着变
ros2 action send_goal /move_servo cquick_servo_interfaces/action/MoveServo \
  "{command: {id: 0, pwm: 2050, duration_ms: 1500}}" --feedback

# ⑤ 故意越域，应当被拒（代码校验域 500–2500）
ros2 param set /servo_driver pwm_max 2600
#   → 报"超出 500~2500"，值不变

# ⑥ 确认没被改坏
ros2 param get /servo_driver pwm_max
```

判据：**③ 成功、④ 行为立刻变化、⑤ 被拒、⑥ 值仍是 1900**。四条都对，才算"当帧生效"。

## 四、三个坑（都踩过）

| # | 现象 | 真因 | 处理 |
|---|---|---|---|
| 1 | 一启动就进仿真，舵机不动，只有一行"串口打开失败" | `port` 写的是 `/dev/ttyUSB0`，实际枚举成 `ttyUSB1` | 每次按 `ls -l /dev/ttyUSB*` 改 yaml；或 `ros2 launch ... port:=/dev/ttyUSB1` 临时覆盖。**静默降级最坑，先看日志有没有「串口已打开」** |
| 2 | goal 走到一半 ABORTED：`not in position: target=1800 PRAD=1508` | `default_duration_ms = 800` 太短，没走到位就判超时 | 改 1500；判定逻辑本身也改成轮询 PRAD（150 ms 一次，最多 1 s），落进 ±30 才算到 |
| 3 | `ros2 param set` 说成功，但行为没变 | yaml 最外层 key 不是节点名，或代码里 `get_parameter` 存了副本 | 对照铁律 1、2；代码里每次判断都重新 `get_parameter` |

---

## 五、会被追问的三句

- **"为什么默认值不写在代码里？"** —— 写进去就等于硬编码，换设备要改代码、重编译；放 yaml 换硬件只改一行。
- **"为什么要给 baudrate 白名单？"** —— 波特率错了不会报错，只会收到乱码或静默无响应，比报错更难查。白名单把"手滑写成 1152000"挡在启动阶段。
- **"改限位为什么不用重启？"** —— 参数每次判断时现读，不缓存副本；`param set` 之后下一条 goal 就用新值。
