## 先说三条会踩的坑（省你半小时）

1. **串口是独占的。** `servo_driver` 起来后，`t1_servo.py` 一律打不开口。要扫 ID / 回中位 / 卸力，先：

   ```bash
   pkill -f "[s]ervo_driver"        # 中括号防自杀，别写成 "servo_driver"
   ```

2. **改了 `src/` 再 `colcon build` 可能报 `cquick_servo_interfaces` 失败**（旧 build 缓存）。直接：

   ```bash
   cd ~/rec_ws && rm -rf build install log && colcon build --symlink-install
   ```

3. **USB 转 TTL 会掉线**（今天已经遇到一次）。特征：某只开始全读不到 + `/dev/ttyUSB0` 时间戳变新 + open 报 `Errno 5`。修法：VirtualBox → 设备 → USB → 取消勾选 CH340 再勾上。

### E9 · 三个必须能答的问题

| 问题 | 答法（一句话） |
|---|---|
| 为什么不用 `sleep`？ | 舵机实际走完的时间 ≠ `duration_ms`，sleep 会累积误差，第二三遍必然不一样；result 才是"真到位"的信号 |
| 一步之内怎么让两个关节同时动？ | 放同一个 step，播放器一次性把两个 goal 都发出去；驱动侧线程数 ≥ 关节数才不会排队 |
| 一步之内怎么让它们先后动？ | 拆成两个 step，靠 result 隔开；**不许靠调 duration 硬凑** |

## 卡住了按这个顺序查

| 症状 | 先查 | 再查 |
|---|---|---|
| 舵机完全不动 | 日志有没有「串口已打开」 | 有没有「进入仿真模式」→ 查 port |
| 只有部分关节动 | `t1_servo.py scan`（先停节点） | 通道插错 / ID 与登记表不符 |
| 某个 goal `success=False` | `message` 里是 `not in position` 还是 `canceled` | duration 加大 100–200 ms |
| 动作打架 | 谁和谁在同一个 step | 拆 step，让前者 result 回来再发 |
| 三遍不一致 | `~/wave3.log` 里的 `final_pwm` 差异 | 结构松动 / 电池掉压 / 线程数 |
| 串口 `Errno 5` | `/dev/ttyUSB*` 时间戳 | USB 重挂载 |
| 全部读不到但刚才还好 | USB 掉线的典型表现 | 同上，别换舵机 |
