# 接口契约 · MoveServo

> 一句话：**goal 说"去哪、多久到"，feedback 报"我估计走到哪了"，result 才回答"到底到没到"。**
> feedback 是**按时间插值的估算值**，不是读回的实测值 —— 这是这套接口最容易被问倒的地方。

---

## 一、定义原文

```text
# Goal
cquick_servo_interfaces/ServoCommand command
---
# Result
bool   success
uint16 final_pwm
string message
---
# Feedback
uint16  current_pwm
float32 progress
```

goal 直接嵌套自定义 msg `ServoCommand`，没有另起一套字段 —— 一条消息描述一件事。

---

## 二、goal：三个字段

| 字段 | 类型 | 含义 | 取值范围 | 不合法会怎样 |
|---|---|---|---|---|
| `command.id` | `uint8` | 舵机 ID，协议里补 3 位（`000`–`255`） | 必须 ∈ `servo_ids`（当前 `[0..6]`） | `goal_callback` 直接 **REJECT**，不进 execute |
| `command.pwm` | `uint16` | 目标位置（PWM 值），1500 = 中立位 | 必须 ∈ [`pwm_min`, `pwm_max`] = 900–2100 | 同上，REJECT |
| `command.duration_ms` | `uint16` | 动作时长，毫秒；**0 表示回落到 `default_duration_ms`** | 0–60000；`> 60000` 拒 | REJECT |

**什么时候发**：客户端收到用户指令时发一次，然后等服务端 ACK。一次 goal 只对应一个舵机的一次动作，不做批量。

三个字段的校验**全部在 `goal_callback` 里做**，也就是"没开始动就被拦住"，不会出现"动了一半发现越界"。

---

## 三、feedback：两个字段，每 200 ms 一条

| 字段 | 类型 | 含义 | 怎么算的 |
|---|---|---|---|
| `current_pwm` | `uint16` | **估算**位置 | `start + (target − start) × progress`，线性插值 |
| `progress` | `float32` | 进度 0.0 → 1.0 | `已过时间 / duration_s`，到 1.0 封顶 |

**什么时候发**：

- 发完位置指令后**立刻**发第一条（`progress` 从 0 开始）；
- 之后每 `FEEDBACK_PERIOD_S = 0.2` 秒一条，直到 `progress` 到 1.0 或收到 cancel；
- `progress = 1.0` 那条**一定会发**（先 publish 再 break），所以 1500 ms 的动作大约 6–9 条；
- 如果 cancel 在第一条 feedback 之前就到了，**可能一条 feedback 都没有**。

> ⚠️ `current_pwm` 是算出来的，不是 `PRAD` 读回来的。它只保证"看起来平滑"，不保证"真的到位"。
> 到位判定在服务端用 PRAD 轮询做（±30，最多等 1 s），结果只出现在 `result` 里。

---

## 四、result：三个字段，三种结局

| 字段 | 类型 | 成功 | 超时/未到位 | 取消 |
|---|---|---|---|---|
| `success` | bool | `true` | `false` | `false` |
| `final_pwm` | uint16 | 实测 PRAD（如 1492） | 实测 PRAD | 中位（1500） |
| `message` | string | `ok, PRAD=1492` | `not in position: target=1800 PRAD=1508 diff=292` | `canceled` |

**什么时候发**：一次 goal 结束**必定**发一次，且只发一次。四种出口：

| 出口 | goal 状态 | 有没有 result | 触发条件 |
|---|---|---|---|
| 被拒 | `REJECTED` | ❌ 没有 | ID / 限位 / duration 任一不合法 |
| 成功 | `SUCCEEDED` | ✅ `success=true` | 轮询到 \|PRAD − target\| ≤ **30** |
| 失败 | `ABORTED` | ✅ `success=false` | 1 s 内没进 ±30 容差带 |
| 取消 | `CANCELED`（status=5） | ✅ `success=false`, `message=canceled` | 收到 cancel 后立即回中位（300 ms），再置 canceled |

## 五、一次 goal 的时间轴（duration = 1500 ms）

```text
t = 0        收到 goal
             └─ goal_callback：ID / 限位 / duration 三重校验 → ACCEPT

t ≈ 0        execute 开始
             ① 读起始位置（PRAD 最多 3 次，读不到取中位）
             ② 发 #000PULR!（恢复扭力）+ #000P1800T1500!

t + 0 ms     feedback #1   progress=0.00  current_pwm≈start
t + 200 ms   feedback #2   progress≈0.13  current_pwm 线性上移
   …         每 200 ms 一条 …
t + 1500 ms  feedback #N   progress=1.00  → 跳出循环

t + 1500 ms  开始 PRAD 轮询（每 150 ms 一次，最多 1 s）
t + ≤2500    |PRAD − 1800| ≤ 30 → succeed，result.final_pwm=实测值
             否则 → abort，message 里带 target / PRAD / diff

（若中途 cancel）
t + x        cancel_callback 接受 → while 里看到 is_cancel_requested 退出
             → 发 #000P1500T300!（回中位）→ canceled，result.final_pwm=1500
```

**为什么要多线程**：execute 里那个 200 ms 循环会占住线程，单线程 executor 下 cancel 回调排队进不来，`is_cancel_requested` 永远是 false。所以 `MultiThreadedExecutor` + `ReentrantCallbackGroup` 不是优化，是取消功能能不能用的前提。

## 六、命令行怎么试

```bash
# 正常一条，边跑边看 feedback
ros2 action send_goal /move_servo cquick_servo_interfaces/action/MoveServo \
  "{command: {id: 0, pwm: 1800, duration_ms: 1500}}" --feedback

# 越界：应当立刻 REJECT，舵机不动
ros2 action send_goal /move_servo cquick_servo_interfaces/action/MoveServo \
  "{command: {id: 0, pwm: 3000, duration_ms: 1500}}"

# 不存在的 ID：同样 REJECT
ros2 action send_goal /move_servo cquick_servo_interfaces/action/MoveServo \
  "{command: {id: 99, pwm: 1500, duration_ms: 1500}}"

# 取消：用显式调 cancel_goal_async() 的客户端
# （timeout -s INT 打断 send_goal 走不到 cancel 分支，别用它测取消）
```

## 七、服务端承诺的契约边界

1. **非法 goal 一律 REJECT**，不会"先动一下再报错"；
2. **接受后必定有 result**（成功 / ABORTED / CANCELED 三选一），不会静默消失；
3. **取消一定先回中位**再置 `canceled`，不会停在半路；
4. **`/servo/command` 只记 `record=True` 的指令** —— 启动回中位和 bag 回放本身都不记，否则回放会越放越多；
5. **限位判定用当前参数值**，`param set` 之后下一条 goal 立即按新限位判。

---

## 八、三个必须记住的坑

| # | 坑 | 后果 | 正确说法 |
|---|---|---|---|
| 1 | 把 `current_pwm` 当实测位置 | 答辩被追问"这个值是读回来的吗"就露 | 它是时间插值估算；实测值在 `result.final_pwm` |
| 2 | 串口没开时进仿真，`success` 仍是 `true` | 演示时看起来"成功"，但舵机根本没动 | 先确认日志有「串口已打开」；仿真时 message 带 `(simulated: 串口未打开)` |
| 3 | `duration_ms` 给太小（800） | 舵机没走到位就被判超时，ABORTED | 给 1500；`duration_ms=0` 是"用默认值"，不是"立即" |
