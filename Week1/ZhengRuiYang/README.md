## 任务 1：系统安装与 ROS2 环境自检
完成情况：
1.安装了VMware pro 26H1，Ubuntu 22.04，ROS2。
2.进行环境自检，版本符合要求。
遇到的问题与解决过程：
1. 一开始，我跟着一个比较老的视频安装了VMware 16 和 Ubuntu 20.04，在安装时，出现了软件依赖冲突。在询问AI后，我认为此时升级大版本容易出错，所以选择从磁盘中移除该虚拟机，删除了VMware16。然后在b站较新视频找到VMware pro 26H1的安装包，在清华镜像站找到Ubuntu 22.04的iso，完成安装。
2.我在安装tools时，出现了网络源报错。通过阅读报错信息和询问群友，明白了是清华源被拦截的缘故。在AI的帮助下，我在终端输入命令进行换源，最终换成了阿里源，成功安装tools。

## 任务 2：小乌龟
节点，是一个独立运行的程序，用来实现特定功能。它把功能封装在一个地方，我觉得类似于（只是类似于）一个project下不同功能的.c文件。话题，顾名思义，就像一个广播频道，是一个用来连接各个节点的通道。不同节点订阅同个话题后，其中一个节点发布消息，其他节点可以收听到消息。就比如这次让我们做的这个任务，turtle_teleop_key节点将键盘输入值发布到/turtle1/cmd这个话题中，而turtlesim节点订阅了这个话题，收听到了这条消息，所以根据这些数据完成了坐标移动。节点将功能封装，再由话题进行交流，这样方便后续修改，符合“高内聚，低耦合”的思想。

## 任务 3：Git 提交
1.第一次学习Git和Github。经过学习，我知道了战队在Github上有个主仓库，我要通过fork在自己的账号下复制一个相同的仓库，然后我再用clone把这个仓库复制到Ubuntu上，然后在上面修改内容，然后用add和commit把东西装好，写上备注，然后push到自己的仓库里，最后Pull Request，提交申请。
2.我觉得，这样设置，避免了不小心破坏了主仓库的风险。我们可以从主仓库中fork+clone自己需要的东西，完成内容后，push+Pull Request,申请上交。用好Git和Github，我们就可以远程完成资源和代码的共享和合作，方便又安全。
3.一开始git clone时才发现连git都没有安装，根据报错把git安装后就好了。
