## 任务 2： 小乌龟
我分别运行了 turtlesim_node 和 turtle_teleop_key，并使用方向键控制小乌龟移动。

节点和话题：1.节点是独立运行的，负责特定功能的ROS程序。

           2.话题是节点之间传递消息的通道。发布消息的节点叫发布者，接收消息的节点叫订阅者。发布者和订阅者不需要直接调用对方，只需要约定相同的话题名称和消息类型，就可以进行通信。一个话题可以同时具有多个发布者和订阅者

在本实验中，turtle_teleop_key节点通过 /turtle1/cmd_vel 话题向 turtlesim_node 发送运动指令。
## 任务 3：Git提交
我学习了 Fork、Clone、Add、Commit、Push 和 Pull Request 的基本流程，并了解了应该把自己的修改先推送到个人 Fork，再向主仓库提交 Pull Request。

问题：1.一开始我把‘cquick-recruitment’给克隆到了另一个Git仓库‘Github-for-beginners’的内部，形成了嵌套的仓库。后来才把他移到了外层，使两个仓库成为相互独立的文件夹。

2.移动文件夹时，我没有先确认当前路径，执行 `cd ../..` 后所在位置发生了变化，后续又因为路径中漏写了 `chatgpt` 而出现 `No such file or directory`。这让我学会了在操作前先使用 `pwd` 确认当前位置、使用 `ls` 查看目录内容，再编写正确的相对路径或绝对路径。

3.我还一度误以为 `mv` 是删除命令。后来了解到，`mv` 用于移动或重命名，`cp` 用于复制，真正的删除命令是 `rm`。涉及文件移动或删除时，需要先核对源路径和目标路径，避免误操作。

4.整理考核材料时，我最初把截图放在仓库外的“考核图库第一周”文件夹中，之后才按照要求复制到 `Week1/dingziqian` 目录。这让我认识到，只有放进 Git 仓库目录内的文件才能被 Git 检测、提交并推送。

感悟：通过本次考核，我理解了 Git 的基本流程：先在工作区修改或添加文件，使用 `git add` 将指定内容加入暂存区，使用 `git commit` 在本地仓库中生成一次有说明的版本记录，再使用 `git push` 推送到自己的远程 Fork，最后通过 Pull Request 请求将修改合并到主仓库。
