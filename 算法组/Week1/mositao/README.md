### 5.2 参数影响分析

**(1) 滤波前后的变化**

三种 5×5 滤波后整体白色占比几乎不变（灰色图像素分布没变），变化在局部纹理：桌面木纹和纸面细节被抹平，边缘变柔和。三者差别在细节：

- 均值滤波：邻域等权重，边缘最糊，噪点和真实边缘一起被削平；
- 高斯滤波：权重随距离衰减，中心保留多一点，边缘比均值清晰，是最常用的预处理；
- 中值滤波：取中位数，对孤立的极亮/极暗点（椒盐噪声）最有效，但细线和小尖角容易被吃掉。

**(2) 阈值调高或调低，哪些区域变化**

阈值从 80 提到 180，白色占比从 79.0% 掉到 15.9%，减少约 63 个百分点：

- 阈值 80（偏低）：大面积中灰区域（桌面、阴影）也被判成白色，目标和背景粘成一片，白色占掉 79%；
- 阈值 180（偏高）：只有接近高光的部分存活，主体被切碎成零散小块，白色只剩 15.9%；
- Otsu（131）：自动取直方图双峰间的谷底，落在上面两者中间，36.8%，是这张图最均衡的结果；
- 自适应阈值（87.2%）：按局部邻域算阈值，光照不均处也能分割，但代价是纹理也被判成黑白，白色区域反而最多，适合文档扫描而不适合自然场景。

**(3) 边缘是否完整**

- Canny 30/100：边缘像素 7763（1.62%）
- Canny 100/200：边缘像素 3490（0.73%）

高阈值把边缘数量砍掉一半以上，说明大量弱边缘被丢弃。低阈值图里能看到更多细节轮廓，但同时包含噪声产生的假边缘；高阈值图更干净，代价是某些对比度低的边界会断成线段。取 50/150 是折中（4937 像素，1.03%）。

**(4) 开运算或闭运算解决了什么问题**

以 Otsu 二值图为基准（10 个连通域，3 个面积小于 50 像素的碎片）：

| 操作 | 白色占比 | 连通域数 | 小于 50 像素的碎片 |
|---|---|---|---|
| Otsu 原始 | 36.8% | 10 | 3 |
| 开运算 3×3 | 36.8% | 11 | 4 |
| 闭运算 3×3 | 36.8% | 10 | 3 |
| 开运算 5×5 | 36.7% | 15 | 2 |
| 闭运算 5×5 | 36.9% | 9 | 2 |
| 开运算 7×7 | 36.4% | 35 | 5 |
| 闭运算 7×7 | 37.1% | 8 | 2 |

- 闭运算：膨胀后腐蚀，把小暗孔填上，连通域从 10 降到 8（7×7），白色占比略升，说明稀疏区域被连起来；
- 开运算：腐蚀后膨胀，理论上清掉小白点。但本图核取 7×7 时连通域从 10 猛增到 35，白色占比下降——因为开运算把宽度不足 7 像素的白色细连接腐蚀断了，原本连成一体的区域被切成多块。

### 5.3 一次失败案例与改进

**现象**：任务二里用 7×7 核做开运算，期望"减少噪声、连通域变少"，实测连通域从 10 增至 35，区域被切碎。

**原因**：开运算的腐蚀阶段用全 1 方形核，宽度小于核尺寸的白色细梁会被完全腐蚀掉，随后的膨胀无法恢复已经消失的连接。本图目标之间存在 5~7 像素宽的浅色细线，正好被 7×7 核切断。

**改进**：把核降到 3×3（连通域 11，接近原始 10），或改用椭圆核 `cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5,5))` 减少各向同性的过度腐蚀；若目标确实是"去小白点"，更稳的做法是按面积过滤轮廓（`contourArea`）而不是靠形态学，因为面积阈值是可控、可解释的参数。

## 6. 任务三：颜色目标提取与轮廓定位

脚本 `src/task3_color_detect.py`，处理流程：

```
BGR → HSV → inRange 掩膜 → 开运算 → 闭运算
    → findContours → 面积过滤 → boundingRect 外接框 + 矩求中心
```

### 6.1 参数怎么来的

先用 `src/check_photo.py` 对每张图做量化体检，它把画面外圈 8% 当作背景样本，判断背景是否本身带颜色，再据此寻找目标连通块：

```bash
python src/check_photo.py data/images/obj1.jpg
```

三张图的体检结果：

| 图片 | 原图尺寸 | 背景外圈高饱和占比 | 背景主色相 | 全图高饱和占比 | 候选目标中位值 |
|---|---|---|---|---|---|
| obj1 | 800×600 | 0.0% | —（中性） | 7.0% | H=108 S=236 V=188 |
| obj2 | 800×600 | 100.0% | H≈15（橙） | 97.4% | H=108 S=246 V=182 |
| obj3 | 3840×2160 | 36.0% | H≈15（橙） | 34.0% | H=127 S=128 V=185 |

由此分两种情况定参数：

- **背景是中性的**（obj1）：目标就是"所有高饱和像素里最大的连通块"，S 下限可以定得高一些（120），直接把白/灰背景排除；
- **背景本身有颜色**（obj2、obj3）：S 分不开（obj2 背景 S 高达 124~155），只能靠 H 分离——目标是 H≈108~127，背景是 H≈15，色相环上差了约 90 度。

最终参数：

| 图片 | lower | upper | min_area | 依据 |
|---|---|---|---|---|
| obj1 | (98, 120, 80) | (120, 255, 255) | 5000 | 背景 S≤5，S 下限 120 完全排除背景 |
| obj2 | (95, 80, 50) | (125, 255, 255) | 5000 | 背景 S 124~155 分不开，靠 H 分（目标 108 / 背景 15） |
| obj3 | (110, 90, 110) | (145, 255, 255) | 3000 | 暖光把全图染成 H≈15，只能取孤立的蓝紫色块 |

面积阈值的依据：目标面积最小的是 obj3（9643 像素，占画面 2.7%），形态学后残留噪声轮廓都在 500~1500 像素，所以 obj1/obj2 取 5000、obj3 取 3000，都留有余量。

### 6.3 哪些情况稳定、哪些容易失效

**稳定**：obj1（白墙背景 + 目标高饱和 S=236）、obj2（木桌背景，靠色相差异硬分）。两者的共同点是"目标与背景在色相或饱和度上有明确差距"，这是 HSV 阈值法能成立的前提。

**容易漏检**：obj3 的原始拍摄条件最差——暖色灯光把整个画面压到 H≈15，高饱和像素里 87.5% 都是背景的橙色，只剩不到 5% 的蓝紫色可抓。目标面积从 obj1 的 7.0% 掉到 2.7%，中心点也偏到 (458,301)。这种情况下如果把 S 下限从 90 提到 120，掩膜只剩 1.19%，面积过滤后**一个目标都检不出来**——参数稍有偏差就全盘失效。

**实测的失败案例**：换用新 obj3 之前，曾拍过一张只有黑色物体和暖光背景的照片。19 个取样点的 S 全部在 0~113 之间，最高只有 113；深色物体那一块的 HSV 是 H=125 S=40 V=56，几乎是无彩色。此时：

- 用色相选：选不出来，黑色没有色相；
- 用饱和度选：目标和灰色背景的 S 都是 30~60，分不开；
- 用明度选：能分开，但那就不是"颜色提取"了。

结论：**HSV 阈值法只适用于"目标有明确颜色、且与背景颜色不同"的场景**，对黑色、白色、灰色、金属反光的目标无能为力。这类目标应该改用边缘/轮廓方法（Canny + 形态学）或深度学习分割。

### 6.4 已知限制

- `cv2.putText` 只支持 ASCII，标注文字用英文，写中文会渲染成 `???`；
- 每张图的 HSV 范围必须单独标定，无法用一组参数通吃三张——这不是实现缺陷，而是颜色阈值法对光照变化的固有限制；
- `check_photo.py` 的判定阈值（面积 2%、S 110、背景高饱和 50%）是经验值，用于快速筛查而不是精确评估。

## 8. 遇到的问题

1. **OpenCV 5.0 在 Windows 上不支持中文路径**（本项目最麻烦的一个坑）

   现象：`cv2.imread` 读 `E:\MST\照片\...` 下的文件全部返回 `None`，控制台只打一行 `can't open/read file: check file path/integrity`，**不会抛异常**，所以不检查返回值的话会以为读到了空图。写入同理，`cv2.imwrite` 返回 `False`。

   实测对照（同一个文件）：

   | 路径 | `cv2.imread` 结果 |
   |---|---|
   | `E:\MST\robot_version\w1_mositao_version\data\images\obj1.jpg` | 成功 |
   | `E:\MST\robot_version\W1_莫思韬_视觉算法\obj1.jpg` | 失败（返回 None） |

   原因：OpenCV 的 Windows 文件接口按本地窄字符（GBK）转换路径，Python 传进去的 UTF-8 字符串在中文段被截断。

   解决：新增 `src/io_utils.py`，用 `np.fromfile` + `cv2.imdecode` 绕过：

   ```python
   data = np.fromfile(path, dtype=np.uint8)
   img = cv2.imdecode(data, cv2.IMREAD_COLOR)   # 读
   ok, buf = cv2.imencode(".png", img)
   buf.tofile(path)                              # 写
   ```

   全部脚本改为 `from io_utils import imread, imwrite`，路径全 ASCII 时仍走原生 `cv2.imread`（更快），含中文时自动切换。已实测在 `W1_莫思韬_视觉算法` 这样的中文目录下，三个任务脚本都能正常跑完。
2. **`findContours` 返回值数量**：OpenCV 3.x 返回 3 个值，4.x/5.x 返回 2 个。本项目按 5.0 写 `contours, _ = cv2.findContours(...)`，在 3.x 上会报 `too many values to unpack`。
3. **文件名大小写**：Windows 不区分大小写，`01.jpg` 能打开 `01.JPG`，但换到 Linux 会失败，因此代码里统一写实际大小写。
