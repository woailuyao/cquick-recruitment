## 参数是怎么定的

阈值：蓝块比浅灰背景暗，所以要用 `THRESH_BINARY_INV`，用普通 BINARY 拿到的是背景。
Otsu 自动算出 150，前景占 6.5%。手动阈值 T=127 时前景 4.8%，T=180 时背景也被判成前景，
前景涨到 30%、碎成 39 块，所以阈值不能随便调高。

滤波：高斯核从 5 加到 15，边缘像素 2006 掉到 1025，锐度从 2.7 掉到 0.7，核太大就把边缘抹掉了。

颜色范围：先用 cvtColor 采样目标区域的 H/S/V 分布，再看背景能不能分开。
蓝色目标和灰背景色相几乎一样（都是 105），只能靠饱和度（目标 160 以上，背景只有 9）；
绿色靠色相，木纹背景 H 是 14，绿色是 58~62；橙色靠饱和度，白布背景 S 接近 0。

面积阈值取 `max(800, 0.2% * 宽 * 高)`，1280x960 下是 2457。目标占全图 2.5%~7.7%，
开运算后残留的噪点一般不到 500 像素，0.2% 正好卡在中间。

## 遇到的一次失败

04 那张图的橙块整个在阴影里，饱和度只有 137、亮度只有 95。
用从顺光图定的 S≥150、V≥120 去检测，直接漏检，掩膜全黑。

把阈值放宽到 S≥90、V≥45 就能检出来，中心 (949, 600)，和真实位置差 6 个像素以内。
但代价是 02 那张图的木纹背景也被当成目标，整幅画面都被框住，面积 122 万像素。

所以固定阈值换个光照就不行了。后面想这样改：用自适应阈值代替固定值、
先把画面裁到取料区再检测、再加个面积上限（比如不超过全图 15%）把这种误检直接拒掉。

## 踩过的坑

- 中文路径下 `cv2.imread` 会静默失败，这个目录名本身就带中文，所以读写都换成
  `np.fromfile + imdecode` 和 `imencode + tofile`。
- `cv2.putText` 不支持中文，画出来是问号，所以图上的标注都用英文。
- `shape` 是 (高, 宽, 通道)，索引写 `img[y, x]`，但 `rectangle` 的参数又是 (x, y, w, h)，容易搞混。
- 灰度图回读要用 `IMREAD_UNCHANGED`，不然会被自动扩成 3 通道。
- 某行 f-string 里嵌套了同类引号，3.12 能跑，3.10 直接语法报错，已改掉。
