### 3.5 中文路径兼容

提交目录名含中文字符，而 OpenCV 的 `cv2.imread` / `cv2.imwrite` 在 Windows 上**不支持非 ASCII 路径**：

因此三个脚本各自定义了替代函数，把文件读写交给 Python（完整支持 UTF-8），OpenCV 只负责内存中的编解码：

```python
def imread_cn(path, flags=cv2.IMREAD_COLOR):
    """支持中文路径的读图：先由 Python 读字节，再交给 OpenCV 在内存中解码。"""
    data = np.fromfile(str(path), dtype=np.uint8)
    if data.size == 0:
        return None
    return cv2.imdecode(data, flags)

def imwrite_cn(path, img):
    """支持中文路径的存图：先在内存中编码，再由 Python 写字节。"""
    path = str(path)
    ext = "." + path.rsplit(".", 1)[-1]
    ok, buf = cv2.imencode(ext, img)
    if not ok:
        return False
    buf.tofile(path)
    return True
```

调用方式与原函数完全一致，仅名称不同：

```python
img = imread_cn(img1_path)          # 代替 cv2.imread
imwrite_cn(out_path, mask)          # 代替 cv2.imwrite
```

### 6.3 滤波前后的变化

**参数**：`cv2.GaussianBlur(grey, (5,5), 0)`

| 指标 | 滤波前 | 滤波后 | 变化 |
|---|---|---|---|
| 背景区域标准差 | 0.81 | 0.80 | 无变化 |
| 全图平均梯度 | 11.16 | 6.83 | -38.8% |
| 最大梯度 | 488 | 316 | -35.3% |

**这张图的滤波没有起到去噪作用，唯一效果是削弱边缘。** 背景标准差仅 0.81，说明图像本身几乎不含噪声；对无噪声图像做 5×5 高斯模糊，只会降低所有梯度。后果是弱边缘（苹果底部与阴影交界）梯度不足以越过 Canny 阈值，造成轮廓断裂。

### 6.4 阈值调高或调低后哪些区域发生变化

**参数对比**：固定阈值 `32` vs `Otsu` 自动阈值（算出 **73**）

| 方案 | 白像素数 | 占全图比例 |
|---|---|---|
| 固定阈值 32 | 62438 | 14.64% |
| Otsu 自动 73 | 38720 | 9.08% |

**阈值从 32 升到 73，减少的 5.56% 全部集中在苹果右下方**——该处为背光面，灰度 17~73，低于 73 被判为背景。

规律：**阈值升高先丢目标暗部，阈值降低先出现背景碎片。** 本图背景灰度最大 63、目标暗部最低 31，两者存在重叠，因此不存在能完美分离的单一阈值。

### 6.5 边缘是否完整

**参数对比**：三组 Canny 双阈值

| 阈值 | 边缘像素数 | 占全图比例 | 视觉效果 |
|---|---|---|---|
| 100 / 200 | 673 | 0.158% | 仅剩强轮廓，大段缺失 |
| **30 / 150** | 1241 | 0.291% | 轮廓基本完整，底部断裂 |
| 20 / 100 | 1598 | 0.375% | 边缘增多，开始出现伪边缘 |

**边缘不完整，缺口位于苹果底部。** 该处梯度中位数 14.6、25% 分位仅 7.2，而背景梯度 95% 分位已达 7.1，两者落在同一区间。继续降阈值实测：底部边缘从 420 增至 908，背景伪边缘从 1 激增至 1272，信噪比跌破 1，结果不可用。

**30/150 是该图的最优折中**；底部断裂源于采集阶段对比度不足，无法通过调参解决。

### 6.6 开运算或闭运算解决了什么问题

**参数**：5×5 矩形核，先开运算后闭运算

| 阶段 | 白像素数 | 连通轮廓数 |
|---|---|---|
| 原始阈值结果 | 62438 | 29 |
| 开运算后 | 62251 | 2 |
| 闭运算后 | 62337 | 2 |

**开运算消除背景碎片**：轮廓数 29 → 2，白像素仅减少 187（占面积 0.04%），主体未受损。原因是碎片尺寸小于 5×5 核，在腐蚀阶段被完全抹除，后续膨胀无法复原。

**闭运算填补目标内部小孔**：补回 86 个像素，对应苹果表面高光造成的空洞。

两者分工不重叠，且**顺序不能颠倒**——若先闭后开，闭运算会把噪点与目标连成一体，之后就无法清除。

### 7.4 HSV 范围的设定依据

参数不是试出来的，而是从目标区的实测分布反推。

| 图片 | 实测中位值 | H 范围 | S 下限 | V 下限 |
|---|---|---|---|---|
| img1 青杯 | H 88 / S 141 / V 134 | 78 ~ 108 | 100 | 40 |
| img2 青苹果 | H 30 / S 244 / V 17~179 | 25 ~ 100 | 30 | **8** |

两处非直觉的取值：

- **img1 的 H 下限取 78 而非 85**：高光侧色相偏移到 80 附近，取 85 会切掉杯身右侧一条竖直缺口
- **img2 的 V 下限只有 8**：背光面 V 仅 35~39，按常规取 40 以上会整片丢失暗部；该图背景纯黑，靠 S 即可排除

img3 未用 HSV，原因见 7.5。

### 7.5 使用 Lab 空间的原因

任务建议 HSV，前两张图也确实如此，但 **img3 用 HSV 得不到可用结果**，改用 Lab 的 a 通道。

**问题：红色目标与它的投影无法用 S 分开。** 红苹果置于浅色布纹桌面，右下方投影被苹果反射的红光染红。饱和度出现重叠，无法使用S调节


 a 更抗干扰，S 是相对量 `(max−min)/max`，混入环境白光后三通道一起抬高、分母变大，S 暴跌；a 是绝对量，编码红绿轴上的绝对偏移，被稀释后降低少。

### 7.6 面积阈值的设定依据

```python
min_area = int(img.shape[0] * img.shape[1] * 0.001)    # 画面面积的 0.1%
```

依据：真实目标占画面 5%~25%，噪声碎片普遍小于 0.1%，两者相差一个数量级以上。取值原则是**偏小**——漏删噪点只是画面杂乱，误删目标则全盘作废。

### 7.7 参数调节方法与优先级

调参按固定顺序逐维推进，**每次只改一个维度**，否则无法判断是哪个参数起了作用。

| 步骤 | 维度 | 怎么定 |
|---|---|---|
| 1 | **H 范围** | 取目标区 H 的 5%~95% 分位；若低分位接近 0、高分位接近 179，必须拆双段（红色） |
| 2 | **S 下限** | 排除灰白背景；设太高会切掉目标反光边缘 |
| 3 | **V 下限** | 排除过暗区域；目标有背光面时必须放宽（img2 暗部 V 仅 35） |
| 4 | **面积阈值** | 画面 0.1%；过滤后剩 0 个说明阈值过高 |
| 5 | **形态学核** | 开运算去外点、闭运算补内孔，从 3×3 起步；边缘被磨损说明核过大 |

优先级：`H > S > V > 面积阈值 > 形态学核`。前三个决定"能不能分出来"，后两个只决定"分得干不干净"——**分离失败的图靠形态学救不回来**。

掩膜缺一块时，用参照掩膜定位是哪个维度卡住：先取灰度低阈值 + 最大轮廓造一个更完整的 `ref`，再用 `ref − mask` 得到缺失区，统计各维度的越界比例，**哪个越界最多就放宽哪个**。

```python
missing = cv2.bitwise_and(ref, cv2.bitwise_not(mask))
v = hsv[missing == 255]
print((v[:,0] < lower[0]).mean(), (v[:,1] < lower[1]).mean(), (v[:,2] < lower[2]).mean())
```

实测 img2 的缺失区有 96.9% 由 `V < 40` 造成，据此把 V 降到 8，缺口即消失。

### 7.8 稳定性与误检记录

| 图片 | 光照条件 | 稳定性 | 主要问题 |
|---|---|---|---|
| img1 青杯 | 粉色纯色背景，柔和漫射光 | **稳定** | 无，单次调参即达标 |
| img2 青苹果 | 纯黑背景，强方向光 | **较稳定** | 内部亮度跨度 150（17~179），V 下限须放到极低 |
| img3 红苹果 | 浅色布纹背景，暖调侧光 | **HSV 不稳 / Lab 稳定** | 投影阴影色相与目标相同，S 无法分离 |

规律：**纯色背景 + 均匀光照**最稳定；**强对比背景 + 内部光照不均**需为最暗处单独放宽 V；**彩色背景 + 目标投影**最易误检，须换颜色空间。

| 误检类型 | 表现 | 成因 |
|---|---|---|
| 阴影误检 | 掩膜溢到目标下方投影上 | 投影由目标反射光构成，色相相同，仅饱和度/红度不同 |
| 暗部漏检 | 背光面整片缺失 | 背光面 V 低、S 低、H 不稳定，三维同时偏离 |
| 高光漏检 | 强反光处出现空洞 | 镜面反射接近白色，S 趋近 0 |

## 8. 失败案例与改进思路

### 8.1 现象

使用 Otsu 自动阈值（73）对青苹果做分割时，**苹果右侧与下方整片区域未能提取出来**，掩膜出现大面积缺口。

### 8.2 原因

实测数据：

| 区域 | 灰度范围 |
|---|---|
| 苹果左上（受光面） | 150 ~ 179 |
| 苹果右下（背光面） | **17 ~ 73** |
| 背景 | 均值 13.8，最大值 63 |
| Otsu 阈值 | **73** |

苹果的背光面整片低于阈值 73，被判定为背景。

更深层的原因是**目标与背景在灰度上重叠**：背景最大 63，目标最低 31，重叠区达 32 个灰度级。Otsu 的前提是直方图呈双峰且两峰分离良好，而本图的目标内部跨度达 148 个灰度级，直方图实际呈单峰宽分布，Otsu 只能在中间切一刀，必然牺牲一侧。

### 8.3 尝试过的方案

| 方案 | 结论 |
|---|---|
| Otsu（73） | 右下整片丢失，不可用 |
| 固定阈值 50 | 仍缺一小块 |
| **固定阈值 32** | **基本完整，采用此方案** |
| 固定阈值 20 | 目标最完整，但背景碎片占 30.9% |
| 阈值 32 + 5×5 开运算 | 碎片清除，主体未损——**最终方案** |
| 闭运算 7×7 补缺口 | 无效，缺口与背景连通，不属于内部孔洞 |
| 凸包补全 | 底部虽补齐，但苹果上方凹陷被误填，反而更差 |
| Canny + 闭运算 + 轮廓填充 | 低阈值引入大量背景伪边缘，严重过度分割 |

### 8.4 改进思路

**短期（本作业采用）**：降低固定阈值至 32，保证目标暗部不被丢弃；再用 5×5 开运算清除随之出现的背景碎片。这是灰度框架内的最优解。

**根本方案**：改用 HSV 颜色空间分割，用色相而非亮度作为判据——苹果背光面虽然暗，但色相仍是黄绿色，颜色信息不受光照强度影响。

## 9. 参数影响汇总

| 参数 | 调整方向 | 直接后果 | 适用场景 |
|---|---|---|---|
| 高斯核大小 | 增大 | 平滑增强，边缘过渡带变宽（宽度 ≈ 核宽-1） | 有噪声时；无噪声时有害 |
| 阈值 | 降低 | 白色区域增多，目标更完整，但背景碎片增加 | 目标暗部丢失时 |
| 阈值 | 升高 | 白色区域减少，背景更干净，但目标暗部丢失 | 背景噪声过多时 |
| Canny 双阈值 | 降低 | 边缘增多（本次 673→1241→1598），细节显现但伪边缘增加 | 需要更多细节时 |
| Canny 双阈值 | 升高 | 只留强轮廓，弱边缘断裂 | 只关注主要边界时 |
| 形态学核大小 | 增大 | 去噪/填洞能力增强，但可能侵蚀目标 | 碎片或孔洞尺寸较大时 |
| 开运算 | — | 去外部小噪点，主体尺寸不变 | 掩膜外有零星碎片 |
| 闭运算 | — | 填内部小孔，主体尺寸不变 | 目标内部有空洞 |
| **HSV 的 H 范围** | 收窄 | 分割更精确，但可能漏掉色相偏移的区域 | 目标色相稳定时 |
| **HSV 的 S 下限** | 提高 | 排除灰白背景与投影阴影，但会切掉目标背光面 | 背景有灰白色或红色阴影 |
| **HSV 的 V 下限** | 降低 | 保留目标暗部，但可能引入暗背景碎块 | 目标存在背光面 |
| **Lab 的 a 阈值** | 提高 | 只保留"更红"的区域，有效排除同色相阴影 | 目标投影与本体色相一致时 |
| **面积阈值** | 提高 | 噪点清除更彻底，但有过早误删小目标的风险 | 噪点面积较大时 |
