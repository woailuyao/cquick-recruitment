### 任务二 · 基础图像处理对比

| 处理 | 关键参数 | 结果文件 | 现象观察 |
|---|---|---|---|
| 灰度 | — | `sample2_gray.jpg` | 三通道压成单通道，蓝、绿、橙都变成亮度接近的灰，靠明暗区分的条纹反而更清楚 |
| 高斯滤波 | ksize=(5,5) | `sample2_gaus.jpg` | 噪点变柔，条纹边界轻微发软，整体和原图差别不大 |
| 高斯滤波 | ksize=(21,21) | `sample2_gaus2.jpg` | 明显更糊，条纹被揉成一片，颜色还往周边渗开，小色点变大色团 |
| 阈值分割 | thresh=130 | `sample2_thres.jpg` | 灰条纹按明暗切成黑白条纹，三个色块变成纯蓝 / 纯绿 / 黄白；阈值调高黑条纹变宽，调低亮条纹变白更多 |
| Canny | low=50, high=150 | `sample2_can.jpg` | 条纹边界和三个图形轮廓都成了细线，画面的圆点噪点也被描成小圈 |
| 形态学开 | kernel 3×3 | `sample2_mpeopen.jpg` | 零散小白点没了，图形边缘略瘦 |
| 形态学闭 | kernel 3×3 | `sample2_mpeclose.jpg` | 小黑点被填上，条纹缝隙合拢一点 |
| 形态学开 | kernel 21×21 | `sample2_mpeopen2.jpg` | 核太大，细条纹被整块吃掉，像散光 |
| 形态学闭 | kernel 21×21 | `sample2_mpeclose2.jpg` | 黑白边界被抹宽，细节丢失 |

至少换的 2 组参数对比：

1. 高斯 5×5 对 21×21：5×5 只压噪点，结构还是清楚的；21×21 把结构和噪音一起抹平、颜色互相污染。结论是核要比想保留的细节小。
2. 形态学 3×3 对 21×21：3×3 只清掉孤立的小点，21×21 连条纹本体都破坏。结论是先从 3×3 这种小核试，效果不够再放大。

### 任务三 · 颜色目标提取与轮廓定位

- 目标颜色：蓝色（蓝菱形）
- HSV 范围：lower = (100, 120, 70)，upper = (130, 255, 255)
- 面积阈值：300。条纹和 JPEG 压缩噪点连出来的小斑块面积基本都在 100 以下，而目标最大面积 8434，取 300 能砍掉噪声、又给缩放和远一点的目标留余量。
- 形态学处理：开运算 kernel 5×5（去小噪点）+ 闭运算 kernel 5×5（补目标被条纹切开的洞）

| 01 `sample_scene.png` | 灰条纹背景，正常光 | (200, 185) | 8434 | 稳定 | H 在 100–130 区间、S/V 都高，阈值刚好框住菱形 |
| 02 `test_dark.png` | 压暗约 35%，有噪点 | (199, 185) | 8444 | 稳定 | 亮度降了但 S 还够，H 基本没偏，中心只差 1 像素 |

## 四、一次失败案例与改进思路

**现象**：做颜色识别时，最初把形态学核设成 11×11，结果蓝菱形边缘被啃掉一圈，轮廓和实际形状完全对不上，画出来的框比目标小很多。

**我是怎么查的**：把开运算的中间掩膜（`sample3_maskaOpen.jpg`）存下来，一张一张和原图叠着看；再把 `contourArea` 打出来，发现面积比真实值小了一两千。

**原因**：开运算会用核去腐蚀边缘，核 11×11 意味着边缘先往里缩 5 个像素，对 800×600 的图、几百像素宽的目标来说，这个比例太大了。

**改进**：核从 11×11 → 7×7 → 3×3 → 5×5 逐步试，每次都存图对比；最后 5×5 是「去掉条纹切出来的小洞」和「不吃掉目标本体」之间的折中。

**改进后效果**：3 张主测图（正常光、暗光、暖光）都能稳定框到菱形，中心坐标几乎重合；但换蓝色背景的 `test_bluebg.png` 依然会把背景整块当目标，这个靠颜色阈值本身解决不了，得靠前景分割或者先验位置。

（另一个踩过的坑：拿 CS2 截图做暗色人物检测时，暗区阈值会把匪门上的弹孔和瞄准镜的黑边也框进去。后来加了「面积 > 20000 且高 ≥ 宽」两道限制，能滤掉大部分小阴影，但开镜图和人物贴墙进阴影时还是会误检——目前只对站立的全身角色比较稳。）
