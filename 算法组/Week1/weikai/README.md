### 任务二 · 基础图像处理对比

测试图 `test_green_rect.jpg`，输出 8 张结果到 `outputs/task2/`（要求 ≥5 张）。下表的"白点数"是把结果转灰度后统计 `>127` 的像素个数，用来量化对比：

| 处理 | 关键参数 | 结果文件 | 现象观察 |
| ------- | ------- | ------- | ------- |
| 灰度 | — | `01_gray.jpg`  | 3 通道压成单通道，颜色信息丢失，只剩亮度    |
| 高斯滤波 | ksize=5×5 / 15×15 | `02_gaussian_5x5.jpg`、`02_gaussian_15x15.jpg` | 滤波后整体变平滑、细小噪点被削弱；5×5 保留细节多，15×15 明显更糊 |
| 阈值分割 | thresh=80 / 160 | `03_threshold_80.jpg`、`03_threshold_160.jpg`  | 阈值 80 → 白点 42399，目标区域基本连成一片；阈值 160 → 白点仅 6，几乎全部判为背景，目标断裂/丢失 |
| Canny 边缘 | (low, high)=(30,80) / (100,200) | `04_canny_30_80.jpg`、`04_canny_100_200.jpg`   | (30,80) 白点 70066，轮廓完整但夹带大量碎噪点边；(100,200) 白点 821，边缘干净但弱边丢失、轮廓不闭合  |
| 形态学（开运算） | kernel=5×5 矩形 | `05_morph_open.jpg` | 作用在 Canny(30,80) 上，白点数降到 0——边缘只有 1 px 宽，5×5 结构元比特征还大，细边连同噪点一起被抹掉 |

**至少换的 2 组参数对比（实测）**：

1. **高斯核 5×5 → 15×15**：模糊程度显著增加，细节减少，边缘宽度变宽；
2. **阈值 80 → 160**：白点数从 42399 骤降到 6，说明阈值直接决定前景面积，过高会让目标整体消失；
3. **Canny (30,80) → (100,200)**：白点数 70066 → 821，边缘由"密而全但含噪"变为"干净但漏弱边"。

**结论**：滤波核越大越模糊；阈值越高前景越少；Canny 双阈值越高边缘越稀。开运算去噪的有效前提是**结构元小于要保留的特征宽度**。

### 任务三 · 颜色目标提取与轮廓定位

对 3 张测试图各检测对应颜色，HSV 范围与结果如下（H 用 OpenCV 的 0–179，不是 0–360）：

| 测试图                      | 目标颜色 | lower (H,S,V)  | upper (H,S,V)   | 中心坐标 (x,y) | 轮廓面积  |
| ------------------------ | ---- | -------------- | --------------- | ---------- | ----- |
| test_blue_circle.jpg     | 蓝    | (100, 50, 50)  | (130, 255, 255) | (300, 200) | 26608 |
| test_green_rect.jpg      | 绿    | (35, 50, 50)   | (85, 255, 255)  | (301, 216) | 41916 |
| test_orange_triangle.jpg | 橙    | (10, 100, 100) | (25, 255, 255)  | (300, 212) | 14383 |

- **形态学处理**：`inRange` 后做开运算（`MORPH_OPEN`，5×5 矩形结构元），去掉掩膜上的孤立噪点，再做 `findContours`（OpenCV 4/5 只返回 2 个值：`contours, hierarchy`）。
- **HSV 范围怎么定的**：三步——① 用 `cv2.cvtColor(img, cv2.COLOR_BGR2HSV)` 后打印目标像素的 HSV 值采样；② 以采样值为中心，`H` 给 ±15 左右，`S/V` 下限放宽到 50（橙色用 100，因为橙色本身饱和度高）；③ 跑一遍看 mask 有没有把目标抠全、有没有把背景抠进来，再微调。用 `H` 区分颜色是因为 `H` 只表色相，不像 BGR 那样受亮度影响。
- **面积阈值 `MIN_AREA = 500` 怎么定的**：先打印所有轮廓的 `contourArea`，发现噪点轮廓面积都在几十到一两百量级，而三个目标都在 14000 以上，取 500 留出约 2 倍余量——既能滤掉噪点，又不会误删小目标。
- **稳定 / 误检 / 漏检记录**：

| 测试图 | 背景/光照     | 结果                                      | 原因分析                                           |
| --- | --------- | --------------------------------------- | ---------------------------------------------- |
| 蓝圆  | 浅灰背景、均匀光照 | 稳定，中心 (300,200) 与几何中心吻合、面积 26608 接近 πr² | 目标色与背景色相差大，H 区间无重叠   |
| 绿矩  | 浅灰背景、均匀光照 | 稳定，面积 41916 最接近理论矩形面积 | 同上，且绿色在 HSV 中 H 区间窄，不易混入其他色   |
| 橙三角 | 浅灰背景、均匀光照 | 稳定，但面积 14383 明显小于矩形/圆形同类目标 | 三角形实际面积本就小；若换成暗光图片，橙色 V 值下降会先跌破 V 下限，是最容易漏检的一类 |

易误检场景：背景里出现与目标同色系的物体（如橙色目标旁放红色块，H 接近 10–25 会一起被抠进来）；易漏检场景：强逆光或偏色光源让目标 H 整体偏移、S 被压低，超出设定区间。

## 四、一次失败案例与改进思路

- **现象**：任务一保存灰度图 `blue_gray.jpg` 后，用 `cv2.imread('outputs/task1/blue_gray.jpg')` 重读，打印出来的 `shape` 是 `(400, 600, 3)`，而不是保存前的 `(400, 600)`，多出了一个通道维度。
- **我是怎么查的**：先在保存前后各 `print` 一次 `shape`，确认保存前确实是单通道；再把重读的数组和 `gray` 做比较，发现通道数对不上；最后查 `cv2.imread` 的默认参数才发现问题。
- **原因**：`cv2.imread` 默认用 `IMREAD_COLOR` 方式加载，**无论原文件是几个通道，都会统一补成 3 通道 BGR**。文件本身没坏，是读取方式把单通道"补"成了三通道。如果后面拿这个数组去做掩膜位运算（要求单通道），就会直接报维度不匹配。
- **改进**：读取灰度图时显式传标志 `cv2.imread(path, cv2.IMREAD_GRAYSCALE)`，读回来就是 `(400, 600)`。另外验证"存得对不对"时只比 `shape` 和尺寸，不做逐像素相等比较——因为 `.jpg` 是有损压缩，重读的像素值可能有 ±1~2 的偏差，需要像素级一致时应改存 `.png`。
- **改进后效果**：三张结果图重读后 shape 全部与保存前一致，`assert` 全部通过。
