## 任务一：图像基础操作

任务书要求：在至少 2 张图上，读取并打印宽高通道、做缩放/指定区域裁剪/灰度、保存后能重新读出来，原图不能被覆盖。我 7 张图都跑了。

每张输出五样：缩放图、中心裁剪、指定区域裁剪、灰度图、四联对比图。35 张，比要求的“每种操作至少一张”多不少。

几个关键点：

- 缩放是等比缩到宽 640，没直接用 `resize(img, (640, 480))`，因为那样会拉伸变形。竖版的那张笔记本原图是 1708×2298，缩完是 640×861，能看出来宽高没写反。
- 裁剪用切片 `img[y1:y2, x1:x2]`，注意是先 y 后 x，我一开始写反了，切出来一条细缝。
- 指定区域这块返工过一次。一开始按固定比例裁右上角，结果拖鞋那张裁出来全是木纹，等于白裁。后来改成每张图标一块细节区域，代码里写成一个 ROI 字典：笔记本裁右上角标签、橙子裁果蒂和果皮纹路、拖鞋裁鞋面网格、笔裁笔身中段、蓝充电宝裁二维码、白充电宝裁印刷文字。
- 每张图存完之后都重新读了一遍，打印读回来的 shape 确认不是假成功。这里有个坑：回读如果用默认的 `IMREAD_COLOR`，灰度图会被强行扩成三通道，看着像存错了，其实文件是对的，要用 `IMREAD_UNCHANGED` 才看得到真实的通道数。
- 原图没有被覆盖，所有输出都带后缀，`data/images` 里的文件改时间一直没变。

还顺手量了一下灰度到底丢了多少信息，在 `01_green_notebook.jpg` 上取粉色书脊和绿色封面两点：

| 取样位置 | BGR | 灰度 | HSV |
|---|---|---|---|
| 粉色书脊 | 155,147,140 | 146 | 106,25,155 |
| 绿色封面 | 146,191,164 | 178 | 48,60,191 |

灰度只差 32，色相差 58（大概 116 度）。所以灰度基本把这两个颜色压成同一个亮度了，后面做颜色分割还是得用 HSV。

## 任务二：基础图像处理对比

任务书要求：选一张目标清晰的图，输出灰度、高斯滤波、阈值分割、Canny 边缘、一次形态学处理，至少换 2 组参数对比，并在 README 里记录四个问题。

用的是 `02_orange_cream.jpg`（4004×2930）。本来想用蓝色充电宝那张，试了一下阈值 127 和 180 的白像素占比分别是 56.0% 和 54.8%，几乎没区别，因为背景亮度太集中了，看不出阈值的影响，换成橙子这张才明显。

输出 8 张中间结果和 4 张对比图：

- `01_gray.jpg` 灰度
- `02_gauss5.jpg` 高斯 5×5
- `03_threshold_127.jpg` 固定阈值 127
- `04_canny_50_150.jpg` Canny 50/150
- `05_morph_open.jpg` 开运算（做在自适应阈值的结果上）
- `06_otsu.jpg`、`07_adaptive.jpg`、`08_morph_close.jpg`
- `compare_gauss.jpg`、`compare_threshold.jpg`、`compare_canny.jpg`、`compare_morph.jpg`

实测数据：

| 指标 | 数值 |
|---|---|
| 阈值 127 白像素占比 | 70.80% |
| 阈值 180 白像素占比 | 40.94% |
| Otsu 算出来的阈值 | 144 |
| Canny 50/150 边缘像素 | 6397 |
| Canny 30/90 边缘像素 | 17851 |
| 自适应阈值白像素占比 | 95.69% |
| 自适应阈值开运算后 | 93.85% |
| 自适应阈值闭运算后 | 99.95% |

任务书问的四个问题，逐个答：

**滤波前后变化**：5×5 高斯之后橙子皮的细纹就没了，轮廓还在；换成 15×15 之后连投影边缘都开始糊，边缘位置往外飘。三种滤波都试过，中值对椒盐噪声最好，但这张图没有那种噪声，看不出优势，最后还是用高斯。

**阈值调高调低**：从 127 提到 180，白区从七成掉到四成。看图就明白：127 的时候橙子的受光面和桌面都是白的，只有暗部黑；180 的时候橙子暗部整块变黑，等于把目标自己吃掉了。所以阈值越高前景越少，先被牺牲的是暗部。

**边缘是否完整**：Canny 用 50/150 的时候边缘像素 6397，只勾出橙子轮廓和投影边界；降到 30/90 就变成 17851，桌面纹理和果皮颗粒全进来了。低阈值不能压太狠，我现在习惯按 1:3 一起调，比如 50/150、30/90。

**开闭运算解决什么**：自适应阈值在这张图上几乎是满屏噪点（白像素 95.69%），因为它是用局部均值减 C，桌面这种大片平坦的地方也被判成前景。对它做 5×5 开运算，噪点去掉一大片（降到 93.85%），只剩几条边线；闭运算反过来把小孔填满（99.95%），整张图快全白了。结论是开运算去小白点、闭运算补小黑洞，但得先在合适的二值图上做，自适应阈值在这种大面积均匀的图里不适合直接用。

## 任务三：颜色目标提取与轮廓定位

任务书要求：选一种颜色明确的物体（蓝绿橙），BGR 转 HSV 用 inRange 生成掩膜，开闭运算改善，findContours 找轮廓按面积过滤，画外接矩形和中心点输出坐标面积，至少 3 张不同背景/光照测试并记录稳定和误检漏检。

流程是：读图 → 转 HSV → `inRange` 出掩膜 → 开运算去噪点、闭运算补洞 → `findContours` → 按面积过滤 → 算外接矩形和中心点，画在原图上，同时打印坐标和面积。7 张图都跑了，输出在 `outputs/task3/<图片名>/` 下面，每张一组 `mask.png` 和 `result.jpg`，汇总数字存在 `outputs/task3/检测记录.txt`。

### 颜色范围怎么定的

不是一个个试出来的。做法是先把图转成 HSV，打印目标区域和背景区域的 H、S、V 分位数，然后取中间的余量。比如蓝色充电宝，目标 H 在 107~113、S 在 82~110、V 在 84~125，背景桌面 H≈20、S≈59、V≈229，所以我取 `(100,65,60)~(125,255,200)`，S 下限 65 卡在背景 59 上面一点。

| 图片 | 颜色 | lower | upper |
|---|---|---|---|
| 01_green_notebook | 绿 | (33,40,140) | (55,110,255) |
| 02_orange_cream | 橙 | (7,100,60) | (22,255,255) |
| 03_blue_slipper | 浅蓝 | (90,35,120) | (115,255,255) |
| 04_pen_small_target | 红 | (0,60,25)/(160,60,25) | (8,255,160)/(179,255,160) |
| 05_orange_on_orange_trap | 橙（收紧） | (6,185,60) | (22,255,255) |
| 06_blue_powerbank | 蓝 | (100,65,60) | (125,255,200) |
| 07_white_powerbank_dark | 白 | (0,0,150) | (179,70,255) |

绿色那张封面 S 只有 59~66，比我预想的低很多，所以 S 下限只能给 40。红色的笔 H 是 170~176，红色在色环上跨 0 和 179 两头，得分两段 `inRange` 再取并集，不然只框到一半。

### 面积阈值

没写死像素数，按面积比例取：

```
h, w = img.shape[:2]
min_area = max(600, 0.0008 * w * h)
```

因为 7 张图分辨率从 1708×2298 到 4096×3072 都有，写死一个 500 在大图上等于没过滤，在小图上又容易把目标删掉。按万分之八取，能滤掉掩膜边缘的碎块。最小的目标是那支笔，轮廓面积 34311 px，阈值 10066 px，还留了余量；最大的是充电宝，差得更远。

## 失败案例与改进

**橙子放在橙色桌面上，基本分不出来。**

这张图橙子 H 是 14~15，桌面 H 是 12，色相几乎一样，一开始按橙色范围一卡，整张图 99% 都被判成目标了。改成只在 S 上下手，把 S 下限提到 185（橙子 S 211~226、桌面 S 151），掩膜占比才压到 49.60%，但桌面暗角和反光的地方还是漏进来一些，外接矩形比橙子大一圈。

结论是这张图 H 根本没用，只能靠 S 和 V，而这两者本身也有重叠，光调阈值解决不了。真要做得先把连片区域断开再按圆形度筛，或者干脆承认颜色法在这种场景不合适，换边缘、纹理去做。

**白色的充电宝用颜色法完全不行。**

白色物体的 S 接近 0，H 是没有意义的随机值，我试了红、蓝、绿几个范围都框不出东西。后来改用亮度，背景深灰织物的 V 大概是 55，白色物体 V 在 150 以上，用 `S≤70 且 V≥150` 就干净分开了，掩膜占比 33.18%，矩形也贴合。这也说明任务二学的阈值法不是白学的，颜色不管用的时候它还能顶上。

**笔记本左边的粉色书脊没被算进目标。**

粉色的 S 只有 18，低于绿色范围要求的 S 下限 40，被判成背景了，所以外接矩形左边界比物体实际边缘往里缩了一截（bbox 起点 x=337，物体实际从 150 左右开始）。这是收窄范围换纯净度的必然代价：要是把 S 下限放到 20，灰色布背景（S 13~18）也会被吸进来。更好的做法是对绿色和粉色各做一次掩膜再合并。

## 其他

这套方法全靠颜色阈值，光照、白平衡、反光都会影响，换台手机或换个场地基本要重调参数；目标被遮住一半以上时轮廓面积会掉得厉害，面积过滤有可能直接把它当噪声删掉。
