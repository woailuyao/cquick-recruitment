## 1. 坐标系与输出口径

- 地图：C0，原点 O = 场地中心；**+X 指向唯一球门**，+Y 为面向 +X 时的左侧，
  +Z 垂直向上；单位米；yaw 绕 +Z 逆时针为正，**单位为度**。
- 载体：独立移动测试架。按细则以**相机光心**为载体参考原点，
  `x_carrier_map = x_camera_map`，输出坐标系记为 **`camera_frame`**。
  不把机器人位置误标成相机光心位置（机器人本轮未参与、不能移动）。
- 场地实测 8.35 m × 6.00 m（含白线），`config/field_geometry.yaml`
  `map_version: c0-self-measured-v1`。

## 2. 解算链路（每一步都可复现）

```
实拍帧 → pick_points.py 目视点真实白线交点（≥4 个，看不见的按 s 跳过）
       → diagnose_clicks.py 核对点名 + 消掉地下镜像解（始终写 *_candidate.yaml 副本；
         编号自洽时副本内容与原文件完全一致，只改点名的情况才需要目视确认）

```

红线：真值不参与解算；理论投影值不得当观测；RANSAC 点名建议必须本人对照
`docs/field_measured_map.png` 目视确认后才能作为正式观测。

### 3.2 歧义处理案例：平面 PnP 的地下镜像解

同一组点，类别级 RANSAC **不加先验**时给出：

```

```

位姿看起来像 **pose_C**（x=-3.085, y=-2.050, yaw=+18.9°），但 **h 为负、
pitch 为负** = 相机在地面以下的镜像分支，物理不可能。
加入现场卷尺实测的 **`h=0.55 m` 高度先验**后：

```
rms=6.97px  x=-2.531 y=+1.684 h=+0.584  yaw=-18.2° pitch=+6.1°
```

回到 pose_B 附近。`run_task2.py clicks` 已默认启用 `--h-prior 0.55`
（`solvePnPGeneric` 取 IPPE 全部解，按 h>0 / rms 最小 / 最接近 h 选优）。
这就是细则要求的「同类标志多候选匹配与场地对称歧义处理」的真实证据，
**不是合成数据演示**。
