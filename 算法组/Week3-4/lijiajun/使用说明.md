# 使用说明（全部可直接复制粘贴）

两条路，按需选：

- **A｜单机（Windows）**：自检 / 单图 / 视频 / 相机实时 / 左右分屏。第 1~5 节。
- **B｜联调（Windows 推理 → UDP → VM 里的 ROS2）**：第 6 节。

下面每条命令都是**完整形式**（自带 `cd`、自带 venv 的 python、绝对路径），不需要你先改任何东西。
唯一可能变的是 **VM 的 IP**，默认按 `192.168.65.128` 写死；换网络时在 VM 里跑一次 `hostname -I`，
把第 6 节里出现的这个 IP 改掉即可。

> 一律用**项目 venv 的 python**（`$PY`）。用系统 python 会报 `No module named 'cv2'`。

下面 4 步对应 4 个窗口，每块都可整块粘贴。

## 7. 发布的内容（字段契约）

`/localization/field_pose`（`FieldPose`）：

| 字段 | 含义 |
|---|---|
| `header` | 时间戳 + `frame_id="field"` |
| `x_camera_map` / `y_camera_map` / `yaw_camera_map` | 相机光心在官方地图系的 x / y（m）与 yaw（deg，逆时针） |
| `x_carrier_map` / `y_carrier_map` / `yaw_carrier_map` | 载体位姿；当前直接把相机当载体，三点与上面相同 |
| `valid` | 位姿可信（=`ok`：场内 + 残差<45px + 内点≥3） |
| `marker_count` | 本帧参与求解的标记点数（去重后） |
| `supplement_added` | 线交点补点新增的点数（默认关，通常 0） |
| `residual` | 重投影残差（px） |
| `status` | `ok / insufficient_markers / ambiguous / high_residual / lost` |

`/soccer/ball`（`Ball`）：`u` `v`（像素）、`conf`、`visible`（本帧有没有球）。

视频/相机模式额外做了时序滤波：JSON 行里会多一个 `filter` 字段（`predict+AB` / `locked(median)`），
`x/y/yaw` 是滤波后的值；这个字段不发布到 ROS2 话题，消息字段与上表一致。

## 8. 参数速查

| 参数 / 变量 | 作用 |
|---|---|
| `--weights` | marker 权重，默认 `week34_data/runs/marker_v6/weights/best.pt` |
| `--ball-weights` | 球权重，默认 `week34_data/runs/ball_v2/weights/best.pt` |
| `--conf` | 检测置信度，默认 `0.25` |
| `--device` | `0` = GPU，`cpu` = CPU |
| `--no-ball` | 关掉球检测（快一点） |
| `--supplement` | 开线交点补点（默认关，实测增益≈0） |
| `--send IP:PORT` | 每帧 UDP 发给 VM 节点 |
| `--out 文件.json` | 结果落盘 |
| `--intrinsics` / `--geometry` | 覆盖默认内参 / 场地几何 yaml |
| `W34_DATA` | 数据根目录，默认 `D:\Desktop\CQuick\week34_data`；数据搬家时设它 |
| `MARKER_WEIGHTS` / `BALL_WEIGHTS` | 环境变量覆盖两个权重路径 |

## 10. 已知限制

- 走动素材里一帧常常只有 2~3 个标记，单帧定位不稳；可靠结果靠静止机位多帧或画面里 ≥4 个铺开的点。
- 3 个点的 PnP 有镜像歧义（真解 + 镜像两个解残差都≈0），多帧取中位可消歧。
- mAP50-95 偏低是因为标注框统一 96px 方形，不代表检测差；定位只用框中心。
- 球检测器只在任务一的球域可靠，marker 素材里的球不一定认。
