# 帧级命中率评估（marker_v9）

> 为什么换这个口径：任务二评的是位姿误差，不是 mAP。外参加 PnP 至少要 3 个已知点
> 才能解出无歧义的位姿，所以真正该看的是「单帧里能稳稳抓到几个标志」。
> mAP 会把一个框摊平计分，看不出「一帧漏两个」与「每帧各漏一个」的区别。

## 口径

| 项 | 定义 |
| --- | --- |
| 正确命中 | 类别一致 且 IoU ≥ 阈值（一对一贪心匹配） |
| 类别无视命中 | 任意类别 且 IoU ≥ 阈值；与上一项之差 = 「看见了但认错类」 |
| 有效帧 | 该帧 GT 中标志数 ≥ 3，且正确命中数 ≥ 3 |

权重 `weights/best_marker_v9.pt`；测试集 `dataset_marker/images/test`（52 帧 / 114 框）；
脚本 `tools/marker_frame_recall.py`；逐帧明细 `outputs/marker_frame_recall_detail.csv`。

## 置信度扫描（IoU ≥ 0.5）

| conf | 正确命中 / 总框 | 框召回 | 帧均命中 |
| ---: | ---: | ---: | ---: |
| 0.50 | 56 / 114 | 49.1% | 1.08 |
| 0.35 | 76 / 114 | 66.7% | 1.46 |
| **0.25** | **80 / 114** | **70.2%** | **1.54** |
| 0.15 | 83 / 114 | 72.8% | 1.60 |
| 0.10 | 85 / 114 | 74.6% | 1.63 |

conf 从 0.25 降到 0.10 只换来 +4.4 个点：**不是阈值卡掉的**，是模型确实没给出框。

## IoU 放宽后的召回（conf 0.25）

| IoU 阈值 | 框召回 | 帧均命中 | 类别无视召回 |
| ---: | ---: | ---: | ---: |
| 0.5 | 70.2% | 1.54 | 70.2% |
| 0.4 | 79.8% | 1.75 | 80.7% |
| 0.3 | 84.2% | 1.85 | 85.1% |

两点读法：

1. **类别几乎不混淆** —— 类别无视召回只高出 0.0～0.9 个百分点（放开到 0.3 时也只多 1 个框）。
   失分几乎全在「看不见 / 框不够贴」，不在「认错类」。
2. **框偏松是主要损失** —— 门槛从 0.5 放到 0.3 就多捞回 16 个框。而细则 §2.3 要求的是
   在框内做几何细化求交点，框只当区域提议，所以这一部分在管线里可以补回来。

## 有效帧（GT ≥ 3，共 12 帧）

| IoU 阈值 | 命中 ≥ 3 的帧 | 占比 |
| ---: | ---: | ---: |
| 0.5 | 9 / 12 | 75% |
| 0.4 | 9 / 12 | 75% |
| 0.3 | 10 / 12 | 83% |

**必须写进 README 的限定**：这 12 帧全部来自 `s03` 的连续 12 帧（frame 0054–0065），
是同一机位、同一构图的一段推镜头，彼此高度相关，不能当作泛化指标。
另外测试集里 35 帧只有 1 个标志、5 帧 2 个，单一目标的简单帧占了大头。

## 失败的 2 帧长什么样

`marker_s03__frame_0059` / `0061`：镜头转到空旷半场，可见标志落在画面上缘的远景，
反光过曝、线宽只剩几个像素，人眼也要凑近才分辨得出。这类帧不加切片放大，靠加 epoch 收效甚微。

## 结论

- **不需要再堆训练轮次。** 分类已近饱和，剩余误差是「小目标 + 远景」的尺度问题，不是收敛问题。
- 想真的提升，按性价比排序：
  1. 推理端切片放大（tiling / SAHI 思路），免训练，直接针对远景小目标；
  2. 补拍并标注「多标志远景」帧，把这类构图真正喂进训练集；
  3. 强透视增强——成本低，但治的是视角，不是尺度，对当前失败模式帮助有限。
