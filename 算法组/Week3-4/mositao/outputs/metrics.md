## 任务二 · 场地标志检测

### 正式口径：`best_marker_v11.pt`

| 项 | 值 |
| --- | --- |
| 权重 | `weights/best_marker_v11.pt` |
| 训练集 | `dataset_marker_v10`（211 张 / 1264 框，高姿 5 段 + 低姿 3 段） |
| 类别 | 3 类：`LCross` / `TCross` / `XCross` |
| 训练参数 | 60 epochs，imgsz 640，batch 8，workers 0 |
| 推理参数 | **imgsz 1280**，conf 0.35（现场实测：640 只出 1 个框、960 出 3 个、1280 出 4 个） |

### 统一测试集上的横向对比（六代权重同一把尺）

测试集 = `dataset_marker_v12` 的 test 分片（`marker_low_02` 后 31 帧 / 108 框，
**按段整体留出**，标注全部按实际尺寸，无固定大框），`model.val(imgsz=1280)`：

| 权重 | Precision | Recall | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: |
| `best_marker_v7.pt` | 0.033 | 0.074 | 0.014 | 0.003 |
| `best_marker_v8.pt` | 0.126 | 0.122 | 0.063 | 0.019 |
| `best_marker_v9.pt` | 0.346 | 0.293 | 0.187 | 0.057 |
| `best_marker_v10.pt` | 0.287 | 0.329 | 0.207 | 0.071 |
| **`best_marker_v11.pt`** | **0.768** | 0.282 | 0.252 | 0.053 |
| `best_marker_v12.pt` | 0.346 | **0.386** | **0.269** | **0.087** |

读法（重要，别只看 mAP）：

- v11 的**精确率最高**（0.768），但召回只有 0.282 —— 这就是现场「框太多」与
  「漏检」并存的原因；
- v12 在这份测试集上召回与 mAP 最高，但**现场夜间帧反而最差**（见 README 4.3 的
  现场帧对比：v11 8/6/10/7/12，v12 1/1/0/2/2）；
- 故选 v11 作为交付权重，v12 只作对照实验。

### 历史口径（供追溯，不要引用这个数字）

旧版 `best_marker_v9.pt` 在 `dataset_marker` 的 test（52 张 / 114 框）上、
按**段内时间划分**（train/val/test 共享同一批场景）测得：

| Precision | Recall | mAP50 | mAP50-95 |
| ---: | ---: | ---: | ---: |
| 0.6977 | 0.7082 | 0.5826 | 0.2805 |

这一组数字偏乐观：按段整体留出的 v8 test 只有 mAP50 **0.037**。
上表之所以仍列出 v9，是为了让「为什么最终不用它」有据可查。

### 帧级口径

任务二真正决定成败的是「单帧能稳稳抓到几个标志」，不是 mAP。
`outputs/frame_recall.md` 记录了 v9 的帧级命中率与失败帧分析（远景、过曝、线宽只剩几个像素），
结论是**剩余误差属于小目标尺度问题，不是收敛问题**，所以没有再堆训练轮次。
