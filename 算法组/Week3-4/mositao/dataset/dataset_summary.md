| 项 | 值 |
| --- | --- |
| 数据来源 | 本人实验室/场地实拍，配发 USB 单目相机（Windows 索引 1，VID:PID `0BDA:5844`），1280×720@30 |
| 采集日期 | 2026-11-05 – 2026-11-08 |

| 抽帧总数 | **307 张**（1280×720 jpg） |

| 标注方式 | 先用 YOLOv8n(COCO) 的 `sports ball` 生成初始框，再逐张人工修正 |

## 划分结果（按段整体分配，磁盘实测）

| 集合 | 视频段（段 → 图片数） | 图片数 | 占比 |

数据集描述文件：[`ball_data.yaml`](ball_data.yaml)（与 `data.yaml` 内容一致）。

## 为什么不是 70/20/10

5 段视频做 70/20/10 无法精确命中（段不可再分），这里穷举所有段分配方案，
取与目标比例图片数偏差最小者。硬约束是「同一段不跨集合」，比例只是近似。

## 已知局限

- 数据以「草地 + 较大足球」的近景为主，远景小目标样本偏少；
- 光照以室内灯为主，强光/逆光样本有限；
- **测试集与验证集都是 0 误检**，误检案例只能来自开放场景（地球仪 / 人头 / 护栏），
  见 `../outputs/cases_ball/fp_*.png` 与根目录 README 3.4。

# 二、任务二 · 场地标志检测

| 项 | 值 |
| --- | --- |
| 数据来源 | 本人现场实拍，同一台配发相机，1280×720@30，全程不动对焦环、不改分辨率 |
| 采集时段 | `marker_s01–s05`：2026-11-15（白天强光，机位较高，约 1.375 m）<br>`low_01–low_03`：2026-11-21（低机位 0.73 m 掠射角） |
| 原始视频数量 | **8 段**（`marker_s01`–`marker_s05` 各约 50 s；`low_01`–`low_03` 各约 40 s），本地保存，不入库 |
| 现场存在的类别 | 3 类：`LCross` / `TCross` / `XCross`。**点球点在现场没有可见实体标记**，不纳入检测（见 `../config/field_site.yaml`） |

## 正式交付模型（v11）所用的合并集 `dataset_marker_v10`

| 项 | 值 |
| --- | --- |
| 抽帧总数 | **467 张** |
| 标注框总数 | **1753 个** |

| 集合 | 视频段 | 图片 | 框 | 类别分布 |
| --- | --- | ---: | ---: | --- |
| train | `marker_s01` + `marker_s03` + `marker_low_01` + `marker_low_03` | 211 | 1264 | LCross 529 / TCross 515 / XCross 220 |
| val | `marker_s04` | 63 | 99 | TCross 99 |
| test | `marker_s02` + `marker_s05` + `marker_low_02` | 193 | 390 | LCross 201 / TCross 114 / XCross 75 |

划分方式：**按视频段整体留出**（同段帧只出现在一个集合里），因此 test 覆盖的是
「没见过的新机位 / 新光照」，指标偏保守，不会因相邻帧泄漏而虚高。

## 对照实验集 `dataset_marker_v12`（不用于交付模型）

为验证「低姿素材是否干扰特征点检测」而建的干净对照集：剔除第一批高姿素材里的
`marker_s01 / s02 / s04 / s05`（这几段标注是固定大框 220×220 px，与实际尺寸不符），
只留 `marker_s03` + `marker_low_01` + `marker_low_03` 训练：

| 集合 | 视频段 | 图片 | 框 |
| --- | --- | ---: | ---: |
| train | `marker_s03` + `marker_low_01` + `marker_low_03` | 176 | 1227 |
| val | `marker_low_02` 前 30 帧 | 30 | 137 |
| test | `marker_low_02` 后 31 帧 | 31 | 108 |
| **合计** | 4 段 | **237** | **1472** |

结论（详见根目录 README 4.3）：v12 在这份测试集上召回与 mAP 最高，
但**现场夜间帧反而更差**，所以交付模型仍取 v11。

## 类别顺序

```text
0 = LCross     线在此终止并拐弯，形成「L」
1 = TCross     一条线穿过另一条，形成「T」
2 = XCross     两条线交叉，形成「X」
```

`dataset_marker_keepP` 里的第 4 类 `PenaltyPoint` 已废弃：79 个标注框核对后
全部落在白色线条上、没有真实点球标记，已整批删除。

## 通用说明

- 未标注（无 `.txt`）的图片已排除；空 `.txt` 视为明确的负样本保留；
- 各段拍摄对象不同（`s02` 近景中圈交点、`s04` 部分遮挡、`s05` 另一时段光照、
  `low_0*` 低机位掠射），划分时已尽量让 train/val/test 各含多类；
- 本仓库只提交 yaml 与统计，**图片与标注整套不入库**；复现时按上表自行放回对应目录。

数据集描述文件：[`marker_data.yaml`](marker_data.yaml)（`path: dataset_marker_v10`，按项目根相对路径书写）。
