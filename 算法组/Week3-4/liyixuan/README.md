- 场地尺寸与地图一致性：**未用卷尺逐一核对**，以组长发布的 field.yaml 为准
- 使用的场地标志类别：**LCross、TCross 两类**（经现场查看，C0 场地未绘制 X 型交叉与点球点）
- 场地标志检测模型与训练指标：
  YOLOv8n，60 epochs，imgsz=640，batch=8，device=cpu，67 张标注 / 91 个实例
  - 验证集（7 张）：Precision 0.787，Recall 0.81，**mAP50 0.838**，mAP50-95 0.386
  - 分类别 mAP50：LCross 0.715，TCross 0.962
  - 现场实测：置信度阈值必须降到 **0.10** 才能稳定检出（0.35 时 2665 帧仅 4 帧有效）
- 几何特征点提取方法（L/T/X/点球点）：
  检测框外扩 20% → 白线掩膜（HSV：V>140 且 S<70）→ 形态学开运算 → HoughLinesP →
  按方向做圆周聚类分两组 → 每组加权 fitLine → 求两直线交点。
  校验：交点须落在 ROI 内、离框中心不超过 0.6×对角线、两线夹角 >20°，否则回退框中心
  并把该观测 σ 放大 2.5 倍。点球点取轮廓质心（本次场地无点球点）。
- 相机内参 fx / fy / cx / cy：`fx=1662.76  fy=1649.14  cx=739.14  cy=309.06`
- 畸变系数 k1 / k2 / p1 / p2 / k3：`[0.13497, -0.17790, -0.01139, 0.01500, 0]`
  （56 张棋盘格，重投影误差 1.317 px；棋盘格为 A4 软纸、手持弯曲导致偏大）
- 相机外参 / 相机高度 / 俯仰角 / 滚转角：
  `h = 0.7816 m`，`pitch = 22.63°`（向下），`roll = 0°`（按定义）
  - base 坐标系：原点 = 相机光心在地面的垂直投影，+X = 相机光轴的水平投影方向，+Z = 地面法向。
    对应细则允许的"把相机光心定义为载体参考原点"。
  - 标定方法：棋盘格平放地面 → solvePnP → 由棋盘格法向确定地面法向 → 构造 base 系。
    该方法**不依赖棋盘格在地面上的摆放朝向**，经 8 组不同朝向（含板面正反）数值验证：
    高度/俯角还原误差 < 1e-6，地面点投影到 Z=0 的残差 < 1e-16。
  - 视野自检（`tools/check_extrinsics.py`）：画面覆盖地面 **1.09~3.59 m**。
- 地面投影方法：
  去畸变 → 相机系射线 `d_c = K⁻¹[u,v,1]ᵀ` 归一化 → 外参转到 base：`d_b = R·d_c`，光心 `O_b = t`
  → 与 Z=0 求交 `λ = -O_bz / d_bz`，`P_b = O_b + λ·d_b`。
  有效性判据：射线朝下（d_bz < -0.001）、地面距离 ≤8 m、交点落在场地外框内。
  观测权重按误差传播 `σ ≈ D²·δp/(fy·h)`，`w = 1/σ²`（3 m 处权重约为 6 m 处的 16 倍）。
- 地图匹配算法与同类标志消歧方法：
  1) 成对假设生成：两观测间距与地图同类点对间距一致（容差 10%）即解出一个 SE(2) 候选位姿；
  2) 内点打分：带类别约束、一对一占用、门限 0.35 m 的最近邻匹配，按加权残差排序；
  3) 精修：内点加权刚体最小二乘（尺度固定 1），再重匹配一次；
  4) 歧义判定：存在位姿差 >0.5 m 或 >10°、内点数不少于最优、残差不劣于 1.3 倍的次优假设
     时输出 `ambiguous / valid=false` 并给出 rival 位姿；
  5) 时序：观测累积（最近 4 帧合并去重）+ 时间一致性门控（与轨迹差 >0.8 m/>25° 不采纳，
     连续 6 帧不符则重定位）+ EMA 滤波（失效 15 帧后丢弃先验）。
- 输出坐标系：`camera_ground_projection`（原点=相机光心地面投影）；相机位姿
  `T_map_camera = T_map_base · T_base_camera`
- 3 个以上测试点的误差表：**未完成**（见下"未达标部分"）
- marker_count / residual / valid / status（784 帧现场记录）：

### 未达标部分（如实记录）

**现场实时定位不稳定，未通过三个点位的精度验收。** 具体事实：

1. 手持相机录制 784 帧，仅 47 帧 `valid=true`（6.0%），最长连续有效段 15 帧。
2. 所有有效解均为 **2 个内点**的退化解——两点在数学上必然精确拟合（残差 0.000 m），
   因此这些解不构成可靠的位姿证据。
3. 其中一段稳定解算得 `y = 3.74 m`，**超出场地 y 范围 [-4.01, 2.93]**，可判定为错误解。
4. 因此**不宣称完成 C0 三位置精度验收**，也不输出任何伪造或人为设定的位姿。
   程序在无法可靠定位时正确输出 `valid=false` 及 `insufficient_markers` / `not_converged` / `ambiguous`。

**原因分析**

- 相机为**手持**，与载体非刚性固定。外参 h=0.78 m、pitch=22.6° 只在标定时刻成立，
  移动过程中俯仰角变化即导致地面投影系统偏移，观测与地图无法对应（`not_converged` 占 57%）。
- 相机视场仅 42°×25°，可视地面 1.1~3.6 m。在 `field.yaml` 的 14 个特征点上做网格搜索，
  该视野内**最多只能同时看到 3 个**地图标志（多数位置仅 1~2 个），
  而仿真实验表明 2~3 个标志时约 1/3 的解会出错（见下方对比实验）。
- C0 场地上实际绘制的白色交界（如中圈与场地线的切点、球门区角）**多于 field.yaml 的 14 个点**，
  模型检出的这些交界无法与地图对应，进一步减少了可用内点。

**改进方向**：把相机用刚性支架固定在移动底盘上并重标外参；扩大视场或提高安装高度；
在标定后固定姿态不变的前提下完成三点位测试；必要时用多帧观测累积 + 位姿图优化替代单帧求解。

### 算法自测（不需要相机的合成数据验证，评审可直接复跑）

### 歧义处理对比实验（`tools/compare_matching.py`，加分项）

400 个随机场景（视野 3.6 m、观测噪声 6 cm、25% 误检率）：

| 配置 | 成功 | 错但报有效 | 正确拒绝 | 有效结果正确率 |
| --- | ---: | ---: | ---: | ---: |
| A. 不做歧义处理（总报 valid） | 61.8% | **33.0%** | 5.2% | 65.2% |
| B. 做歧义处理（本工程实现） | 60.5% | **28.5%** | 11.0% | 68.0% |

按单帧可见标志数量分组（配置 B）：

| 同时可见标志数 | 成功 | 错报有效 | 说明 |
| ---: | ---: | ---: | --- |
| 2 个 | 105 | 61 | 约 1/3 会算错 |
| 3 个 | 83 | 50 | 约 1/3 会算错 |
| **4 个** | 48 | **3** | 仅 6% 出错 |
| 5 个 | 6 | 0 | 全部正确 |

结论：**同时可见 4 个以上标志时定位才可靠**；只有 2~3 个时程序应倾向输出 `ambiguous / valid=false`。
这一结论也与本次现场测试的失败现象一致。

## 问题与解决过程

**问题 1：录制视频播放速度异常（约 2~3 倍速）**
- 现象：录 15 秒只有 5 秒，播放像快进。
- 排查：实际出帧 149 帧 / 15.4 秒 = 9.7 fps，而文件头写的是 30 fps，149/30 ≈ 5 秒，与现象吻合。
- 定位：DSHOW 后端在 1280×720 拿不到 MJPG，退化为 YUY2，被 USB 带宽限到 9.9 fps。
- 解决：相机后端改为 MSMF 优先；录制时先实测真实帧率再按真实帧率写文件。
  修复后 1548 帧 / 51.6 秒、文件头 30 fps，时长一致。

**问题 2：`labelImg` 在 Windows + Python 3.10 下闪退**
- 现象：画框时报 `TypeError: setValue(self, a0: int): argument 1 has unexpected type 'float'`。
- 排查：labelImg 与 PyQt5 版本不兼容的已知问题。
- 解决：自写本地标注工具 `tools/annotate.py`（OpenCV 鼠标拖框，支持多类别，
  直接写 YOLO txt），323 张足球标注与 67 张标志标注均用它完成。

**问题 3：内参重投影误差 1.317 px 偏大**
- 排查：抽帧查看棋盘格录像，发现是 A4 软纸、手持明显弯曲，平面假设不成立。
- 处理：改用 `CALIB_FIX_K3`（只拟合 k1、k2）并剔除离群摆位，从 1.46 降到 1.32 px。

**问题 4：外参标定第一次算出"离地高度 -1.27 m、俯角 -74°"**
- 排查：原实现假设"棋盘格坐标系 = base 坐标系"，但棋盘格的 Z 轴在实际地面上朝下，
  两者差一个翻转，导致相机被算到地面以下。
- 解决：改为**只用棋盘格所在平面的法向**确定"上"方向，并令 base 原点为相机光心的地面投影。
  该做法与棋盘格在地面上的朝向无关，经 8 组朝向数值验证（高度/俯角误差 <1e-6）。
  修复后又发现 `translation` 符号写反（相机应在原点上方 +h），由工具内置的
  "地面点 z 应≈0" 自检暴露并修正。

**问题 5：现场标志检测几乎全漏（2665 帧仅 4 帧定位成功）**
- 排查：标志模型训练时用的近景特写帧，现场视角线更细更远。
- 解决：置信度阈值 0.35 → 0.10，`obs` 从 0 恢复到 3~5，出现 `valid=true`。
  说明标志检测的阈值必须按现场重新整定。

**问题 6：定位结果一闪而过**
- 排查：逐帧统计发现单帧观测数多为 1 个（同一标志有时检出有时漏检），
  且 2 内点解在数学上必然完美拟合，会在等价解之间跳动。
- 解决：增加观测累积（最近 4 帧合并去重，单帧 1 个 → 累积最多 9 个）
  与时间一致性门控（位姿跳变 >0.8 m/>25° 不采纳）。

**问题 7：界面窗口超出屏幕，右侧地图被切掉**
- 排查：分屏总宽 2040 px > 屏幕逻辑宽度 1440 px。
- 解决：读取系统逻辑分辨率（2880×1920 物理 / 200% 缩放 = 1440×960 逻辑），
  按可用空间等比缩放窗口。
