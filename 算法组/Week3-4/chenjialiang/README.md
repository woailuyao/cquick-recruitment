### 同类标志消歧

本场地的困难在于：**两端各有一个禁区，两个禁区角的外观完全一样**，  
模型输出 `goalarea_far_left/right` 时，无法直接判断这对角属于前场还是后场。  
歧义一旦配错，解出的位置会镜像到场地另一头，而且**残差依然很小、不会报错**。

采用**三层消歧**，全部是几何/时序判据，不依赖外观：

1. **假设枚举 + 对称配对筛选 + 时序连续性**  
   每一帧先按类别家族分组（`goalarea_far` / `penalty_far` / `corner_front` / `corner_back`），  
   **只取"左右两侧都检到"的那一组**参与解算。若把同侧大小禁区两个角混在一起，  
   构型本身不正定，解出的位姿会明显偏掉——这是实测踩到的问题。  
   然后对"属于前场 / 属于后场"两种假设各解一次，按  
   （是否落在场地内 → 与上一帧的距离）两级排序取最优。
2. **朝向自洽校验（`wrong_facing`）**  
   光轴必须大致指向所使用标志的中心。两个禁区角左右近对称时，模型偶尔会把  
   left/right 认反，解出一个"绕场地中心旋转 180°"的镜像位姿——此时光轴会背离  
   标志点，夹角 147°，远超 45° 阈值，直接剔除。实测 P3 视频中 **16%（217/1351）  
   的帧存在此类镜像解**，全部被该判据拦下。
3. **可见侧与场地范围校验（`out_of_field`）**  
   解出的相机位置必须落在场地范围内（各方向外扩 1 m）。后场禁区被误配成前场时，  
   解出的位置会跑出场外，同样被拦下。

**为什么不给前后禁区各设一个类别**：两类正样本外观完全一致，只会互相干扰，  
实测会让两类 mAP 同时下降；而"同一类 + 几何假设"的方案把消歧交给可解释的  
几何约束，出错可定位、可复现。

## 已知局限

1. **可用区域受 42° 水平视场限制，是一个"越靠后越宽"的楔形区域，不是一条线。**  
   两个小禁区角要同时落在 ±21.2° 半角内，横向上限为
   ```
   |y|max = 0.388 × (3.3 − x) − 1.45
   ```

   | 站位 x | 允许横向    | 说明                       |
   | ---- | ------- | ------------------------ |
   | −1.0 | ±0.22 m | 最窄                       |
   | −2.0 | ±0.61 m |                          |
   | −3.0 | ±0.99 m |                          |
   | −3.5 | ±1.19 m |                          |
   | −4.0 | ±1.38 m | 后场底线附近，接近场地半宽 2.95 m 的一半 |

   **纵向可用区间为 x ∈ [−4.20, −0.50]**。越靠近球门越差——与"球太远看不清"相反，  
   这里是目标过大、超出视场。可用区内只要两个角都在画面里、且不贴边，定位即成立；  
   一旦有一角出画，系统报 `insufficient_markers` 或（经由配对校验）报  
   `no_valid_hypothesis`，不输出错误位姿。

   **实测注意**：站 `(-2.0, +0.9)` 属于楔形区之外（该处上限仅 0.61 m），必然失败；  
   这不构成"偏一点就不能用"的证据，只是站位超出了几何允许范围。
2. **可用的偏航角约为 ±15°（相对场地中心线）。**  
   两个原因叠加：① 偏航 15° 时画面横移约 440 px，原本贴边的角点被挤出视场；  
   ② 训练样本以"正对球门"视角为主，转到 45° 时角点变成极扁的锐角，  
   形状超出训练分布，检测置信度显著下降。
3. **无法凑到 4 个共视标志点，故采用"2 点 + 已知安装高度"解算。**  
   本可用的第 3、4 个点是大小禁区远边角点，但站到能同时看到两者的位置  
   （x < −3.2）时，大禁区角距画面边缘不足 90 px、俯视角降到 9° 以下，  
   白线被压缩成细线，检测不可用；退到 x = −4.2 时虽在画面内但置信度低于 0.2。  
   **这是镜头视场与安装高度共同决定的限制，不是标注数据量的问题。**  
   代价是解算必须依赖外部标定的俯角（见下条）。
4. **俯角必须每次重新标定。** 距离误差对俯角极敏感：Δd ≈ (d²/h)·Δpitch。  
   实测俯角从 3.5° 变成 2.0°（仅挪动支架），在 5.3 m 处造成 **0.68 m** 位置误差。  
   因此本工程要求"每移动一次支架，重跑一次 `fit_pitch.py`"。
5. **只用 2 个共线标志点时无法同时估计俯角与距离**（两者投影等价，几何病态），  
   俯角必须外部给定，这也限制了移动中的稳定性。
6. **场地前后两端禁区外观完全一致**，仅凭角点无法判断"站在哪一端朝哪边看"。  
   本工程的处理是三级：① 每帧枚举两种假设，用"解出位置必须落在场地内"筛掉错端；  
   ② 有历史位置时按连续性选择，转身导致球门出画也不会跳变；  
   ③ **仅在冷启动的第一帧**（尚无历史位置）参考球门是否出现在画面中，  
   确定这次初始化属于哪一端。`goal` 类别**不参与位姿解算、界面上不绘制球门框、  
   不作为定位标志**，只在这一帧充当"前后场提示"。  
   若冷启动时球门不可见且处于中线附近，端别可能判错（位置整体偏 6.6 m），  
   因此在 README 的使用约定中要求"提起-放下后先面朝球门完成初始化"。
7. **ROS2 节点已构建通过、启动自检通过，但话题输出未做实机联调。**  
   `colcon build` 成功（`Summary: 1 package finished`），节点能正常构造并进入 spin、  
   退出无异常；由于交付当天相机不可用，`/camera_pose` 的实际数值未与分屏程序逐帧比对。  
   节点直接 import 主程序的解算函数，数字口径与分屏程序一致。
8. **标定重投影 RMS 0.53 px**，略高于学习路线给出的 0.5 px 参考值，  
   原因是标定板距离较近、边角姿态样本偏少。
