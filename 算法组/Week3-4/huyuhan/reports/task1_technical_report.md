# 任务一技术报告：基于 YOLOv8 的足球目标检测

## 摘要

本任务构建单类别足球检测模型，使用 YOLOv8n 与 YOLOv8s
进行训练验证比较，并依据测试前冻结的验证集 mAP50-95
选择正式模型。最终选择 YOLOv8s，权重 SHA256 为
`732ecee9f41639b6888632e1cd8417569807f570a680423b29547c9752824eae`。在
76 张 Test 图片上，Ultralytics 原生评估得到
mAP50=0.995、mAP50-95=0.947860。固定置信度阈值 0.50、匹配 IoU=0.50
时，Precision=0.973684、Recall=1.000000。结果显示模型在当前测试素材上具有较高检出能力，但高置信度阈值会显著降低召回率，复杂高亮背景仍会产生误检。

## 1. 任务目标与范围

任务目标是对输入图像中的足球进行目标检测，输出足球边界框及其置信度。检测类别为单类
`ball`，类别 ID 为 0。

本报告覆盖： 1. 数据集划分与一致性审计； 2. YOLOv8n / YOLOv8s
训练及验证集模型选择； 3. 正式权重冻结与 Test 评估； 4.
固定置信度阈值下的 Precision、Recall、F1 与逐图错误分析； 5.
实验局限与后续改进方向。

## 2. 数据集构建与审计

### 2.1 数据规模

  子集      图片数
  ------- --------
  Train        514
  Val          145
  Test          76
  合计         735

数据计划记录共 735 条，类别配置为 `nc=1`、`names={0: ball}`。图像尺寸为
1280×720。Test 包含 76 张图像、74 个真实足球实例，其中 2
张为空标签背景图。

Test 的 76 张图像均来自
`WIN_20261108_15_54_49_Pro.mp4`。质量标记包含强/普通高亮、运动模糊、边缘截断等情况。Test
数据与计划的一致性审计结果： - 缺失图片/标签：0； - 图片 SHA256
不一致：0； - 图片尺寸不一致：0； - 标签内容不一致：0； -
空标签图片：2。

Val 数据一致性审计结果同样为：缺失图片 0、缺失标签 0、SHA256 不一致
0、尺寸不一致 0、标签内容不一致 0。冻结计划 SHA256 为：

`5de8ce62cd171d54dff06cf7dd81ee6889facc35f140292ce7eae01e5880e2a8`

### 2.2 数据范围限制

实验记录指出，视频文件按划分隔离，但实验室/拍摄场景相同，且相关素材此前曾在开发过程中被观察。因此，当前
Test
更适合说明模型在这批固定素材上的表现，不能据此声称模型已在跨场景、跨设备或完全独立外部数据上得到验证。Test
仅来自一个视频，也限制了对背景多样性和场景泛化能力的判断。

## 3. 模型与训练设置

### 3.1 模型

比较模型为 YOLOv8n 与 YOLOv8s，均从 COCO 预训练权重初始化。正式选中的
YOLOv8s 检测模型摘要为 72 层、11,125,971 个参数、28.4 GFLOPs。

### 3.2 训练环境

-   Ubuntu 22.04（WSL）
-   Python 3.10.12
-   PyTorch 2.9.1+cu126
-   CUDA 12.6
-   NVIDIA GeForce RTX 4050 Laptop GPU
-   Ultralytics 8.4.208

### 3.3 主要训练参数

  参数                 设置
  -------------------- --------------
  Epochs               100
  Patience             20
  Batch                4
  Image size           640
  Optimizer            AdamW
  lr0 / lrf            0.001 / 0.01
  Workers              2
  Seed                 42
  Deterministic        True
  AMP                  True
  Mosaic               0.5
  Close mosaic         10 epochs
  MixUp / Copy-Paste   0 / 0

其余参数以交付文件 `training/args.yaml` 为准。

### 3.4 收敛情况

训练共完成 100 epochs。训练日志中 Epoch 87 的 Val mAP50-95 最高，为
0.93309；对应
mAP50=0.995、Precision=0.99962、Recall=1.0。训练损失从首轮到末轮的变化如下：

  损失项             Epoch 1   Epoch 100
  ---------------- --------- -----------
  train/box_loss     0.83745     0.36454
  train/cls_loss     2.17521     0.19296
  train/dfl_loss     1.02362     0.81463

训练损失总体下降。Epoch 87 的验证损失分别为
val/box_loss=0.36548、val/cls_loss=0.16516、val/dfl_loss=0.80164。末轮验证损失与最佳轮次接近，但
CSV 中末轮 mAP50-95 为 0.92927，低于 Epoch
87。因此采用训练过程中保存的最佳权重，而不是简单采用最后一轮权重。

## 4. 模型选择与测试前冻结

### 4.1 选择规则

模型只依据 Val mAP50-95
选择；若结果相同，则选择模型规模较小者。选择结果在 Test 开始前写入
`selection_before_test.json`，随后才进行最终 Test 评估。

  模型        Val mAP50-95
  --------- --------------
  YOLOv8n     0.9179028656
  YOLOv8s     0.9309796305

因此选择 YOLOv8s。冻结记录中的权重 SHA256 与正式交付的 `best.pt` 一致：

`732ecee9f41639b6888632e1cd8417569807f570a680423b29547c9752824eae`

冻结计划哈希与当前计划哈希一致。Test 评估指纹记录了同一权重
SHA256、同一数据计划 ID 和 `split=test`。

### 4.2 训练日志与独立验证数值差异

需要区分以下两个结果： - `training/results.csv` 中 Epoch 87
的训练期验证记录：mAP50-95=0.93309； - 测试前冻结选择记录中的 YOLOv8s
Val 独立评估：mAP50-95=0.9309796305。

后续按 batch=1、FP32 的冻结评估设置复测，得到
0.9309796305，与冻结记录一致。另行进行的不同 batch / FP16 评估得到约
0.93315。具体结果记录在 `validation_precision_matrix.json`：

    Batch 精度模式        Val mAP50-95
  ------- ------------- --------------
        1 FP32            0.9309796305
        1 FP16            0.9331632023
        4 FP32            0.9309580326
        4 FP16            0.9331530902
        8 quantize=16     0.9331530902

因此，报告保留两套结果各自的来源，不将其混为一个数字，也不使用测试后的复测结果改写模型选择。模型选择的正式依据仍为测试前冻结记录中的
0.9309796305。

## 5. 最终 Test 评估方法与结果

### 5.1 原生 AP 评估

独立评估脚本调用 Ultralytics 原生验证流程，关键设置为： - `imgsz=640` -
`batch=1` - `conf=0.001` - `iou=0.7` - `max_det=300`

最终结果：

  指标              Test
  ----------- ----------
  Precision     1.000000
  Recall        0.998792
  mAP50         0.995000
  mAP50-95      0.947860

原生 AP 评估中的 Precision/Recall 使用 Ultralytics
选定的工作点，不等同于后续固定置信度阈值统计。

### 5.2 固定阈值评估

固定阈值统计基于类别 0 的预测框，置信度阈值分别取
0.25、0.50、0.90、0.95、0.97、0.99。预测框与 GT 的匹配 IoU 门槛为 0.50。

    阈值   TP   FP   FN   Precision     Recall         F1
  ------ ---- ---- ---- ----------- ---------- ----------
    0.25   74    5    0    0.936709   1.000000   0.967320
    0.50   74    2    0    0.973684   1.000000   0.986667
    0.90   73    0    1    1.000000   0.986486   0.993197
    0.95   25    0   49    1.000000   0.337838   0.505051
    0.97    0    0   74         N/A   0.000000   0.000000
    0.99    0    0   74         N/A   0.000000   0.000000

解释： - 阈值 0.25 时检出全部 74 个 GT，但产生 5 个误检。 - 阈值 0.50
时仍检出全部 74 个 GT，误检减少至 2 个。 - 阈值 0.90 时没有误检，但漏掉
1 个 GT。 - 阈值升至 0.95 后，召回率降至约 33.78%。 - 阈值 0.97 和 0.99
时没有输出预测框，Precision 无定义，不能将其表述为 Precision=1。

若任务更重视不漏检，0.50
是更合适的候选阈值；若任务更重视避免误检，可评估
0.90，但需接受少量漏检。最终阈值仍应通过真实摄像头场景验证。

## 6. 误检与漏检案例分析

交付目录保存了 6 张逐图复核图，案例编号如下：

  图片       主要现象                               相关置信度
  ---------- ------------------------------------ ------------
  f0000298   阈值 0.90 下漏检；降低阈值后可检出         0.8793
  f0000894   阈值 0.25 下额外误检                       0.3638
  f0000968   阈值 0.25 / 0.50 下额外误检                0.7291
  f0000983   阈值 0.25 / 0.50 下额外误检                0.6610
  f0000998   阈值 0.25 下额外误检                       0.4287
  f0001057   阈值 0.25 下额外误检                       0.4245

从复核图观察： 1.
若足球靠近白色绳网或高亮边界，模型给出的置信度可能下降；f0000298
的足球置信度约 0.8793，因此在阈值 0.90 下被过滤。 2.
画面边缘的高亮白色物体/结构可能触发额外检测框。 3. 阈值 0.50
可以滤除其中 3 个低置信度误检，但仍有 2
个高置信度误检，说明仅提高阈值不能彻底解决背景混淆。

## 7. 结果讨论

### 7.1 主要结论

-   冻结选择流程完整：先依据 Val mAP50-95 选出 YOLOv8s，再进行 Test。
-   正式权重 SHA256 与冻结记录一致。
-   Test 原生 mAP50-95 为 0.947860，mAP50 为 0.995。
-   固定阈值 0.50 时，Test Recall 为 1.0，Precision 为 0.973684。
-   置信度阈值提高到 0.90 可消除本次 Test
    中的误检，但会漏掉一个真实足球。
-   阈值 0.95 及以上不适合当前模型的高召回检测目标。

### 7.2 局限性

1.  Test 仅 76 张图片，且均来自单一视频，样本规模和场景多样性有限。
2.  Test 中仅有 2 张空标签背景图，尚不足以充分评估复杂背景下的误检泛化。
3.  实验室/拍摄场景相同，素材此前也曾在开发过程中被观察，不能将结果包装为完全独立的外部泛化验证。
4.  固定阈值指标受阈值影响明显；不能只报告高 Precision 而忽略 Recall。
5.  当前给出的离线图片推理速度不能等同于摄像头端到端
    FPS；实时性仍需在实际摄像头、视频流和部署设备上单独测量。
6.  当前交付暂存包包含模型和主要实验产物，但原始图像/标签、完整训练/评估源码、冻结计划和初始权重仍需配套归档，才能构成从零复现实验包。

## 8. 后续改进建议

1.  **补充负样本与困难背景：**
    增加无球背景、白色高亮物体、绳网、边缘遮挡等负样本，重点降低高置信度背景误检。
2.  **扩充独立测试素材：**
    采集不同场地、光照、摄像机高度、拍摄角度和不同视频来源的数据，建立真正独立的外部测试集。
3.  **针对困难样本迭代：**
    在开发集上补充白色结构误检和边缘球低置信度样本；若使用当前 Test
    错误案例进行训练，应将该 Test 降级为开发集，并另建新的最终测试集。
4.  **阈值标定：**
    根据实际任务对漏检和误检的代价，在独立验证集上确定阈值，不在最终
    Test 上反复调阈值。
5.  **端到端部署测试：**
    记录摄像头采集、预处理、模型推理、后处理和显示的完整延迟及实际 FPS。

## 10. 总结

本次任务完成了 YOLOv8n / YOLOv8s
的验证集比较、测试前模型选择冻结、正式权重哈希核验、Val/Test
数据一致性审计、最终 Test 评估及错误案例复核。YOLOv8s 在当前 Test 上取得
mAP50-95=0.947860；固定置信度阈值 0.50 时取得
Precision=0.973684、Recall=1.000000。后续工作的重点不应是继续在当前 Test
上调参，而应是扩充独立场景数据、改善高亮背景误检，并完成真实摄像头端到端性能验证。
