# 任务一第三版：完整视频分组、n/s训练对照与最终测试

本包仅使用此前已复核的本人实拍数据。保留原始复核项目、v1/v2数据集与权重，新建`task1_ball/yolo_ball_v3`。不是继续微调v2，也不改变检测框上的置信度数值。

## 为什么重新训练

v2的640/960对照已完成：在相同49份内部样本上，640检出43、误检0、漏检2；960检出43、误检5、漏检2，正确检测的置信度中位数也下降。本版维持输入640，把重点转为整段视频划分与模型训练。

现有v1/v2训练过将被本版划为测试集的视频，因此不能直接沿用v1/v2权重。本版两种模型均从官方80类COCO预训练权重开始，仅使用本版train；验证选择模型，测试仅评估选定模型。

训练另加入已视觉复核的21张有球上下文裁剪、21张无球背包裁剪、21份遮挡原图重复采样，均继承训练原视频；所以训练目录514份（475有球、39无球）。验证、测试不加派生裁剪或重复。672是去重后原图数，735是含训练派生/重复的文件份数；不能把735说成独立拍摄图片。

### 评估边界必须保留

- 按源视频文件隔离，不出现同一原图、派生图或相同JPEG跨集合。但这些视频同属一个实验室、同一下午，独立文件不自动证明不同采集轮次。如果你确认其中某些文件是同一连续拍摄拆段、重叠录像或必须合组的同一轮采集，先停止运行并说明实际关系，需要在训练前合组重划。
- 所有素材此前已被开发观察；本版可做到模型训练样本隔离，不能声称是全新素材/全新场景的盲测。
- val没有空帧，test只有2张无球帧；背景误检覆盖有限，不承诺Precision泛化。
- 背包视频整体在train，因此本版没有独立背包测试视频。以后播放该视频只能作训练素材回归展示，不能将它作为遮挡泛化测试，也不能与v2那11张时间留出结果直接比较。
- 不重新纳入此前76张剔除图或20张近重复图。继续按足球可见区域标注，不把遮挡后完整球体补画出来。

## 运行

将ZIP里面的`ball_formal_v3`文件夹完整解压到：

```text
\\wsl.localhost\Ubuntu-22.04-F\home\hu_yuhan\Cquick\Week3-4\task1_ball
```

如果在PowerShell，先进入Ubuntu：

```powershell
wsl -d Ubuntu-22.04-F -u hu_yuhan
```

在Ubuntu运行（不需要重装环境）：

```bash
cd "$HOME/Cquick/Week3-4"
source .venv/bin/activate
python task1_ball/ball_formal_v3/run_v3.py
```

默认连续执行：

1. 核对768张原复核状态/标签、被选原图和裁剪资源哈希，生成新的train/val/test目录与完整data.yaml。
2. 查找本地`yolov8n.pt`、`yolov8s.pt`，缺少时通过Ultralytics官方资产下载。只接受80类COCO初始化；不会把v1/v2的单类别best.pt当作预训练模型。
3. 分别训练YOLOv8n与YOLOv8s，记录官方初始化文件及SHA256、全部参数、曲线和最佳权重。
4. 分别评估val，比较mAP50-95，并记录固定阈值0.25、0.50、0.90、0.95、0.97、0.99下的检出/误检/漏检和正确框置信度分布。
5. **只按val的mAP50-95选模型**，相同时选较小的n；把选择写入`selection_before_test.json`后才读取test做模型评估。不会在test上比较两种模型后挑分数高的。
6. 只对选定模型输出test的Precision、Recall、mAP50、mAP50-95，以及固定阈值结果。原生P/R工作点与固定0.25阈值分开标注。
7. 打包`task1_ball/yolo_ball_v3/v3_results_for_review.zip`，终端打印完整路径和选定权重位置。上传该ZIP供核对，不需要上传全部训练目录或权重。

只检查和生成数据、不训练：

```bash
python task1_ball/ball_formal_v3/run_v3.py --prepare-only
```

### 默认训练设置

两个模型相同：imgsz=640、batch=4、最多100轮、patience=20、AdamW、lr0=0.001、lrf=0.01、cos_lr=True、预热3轮、weight_decay=0.0005、mosaic=0.5、最后10轮关闭mosaic、scale=0.3、translate=0.1、fliplr=0.5、hsv_s=0.4、hsv_v=0.3、seed=42、workers=2、cache=False、AMP开启。相同batch便于对照，先用4照顾RTX4050约6GB显存；实际是否足够仍需运行验证。

由较小模型开始作基线，再观察更大s是否带来实际收益；不保证模型变大就达到0.97/0.99。训练后不得只筛选出高分框来代替漏检/误检统计。两个模型为同一数据和设置上的一次对照，单次随机种子结果不能证明普遍优越性。

若训练意外中断，再运行同一命令，优先使用本次v3的last.pt继续；已经完成的模型不会重复训练，原v1/v2保留。本次结果在`results/task1_ball_yolo/formal_v3_日期时间/`。

若显存不足且最终测试尚未开始，可保留旧实验并降batch新开实验：

```bash
python task1_ball/ball_formal_v3/run_v3.py --batch 2 --new-run
```

如果电脑已重启，先重新进入Ubuntu并激活`.venv`。不要在两次运行中更换模型/数据/训练参数后继续沿用原状态。

若权重下载失败，终端会提示缺少的文件。将官方同名COCO预训练权重放到`~/Cquick/Week3-4/pretrained_coco/yolov8n.pt`或`yolov8s.pt`后重新运行。`best.pt`不能通过改名变成官方权重。字体继续使用本地DejaVu Sans，避免重复等待Arial.ttf下载。

### 最终测试纪律

本包测试前冻结选择，测试后默认重跑仅核验模型并重新打包，不重训/重测。最终测试已开始后，脚本阻止`--new-run`继续在同一test上调参；若后续根据测试失败案例改变训练，需要新的最终测试素材或如实将旧test降为开发验证集。测试失败或程序中断后可重试同一已冻结模型，不允许更换模型选择。
