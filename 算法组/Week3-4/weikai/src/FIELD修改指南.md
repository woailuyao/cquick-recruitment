# field.yaml 修改指南（新增边缘 L/T 标志）

## 1. 代码侧结论：新增标志不用改代码

定位主链路（`locator.py` / `locator_fixed.py` / `realtime_locate.py` / `make_loc_figs.py`）
都通过 `field_type(name)` 自动识别类型——只看名字首字母：
- `TCross...` / `T...` → 类型 `T`
- `LCross...` / `L...` → 类型 `L`
- 其他（如 `PenalityPoint`）→ 返回 None，不参与定位匹配

所以只要你给新标志起 **T 开头或 L 开头** 的名字，代码自动认。
唯一要注意：`realtime_locate.py` 地图绘制里对 `PenalityPoint` 做了特判跳过，
新标志不受影响。

## 2. 修改 field.yaml 的 5 个步骤

### 步骤 1：确认边缘拐角的物理形状与坐标

先想清楚"场地边缘拐角"具体是哪一类：

| 实际形状 | 类别 | 命名建议 | 说明 |
|---|---|---|---|
| 场地四角：边线与端线垂直相交成 90° | **L**（拐角） | `LCross5`~`LCross8` | 边线+端线组成的直角，视觉上是 L 形 |
| 边线中点与中线相交成 T 形 | **T** | `TCross5`~`TCross6` | 三条线交汇，视觉上是 T 形 |
| 球门线中点（若地面有标记） | T | `TCross7` | 按实测决定 |

按现有坐标约定实测：
- 场地尺寸：`field_length=7.954`（X 向）、`field_width=5.982`（Y 向）
- 原点在中心，球门侧端线 x=+3.977，对侧 x=−3.977
- +Y 为面向球门时的左侧，边线 y=±2.991

四角理论坐标（实测核对后填入，别直接抄）：
```
(+3.977, +2.991)  (+3.977, −2.991)
(−3.977, +2.991)  (−3.977, −2.991)
```

### 步骤 2：实测并记录

- 用卷尺从原点（中线交点）量到每个拐角，X/Y 分别量
- 记录测量日期、工具、测量人，写进 field.yaml 注释区
- **注意**：如果拐角白线较宽，取两条线的中心线交点，不是外边缘

### 步骤 3：编辑 field.yaml

在 `templates/field.yaml` 的特征点坐标区追加，例如：

```yaml
# --- 新增：场地边缘拐角（实测 2026-11-20）---
LCross5: [ 3.977,  2.991]   # 球门侧左角（边线×端线）
LCross6: [ 3.977, -2.991]   # 球门侧右角
LCross7: [-3.977,  2.991]   # 对侧左角
LCross8: [-3.977, -2.991]   # 对侧右角
TCross5: [ 0.000,  2.991]   # 左边线中点×中线
TCross6: [ 0.000, -2.991]   # 右边线中点×中线
```

规则：
- 键名必须 T/L 开头（`field_type` 靠首字母识别）
- 坐标单位米，[x, y]，与现有格式一致
- **不要改已有 8 个标志的名字和坐标**（改了要重新标注+重训）

### 步骤 4：训练数据必须同步补

这是最容易漏的一步：YOLO 权重 `best_manual_150.pt` 只见过原来的 8 个标志局部图。
新拐角的外观（90° 直角 vs 原来的 L 形）**没训练过，检测器大概率认不出**。

必须：
1. 补拍包含新拐角的视频（或从已有视频里抽含拐角的帧）
2. 用 LabelImg 按同样规范标注（L 类 / T 类，框住拐角交点）
3. 合并进现有 landmark 数据集，重新运行 `prepare_landmark_dataset.py` +
   `train_landmarks.py`
4. 验证 mAP50 没明显下降

不补数据就直接加地图点，等于地图上有、画面里检不出，白改。

### 步骤 5：配套文件（细则要求的 config/ 三件套）

细则 397-401 行要求提交：
```
config/
├── field.yaml              # 你改的这个（放 src/templates/field.yaml）
├── field_geometry.yaml     # 尺寸/原点/轴向/版本 —— 必须同步更新
└── camera_extrinsics.yaml  # 固定外参
```

- `field_geometry.yaml` 里如果写了标志点数量或版本，要同步改；
  建议加 `map_version: 2` 和 `updated: 2026-11-20`
- README 里的"8 个标志"要改成实际数量
- 定位报告里"场地图 8 标志"的表述同步改

## 3. 改完怎么验证

1. `python locator.py --selftest` — 合成数据自检（新增点会自动进地图）
2. 用含新拐角的视频跑定位，确认检出数增加、误差不恶化
3. 检查 `realtime_locate.py` 地图上新点是否正确着色（T 橙 / L 蓝）

## 4. 风险提醒（为什么我之前不推荐先做这个）

- 你实际测试机位 M1/M7 的视野里，新加的 6 个点只多看到 0~1 个（我算过），
  对定位精度提升有限；
- 真正的失败案例 M5（两点类别判反）和 M8（过曝）不是"地图点不够"造成的；
- 重标+重训至少 1 天，而固定外参+重拍也是 1 天——**优先级建议：先固定外参重拍，
  地图点等 C0 现场测试前再看要不要加**。

如果组长已经确认可以改（你说可以），按上面 5 步做是合规的；只是收益要预期合理。
