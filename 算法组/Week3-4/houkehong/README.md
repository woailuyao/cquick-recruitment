### 问题与解决过程

**问题**：标志检测模型在低机位多角度下「只对某个特定角度有效」。

**现象**：同一场地、同一相机，仅转动云台改变方位角 ——
角度 A 能稳定解出位姿（`valid=true`，residual 0.094 m），
角度 B 则 **7 个观测全被判成 `LCross`、无一 `TCross`**，
而地图中只有 4 个 LCross，导致必然 `ambiguous`。

**排查**：

1. 先怀疑参数 → 对 gate / max_residual / 歧义阈值做网格搜索，**没有任何组合能救活该帧**，排除调参问题
2. 再怀疑类别混淆 → 用忽略类别的 IoU 匹配统计，发现 **T 从未被判成 L**，排除混淆
3. 对比漏检与命中的 T 框尺寸 → 面积比 **1.05**，尺寸几乎相同，排除"小目标"解释
4. 可视化失效帧 → 白线很淡、T 的竖臂仅数像素，确认是**外观随方位角剧变**

**根本原因**：训练数据只覆盖两组视角（手持俯视、三脚架 0.67 m），
模型从未见过 1.0 m/−13° 下的多数方位角；而 L/T 的形态完全取决于两条臂在画面中的可见比例。

**解决**：在同一机位**只转云台**，录 9 段覆盖 ±30° 方位角的视频，
标注 90 帧 / 352 个框后微调。未参与训练的方位角召回从 **0.08~0.30 提升到 0.68~1.00**，
test mAP50 从 0.515 提升到 **0.623**。

**附带发现（写进代码注释与 4.10.4）**：只看检测召回会得出错误结论 ——
gamma 增强在低阈值下让端到端有效率**反而下降**（假阳性毒化了地图匹配），
必须同时抬高置信度才有效。**调参必须以端到端指标为准，不能只看检测指标。**

`status` 取值：`ok` / `insufficient_markers` / `not_converged` / `high_residual` / `ambiguous`。
**定位失败时 `valid=false` 且位姿字段为 null，不会沿用上一帧的旧位姿。**

## 3. 算法链路

```
相机帧
  ├─ → YOLO（足球模型）─────────────────────→ 检测框 / 置信度 / 像素中心
  └─ → YOLO（标志模型）→ landmarks.py 几何细化 → (u, v) 精确特征点
                          ↓
              geometry.py: 去畸变 → 归一化射线 → 外参转到载体系
                          ↓
              射线与地面 Z=0 求交 → 载体系地面米制坐标
                          ↓
              matching.py: 同类点对枚举刚体假设 → 最近邻门限打分
                          → Kabsch 精化 → 歧义 / 残差 / 内点检查
                          ↓
              载体地图位姿 (x, y, yaw) → 外参换算 → 相机光心地图位姿
                          ↓
              指数滤波（失效即复位）→ 左右分屏可视化 / JSON / ROS2
```

### 关键点说明

| 环节 | 做法 | 为什么这样做 |
|---|---|---|
| 标志特征点 | `landmarks.py`：白线提取 → Hough 线段 → 按方向聚类 → 两条主直线求交点 | 细则 2.3 明确禁止把 bbox 中心当交点；L/T/X 的真实几何点都是"两条线的交点"，PenaltyPoint 取质心 |
| 地面投影 | `d_c = K⁻¹[u,v,1]ᵀ`，转到载体系后 `λ = -O_z/d_z` | 单目没有深度，必须靠已知地面平面约束；`d_z ≥ 0` 或 `λ ≤ 0` 一律判为无效，不产生 NaN |
| 地图匹配 | 不用"按类别最近邻"，而是枚举同类点对生成的刚体假设 | 最近邻会把 A 处的 X 配到 B 处的 X，位姿偏了半个场却残差很小；枚举假设能显式暴露这种多解 |
| 歧义处理 | 存在内点数相同、残差接近、但位置差 > 0.75 m 或航向差 > 12° 的第二个解 → `ambiguous` + `valid=false` | 细则 2.8 要求必须处理同类标志身份歧义，宁可报无效也不能给错的位姿 |
| 滤波 | 指数滤波，位姿跳变 > 1.5 m 或 > 45° 时复位 | 细则 2.10 要求避免在失败时无限沿用旧位姿 |

## 4. 可调参数

| 参数 | 默认 | 作用 |
|---|---:|---|
| `--gate` | 0.6 m | 单个观测匹配到地图特征的距离门限。调大→更容易匹配但更容易误配 |

### 为什么本机要用 TCP 转发

**相机在 Windows、ROS2 在 WSL2，两者不共享设备和内存。**

采用的方向是**Windows 主动连 WSL**：

```
Windows: run.py live --status-port 5056      # 主动 connect 127.0.0.1:5056
WSL2   : ros_bridge_node.py --port 5056      # 监听，收到后发 ROS2 话题
```

方向不能反过来——实测确认 **WSL → Windows 的 TCP 会被防火墙/NAT 挡住**，
而 **Windows → WSL 的 localhost 转发是 WSL 原生支持的**。

完整流程：

```powershell

source /opt/ros/humble/setup.bash
ros2 topic echo /localization/field_pose
```

### 误检案例分析（任务 1）

**案例：白色球鞋被误判为足球**

| 项目 | 内容 |
|---|---|
| 现象 | 白色运动鞋出现在画面中时，被检测为 `ball`，置信度 0.44~0.47 |
| 根因 | 白色球鞋 = 白色 + 椭圆轮廓 + 深绿色背景，与足球的视觉特征高度重合；训练集中白鞋样本极少 |
| 为什么黑鞋不误检 | 颜色差异大，模型容易区分 |
| 量化 | 置信度扫描显示：`conf=0.35` 时 Precision 仅 0.688，`conf=0.70` 时升到 **0.971**，而 Recall 只从 0.885 降到 0.811 |
| 处理 | 把足球检测阈值默认值定为 **0.70**（F1 最高点）；白鞋误检的置信度 0.47 被直接滤除 |
| 另外尝试过但无效 | 用长宽比过滤（球圆、鞋扁）—— 实测真球中位长宽比 1.02、误检 1.12，**无法分开**；且真球有 10% 的框长宽比超过 1.5（贴画面边缘或与阴影粘连） |
| 根治方向 | 负样本挖掘：把白鞋出现的帧标成空标注加入训练|

### 已知局限

1. **跨视角泛化仍偏弱**：每个视频片段对应单一视角，按片段划分得到的 test 指标本质上是跨视角指标，会明显低于 val。
2. **`TCross` 的 Precision 偏低（0.468~0.745）**：模型会把草地上的白色亮斑误检为标志。
3. **L / T 区分依赖线的可见长度**：某条臂被透视线严重压缩时，T 型可能被判成 L 型。

### ⚠️ 现场实测暴露的最严重局限：低机位掠射视角
> **⚠️ 重要更新（v6）**：本节记录的是 **v5 模型**的问题。补录 9 段方位角数据后，
> v6 在该机位下的多角度召回已从 0.08~0.30 提升到 **0.68~1.00**，
> 9 个方位角中 **8 个可用**（39/45 帧能解出有效位姿）。
> 下面保留原始分析，因为它解释了**为什么必须补方位角数据**，也是踩坑记录的一部分。


本轮考核用的相机固定在**离地 0.67 m 的三脚架**上。在这个高度下：

- 画面沿视线方向的压缩比约为 `相机高度 / 距离 ≈ 0.17`，而训练数据多在 0.5~0.87
- **T 型的竖臂几乎沿视线方向，被压缩到消失**，画面里只剩一条横线加一个小凸起
- 实测：正对球门区拍摄时，一帧只能检出 0~1 个标志，定位报 `insufficient_markers` / `ambiguous`

**尝试过的补救措施与结果：**

| 措施 | 结果 |
|---|---|
| 提高输入尺寸 416→640→960 | ❌ 无效，960 反而更差（2.2→1.5 个/帧） |
| 降低置信度 0.25→0.08 | ⚠️ 检出变多但假阳性同步上升 |
| 改从侧后方斜看（约 35°） | ✅ 标志像素尺寸从 70 px 提升到约 250 px，能检出 3~5 个 |
| 多尺度推理 / TTA | ⚠️ 每帧提升到 1 个 T + 2~4 个 L，仍不足以稳定消歧 |
| 补录该机位 50 帧并微调 | ✅ 正对机位的检出从 0 提升到 1.3~2.3 个/帧 |

**结论**：该机位下检测能力仍处于"勉强可用"边缘，定位需要在**画面中同时出现 3 个以上
同类型标志**才可靠（2 个同类标志时存在多个精确解，匹配器会正确报 `ambiguous` 而不是给错位姿）。
推荐演示时采用**侧后方约 35° 斜视**的机位，并保证画面里球门区矩形的边呈斜角而非横平竖直。

### 4.10.1 相机姿态的两次迭代

| 阶段 | 高度 | 俯角 | 标定残差 | 现象 |
|---|---:|---:|---:|---|
| 第 1 次 | 0.67 m | -15.06° | 0.128 m | 正对球门区时一帧只检出 0~1 个标志，定位全部 `insufficient_markers` |

**为什么升高机位有效**：标志在画面里的纵向压缩比约等于 `相机高度 / 距离`。

| 高度 | 距离 4 m 处 h/D | 与训练分布（0.5~0.9）比较 |
|---|---:|---|
| 0.67 m | 0.17 | 差 3~5 倍，模型认不出 |
| **1.00 m** | **0.25** | 改善但仍偏低 |
| 1.20 m（未采用） | 0.30 | — |

同时把观察角度改成**侧后方 35° 斜视**，使画面里球门区矩形的边呈斜角。
这一步比单纯升高更重要：正对时 T 型的竖臂沿视线方向被压扁到几乎消失，
斜视后两条臂都呈斜向，才能同时被检出。

### 4.10.2 三点位移测试（细则 2.11 多位置现场实时复测）✅ 通过

在同一机位下按 `A → 后退 1.0 m → 左移 1.0 m` 做位移测试，每个位置重新对准标志群，
每次连续采集 90 帧。

| 位置 | 估计位姿 (x, y, yaw) |
|---|---|
| A（基准） | (-0.612, -2.288, +7.41°) |
| B（后退 1.0 m） | (-1.608, -2.261, -1.28°) |
| C（左移 1.0 m） | (-0.837, -1.330, -9.33°) |

| 位移 | 卷尺实测 | 程序估计 | 比例 | 判定 |
|---|---:|---:|---:|---|
| A → B（后退） | 1.00 m | 1.00 m | **1.004** | ✅ |
| A → C（左移） | 1.00 m | 0.98 m | **1.017** | ✅ |
| **综合** | | | **1.011** | ✅ |

**结论：位移比例误差约 1%，远优于 ±10% 的判定门限。**

这条结果直接验证了三件事：

1. **相机外参正确** —— 地面距离与相机高度成正比，高度错 10% 位移就会错 10%；
   实测比例 1.011，说明 `h = 1.00 m` 与 `pitch = -13.12°` 可信。
2. **实测地图正确** —— 位移是在地图坐标系里算的，地图尺度错会同比例反映到比例上。
3. **定位可信** —— 三个位置的绝对位姿与相对位移自洽。

X/Y/Yaw 的绝对误差无法在本轮测量（现场没有独立参考位姿），
但相对位移的 1% 一致性已经能证明整条链路没有系统性尺度偏差。

#### 迭代过程：为什么之前两次失败

| 轮次 | A | B | 位移比例 | 结论 |
|---|---|---|---|---:|
| 1（每位置 60 帧、直接平均、min_inliers=2） | (-0.659, -2.246) | (-2.272, **+0.179**) | 0.515 / 0.991 | ❌ 0.706 |
| 2（同上） | (-0.634, -2.348) | (-2.292, **-2.533**) | 0.899 / 0.942 | ❌ 0.916 |
| **3（每位置 90 帧、稳健聚类、min_inliers=3）** | (-0.612, -2.288) | (-1.608, -2.261) | **1.004 / 1.017** | ✅ **1.011** |

前两轮失败的根因**不是外参错**（A 点两轮只差 0.1 m，说明外参自洽），而是：

1. **别名解**：可见标志少时，2 个标志虽然能解出唯一刚体变换，但对应关系有多解，
   匹配器偶尔选错，位姿跳到场地另一侧 → B 的 y 差 2.7 m。
2. **平均聚合放大了错误**：把少数错误帧和正确帧一起平均，结果被整体拉偏。
3. **后退后标志跑出视野**：只重新对准、把标志保持在画面中心，才拿到足够观测。

**对应修复**：每位置采集 90 帧 + **稳健聚类取最大一簇** + `min_inliers` 提到 3 +
每个位置都重新对准标志群。修复后一次通过。

> **没有采纳第 1 轮工具给出的"高度应修正为 0.706 m"建议** ——
> 该结论建立在别名解之上，照着改会把原本正确的外参改坏。这一点也说明
> 自动标定工具必须配合合理性检查，不能盲信输出。

#### 绝对位置与航向误差如何评估

细则要求"记录位置与航向误差"。本轮**没有全站仪/动捕这类独立参考位姿**，
所以无法直接测量绝对误差。采用的做法是**误差上界估计**，并如实说明依据：

| 误差来源 | 依据 | 量级 |
|---|---|---|
| 外参标定残差 | 3 个地面点反解，平均距离误差 **0.014 m** | 0.014 m |
| 地图坐标实测误差 | 卷尺读数，两次复核一致性约 ±0.02 m | 0.02 m |
| 当前帧匹配残差 | 面板 `residual` 字段，正常运行 0.01~0.16 m | ≤0.16 m |
| 尺度（比例）误差 | 三点位移比例 1.004 / 1.017，综合 **1.011** | ~1% |
| 标志像素细化误差 | 2 px 噪声下的闭环仿真 | 位置 0.03~0.08 m、朝向 0.2~0.3° |

**结论**：绝对位置误差估计在 **0.2 m 以内**、朝向在 **2° 以内**，均优于 0.5 m 的验收线；
但这是**上界估计而非实测值**，如实标注为"未用独立真值直接测量"。

相对位移的一致性（1%）反而是更强的证据：它排除了系统性尺度偏差 ——
如果相机高度或地图尺度错了，三个位置的位移会等比例偏离，不可能两点都落在 1% 内。

### 4.10.3 当前能力边界

| 场景 | 能否定位 | 说明 |
|---|---|---|
| 侧后方约 35° 斜视、画面中 ≥3 个同类标志 | ✅ 可以 | 实测 `valid` 稳定为 True |
| 正对球门区、标志在 4~6 m | ❌ 不可以 | 压缩比过低，检出不足 |
| 画面中只有 2 个同类标志 | ❌ 正确报 `ambiguous` | 数学上无法唯一确定，这是正确行为 |

**根本限制**来自三个因素的叠加：相机高度仅 1.0 m（视线掠射）、水平视场仅 ±22.2°、
场地标志全部集中在 1.9 × 4.0 m 的球门区范围内。三者共同导致
「站得远才装得下 3 个标志，但那时标志太小认不出；站近了标志够大，画面里却只剩 1~2 个」。

**改进方向**（本轮未及实施）：补录斜视机位的训练数据、或在场地其他区域增测标志点，
使任意机位下都能同时看到 3 个以上同类标志。

#### TCross 召回是怎么提上来的

最初 test 集 `TCross` 召回只有 **0.364**，是最主要的短板。诊断分三步：

**第一步：排除类别混淆。** 用 IoU≥0.5 忽略类别匹配，检查"T 的 GT 是否被 L 的框命中" ——
结论是 **0 次混淆**，T 从未被判成 L。所以不是分类问题。

**第二步：确认不是小目标。** 对比漏检与命中的 T 框尺寸：
命中中位 1251 px²、漏检 1312 px²，**面积比 1.05**。同尺度的 T 有的检出有的漏检，
说明差异在**外观**而不是尺度。

**第三步：定位到低对比度。** 可视化显示失效方位角的画面里白线很淡、
T 的竖臂只有几像素，且多处交点位于线条收敛的区域。

**试过的方案与结果**：

| 方案 | 164427 的 T 召回 | 结论 |
|---|---:|---|
| 原图（基线） | 0.55 | — |
| CLAHE 增强 | 0.42~0.45 | ❌ 反而变差 |
| 锐化 | 0.50 | ❌ 变差 |
| 降置信度到 0.05 | 0.57 | ❌ 收益极小，假阳性暴涨 |
| **gamma 0.7** | **0.65** | ✅ 提升 |
| **gamma 0.7 + conf 0.32** | **端到端 79.1%** | ✅ **最终方案** |

**关键教训**：只看检测召回会得出错误结论。gamma 0.7 在 **conf=0.18** 时
端到端有效率反而从 29.6% 掉到 16.5% —— 召回上去了，假阳性也跟着上去，
把地图匹配毒化了。**必须同时抬高置信度**（0.18 → 0.32）滤掉多出来的假阳性，
端到端才从 29.6% 跳到 **79.1%**，位姿抖动也从 29.4 cm / 5.27° 降到 **2.9 cm / 0.40°**。

> 这也说明：**检测指标和定位指标不是一回事**，调参必须以端到端指标为准。

### 4.10.5 现场发现的两个具体问题

**1. 有一个 `TCross` 紧贴球门柱，基本检测不到**

该标志的坐标已被正确测量并保留在地图中，但在实际拍摄时它与球门柱的立柱在地面附近重叠，
YOLO 无法把它和球门结构区分开。

**这不影响系统工作**：匹配器是「遍历观测 → 在地图中找同类最近点」，
**从不要求地图中的每个特征都被观测到**。一个从未被检出的地图点不会参与匹配，
既不会拉低精度，也不会造成歧义。保留它反而是对的——换个角度若能看见，它就能贡献一个约束。

## 7. 已知限制

1. 演示地图（`config/field.yaml`）是**构造**的，只用于算法验证；C0 实测地图是
   `config/c0_field.yaml`，由本人卷尺实测生成。
2. 相机水平视场仅 **±22.2°**，站在场地一角往往只能看到 1–2 个标志，此时会正确输出
   `insufficient_markers`。这是几何限制，不是 bug —— 实拍时要靠走位保证至少 3 个同类标志可见。
3. **低机位掠射视角是任务 2 的主要瓶颈**：相机只有 1.0 m 高时，画面纵向压缩比约 0.25，
   而训练数据多在 0.5~0.9，导致标志检出不稳定。详见 4.9 与 4.10 节。
3. 几何细化依赖白线对比度，强逆光或线被踩脏时可能失败，此时回退 bbox 中心并置 `refined=False`，
   但上层目前**没有**因此降权，后续应加。
4. 滤波会引入 1.5° 左右的航向滞后（见实测数据），演示时建议同时显示原始解。
