# 录屏操作清单（重录版 · 覆盖细则全部视频证据要求）

> 目标：一条连续录屏，覆盖任务 1、任务 2 和 ROS2 输出的**全部**细则要求。
> 细则硬性规定：录屏无姓名或时间 → 按未自证处理；只展示静态图片 / 离线推理 → 扣 10 分。
>
> **预计时长 8~10 分钟。**

---

## 阶段 0 · 录屏前 10 分钟

### 0.1 关掉抢 CPU 的程序

任务 2 要同时跑两个 YOLO 模型，内存紧张时帧率会从 14 掉到 7。

| 关闭 | 原因 |
|---|---|
| 浏览器（Edge / Chrome） | 最占内存 |
| GameViewer / 远控投屏 | 实测占 CPU 明显 |
| 微信、QQ | 会弹通知，污染画面 |
| 多余的 PowerShell 窗口 | |

### 0.2 确认相机编号

```powershell
cd D:\vision_ws\k1_soccer_vision
.\.venv\Scripts\python.exe scripts\camera_select.py --max-index 3
```

记住外接 USB 相机的编号（通常是 **1**）。按 `q` 退出。

### 0.3 摆好三脚架（关键，决定成败）

| 参数 | 值 | 说明 |
|---|---|---|
| 高度 | **1.00 m** | 外参就是按这个标的，改了要重标 |
| 俯角 | **-13.1°** | 同上 |
| 位置 | 球门区侧后方约 3 m | 你三点测试通过的那个机位 |
| 朝向 | 斜对球门区，**矩形边在画面里呈斜角** | 横平竖直就检不出 |

**摆好后锁死云台，贴胶带做记号。录屏全程高度和俯角都不能动。**

### 0.4 先试跑，确认能出 valid

```powershell
.\.venv\Scripts\python.exe run.py live --camera 1 --marker-weights weights\marker_best.pt --field config\c0_field.yaml --geometry config\c0_field_geometry.yaml
```

只盯三个数：

| 位置 | 应该是 |
|---|---|
| 左上 `marker=` | **≥3** |
| 右侧 `valid=` | **true** |
| 右侧 `residual` | **< 0.25 m** |

不满足就左右微调 5~10°，直到满足。**这一步不通过不要开始录。** 按 `q` 退出。

## 阶段 3 · 任务 1 足球检测（2~3 分钟）

### 3.1 启动

```powershell
.\.venv\Scripts\python.exe run.py live --camera 1 --ball-weights weights\ball_best.pt --imgsz 416 --task1 --field config\c0_field.yaml
```

> 画布会自动缩放到 1120×630，**底部 FPS 那行一定看得见**（这是细则要求项）。

### 3.2 场景清单，每项停 3~5 秒

| # | 动作 | 要说的话 |
|---|---|---|
| 1 | 球放画面中央 | "检测框、类别名 ball、置信度、像素中心、FPS 都在实时更新" |
| 2 | 球移到画面左边缘 | "不同位置" |
| 3 | 球移到右边缘 | "边缘也不丢" |
| 4 | 球拿近到 2 m | "不同大小 —— 近处目标大" |
| 5 | 球放到 8 m | "远处目标小，仍能检出" |
| 6 | **踢一下让球滚** | "滚动中的球连续跟踪" |
| 7 | **用脚挡球一半** | "短暂遮挡" |
| 8 | 球滚到白线上 | "贴着白色场地线不会误检" |
| 9 | **白鞋入镜** | ⭐ 见 3.3 |
| 10 | **球退到 10 m 外** | ⭐ 见 3.4 |

### 3.3 ⭐ 误检案例（细则硬性要求）

**把白色运动鞋放进画面**（穿白鞋抬脚即可）。

> "这里展示一个典型的误检来源：白色球鞋。白鞋的颜色、椭圆轮廓和深绿草地背景
> 跟足球高度相似，在置信度 0.35 下会被判成足球、置信度约 0.47。
> 我把足球阈值定在 0.70 —— 阈值扫描显示 0.35 时 Precision 只有 0.688，
> 0.70 时升到 0.971，而 Recall 只从 0.885 降到 0.811。所以 0.47 被滤掉，
> 现在默认参数下不出现这个误检。"

**想让它真的出现在画面上**（可选，多花 20 秒）：按 `q` 退出，重跑一次加 `--ball-conf 0.35`，看到误检框后按 `q`。

### 3.4 ⭐ 漏检案例（细则硬性要求）

**把球滚到 10 m 以外**，画面里只剩一个小点。

> "这是一个漏检案例：球在 10 米外，像素直径只有约 34 像素，模型检不出。
> 独立测试集 Recall 0.811，比验证集的 0.888 低 —— 差的这 7.7 个百分点
> 主要就来自远距离小目标和强遮挡。我为此补录过远处小目标数据，
> 但超过 10 米已经接近模型可辨识下限。"

### 3.5 退出

按 **`q`**。终端会打印：

```
本次运行统计（任务 1：实时检测）
  总帧数        842
  平均 FPS      14.8
  平均推理耗时  48.3 ms
```

**让这段入镜并念出来** —— 这是"实时 FPS、推理时间"的书面证据。

> ⚠️ 如果这里仍显示"定位有效率 0.0%"，说明跑的是旧代码 —— 现版本任务 1 只报上面三项。

## 阶段 4 · 任务 2 场地定位（3~4 分钟）

### 4.1 启动

```powershell
.\.venv\Scripts\python.exe run.py live --camera 1 --marker-weights weights\marker_best.pt --field config\c0_field.yaml --geometry config\c0_field_geometry.yaml
```

**参数全用默认**：`imgsz 640 / marker-every 2 / marker-conf 0.32 / marker-gamma 0.7 / min-inliers 3`。
这组是端到端实测最优的（T 型密集方位角有效率从 29.6% 提到 79.1%）。

### 4.2 ⭐ 展示启动横幅（细则要求内参/畸变/外参/地图版本）

**画面里必须能看到这几行**，逐行念：

```
[地图] ...\config\c0_field.yaml  version=C0 measured (personal)  特征 9 个
[地图] 类型分布 {'TCross': 4, 'LCross': 4, 'PenaltyPoint': 1}
[相机] 内参 fx=1567.73 fy=1567.35 cx=666.34 cy=356.51  分辨率 1280x720
[相机] 畸变 [k1,k2,p1,p2,k3] = [0.215722, -1.429494, -0.002699, -0.001402, 1.78549]
[外参] 安装高度 1.000 m  俯仰 -13.118°  滚转 0.00°  yaw_offset 0.0°
[外参] 地面平面 Z=0；相机光心在载体坐标系中的位置 t=(0.000, 0.000, 1.000) m
```

> "这是载入的地图文件 c0_field.yaml，版本 C0 measured personal，共 9 个特征，
> 4 个 TCross、4 个 LCross、1 个点球点。相机内参和畸变系数由棋盘格标定得到，
> 重投影 RMS 0.21 像素。外参是安装高度 1 米、俯仰 -13.118 度，
> 用 3 个地面点反解，残差 1.4 厘米。"

### 4.3 ⭐ 按 `h` 讲字段（30 秒）

按 **`h`** → 右侧叠出 FIELD GUIDE → 讲一遍 → 再按 `h` 收起。

> "右侧面板的字段：x_camera_map 和 y_camera_map 是相机光心在地图里的坐标，
> yaw_camera_map 是朝向；markers 是检出并匹配上的标志数，inliers 是参与求解的内点数，
> residual 是匹配残差；valid 和 status 表示定位是否可信。"

### 4.4 ⭐ 三个位置（细则要求"至少 3 个不同位置/朝向"）

**只平移三脚架，不要改高度和俯仰。** 每个位置停 8~10 秒。

| 位置 | 动作 | 要念的 |
|---|---|---|
| **A** | 当前机位不动 | "位置 A：x 约 -0.3，y 约 2.4，yaw 约 -23 度"（按实际读数念） |
| **B** | 整体左移约 1 m，**可重新对准标志** | "位置 B：x 变成 ……，右侧地图上的绿点同步移动" |
| **C** | 再前移约 1 m | "位置 C：y 变成 ……" |
| 回 A | 移回原位 | "回到 A 点，数值复位" |

**平移时盯这四个地方**：

| 位置 | 应该看到 |
|---|---|
| `x_camera_map` / `y_camera_map` | 数值连续变化 |
| 右侧地图上的**绿色圆点** | 沿地图移动 |
| 绿色**朝向箭头** | 方向与相机实际朝向一致 |
| `marker_count` | 随视角变化 |

> "注意全程只做平移，不改变相机高度和俯仰角，因为外参绑定在这两个量上。"

### 4.5 ⭐ 无效状态演示（细则要求"至少一次"）

**转动云台，只让 1~2 个标志入镜**，面板会变成 `valid=false`。

| 状态 | 含义 |
|---|---|
| `status=ambiguous` | 多组同样合理的解，拒绝猜 |
| `status=insufficient_markers` | 标志数少于 3 |
| `status=high_residual` | 观测和地图对不上 |

> "现在画面里只剩一两个同类标志，系统输出 valid=false 和 ambiguous。
> 这是正确行为 —— 两个标志虽然能解出唯一刚体变换，但对应关系有多解，
> 无法唯一确定位姿。细则要求定位失败不能伪造有效位姿，所以这里必须报无效。"

**然后转回来**恢复 `valid=true`，再平移一下证明能恢复。

### 4.6 退出

按 **`q`**，让统计入镜：

```
本次运行统计（细则 2.10 要求记录的项目）
  总帧数        xxx
  平均 FPS      11~
  平均推理耗时  xxx ms
  有效位姿帧数  xxx / xxx
  定位有效率    xx~100 %
  定位更新频率  xx Hz
```

**逐项念出来** —— 细则 2.10 四项指标的书面证据。

## 阶段 5 · ROS2 输出（1~2 分钟）⭐ 新增，补细则任务 2 第 8 条

**必须三个窗口，顺序不能错。**

### 5.1 窗口 1：WSL 启动桥接节点（先启动）

```bash
wsl
cd /mnt/d/vision_ws/k1_soccer_vision
source /opt/ros/humble/setup.bash
python3 scripts/ros_bridge_node.py --port 5056
```

看到 `[relay]` 字样在监听就对了。**这个窗口不要关。**

### 5.2 窗口 2：Windows 启动带 ROS2 输出的主程序

```powershell
.\.venv\Scripts\python.exe run.py live --camera 1 --marker-weights weights\marker_best.pt --field config\c0_field.yaml --geometry config\c0_field_geometry.yaml --status-port 5056
```

### 5.3 窗口 3：WSL 展示话题

```bash
wsl
source /opt/ros/humble/setup.bash
ros2 topic list
```

应看到：

```
/localization/field_pose
/localization/field_pose_2d
/soccer/ball
```

```bash
ros2 topic echo /localization/field_pose_2d
```

实时刷出：

```
x: -0.285
y: 2.391
theta: -0.4029965242854907
---
```

再展示 JSON 话题：

```bash
ros2 topic echo /localization/field_pose --once
```

> "定位结果同时发布到 ROS2 的三个话题：field_pose 是包含细则要求全部字段的 JSON，
> field_pose_2d 是标准 Pose2D 可直接给 rviz2，soccer_ball 是足球检测结果。
> 因为相机在 Windows、ROS2 在 WSL2，用 Windows 主动连 WSL 的 TCP 转发，
> 刚才终端里实测发布频率 8.5 Hz。"

> ⚠️ **ROS2 没跑通就跳过这一段**（细则原文是"如使用 ROS2"）。不要为它耽误主体。

## 附 · 常见问题

| 问题 | 处理 |
|---|---|
| 任务 2 一直 `valid=false` | 转角度，让画面里**同时出现橙色 L 和蓝色 T 框**；`markers≥3` |
| 任务 1 球拿太近检不出 | 球保持 1.5 m 以外，太近会超出模型工作范围 |
| 帧率低于 5 fps | 关浏览器 / 投屏软件；或加 `--marker-every 3` |
| 相机打不开 | `camera_select.py --max-index 3` 确认编号，改 `--camera` |
| `date` 报错 | 用 `Get-Date -Format`，不是 `date` |
| `run.py` 无法识别 | 必须 `.\.venv\Scripts\python.exe run.py ...`，不能直接敲 `run.py` |
| ROS2 话题 echo 无输出 | 桥接节点是否在跑；主程序是否加了 `--status-port 5056` |
| 忘了字段含义 | 运行时按 **`h`** |
| 想存关键截图 | 按 **`s`**，写入 `snapshots\shot_<时间>_raw.jpg` |
