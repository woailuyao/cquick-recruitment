- 地面投影方法：像素点 → `cv2.undistortPoints` 去畸变得到归一化射线 `d_c` → 用 `R_base_camera` 旋转到载体系得 `d_b` → 与地面平面 `Z=0` 求交，`λ = -H / d_b.z`，`P_b = (λ·d_b.x, λ·d_b.y)`；当 `d_b.z ≥ 0`（射线朝上）、交点超出合理场地范围或像素不可靠时，该观测直接丢弃，不产生 NaN 或伪造地面点
- 地图匹配算法与同类标志消歧方法：
  - **同类去重**：同一标志被重复检出（地面点相距 <0.20 m）时只保留置信度最高的一个（地图同类标志最小间距 0.495 m，不会误合并两个真标志）
  - **按类别数量限流**：利用地图已知数量（L=5 / T=6 / X=2 / P=1）作硬约束，每类只保留置信度最高的前 N 个观测，从源头剔除"同一场地不可能出现的重复标志"这类误检
  - **RANSAC 全组合搜索**：对同类候选做枚举 + 随机采样（300 次迭代），以重投影残差 `tol=0.20 m` 为内点判据
  - **Umeyama / least-squares 精化**：对最优内点集用 SVD 求解 SE(2)，得到 `(x, y, yaw)` 与残差
  - **状态机**：匹配点 <2 → `insufficient`；=2 → `ambiguous`；≥3 且残差 <tol → `ok`；残差超限 → `poor`；解出位置超出场地边界 → `out_of_field`（细则 2.7：不产生伪造地面点/位姿）
- 输出坐标系（camera_frame / base_link / rig_frame）：**rig_frame**（载体参考原点即相机光心铅垂投影点，因此 `x_carrier_map == x_camera_map`、`yaw_carrier_map == yaw_camera_map`）
- 3 个以上测试点的参考相机地图坐标 X/Y/Yaw 与估计误差：见下方「C0 现场测试」
- marker_count / residual / valid / status：每帧输出。`marker_count` 为参与匹配的标志数（去重+限流后）；`residual` 为内点集在 SE(2) 拟合后的均方根残差（m），无解时置为哨兵大值；`valid` 仅在 `status == ok` 时为 true；`status ∈ {ok, ambiguous, insufficient, poor, out_of_field}`
- 实时 FPS / 定位更新频率 / 耗时：全链路（足球+标志双模型推理、几何细化、RANSAC 匹配、分屏渲染，CPU）实测 **7~10 FPS**（约 100~140 ms/帧）；定位逐帧更新，更新频率=帧率；标志模型单帧推理约 50 ms（imgsz=640），足球模型约 25 ms

## 处理链路说明

### 链路一：足球检测

相机帧（BGR）→ YOLO 推理 → 每帧输出 `class=ball`、`confidence`、`bbox(x1,y1,x2,y2)` → 计算像素中心 `u=(x1+x2)/2, v=(y1+y2)/2` → 叠加到画面并打印帧号 / FPS。

### 链路二：场地标志 → 地面坐标 → 地图位姿

1. YOLO 检测 L/T/X/Point 检测框与置信度；
2. `refine_intersection()` 用 Harris 角点把框中心修正为真实几何交点，得到 `landmark_pixel=(u,v)`；
3. `pixel_to_ground()` 去畸变 → 相机系射线 → 经外参旋转到载体系 → 与 `Z=0` 求交，得到标志相对载体的地面坐标；
4. `match()` 用地图已知类别数量做限流，再做 RANSAC + SE(2) 拟合，解出载体（=相机光心）在地图中的 `(x, y, yaw)`；
5. 残差 / 匹配数 / 状态不达标时输出 `valid=false` 与对应 `status`，**不沿用上一帧位姿**；
6. 左侧 RGB 画面叠加检测框、特征点与位姿文本；右侧绘制 `field.yaml` 俯视图、相机位置图标与朝向箭头。

## 问题与解决过程

**问题：定位结果出现 5.5 m 的巨大偏差，且连续帧极不稳定。**

现象：三姿态测试中，位姿 3 的位置误差达 `dx = −5.549 m`，位姿 1、2 的 yaw 标准差达 `±56°～±61°`，同一段静止视频内解算结果大幅跳动。

排查过程：
1. 先怀疑内参 → 做了参数敏感度实验：`fx` 变化 5% 仅引起地面落点 **0.013 m** 偏移，俯角 1° 引起 0.09 m，横滚 1° 引起 0.015 m。**结论：内参/外参的误差量级（<0.5 m）远不足以解释 5.5 m 偏差**，排除标定问题。
2. 再查检测输出 → 用极低阈值（`conf=0.05`）统计各类别框数，发现单帧内出现 **4 个 `Point`** 检测，而场地上点球点**只有 1 个**，属于必然误检。
3. 进一步统计三档阈值下的误检：位姿 3 的录像在 `conf=0.05` 下 35 个框中有 27 个是假的 `Point`；提到 `conf=0.25` 后该段直接 0 个框。

根因：低置信度阈值放进了大量 `Point` 误检，而这些假观测全部被匹配到地图上唯一的 `Point(0,0)`，形成一组"自洽但完全错误"的对应关系，于是解出一个残差很小、但偏差 5.5 m 的伪解。

解决方案：
1. 在 `localize_image()` 中增加**按地图类别数量限流**：以地图中各标志真实数量（L=5/T=6/X=2/P=1）为上限，每类只保留置信度最高的前 N 个观测；
2. 误检被剔除后，状态机对不足 2 个观测的帧输出 `insufficient`，而不是硬凑一个位姿。

效果：位姿 1 的 yaw 标准差从 `±56.0°` 降到 `±0.14°`，位置从 `±1.546 m` 降到 `±0.002 m`，位置误差降至 `0.28 / 0.19 m`；位姿 2、3 改为诚实报 `insufficient`。

**另一个已修复的问题：标注类别编号错位。** 早期一批标注把 `XCross` 与 `Point` 的 `class_id` 写反（标成 0/1/2/3 = L/T/P/X），导致 `Point` 指标虚高、`TCross` 指标近乎为 0。用脚本交换 2↔3 后重新训练，`TCross` mAP50 从约 0.001 恢复至 0.44。

## 当前局限与下一步计划

**1. 视场窄、单帧可见标志少。** 相机水平视场约 43°、垂直约 25°，光轴落地点距相机仅 2.72 m，单帧通常只能看到 2~3 个标志。仅 2 个点时二维位姿存在镜像二义性，航向容易偏 20°~30°。
→ 下一步：后退取景或换用更大视场镜头，保证单帧 ≥3 个不同类标志同框。

**2. 同类标志身份歧义与场地对称。** 场地存在多个 L/T 标志且布局近似对称，仅靠 RANSAC 全局搜索在观测稀疏时仍可能收敛到错误的分支。
→ 下一步：引入连续帧位姿先验（上一帧位姿作为搜索初值、限制搜索范围），并对候选解做时序一致性检验。

**3. 标志遮挡。** 当前实现会在匹配数跌破 2 时立即输出 `insufficient`，不做跨帧补偿，因此遮挡发生时定位会短暂失效（这是刻意的，避免沿用旧位姿）。
→ 下一步：加入短时卡尔曼/滑窗滤波，但需明确标注滤波后位姿与原始观测的差异，避免掩盖失效。

**4. 标志分布不足与置信度偏低。** `Point` 类验证集召回为 0（目标极小、实例仅 39 个）；整体 Recall 仅 0.246；新相机素材仅 6 张并入训练集（约 6%），模型对新画面置信度偏低。
→ 下一步：补充新相机、多角度、多距离的实拍标注（目标 ≥300 张），提升小目标与低对比度场景的召回。

**5. 光照变化与地面不平。** 当前地面按严格平面 `Z=0` 处理，地面起伏、相机高度变化都会直接转化为深度方向误差（高度 1 cm ≈ 0.025 m）；强光/阴影会显著影响检测置信度。
→ 下一步：将地面不平与安装高度纳入误差预算，并在不同光照时段复测。

**6. 相机外参为手工测量。** 高度、俯仰、滚转由卷尺与角度尺测量，俯角误差 1° 即带来约 0.09 m 位置偏移；横滚正负号仍需现场核实。
→ 下一步：用机械限位/水平仪固定安装姿态，并把外参不确定度写入误差预算。

**7. 未封装 ROS2 节点。** 本次以 Python 脚本直接运行，未发布 `/localization/field_pose` 话题。
→ 下一步：封装为 ROS2 节点并提供 launch 文件。
