# 第 3–4 周视觉算法考核｜黄一芮

## 程序解释

我在此简单介绍本工作区的构建思路

本工作区没有按照任务一和任务二的思路严格去写，而是选择了更模块化、复用性更高的打法

简单来说是将不同的工具分到了不同的文件里，将每个工具和功能都分开写，通过互相import和调用的方式构建整体，这也是模块化编程的思路

在本工作区中主要分成四个步骤，或者说是四层框架：输入->感知->换算->输出；在这样的分层搭建下，后期维护和优化会变得更加清晰，特别是算法优化（对于yolo跑得较慢的问题）

然后我根据每一层来介绍我的各个py文件是用来干啥的

### 一、输入层

这一段主要处理代码写入和画面读取的问题

configio.py 这是一切的起点，其作用是处理yaml文件。我在里面编写了一个微型的yaml处理器，当然优先会调用官方的；然后在该文件后面写了一个打包器，将yaml中读完的东西打包进几个类里，方便后面使用

collect_video,py采集视频用的小工具，可以做到r控制开始停止录制，s保存截图，q或者ESC退出录制（自动保存）

calibrate,py没啥好说的，就是用棋盘格算畸变，纯数学处理

Video_source,py是处理视频的脚本，其作用是逐帧去抓取视频，然后将这些帧给弄进处理器里

### 二、感知层

这一段主要在画面里找目标，找足球和场地标志点

detect,py是yolo的核心文件，其作用是将yolo的原始输出转化成识别框，它会将一个对应权重文件检测封装然后通过yolo处理，再经过这个脚本就能直接输出一个框了

refine,py是将显示框重心换成真实几何交点，通过yolo给出的大致的标志所在来定位标志的几何交点，先把框外扩 25% 裁一块 ROI，Canny 出边缘、HoughLinesP 提线段，按角度分两组、各组取最长那条求交点，然后就能算出一个具体的相机位点。

### 三、换算层

这一块主要做几何换算，将像素坐标和场地坐标相对应

geometry.py是将画面像素转化为场地上以米为单位的坐标，通过矩阵变换和像素处理，同时写好后面很多文件都要用到用来记录机器热本身参值的Pose2d类；这个脚本会写好将像素投到地面以及反向投射的函数，后续也会调用到这两个写好的函数，然后再次通过将地面上的点头回来逆向验证；同时还补充了利用相机安装的外参来定位的函数

field_map.py是场地识别的核心脚本，其作用是按照观测出的点，通过选优来求解出一个位姿，这个选优的过程也是全部代码中时间复杂度的主要影响源；这个脚本显示记录场地地图，然后进行地图匹配和检测，对于地图和图像的两两检测对应采用部分记忆化搜索的思想，并对一些明显不符合条件的对象剪枝，虽然最后还是有巨量的运算时长，但能基本保证找到最有匹配点

localizer.py是串联整个检测、细化、投影、匹配和滤波的脚本，其美珍先把足球筛出来完成检测，再从标志狂里找特征细化，然后将摄像头采集到的坐标投到地面上，汇总这些投影点后匹配地图求出朝向和位置，再结合上一帧的位姿做平滑；这个脚本还会自动保存每一步的结果，方便定位问题

extrinsics.py用量取的数据来生成摄像机的外参，定位误差主要在俯角上

### 四、输出层

这一块主要负责画框，然后还有很重要的写日志

visualize.py负责按要求将结果显示成左右分屏的画面，实时更新结果

soccer_interfaces主要负责演算位姿，将位姿投射到地图上

### 五、主函数

本工程通过写run_demo.py文件作为主函数，能够控制整个流程，读帧 -> 跑定位 -> 显示 -> 打印 -> 写结果，包括调用ros2，自检，拉出目录等等，这就是整个工程的int main()

### 六、yolo训练

extract_frames.py负责将实拍的视频抽帧喂给yolo训练，它会自动整理直接喂给yolo并且顺手把label文件写了，注意事项就是尽量抽些不一样的图像，意思就是幺隔几帧抽一次，减少无效训练

check_dataset.py跑之前自检

train_yolo.py利用图片训练搭建小模型

### 七、对于本次任务出现的问题以及解决策略

1.首先是本次任务的工程量较大，本人采用了 构建思路-AI搭建框架-完善代码命名和功能批注-AI填充代码-试运行-AI纠错和补充依赖 的链路，可以看到相比于上次，这次的AI使用量大幅提升，主要原因在于本人对python语言还不是很熟悉且这次调用yolo、opencv的诸多函数以及dataclass等类关键字，这些因素导致不得不大量依赖AI完善代码，但在跑完后有大量的代码改动较大，且由于会修改一些注释导致代码的可读性降低，这导致我后期花了大量的时间来完善注释和整个框架逻辑

2.素材采集较为窘迫，由于实验室还有其他同学也在使用摄像机且平常时间安排比较紧，导致素材采集迟迟不能满足需求，饶是今天完稿11.23还需要去实验室补录几组素材。这个问题相对来说比较好解决；主要是太多数据无效或者误差太大不方便加进数据集里处理

3.运算速度出奇地慢，正常录制视频大概在25-30帧，但在处理时帧率暴跌到8-13帧，18%low帧更是到了惊人的1帧，我推测时refine文件中两两识别匹配的算法占用了较高的时间复杂度，所以我将其从原来的暴力枚举优化了一下，时间复杂度大概降到了O(nlogn),对帧率有一定的提升作用，但感觉仍不明显

4.最后使用gpt对于场地识别进行了歧义处理，自主定位使用机位属于 X≤0 半场的先验。在地图范围内筛选相机候选位姿，观测角点仍取自全场。关闭 camera.yaml 的 negative_half_only 即可恢复全场搜索。具体参考坐标只用于事后比较。镜头高 0.93 米，估计俯角 18.5°。

此前两段有效数均为零。本次 081036 有效 616/626，有效帧位置与航向误差中位数分别为 0.53 米、19.69°；081354 有效 4/516，对应 1.03 米、5.62°。按整段对应同一参考姿态统计。两段同时满足 0.5 米和 10° 的帧均为零。结果为旧素材离线复测。

## 设备与运行

USB UVC 单目相机，固定对焦，1280 × 720；录像标称 30 FPS。Windows 使用设备编号，Linux 使用实际枚举的 UVC 节点。训练机为 RTX 5060 Laptop，Python 3.12.14、PyTorch 2.9.1+cu128、Ultralytics 8.4.208。ROS2 接口在 Ubuntu 22.04.5 / Humble 下完成回放验证。演示录屏 01:16 的界面读数为 8.2 FPS、推理 118.2 ms；这是该时刻读数，整段平均值未统计。

在本目录安装依赖，将两个权重放入 weights/，从工程根目录运行：

```bash
python -m pip install -r requirements.txt
python src/soccer_vision/run_demo.py --source 0
```

回放时将 0 换成视频路径。现场三点记录入口为 `python 现场三点.py --camera 0`。在 ROS2 环境先加载 Humble，并确认运行程序的 Python 可以导入 rclpy。[下载模型权重（百度网盘）](https://pan.baidu.com/s/1eNbPP67JJSWbM3HdSekepg?pwd=0721)，提取码 `0721`。下载后，将 ball_best.pt 和 marker_best.pt 放入本工程的 weights/ 目录。文件校验值如下。

## 任务一 · 足球检测

YOLOv8n，首版训练 50 轮，扩充后针对近景再训练 12 轮；输入 640、batch 8、AdamW、近景阶段初始学习率 0.00015，演示置信度 0.45。足球训练 / 验证 / 测试分别为 358 / 23 / 70 张，测试集共 135 个球。类别与各集合实例数见[数据摘要](dataset/dataset_summary.md)。

| 测试集 | Precision | Recall | mAP50 | mAP50–95 |
|---|---:|---:|---:|---:|
| 完整独立测试片段抽帧 | 93.33% | 49.63% | 50.21% | 42.50% |

检测框中点作为足球像素中心。近景子集中 13 个大球全部检出，另有 1 个误检。远处小球容易漏检，人腿间的高亮背景曾触发误检。首版 ONNX 与 PyTorch 在同一 CPU、640 输入、预热后比较 60 帧，平均前向耗时分别为 30.69 ms 和 27.87 ms，逐帧框数一致。

## 任务二 · 场地坐标与定位

标志 YOLOv8n 训练 50 轮，640 输入、batch 8、AdamW。训练 / 验证 / 测试为 38 / 19 / 12 张。测试集 LCross 的 P/R/mAP50 为 51.73% / 40.00% / 43.19%，TCross 为 76.92% / 61.11% / 76.89%。本场无实体点球标记，测试集缺少 X 类和点球点正例。

内参使用 26 张棋盘格照片求解，9 × 6 个内角点，标称格长 20 mm，重投影 RMS 1.5845 px。fx/fy/cx/cy 为 1665.72/1660.65/568.18/341.51 px；畸变参数为 [0.226251, −1.102906, −0.028620, −0.033338, −4.149041]。当前安装高度 0.93 m，向下俯角根据录像估算为 18.5°，滚转、相对偏航及水平安装偏移取零。

C0 实测地图为 8 × 6 m，中圈半径 0.75 m。原点在中圈，+X 指向唯一球门、+Y 向面对球门时的左侧、+Z 向上。Yaw 从 +X 逆时针为正。参考官方 field.yaml 格式，本次使用自定义 C0 特征坐标（12 个 L 点、10 个 T 点）。两端矩形按同形建模；一侧外框间距的手测读数与推算值相差 0.10 m。地图版本 c0-measured-20261123，field.yaml SHA-256 为 `9955ee519f6896a576a50b1c5d07119df1d6c1096431408484e145b1566ca831`。

检测框内提取线段交点，去畸变后生成射线，经安装外参转入 base_link，与地面 Z=0 求交。按标志类型生成点对匹配，按内点数和残差选解。negative_half_only 开启时，候选机位限于无球门半场；参考坐标只用于误差统计。相近解报告 ambiguous，观测不足报告 insufficient_markers。
