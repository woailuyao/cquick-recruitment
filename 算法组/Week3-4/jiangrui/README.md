### 误检与漏检案例

证据图：`docs/ball_val_batch0_pred.jpg`（验证集 v9 前 16 张，`ball_v2_best.pt`，conf ≥ 0.25，即 Ultralytics 验证默认值）；`docs/ball_error_cases.jpg`（把阈值降到 0.10，保留低置信误检，便于看清问题来源）。

- **误检案例（边缘高对比区域被当成球）**：误检主要集中在画面左右和下边缘。`v9_frame_0017` 左侧边缘一小块白色物体被检出为球，置信度 0.78；`v10_frame_0015` 底部边线转角被检出，置信度 0.49；`v9_frame_0013`、`0014`、`0015` 左侧鞋子/裤腿边缘分别为 0.13、0.20、0.17。原因：这些区域是白色线条转角、鞋面反光等高对比小块，形状与远处小球相似，而训练集中“画面边缘负样本”偏少。缓解：实时程序默认 `--conf 0.40` 可以滤掉 0.13–0.20 的三例，但 0.49 和 0.78 仍会保留；更彻底的做法是在画面边缘设忽略区、补充边缘负样本，或提高输入尺寸。
- **漏检案例（没有真漏检，只有风险样本）**：test 23 张、val 38 张的 recall 均为 1.000，没有找到真实漏检。当前最小目标是 `v9_frame_0018`，框短边约 91 px（此前写的“约 30 px”来自错误的旧统计，已更正），置信度 0.94；test 集最小约 182 px。风险在于更小、更快或更贴边的球：训练集里没有短边 < 90 px 的样本，再小就属于外推，可能最先漏检。缓解：提高输入尺寸到 960，或对画面分块推理。

- 几何特征点提取方法：`src/marker_refine.py`。框内自适应阈值分割白色标线，Hough 提取线段后按方向聚成两簇，总体最小二乘拟合两条直线并求交点；点球点取白色区域形心。框太小、线段不足或交点跑出框外时退回框中心并把 `refined` 置 False。在 3 张实拍图上实测，交点相对框中心的偏移为 9–16 px
- 相机内参 fx / fy / cx / cy：1564.28 / 1564.28 / 639.5 / 359.5（1280 × 720）

- 相机外参 / 相机高度 / 俯仰角 / 滚转角：h = 0.66 m、pitch = 13.3°、roll = 0（2026-11-22 卷尺 + 地面点法实测，俯角由 4 点回算标定交叉验证，残差 0.028 m）；标定脚本 `src/calibrate_extrinsics.py`（手工 / PnP）与 `src/calibrate_extrinsics_auto.py`（单图自动搜索）均已实现
- 地面投影方法：`src/ground_geometry.py`。像素去畸变得到相机系射线，再按外参转到载体系，与 Z=0 平面求交；射线不朝下、交点超出场地范围时判为无效。合成数据正反算往返误差 ≤ 1 mm
- 地图匹配算法与同类标志消歧方法：`src/field_map.py`。枚举两两观测与两两同类地图点的对应，直接解出候选 SE(2) 位姿；用全部观测统计内点数与残差选出最优，再做两轮最小二乘精化；若存在残差相当但位姿差 > 0.4 m / 12° 的对称候选，输出 `ambiguous`
- 输出坐标系：carrier 原点定义为相机光心在地面的垂直投影，外参平移固定为 (0, 0, h)，因此 `x_camera_map/y_camera_map/yaw_camera_map` 与载体位姿一致
- 3 个以上测试点的参考相机地图坐标 X/Y/Yaw 与估计误差：3 个位置（各 3 帧均值）位置误差 0.62 / 1.05 / 1.22 m，航向误差 0.2 / 5.1 / 0.8°，详见下方「C0 现场测试」。**参考坐标为事后根据步测与录像回忆重建，不确定度约 ±0.5–0.8 m，表中误差仅供参考，不代表绝对精度结论**
- marker_count / residual / valid / status：已实现并在界面右侧与文本面板显示
- 实时 FPS / 定位更新频率 / 耗时：现场实测 23–25 FPS，单帧推理 11–17 ms（1280×720，imgsz 960，RTX 5060 Laptop GPU）

## 问题与解决过程

1. **场地地图与实地不符**：最初直接沿用官方 `field.yaml`，现场用 4 个检测点回算时残差高达 0.45 m，原因是官方图 W = 8.95 m、L = 6.94 m，而本队场地实测 W = 6.00 m、L = 7.60 m。按实测重建地图（球门区 3.00 × 0.95 m、罚球区 4.00 × 1.90 m，原点在场地中心、+X 指向球门线）后，同样 4 个点残差降到 0.028 m，同时反推出俯角应为 13.3°（不是最初记录的 12.4°）。
2. **LCross 漏检**：640 分辨率下 test 集 LCross 召回偏低，提升到 960 后 mAP50 从 0.854 提升到 0.883，代价是 TCross 精确率略有下降。
3. **数据划分泄漏**：足球数据集最初 train 与 val 共用 v7、v8、v9 三段视频，后按整段视频重新划分，测试集保持为完全独立的 v10。
4. **增强参数**：垂直翻转必须关闭（`flipud=0`），否则 L 型标志的上下拐角方向会被破坏；水平翻转可以保留（`fliplr=0.5`），因为四角 L 本来就存在左右两种拐角朝向，横翻相当于合法的朝向增强，v2/v3 均按此设置，LCross test mAP50 分别为 0.883 / 0.995。
5. **地面点筛选的坐标系混用**：`field_map.py` 早期版本用地图边界去筛观测点，但传进来的地面点位于载体坐标系（原点在相机下方）。相机站在场地一端朝另一端看时，前方 5–7 m 的标志全部落在“地图边界 +2 m”之外而被丢掉，表现为看到 4 个标志却报 `not_converged`。改为只按“距相机 30 m 内”过滤，位姿解出后再用地图边界检查解本身；用 P1/P2/P3 三个站位的合成观测复核，均恢复到零残差。
6. **场地标志数据划分审计**：确认三份数据按整段视频划分（14 段新视频各归一个 split，`train` 另含 80 张只在 `train` 的旧帧），不存在同一视频被打散到多个 split 的情况。逐帧比对未发现跨 split 的完全重复帧；但 11-20 的新视频为同日同场地连续拍摄，`train` 与 `val` 存在场景级近相似帧（灰度相关 > 0.95 的 3 对，最高 0.956），因此 `val` 指标偏乐观，最终以独立性最好的 `test` 为准。详见 `dataset/dataset_summary.md` 第 3.3 节。
7. **外参 yaml 写入格式错误**：`calibrate_extrinsics.py` 早期版本把旋转矩阵写成三行 `[...],`，缺少外层序列结构，PyYAML 解析成字典，`Extrinsics.from_yaml` 在 `np.array(..., dtype=float)` 处报 `TypeError: float() argument must be ... not 'dict'`。改为写成一行 9 个数的平坦列表（`from_yaml` 本来就按 `reshape(3,3)` 读取），重新生成后 `R_bc` 与 `rotation_from_angles(13.3, 0)` 一致。
8. **3 点观测的对称歧义**：只有 3 个观测时，近端球门左右两侧的标志布置近似镜像，`PoseSolver` 会在 `ok` / `ambiguous` 之间摆动，判据取决于亚像素级的细化点。测试站位刻意选成 4–5 个标志可见；现场若退回 3 个点并报 `ambiguous`，微调朝向往画面里多纳入一个标志即可，不要为此放宽阈值。
