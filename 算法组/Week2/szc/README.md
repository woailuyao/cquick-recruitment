## 整条链路怎么走的

```
images/*.jpg ──cv2.imread──> BGR 图
                              │
                              ├─ cv2.cvtColor ──> HSV 图
                              │                     │
                              │                     └─ cv2.inRange(lower, upper) ──> 二值掩膜 mask
                              │                                                    │
                              │                                                    └─ 开运算 + 闭运算 ──> 清理后的 mask
                              │                                                                          │
                              │                                                                          └─ cv2.findContours ──> 轮廓列表
                              │                                                                                                    │
                              │                                                                       按面积过滤 + 面积降序取最大 ──┘
                              │                                                                                    │
                              │                                                                    cv2.moments ──> 中心点 (u, v)
                              │                                                                                    │
                              └──────────────────────────────────────────────────────────> 画框/中心点/坐标，存图
                                                                                                                   │
                                                                                     TargetPosition{deteced,u,v,area}
                                                                                                                   │
                                                                                                     /target_position 话题
                                                                                                                   │
                                                                                                       订阅节点打印四个字段
```

## 任务 1：颜色目标检测

**目标颜色**：橙色（足球等橙色系物体）。
**HSV 阈值**：`lower=(5,120,120)`，`upper=(25,255,255)`（OpenCV 的 H 范围是 0~179）。
**最小轮廓面积**：800 像素。
**形态学**：5×5 全 1 核，先开运算去小白点，再闭运算补目标内部小洞。
**中心点算法**：`cv2.moments` 求轮廓矩，`u = m10/m00`，`v = m01/m00`；
当 `m00 == 0`（轮廓退化）时退回外接矩形中心，并把 `method` 记成 `bbox`。
**多候选规则**：所有通过面积阈值的候选按**轮廓面积降序**排序，取最大的一个作为本帧目标。
**未检测到目标**：`detected=False`，`u=v=area=0`，并在图上写 `NO TARGET DETECTED`。

6 张测试图（`src/target_vision/images/`）实测结果：

| 图片 | 尺寸 | u | v | area | 候选数 |
|---|---|---|---|---|---|
| 01_orange_ball_blue | 1200×1800 | 765.4 | 680.9 | 164162 | 3 |
| 02_orange_golf_grass | 1200×803 | 522.5 | 361.3 | 27485 | 6 |
| 03_orange_two_balls | 1200×900 | 843.9 | 570.5 | 135800 | 2 |
| 04_orange_dark | 1200×800 | 905.2 | 358.7 | 33876 | 3 |
| 05_orange_ball_small | 1200×1800 | 654.2 | 825.5 | 17720 | 1 |
| 06_no_target | 1200×420 | — | — | — | 0（未检测到） |

`03_orange_two_balls` 里有两个球，程序按面积选中较大的右边那个（135800 > 114699），
符合「多候选按面积排序取最大」的约定。

**素材来源**：图片来自 Pexels 免费图库（可免费商用），原始链接：

- 01：https://www.pexels.com/photo/38482716/
- 02：https://www.pexels.com/photo/12811452/
- 03：https://www.pexels.com/photo/30150862/
- 04：https://www.pexels.com/photo/33399037/

`05_orange_ball_small.jpg` 由 01 缩小到 1/3 后贴到灰画布上（制造「目标较小」的场景）；
`06_no_target.jpg` 从 01 的纯蓝背景区域裁出（画面里没有橙色物体，用来验证失败分支）。

## 任务 2：可视化与参数对比

**标注内容**（见 `02_结果可视化.png`）：目标轮廓（绿）、外接矩形（黄）、中心点十字（红）、
坐标文字 `u=..., v=...`、面积 `area=...`，顶部还印了本次用的 HSV 和面积阈值。
未检测到时图上写 `NO TARGET DETECTED` 与 `u = None, v = None`，不会让人误以为目标在左上角。

**四组参数对比**（见 `02_参数对比.png`，每组只改一个参数）：

| 组 | 改动 | 结果变化 |
|---|---|---|
| A | HSV 的 V 下界 `120 → 90`（在压暗到 45% 的图上） | 改前**漏检**；改后检出，中心 (766,680) 与原图 (765,681) 相差约 1 像素 |
| B | 最小面积 `800 → 30000`（02 图） | 改前检出（球 27485 像素）；改后球被当噪声筛掉 → **漏检** |
| C | 形态学 `开+闭 → 不做`（02 图，min_area 放宽到 200） | 轮廓数 207 → **2149**，掩膜白像素 60857 → 98941（+63%），中心点被拉偏（v 361 → 418） |
| D | V 下界 `120 → 40`（04 弱光图） | 面积 33876 → **296432（8.8 倍）**，杯子和背景被并进来，中心点跑到别处 → **误检** |

**误检案例**：04 图把 V 下限放到 40，深色杯子和背景的 V 也在 40 以上，掩膜连成一片，
最大轮廓面积暴涨到 29 万，中心 (559,317) 已经不在球上了。
**漏检案例**：B 组——面积阈值设得比目标本身还大，颜色范围再准也检不出来；
以及 A 组改前——弱光下目标 V 掉到 114，被 `V>=120` 整块切掉。

**像素坐标 ≠ 真实世界坐标**：`u` 向右增大、`v` 向下增大、原点在图像左上角，
单位是像素。它只描述目标在**画面**里的位置，跟机器人在场地里的位置没有直接换算关系。
要变成米制坐标需要相机内参标定 + 外参（相机相对机器人/场地的位姿），还要知道目标实际尺寸，
这些本周都没做，也不该在控制里直接用像素去驱动底盘。

## 任务 3：ROS2 通信

**消息包**：`target_interfaces`（ament_cmake 类型），消息 `TargetPosition.msg`，四个字段：

```
bool detected      # 本帧是否检测到目标
float32 u          # 目标中心横坐标（像素）
float32 v          # 目标中心纵坐标（像素）
float32 area       # 轮廓面积（像素平方，近似值）
```

约定：`detected=False` 时 `u`、`v`、`area` 一律为 `0.0`，判断有效性只看 `detected`，
不能把「没检测到」当成「目标在图像左上角」。

**话题名**：`/target_position`，类型 `target_interfaces/msg/TargetPosition`。

**发布节点** `target_vision/detector_node`：

- 按固定频率（默认 1.0 Hz）逐张循环处理 6 张测试图，每处理一张发一条消息；
  数据来源是包内 `share/target_vision/images/`，通过 `ament_index_python` 定位。
- 阈值全部做成 ROS2 参数（`lower_h/s/v`、`upper_h/s/v`、`min_area`、`publish_rate`、`image_dir`），
  可以 `ros2 param set` 运行时改，不用重编译。
- 检测逻辑与任务 1 **复用同一个模块** `target_vision/detector.py`，保证「脚本看到的」和
  「发出去的话题」用的是同一套代码。

**订阅节点** `target_vision/listener_node`：订阅 `/target_position`，打印 `detected / u / v / area`；
`detected=False` 时额外标一句「本帧无目标，坐标无效」。

**实际检测结果如何接入**：发布节点不是发写死坐标，每次 `tick()` 都调用 `detect_target()`
拿到当帧的检测结果再填消息，因此消息里的 `u/v/area` 与任务 1 打印的数字完全一致
（对比 `01_检测输出.png` 与 `03_pub_sub分屏.png` 即可看到 765.4/680.9/164162 一一对应）。

**实测**：连续发布 18 条，订阅端收到 18 条，其中 `detected=True` 15 条、`detected=False` 3 条
（每循环到 `06_no_target.jpg` 就发一条 False）。

## 问题与解决过程

**问题：`detected=False` 这条分支一开始根本没被测到。**

第一版只准备了 5 张图，全都是能找到橙色目标的。跑通发布/订阅后发现 18 条消息全是
`detected=True`——也就是说细则要求的「正确表达未检测到目标的情况」其实一次都没被执行过，
代码里那段 `else` 分支是死代码。

排查：先确认逻辑上确实有 else 分支，再回头看测试集的构成，发现全是「有目标」的图，
没有任何一张能触发失败路径。

解决：从 01 的纯蓝背景区域裁出一张 1200×420 的 `06_no_target.jpg`（画面里没有橙色物体），
加进测试集并重新 `colcon build`（data_files 里列了 images/*.jpg，新增文件要重新编译才会被装进 share）。
之后就会周期性地出现：

```
发第 6 条 | 06_no_target.jpg | detected=False u=0.0 v=0.0 area=0.0
收到第 6 条 | detected=False u=0.0 v=0.0 area=0  <-- 本帧无目标，坐标无效
```

**其它踩过的坑**（都在环境层面，一并记下）：

1. WSL 里装的 ubuntu-base 是最小系统，**没有 ca-certificates**，apt 用 https 源会报
   `Certificate verification failed`；必须先用 http 源把证书装上，再切 https。
2. 清华 ubuntu 源在 WSL 的出口 IP 上返回 **403 Forbidden**（Windows 下同一个源却是 20 MB/s），
   换阿里云 http 源解决。
3. `ros2 --install -d Ubuntu-22.04` 要从 `raw.githubusercontent.com` 拉发行版清单，本机 DNS 解析不了，
   于是改成 `wsl --import` 导入 ubuntu-base rootfs，绕开 GitHub。
4. 测试脚本跑完没清干净，WSL 里残留了十几个 `detector_node` 进程，导致订阅端一下子收到几十条消息，
   截图时「姓名/时间」被滚出屏幕；后来按 PID 强杀才恢复。

## 仍未解决的问题

**两个同色目标粘在一起时会被算成一个轮廓。**

`04_orange_dark.jpg` 里马克杯中堆着 4 个橙色球，它们的边缘在掩膜里是连通的，
`findContours` 把它们算成**一个**连通域，于是只输出一个中心点 (905,359) 和一个面积 33876——
而人眼能看到 4 个球。同样的问题出现在 `03_orange_two_balls`：虽然这次恰好是两个球分离的，
但如果它们挨在一起就会合并。

我目前的处理只是「按面积取最大」，并没有真正把它们分开。想到的方向：

- 先做几次 `cv2.erode` 把细连接腐蚀断，再 `findContours`，最后把面积按腐蚀次数粗略还原；
- 或者用分水岭（watershed）以每个球的亮部为种子分割；
- 也可以用距离变换 + 局部极大值找球心，再按球心分配像素。

但这几种都超出本周「传统图像处理入门」的范围，我还没能验证哪个在当前光照下更稳，
所以先如实记在这里，没有硬凑一个看起来能用的结果。

**另外还有一个没完全想通的点**：HSV 阈值对光照的依赖很直接——同一目标压暗到 45%，
V 从 232 掉到 114，就必须重调 V 下限。我知道可以先用 gamma 或 CLAHE 提亮再转 HSV，
但「提亮到什么程度」缺少客观判据，目前只能靠人工看图，这块还没形成稳定的做法。
