## 任务 1：颜色目标检测
- **目标颜色**：橙色（测试对象为橙色盘子、胡萝卜）。
- **HSV 阈值**：下限 `[5, 100, 100]`，上限 `[22, 255, 255]`。
- **最小轮廓面积**：500 像素。
- **多目标选择规则**：按轮廓面积从大到小排序，选择最大的轮廓作为唯一目标。
- **中心点计算方法**：使用 `cv2.moments` 计算轮廓矩。若 `m00` 不为 0，则通过 `u = m10/m00`, `v = m01/m00` 计算中心点；若 `m00` 为 0 则跳过。
- **测试图片结果**：
  1. 橙色盘子：成功检测，中心点 u=596, v=396，面积约 298334。
  2. 胡萝卜：成功检测，中心点 u=256, v=206，面积约 30446。
  3. 无橙色物体图：成功输出“未检测到目标”，未使用未初始化坐标。
- **算法失效情况分析**：
  1. 光照剧烈变化（过暗或过曝）会导致 HSV 像素值偏移，超出设定阈值从而漏检。
  2. 背景存在与目标相近的颜色（如黄色纸箱、木桌）时，容易把背景也识别为目标，造成误检。

## 任务 2：可视化与参数对比
- **可视化说明**：在输出图像上使用绿色线条绘制了目标轮廓，用红色圆点标出中心，并用红色文字标注了 `u=xxx, v=xxx`。未检测到目标时终端会明确打印提示。
- **参数对比实验（面积阈值）**：
  - **参数 A（原阈值）**：`min_area = 500`。胡萝卜成功检出（面积 30446）。
  - **参数 B（修改后）**：`min_area = 50000`。胡萝卜因为面积不足被过滤，终端输出“未检测到目标 (面积太小)”。
  - **现象分析**：这说明最小面积阈值能有效过滤噪点，但如果设置过大，会导致距离较远的小目标“漏检”。
- **坐标约定说明**：图像左上角为 `(0,0)`，u（x）向右增大，v（y）向下增大。像素坐标只表示目标在图像中的二维位置，**不是机器人的世界坐标（米制距离）**。若需控制机器人，必须经过相机内参标定和外参转换。

## 任务 3：ROS2 通信
- **消息定义**：创建了 `target_interfaces` 接口包，定义了 `TargetPosition.msg`，包含 `bool detected`, `float32 u`, `float32 v`, `float32 area` 四个字段。
- **通信流程**：
  1. 发布者节点 (`publisher_node.py`) 使用 OpenCV 读取并处理测试图片，将检测到的真实 u、v、area 数据以及 detected=True 发布到 `/target_position` 话题。若未检测到，则发布 `detected=False` 且 u,v,area 为 0。
  2. 订阅者节点 (`subscriber_node.py`) 订阅 `/target_position` 话题，并实时打印接收到的消息。
- **数据流说明**：输入是一张 BGR 图片 -> 经过 HSV 阈值与轮廓筛选 -> 计算出中心像素坐标 -> 填入 `TargetPosition` 消息体 -> 通过 ROS2 话题发布 -> 订阅端接收并打印。

## 问题与解决过程
1. **WSL2 环境冲突问题**：起初在默认安装的 Ubuntu 26.04 上强装 ROS2 Humble，导致 `libpython3.10` 依赖冲突。**解决**：使用 `wsl --install -d Ubuntu-22.04` 重新安装了原生支持 ROS2 Humble 的 22.04 子系统。
2. **ROS2 密钥拉取超时**：在配置 ROS2 源时，从 GitHub 拉取公钥一直超时（`NO_PUBKEY` 错误）。**解决**：使用中科大和清华的国内镜像源，并在 `sources.list` 中增加 `[trusted=yes]` 属性绕过密钥验证，成功安装。
3. **相对路径读取图片失败**：ROS2 节点运行路径与脚本所在路径不同，导致 `cv2.imread` 读不到图片。**解决**：将图片放置于工作空间根目录下，并在代码中使用 `test2.png` 同级相对路径读取。
