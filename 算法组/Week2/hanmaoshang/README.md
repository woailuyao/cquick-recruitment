## 任务 1：颜色目标检测
- **目标颜色**：足球（黑白相间）。
- **HSV 阈值**：由于足球是黑白色，饱和度（S）极低，我们采用提取低饱和度区域的方法：`lower = [0, 0, 150]`，`upper = [180, 40, 255]`（V 下限设为 150 是为了过滤掉暗色的阴影）。
- **最小轮廓面积**：5000（用于过滤环境中的小噪点）。
- **中心点计算方法**：使用图像矩（`cv2.moments`）计算目标重心。如果计算出的面积为 0，则退化为使用外接矩形的几何中心。
- **多候选目标选择规则**：如果画面中有多个符合条件的轮廓，按面积从大到小排序，选取面积最大的作为最终目标。如果未检测到目标，输出“未检测到目标”并置 `detected=False`，不输出无效坐标。
- **测试图片结果**：成功在 3 张图片上检测到足球。其中蓝底图片中，中心点像素坐标为 `(u=635, v=627)`，面积约 57430。

## 任务 2：可视化与参数对比
- **参数 A（MIN_AREA = 5000）**：正常阈值下，能够完整提取足球轮廓并画出红框，中心点稳定在球心。
- **参数 B（MIN_AREA = 800000）**：故意将最小面积阈值调得极大。由于足球的实际像素面积（约 5-15 万）远小于 80 万，导致目标被当成噪声过滤，图片中未画出红框，发生**漏检**。这证明了最小面积参数必须根据实际相机分辨率和目标大小合理设置。
- **误检案例**：在浅绿色背景下，由于背景颜色饱和度低，常规的 HSV 过滤会把整片浅绿背景当成目标，生成覆盖全图的巨大错误红框。
- **坐标概念理解**：图像左上角为原点 `(0,0)`，u 向右增大，v 向下增大。像素坐标仅表示目标在图像中的位置，不能直接当成机器人的真实世界坐标，必须经过相机标定和坐标转换才能用于底盘控制。

## 任务 3：ROS2 通信
- **消息字段**：`bool detected`, `float32 u`, `float32 v`, `float32 area`。
- **话题名**：`/target_position`。
- **发布/订阅流程**：
  1. 发布者节点（publisher）读取静态图片（由定时器每秒循环读取）。
  2. 进行 HSV 过滤、形态学闭运算填补黑白斑块，并通过图像矩计算坐标。
  3. 将结果封装成自定义的 `TargetPosition` 消息，发布到 `/target_position` 话题。
  4. 订阅者节点（subscriber）订阅该话题，接收并打印检测到的中心点坐标和面积。
- **实际检测接入**：最终版本已将真实的 OpenCV 检测结果接入发布节点，验证截图中终端输出的坐标 `(u=629, v=621)` 与视觉算法计算完全一致。

## 问题与解决过程
- **WSL 安装卡死**：初次安装 WSL 时卡在 OOBE 界面，系统报错无法创建文件。通过以管理员身份执行 `wsl --shutdown` 强制停止，并手动清理 `%LOCALAPPDATA%\Packages` 下的残留文件夹，最终成功重装。
- **ROS2 编译找不到依赖**：在编译视觉包时报错找不到 `interfaces` 包。原因是单独编译了 `vision_pkg`，导致接口依赖丢失。使用 `colcon build --packages-select interfaces vision_pkg` 同时编译两个包后解决。

## 仍未解决的问题
- 足球具有黑白相间的纹理，且受光照阴影影响，传统单一 HSV 阈值极易导致球体被分割成碎块，虽然通过大尺寸形态学闭运算能强行连通，但边缘不够精确。
- 对光照变化和背景颜色非常敏感（如浅绿底误检）。后续需要学习使用深度学习目标检测模型（如 YOLO）来替代传统颜色阈值法。
