## 任务 1：颜色目标检测
- **目标颜色**：红色
- **HSV 阈值**：
  - 红色低阈值段：`lower_red1 = [0, 150, 120]`，`upper_red1 = [15, 255, 255]`
  - 红色高阈值段：`lower_red2 = [170, 150, 120]`，`upper_red2 = [180, 255, 255]`
- **最小面积**：设置了 500 像素的过滤阈值，以排除画面中的细小噪点。
- **中心点计算方法**：使用 `cv2.moments` 计算轮廓矩，处理了 `m00` 为 0 的异常情况。通过 `m10/m00` 得到 u，`m01/m00` 得到 v。
- **测试图片结果**：成功检测到目标，中心点坐标为 `u=221, v=348`。如果找不到目标，终端会明确输出“未检测到任何轮廓”。

## 任务 2：可视化与参数对比
- **参数 A/B 对比**：
  - **参数 A（初始阈值）**：S 和 V 的下限设得过低（如 50），导致画面左侧屋檐的暗红色被误检，绿框把屋檐也圈了进去。
  - **参数 B（优化阈值）**：将 S 和 V 的下限提高到 150 和 120，成功过滤掉了暗色背景，精准框选了灯笼本体。
- **误检/漏检案例**：若环境光照不足，灯笼红色的饱和度会下降，导致漏检（无法识别）；若背景有高饱和度的红色杂物，会发生误检。
- **像素坐标说明**：像素坐标 `(u, v)` 是以图像左上角为原点，向右为 u 轴，向下为 v 轴。它不是真实世界坐标或机器人坐标。要将其转化为机器人的运动指令，还需要相机标定矩阵和几何转换。

## 任务 3：ROS2 通信
- **消息字段**：`bool detected`（是否检测到）, `float32 u`（横坐标）, `float32 v`（纵坐标）, `float32 area`（面积）。
- **话题名**：`/target_position`
- **发布/订阅流程**：
  1. 发布节点 `publisher.py` 读取图片进行真实视觉检测，将结果填入 `TargetPosition` 消息并发布。
  2. 订阅节点 `subscriber.py` 监听该话题，接收并打印数据。
- **实际检测结果如何接入**：在 `publisher.py` 中集成了 OpenCV 的完整检测逻辑，通过定时器每 2 秒处理一次图片，将真实检测到的 `u=217.0, v=346.0` 以及面积通过 ROS 2 发出，接收端完美同步收到，验证了通信稳定性。
