# 测试照片（我自己拍的）

这 4 张是我用手机拍的，**未加滤镜、未做颜色处理**，直接放进仓库。
目标物体是**玻璃罐上的蓝色硅胶杯套**（不是足球，但同样是"指定颜色的目标"）。

| 文件 | 尺寸 | 场景 | 为什么拍它 |
| --- | --- | --- | --- |
| `my_01_clear.png` | 486×648 | 正常室内光，花岗岩台面，白瓷砖背景 | 基准场景，检验正常情况能不能套住 |
| `my_02_two_blue.png` | 486×648 | 旁边放了一个蓝色玩具盒 | 造"同色干扰物"，检验会不会选错/粘连 |
| `my_03_occluded.png` | 486×648 | 左侧被白纸挡住 | 造遮挡，检验中心点会不会偏 |
| `my_04_backlit.jpg` | 1773×2364 | 逆光（对着窗户），杯套是深藏青 | 造"暗 + 低 V"，检验 V 下界；顺便暴露分辨率对 u/v 的影响 |

## 拍摄时的取舍

- **不修图、不加滤镜**：颜色一变，HSV 阈值就全废了；评审也要能看到"原始输入长什么样"。
- **故意留干扰**：`my_02` 的蓝色玩具盒、`my_03` 的白纸、`my_04` 的绿色背景，
  都是**故意**留在画面里的——真实场景不会给你一块纯色背景板，
  能把这些干扰暴露出来，比"四张全对"更有价值。
- **分辨率不统一**：前 3 张是压过的 486×648，第 4 张是原图 1773×2364。
  这不是失误，正好用来说明 `u, v` 是**像素坐标**、跟分辨率绑定（见 README 2.5）。

## 和代码的关系

默认阈值 `(90,20,25)~(130,255,255)` 就是在这 4 张上标定出来的：
先跑 `python3 tools/tune_hsv.py` 看蓝色落在哪个 H、S/V 分位数多少，再定上下界。
具体过程写在 README 的「问题与解决过程」第 2 条。

```bash
# 重新跑一遍（在项目根目录）
python3 tools/run_batch.py            # 默认就是本目录
python3 tools/sweep_params.py         # 3 组参数对比
```
