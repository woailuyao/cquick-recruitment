## 任务 1：颜色目标检测

**输入**：`data/images/photos/` 里的 5 张手机照片（4 张有蓝色杯套，1 张只有木桌面）。
**输出**：每张图里目标中心的像素坐标 `(u, v)` 和轮廓面积；找不到目标就输出"未检测到"。

**处理步骤**（每一步的输出，就是下一步的输入）：

1. **读图**：照片路径 → 一张彩色图。如果读不出来，直接报"读取失败"，不往下算。
2. **转 HSV**：彩色图 → HSV 图。RGB 里颜色和亮度混在一起，同一个杯子在亮处和暗处数值差很多；
   HSV 把颜色和亮度分开，设阈值才稳定。
3. **生成 mask**：HSV 图 → 黑白图（mask）。落在蓝色范围内的像素变白，其它变黑。
   mask 回答的就是一个问题："哪些像素是蓝色的"。
4. **去噪**：mask → 更干净的 mask。开运算擦掉孤立的小白点（噪点），闭运算补上被反光切开的小缺口。
5. **找轮廓**：mask → 几块连通的白色区域，每一块就是一个"候选目标"。
6. **筛选**：候选 → 1 个目标。面积小于 800 像素的丢掉，剩下的取面积最大的那个。
7. **算中心**：目标区域 → `(u, v)`。
8. **画图**：原图 + 中心点 → 标注图 PNG。

**用的参数**

| 项目 | 值 |
| --- | --- |
| 目标颜色 | 蓝色（杯套） |
| 图片尺寸 | 3 张 486×648，2 张手机原图（2364×1773、1773×2364） |
| 目标中心大致位置 | u 在 280~600 之间，v 在 360~1280 之间 |
| HSV 下界 | `(90, 20, 25)` |
| HSV 上界 | `(130, 255, 255)` |
| 最小面积 | 800 像素 |
| 多个候选时 | 取面积最大的 |
| 中心点算法 | 轮廓重心（`cv2.moments`） |

> 为什么 S 下界只有 20：网上教程一般写 `S ≥ 90`，但我量了自己照片里蓝色区域的饱和度，
> 中位数只有 31（照片里的蓝是浅灰蓝，不是纯色块）。按 90 设，2 张照片直接漏检。

**中心点怎么算**

把目标区域里的像素当成一张纸，算它的**重心**。OpenCV 里用 `cv2.moments()`：

```python
M = cv2.moments(轮廓)
u = M["m10"] / M["m00"]      # m00 就是这块区域的面积
v = M["m01"] / M["m00"]
```

如果面积接近 0（轮廓退化成一条线），除法会出错，所以先判断，再退回用外接矩形的中心。

**有多个候选怎么办**

取面积最大的。理由是离得近的目标在画面里本来就大，而噪点和碎片都很小。
但这条规则会出错，`my_02` 那张就是例子（见任务 2 的误检）。

**没检测到时怎么处理**

- 输出 `detected = false`
- `u = v = 面积 = 0`
- 图上打红色横幅 `NO TARGET DETECTED`

⚠️ `(0, 0)` 也是图像左上角的合法坐标，所以**必须先看 `detected`**，不能直接拿 `u, v` 用。

**测试结果**

| # | 照片 | 场景 | 检测到 | u | v | 面积 | 说明 |
| --- | --- | --- | --- | ---: | ---: | ---: | --- |
| 1 | `my_01_clear` | 正常室内光 | ✅ | 280.5 | 374.5 | 37072 | 框得准 |
| 2 | `my_02_two_blue` | 旁边有蓝色玩具盒 | ✅ | 288.1 | 368.3 | 124384 | 两个物体粘一起，中心不准 |
| 3 | `my_03_occluded` | 被白纸挡住 | ✅ | 299.2 | 359.4 | 30730 | 框住了，中心略偏 |
| 4 | `my_04_backlit` | 逆光，深藏青 | ✅ | 599.6 | 1274.7 | 608049 | 框得准 |
| 5 | `my_05_no_target` | 木桌面，没有蓝色 | ❌ | 0 | 0 | 0 | 正确报"没检测到" |

**什么情况下会失败**

- 两个同色物体挨在一起（`my_02`）：mask 连成一片，只算出一个轮廓。
- 目标颜色比阈值淡：S 门槛高了就整块被排除 → 漏检。
- 目标太暗：V 门槛高了也会漏检，甚至转头去框背景里别的蓝色东西 → 误检。
- 遮挡：只剩一半蓝色，中心会往没被挡的方向偏。
- 分辨率变了：`u, v` 是像素，同一物体在 486×648 和 1773×2364 上数值完全不同。

## 任务 2：可视化与参数对比

**输入**：任务 1 检测出的轮廓、中心点和原图。
**输出**：标注好的图片，以及"改哪个参数会让结果怎么变"的结论。

**图上画了什么**

- 绿色：目标轮廓；黄色：外接矩形
- 红点：中心点；左下角写 `u=… v=…`、面积、候选数
- 左上角画坐标轴 `u→` `v↓`，标出 `(0,0)`，说明原点在左上角
- 没检测到时：顶部红色横幅 + 左下角注明"这些 0 是无效值"

结果都在 `output/`：`annotated/` 是标注图，`masks/` 是 mask，`triplets/` 是原图+mask+标注图三联。

**参数对比（每次只改一个）**

| 组 | 只改这个 | 结果 |
| --- | --- | --- |
| A | S 下界 90 → 20 | 90 时 mask 全黑、`my_01` 漏检；20 时检出 (280.5, 374.5) |
| B | V 下界 60 → 25 | 60 时框到右上角天空 (1696, 377)；25 时框住杯套 (599.6, 1274.7) |
| C | 最小面积 800 → 50000 | 50000 时 `my_03` 漏检（它只剩 30730） |

**误检案例**

实验 B：V 门槛调到 60，杯套因为太暗被排除，程序没有报"没找到"，而是框住了右上角
天空和楼房的蓝色区域（`u=1696, v=377`）。图上能看到绿框跑到右上角去了。

**漏检 / 中心偏差案例**

- 漏检：实验 A（S 门槛 90）和实验 C（面积门槛 5 万），都是目标被规则整个切掉。
- 中心偏差：`my_02` 两个物体粘在一起，中心跑到中间；`my_03` 被白纸挡住，中心往右偏。
  这两张 `detected` 都是 `true`，光看这个值发现不了问题。

**像素坐标不是真实世界坐标**

- 原点在图像左上角，`u` 向右增大，`v` 向下增大；
- 单位是像素，不是米、不是角度；
- 同一个杯子拿远一点，`u, v` 就变了，但它在场地上的位置没变。

## 任务 3：ROS2 通信

**输入**：任务 1 得到的 `(detected, u, v, area)`。
**输出**：另一个节点能收到的消息，打印在它的终端里。

**消息**（`cquick_interfaces/msg/TargetPosition.msg`）

| 字段 | 类型 | 含义 | 没检测到时 |
| --- | --- | --- | --- |
| `detected` | `bool` | 这一帧有没有目标 | `false` |
| `u` | `float32` | 中心横坐标（像素） | `0.0` |
| `v` | `float32` | 中心纵坐标（像素） | `0.0` |
| `area` | `float32` | 轮廓面积（像素²） | `0.0` |

**话题和节点**

- 话题名：`/target_position`，类型 `cquick_interfaces/msg/TargetPosition`
- `target_publisher`：读图 → 检测 → 发布
- `target_subscriber`：订阅 → 打印 → 统计条数

**发布/订阅流程**

1. 先发**固定假数据**（`use_fixed_test_data:=true`），只看两个节点能不能通，跟检测算法无关。
2. 通了以后换成**真实检测**（默认模式）：逐张读照片，每张跑一次检测再发。
   实际发出去的是：`my_01 → (280.5, 374.5)`、`my_02 → (288.1, 368.3)`、
   `my_03 → (299.2, 359.4)`、`my_04 → (599.6, 1274.7)`、`my_05 → detected=false`。

**真实检测结果怎么接进去**

```python
result = self.detector.detect(bgr)          # 和任务 1 是同一个函数
msg.detected = bool(result.detected)
msg.u = float(result.u) if result.detected else 0.0
msg.v = float(result.v) if result.detected else 0.0
msg.area = float(result.area) if result.detected else 0.0
self.publisher.publish(msg)
```

关键是 `if ... else 0.0`：**没检测到就写 0**，不能把上一帧的坐标继续发出去。

**怎么跑**

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash

ros2 interface show cquick_interfaces/msg/TargetPosition
ros2 topic info /target_position -v

# 开两个终端，一个发一个收
ros2 run cquick_vision target_publisher
ros2 run cquick_vision target_subscriber
```

**为什么 u、v 不能直接拿去控制机器人**

- 单位是像素，机器人要的是米、角度、速度；
- 一个像素只代表空间里的一条射线，不知道目标离多远；
- `v` 变大只是"目标在画面里更靠下"，不等于"该往后退"。

## 问题与解决过程

**阈值照抄教程，自己拍的照片全漏检**

一开始用 `S ≥ 90`（教程里都这么写），结果 `my_01` 和 `my_03` 的候选数是 0。
排查时写了个小脚本 `tools/tune_hsv.py`，统计照片里"有颜色像素"的分布，
发现蓝色区域的 S 中位数只有 31。把 S 下界降到 20 就正常了。
后来把这件事做成实验 A 放进 README，说明阈值不能照抄。

**`my_02` 显示"1 个候选"，但其实是两个物体**

面积 124384，差不多等于杯套 5 万 + 玩具 7 万，中心点在两者中间。
原因是两个同色物体在画面里挨着，找轮廓时被当成了一整块。
这周没有改算法去切开它们，而是把这个现象写进"会失败的情况"。
教训是：**候选数 = 1，不代表画面里只有一个物体**。
