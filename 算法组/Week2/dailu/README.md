## 三、任务完成情况

### 任务一 · HSV颜色分割与目标中心点检测

- 用了哪几张图：'task1_01.jpg','task1_02.jpg','task1_03.jpg'
- **目标颜色**：橙色（测试使用的是橙色中性笔）
- **HSV 范围**：`lower = (5, 100, 100)`，`upper = (25, 255, 255)`
- **面积阈值**：`100`
- 为什么要这么设：因为测试图 2 中目标距离较远、像素面积较小。若设为 500 会导致漏检，直接忽略掉画面中的橙色笔，设为 100 能有效检出小目标，同时过滤极微小噪点。
- **最小轮廓面积阈值**：100（像素）。
  - **设置依据**：代码中设置 `area > 100` 是为了过滤画面中极微小的噪点。从实际测试看，即使是最小的目标（图2），其实际面积也达到了 4966 像素，远超 100。因此设定 100 作为底线，既能保留小目标（防止漏检），又能剔除碎屑。
- **多候选目标选择规则**：
  先过滤掉面积小于 100 的极小噪点，然后计算剩余轮廓的**长宽比（Aspect Ratio）**。因为笔是细长形状，设定长宽比大于 1.5 才保留；在符合条件的多个轮廓中，保留面积最大的一个。
- **中心点计算方法**：采用外接矩形中心法。先用 `cv2.boundingRect` 获取包围目标的矩形 `(x, y, w, h)`，再计算中心点 `(x+w/2, y+h/2)`，即 `(u, v)` 像素坐标。

### 测试图片结果记录

- 测试图 1（清晰白纸背景）：成功检测，中心坐标约为 `(427, 524)`， 轮廓面积: `39446`。
- 测试图 2（距离远，目标较小）：成功检测，中心坐标 `(668, 1078)`，轮廓面积 `4966`。说明降低面积阈值后小目标也能被识别。
- 测试图 3（存在同色大物体干扰）：成功检测，中心坐标 `(661, 680)`，轮廓面积 `34641`。虽然在输出的那个画面中仍然存在有巨大的黄色海绵球，但通过长宽比过滤，成功排除了球体干扰。

### 失败情况说明

- 误检原因：如果在画面中有其他细长且同色的物体（如另一支橙色笔），算法仅靠“面积最大”可能无法区分。
- 漏检原因：在极端暗光下，笔的明度（V 值）低于 100，会导致无法提取掩膜。
- 遮挡问题：如果笔被其他物体遮挡超过一半，长宽比特征会失效，导致漏检。

### 任务 2：可视化与参数对比

- **结果可视化**：在原图上绘制了绿色轮廓、蓝色外接矩形、红色中心点，并在图像上标注了 `u=..., v=...` 的像素坐标和面积。未检测到目标时，会在图中明确显示 `NO TARGET DETECTED`。
- **参数 A/B 对比**：
  - **参数 A（正常）**：最小面积 2500，成功框出橙色笔。
  - **参数 B（漏检实验）**：将最小面积放大到 7500（或调大 3 倍）。由于笔的面积达不到阈值，被当作噪点过滤，导致图像显示 `NO TARGET`，产生漏检。
- **误检/漏检案例说明**：放宽 HSV 阈值会导致黄球边缘或背景反光被识别为候选轮廓；收紧阈值或调大最小面积会导致真正的目标被过滤掉。
- **坐标概念理解**：图像坐标系原点在左上角，u 向右增大，v 向下增大。像素坐标仅仅代表目标在图像中的位置，**不是机器人世界坐标，也不是米制距离**。若要让机器人运动，必须经过相机标定将像素坐标转换为物理世界坐标，并由控制节点决定如何运动。

### 任务 3：ROS2 通信

- **消息字段**：在 `cquick_interfaces` 包中定义了 `TargetPosition.msg`，包含四个字段：
  - `bool detected`
  - `float32 u`
  - `float32 v`
  - `float32 area`
- **话题名**：`/target_position`
- **发布/订阅流程**：
  1. 发布节点（`vision_publisher`）：接入任务 1 的视觉检测流程，读取图像并计算橙色笔的 u、v 坐标和面积，封装为 `TargetPosition` 消息，以 1Hz 的频率发布到 `/target_position`。
  2. 订阅节点（`vision_subscriber`）：订阅 `/target_position` 话题，接收消息并打印 `detected / u / v / area`。
  3. 使用 `ros2 interface show` 验证了消息定义，使用 `ros2 topic info` 和 `ros2 topic echo` 验证了话题连接正常，接收端连续接收超过了 10 条消息。

## 问题与解决过程

1. **图片读取失败问题**：最初在 ROS2 节点中运行视觉代码时，图片读取一直失败。排查发现是因为 `ros2 run` 运行时的工作目录在 `~/ros2_ws` 下，而不是代码所在的文件夹。
   - **解决**：在代码中将读取图片的路径修改为相对 `ros2_ws` 的路径，或者在终端中把图片复制到当前执行目录，确保路径正确。
2. **找不到自定义接口包**：修改代码后运行报错 `Unknown package 'cquick_interfaces'`。
   - **解决**：每次编译后或新开终端时，必须执行 `source install/setup.bash` 刷新工作空间环境变量，之后系统成功识别了自定义消息类型。
