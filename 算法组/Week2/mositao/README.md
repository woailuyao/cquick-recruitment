## 任务 1：颜色目标检测

**输入 / 处理 / 输出**：输入是 `data/images/` 下的 BGR 图片（先缩到长边 800）；处理是 `cvtColor → inRange → 形态学 → findContours → 面积过滤 → moments`；输出是 `detected, u, v, area`（终端 + `outputs/detect_result.csv` + `obj*_mask.png`），这些数值随后成为任务 2 的可视化对象和任务 3 的消息内容。

**目标颜色**：按图片分别标定 —— `obj1` 粉色（奶茶杯）、`obj2` 黄色（胶带卷）、`obj3` 黑色（圆柱，黑色没有色相，用亮度 V 上限切分）。

**HSV 阈值与最小面积**（阈值均按该图实测标定；`ranges` 每段为 `(lower, upper)`，多段时逐段 `inRange` 后按位或合并）：

| 测试图 | lower (H,S,V) | upper (H,S,V) | min_area | 场景 / 难点 |
|---|---|---|---|---|
| obj1.jpg | (0, 90, 110) 与 (170, 90, 110) | (8, 255, 255) 与 (179, 255, 255) | 3000 | 粉色跨 H=0/180，单段只能圈住部分杯身 |
| obj2.jpg | (10, 120, 90) | (25, 255, 255) | 3000 | 与米色桌角 H≈15 接近，靠饱和度区分（胶带 S≈150，桌角 S≈103） |
| obj3.jpg | (0, 0, 0) | (179, 255, 100) | 3000 | 黑色目标 V≈35~75；浅色地面 V≈200+、木门 V≈123+，用 V 上限切开 |

> 两点取值原因：
> 1. **obj1 用两段区间**：粉色的色相绕过 H=0/180 两端。实测单段 `[0,8]` 时 `area=14364`、中心 `v=374.0`（只圈住上半截）；改成 `[0,8] ∪ [170,179]` 后 `area=21767`、中心 `v=391.2`，轮廓完整贴合杯身。
> 2. **obj3 用 V 上限**：黑色目标没有稳定色相，实测目标 V 中位 38~51、最亮处约 75；地面 V≈200，木门 V 最低约 123。V 上限取 100 时目标与背景一分为二，取 160 就会把木门也圈进来（见任务 2 对比 1）。

**中心点计算方法**：用轮廓矩 `cv2.moments`，`u = m10/m00`、`v = m01/m00`；`m00 == 0` 时按“未检测到目标”处理并返回 0，不使用未初始化坐标。多个候选时按轮廓面积降序取最大者。

**实测结果**（`python src/task1.py`，CSV 见 `outputs/detect_result.csv`）：

| 图片 | 尺寸（长边缩到 800 后） | detected | u | v | area |
|---|---|---|---|---|---|
| obj1.jpg | 600×800 | true | 292.9 | 391.2 | 21767 |
| obj2.jpg | 600×800 | true | 287.9 | 303.6 | 46318 |
| obj3.jpg | 600×800 | true | 316.2 | 225.9 | 26885 |

三张图都检出目标，坐标各不相同（图像左上角为原点，u 向右、v 向下）。目标在画面中的大致位置：obj1 在画面中下部（杯身中部，v≈391），obj2 在画面中央偏上（胶带卷中心，v≈304），obj3 在画面中上部（圆柱柱身，v≈226）。

**失败处理**：找不到候选轮廓或 `m00 == 0` 时打印「未检测到目标」，`detected=false` 且 `u=v=area=0`；任务 2 的结果图会写 “no target”。可运行 `python src/task1.py --demo-no-target` 现场演示该分支。

**可能失效的情况**：

1. **光照 / 反光**：obj2 胶带顶面被光打亮，S 掉到约 55（低于阈值 120），只有侧壁被圈住；换更强的反光会让轮廓断裂甚至漏检。同一目标换到聚光灯下（`data/extra/obj2_light.jpg`）仍能检出，但面积与中心随之变化——见任务 2 对比 4；更极端的光照（暖光房间那一版旧图）还会把背景木门误检成目标，见任务 2 的「补充案例」。
2. **背景同色**：obj2 的米色桌角 H≈15、S≈103，与胶带 H≈15 只差饱和度；S 下限降到 100 以下就会把桌角圈进来。
3. **黑色目标的亮度边界**：obj3 靠 V 上限区分，阈值卡太紧（V≤60）只圈到最暗的一半（area 掉到 17610、中心偏到 v=235.2）；放太松（V≤160）木门成为第二个候选（12419 像素）。
4. **遮挡**：目标被挡住一部分时，外轮廓面积与矩中心都会偏移。

## 任务 2：可视化与参数对比

**输入 / 处理 / 输出**：输入是原图 + 任务 1 的 `detect()`（同一函数、同一套阈值）；处理是对每张图重新跑检测并画标注，再对 obj3 做三组对比（V 阈值分上限/下限、min_area、开闭运算，每次只改一个参数），并对 obj2 与它的暖光版 `data/extra/obj2_light.jpg` 做对比 4（同一套阈值、只换光照）；输出是 `outputs/obj*_result.png`（每张原图一张标注图）与 `outputs/cmp*_combined.png`（每组对比把 A/B 两张标注图用 `np.hstack` 拼成一张），图中 u/v/area 与任务 1 的 CSV 完全一致。

**可视化**：在结果图上画出目标轮廓、外接矩形、中心红点，并标注 `u=..., v=... A=...` 文字，右下角写「`mositao` + 时间戳」，保存到 `outputs/obj*_result.png`；未检测到时在图上写 “no target”。

**参数对比（每次只改一个参数；对比1~3 用 obj3.jpg，对比4 用 obj2 的原光照/聚光灯两张）**：

| 对比 | 参数 A | 参数 B | 现象 |
|---|---|---|---|
| 对比1 · HSV V 上限 | V≤100：白占比 6.17%，候选 1 个，area 26885 | V≤160：白占比 9.36%，候选 2 个（第二个 12419 像素） | **误检**：亮度放宽后木门成为第二个候选，面积 28872、中心 v 偏到 232.8 |
| 对比1 · HSV V 下限 | V≥0：area 26885，中心 (316.2, 225.9) | V≥80：白占比 0.52%，候选 0 个，detected=false | **漏检**：目标亮度 V≈35~75，被 V 下限整块排除 |
| 对比2 · min_area | 500：候选 3 个（26885 / 1108 / 607） | 3000：候选 1 个（只留目标） | 面积阈值过滤掉地面上的两个小暗斑 |
| 对比3 · 是否开闭运算 | 不做：白占比 6.20%，area 26980，中心 (316.1, 225.5) | 做（开+闭）：白占比 6.17%，area 26885，中心 (316.2, 225.9) | 变化很小（面积 −95 px、中心 <1 px）：这张图掩膜本来就干净，开闭主要抹掉边缘毛刺与孔洞 |
| 对比4 · 光照变化 | obj2 原光照：u=287.9 v=303.6 area=46318，白占比 9.45%，候选 1 个 | obj2 聚光灯近照：u=294.4 v=338.6 area=52864，白占比 10.05%，候选 1 个 | 仍能正确检出、没有误检；但**面积 +14.1%、中心下移 35 px**（v 303.6→338.6）——聚光灯更亮、目标离镜头更近，像素面积与坐标都会变，所以 (u,v)/area 只能在同一光照、同一距离下比较 |

> 说明：对比 3 的差异确实不大，但它是排查“轮廓毛刺/小孔”的标准手段；如果图里噪声更多，开运算会把零星噪点先抹掉，效果会更明显。对比 4 说明：换光照/距离后即使仍能检出，面积和中心也会变，像素坐标不能跨光照直接比较，换场地要重新标定阈值或做尺度归一化。

**补充案例：更极端光照下的一次误检（该照片已替换，仅记录数据）**

上一版光照图（暖光房间、背景有木门）用同一套 obj2 阈值时，确实误检了：

| 情况 | 检测结果 | 候选 |
|---|---|---|
| A · obj2 原光照 | u=287.9, v=303.6, area=46318（目标） | 1 个 |
| B · 暖光版（旧图） | 最大候选变成木门：u=428.7, v=133.9, area=46165；目标只排第二 | 3 个（46165 / 15590 / 3103） |
| B · 把 V 下限从 90 抬到 150 | u≈289.3, v≈421.6, area≈15569（目标恢复） | 1 个 |

原因：暖光下木门的 S≈128、V≈102 都落在阈值内，而“取面积最大候选”的规则就把木门当成了目标——这是典型的**背景同色/同亮导致的误检**，中心点直接漂到背景上。把 V 下限抬到 150 后木门被排除，目标重新成为唯一候选。

> 这张照片在最终提交里已换成聚光灯近照（`data/extra/obj2_light.jpg`），所以 `cmp4_light_combined.png` 展示的是换图后的结果；上面的数值作为一次真实的误检记录保留，用来对照「同一套固定阈值换光照后会怎样」。

**坐标概念**：像素坐标 `(u, v)` 只表示目标在图像里的位置，左上角为原点、u 向右、v 向下；它**不是**机器人世界坐标，也不是米制距离，不能直接发给底盘当运动指令。要得到场地/机器人坐标还需相机标定和坐标转换（本周不要求）。

## 任务 3：ROS2 通信

> ✅ 状态：已在 WSL2 Ubuntu 22.04.5 + ROS2 Humble 实测通过，发布端与订阅端同时运行，订阅端连续收到 12 条消息。

**输入 / 处理 / 输出**：输入是 `data/images/` 的图片与任务 1 的检测结果（`detected/u/v/area`）；处理是逐张检测 → 填 `TargetPosition` → 以 1 Hz 发布到 `/target_position`；输出是话题上的消息流，订阅端打印 `detected/u/v/area`，终端窗口即截图 `03_pub_sub分屏.png`。

任务 3 提供两种等价实现，检测逻辑与任务 1 相同、输出数值一致：

| 实现 | 入口 | 说明 |
|---|---|---|
| 单文件双角色 | `python3 src/task3.py --role pub` / `--role sub` | 便于逐任务查看，文件即任务 3 |
| ROS2 包 | `ros2 run vision_pubsub detector_node` / `subscriber_node` | 标准 `ros2 run` 入口 |

**消息设计**（`src/target_interfaces/msg/TargetPosition.msg`，ament_cmake 接口包）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `detected` | bool | 本帧是否检测到目标 |
| `u` | float32 | 目标中心横坐标（像素） |
| `v` | float32 | 目标中心纵坐标（像素） |
| `area` | float32 | 目标轮廓面积（像素平方，近似值） |

**节点**：

- 发布端：读取 `data/images/` 图片 → 任务 1 的检测逻辑 → 以 1 Hz 循环发布 `TargetPosition` 到 `/target_position`（数据来自真实检测，不是写死坐标）；未检测到时发 `detected=false, u=v=area=0`。
- 订阅端：订阅 `/target_position`，打印 `detected / u / v / area`。

**实测结果**：发布端 1 Hz 循环，订阅端连续收到 12 条：

| 图片 | 订阅端打印 |
|---|---|
| obj1.jpg | detected=True u=292.9 v=391.2 area=21767.0 |
| obj2.jpg | detected=True u=287.9 v=303.6 area=46318.5 |
| obj3.jpg | detected=True u=316.2 v=225.9 area=26885.0 |

（area 的小数位来自 float32 存储，例如 21767 存成 21767.0、46318 存成 46318.5；u、v 与任务 1 完全一致。）

```bash

```

真实的发布/订阅仍以 WSL + ROS2 里的运行为准（见上面的实测结果与截图）。

**为什么 u、v 不能直接当运动指令**：像素坐标受相机内参、安装高度与角度、目标距离影响，同一场地坐标在不同画面里会得到不同 (u, v)；必须经过相机标定与坐标变换才能映射到机器人坐标，并由控制模块决定运动。

## 问题与解决过程

1. **本机是 Windows，没有 ROS2 Humble 环境**：ROS2 Humble 需要 Ubuntu 22.04。解决：装 WSL2 + Ubuntu 22.04（发行版虚拟磁盘放 D 盘）。
2. **`wsl --install` 卡住无进展**：先用 `dism /online /enable-feature` 本地启用 WSL 与虚拟机平台两个功能（不依赖联网），再用 WSL 3.0.3 完整 MSI（wsl.3.0.3.0.x64.msi）装内核与运行时，成功。旧内核 MSI（wsl_update_x64.msi）因 LaunchCondition 不匹配 Windows 11 24H2 而失败，加 `WSL_INSTALLING=1` 可绕过但仍缺 wslservice。
3. **OpenCV 读中文路径失败**（沿用第 1 周）：用 `io_utils.py` 的 `np.fromfile + cv2.imdecode` 绕过。
4. **合成测试图说服力弱**：最初两张蓝色目标是程序合成图，检测结果与第三张几乎相同（同一个 u、v），无法说明算法在真实场景下的表现。解决：换成三张手机实拍图（粉色杯、黄色胶带、黑色圆柱），三张坐标各不相同。
5. **粉色目标只能圈住一半**：粉色色相绕过 H=0/180，单段 `inRange` 漏掉另一半。解决：`detect()` 改为支持多段区间（逐段 `inRange` 后取并集），obj1 用 `[0,8] ∪ [170,179]`。
6. **黄色胶带与米色桌角色相几乎相同（H≈15）**：靠饱和度分开（胶带 S≈150、桌角 S≈103），S 下限取 120；同时也说明这类背景一旦变亮就会误检。
7. **黑色目标不能按色相找**：黑色没有稳定色相（实测目标 H 乱跳、S≈0~20），只能按亮度 V 上限切分；V 取 100 时干净；上限放到 160 会把木门带进来，下限抬到 80 又会把目标整块排除——这些正好成了任务 2 对比 1 的两组素材。
8. **没有图形界面时怎么截真实终端图**：用 conhost 起真实控制台窗口执行命令，再按窗口句柄 `PrintWindow` 抓图，窗口内先打印姓名与系统时间；截图完成后关闭窗口，不留在桌面。
