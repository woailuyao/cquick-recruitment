## 一、本周目标

第 1 周你学会了读取一张图片、转换颜色空间和做阈值分割。但真实机器人比赛中，摄像头会不断产生新图像，视觉程序需要持续处理，并把目标位置交给其他节点。

本周要走通这条最小视觉链路：

```text
摄像头图像 / 测试图片
       ↓
OpenCV 颜色分割与轮廓筛选
       ↓
目标中心点（像素坐标 u、v）
       ↓
结果图像标注 + 终端输出
       ↓
ROS2 话题发布目标信息
       ↓
另一个节点订阅并打印目标位置
```

本周不要求训练 YOLO，不要求真实机器人运动，也不要求把像素坐标直接当成机器人坐标。重点是：**从图像中提取一个可解释的目标位置，并通过 ROS2 稳定传出去。**

| 任务 | 对应链路环节 | 干什么 |
| --- | --- | --- |
| 任务 1 | 视觉算法 | 用 HSV 阈值与轮廓检测找到指定颜色目标，输出中心点 |
| 任务 2 | 结果验证 | 在图像上画出轮廓、中心点和坐标，分析参数对检测的影响 |
| 任务 3 | 节点通信 | 定义目标位置消息，发布检测结果并由订阅节点打印 |

> ⚠️ 本细则只给流程与验收要求，不提供现成完整代码。允许查文档、教程和问 AI，但必须能解释检测逻辑、坐标含义和消息字段。

## 三、考核任务清单

### 任务 1：HSV 颜色分割与目标中心点检测（40 分）

**要做什么**：从一张测试图片中找到指定颜色的目标，输出目标中心的像素坐标，并说明算法在哪些情况下会失效。

#### 1.1 算法流程

```text
读取 BGR 图像
    ↓
转换到 HSV
    ↓
根据颜色范围生成二值掩膜（mask）
    ↓
形态学处理（可选，但建议尝试）
    ↓
提取外轮廓
    ↓
按面积等条件筛选目标
    ↓
计算目标中心点 (u, v)
```

#### 1.2 必须实现的功能

- 读取图片并检查是否成功；
- 使用 HSV 颜色范围生成二值 mask；
- 找到轮廓，并用面积阈值过滤明显噪声；
- 对筛选出的目标计算中心点坐标；
- 如果没有找到目标，输出明确的“未检测到目标”，不能使用未初始化的坐标；
- 如果检测到多个候选目标，至少按轮廓面积排序或说明最终选择规则。

中心点可以通过轮廓矩计算获得。若使用矩计算，需处理面积或 `m00` 为 0 的情况。也可以先用外接矩形中心，但必须在 README 说明所用方法。

#### 1.3 统一验收规则

为了让不同成员结果可比较，请在 README 写明：

- 你选择的目标颜色；
- HSV 阈值上下界；
- 最小轮廓面积；
- 多个候选目标时如何选择；
- 图片尺寸与目标实际中心大致位置。

**完成标准：**

- [ ] 对至少 3 张测试图片运行检测；
- [ ] 至少 2 张图片能检测到目标并输出 `(u, v)`；
- [ ] 目标不存在时有正确的失败提示；
- [ ] 能解释 HSV 阈值、轮廓面积筛选、中心点计算各自的作用；
- [ ] 能指出至少 2 个失败原因，例如光照变化、反光、背景同色、目标遮挡。

**截图要求：**

1. 一张成功检测图的终端输出；
2. 至少两张测试图的检测结果或汇总；
3. 代码运行成功且有姓名、时间戳的截图。

### 任务 2：检测结果可视化与参数对比（30 分）

**要做什么**：把检测到的轮廓、中心点和像素坐标画回原图，并通过改变参数展示检测结果如何变化。

#### 2.1 可视化要求

在输出图像上至少标注：

- 检测到的目标轮廓或外接矩形；
- 目标中心点；
- 中心点坐标文字，例如 `u=320, v=240`；
- 如果没有检测到目标，应在图像或终端中明确显示未检测到。

将结果保存到文件，不能只依赖临时显示窗口。

#### 2.2 参数对比实验

至少完成下面两种对比中的两项：

1. 调整 HSV 的上下界；
2. 调整最小轮廓面积；
3. 对比是否使用形态学开运算 / 闭运算；
4. 对比目标清晰与光照变化图片。

每次只改变一个主要参数，并记录结果。不要只写“效果变好了”，要说明误检、漏检、轮廓完整性或中心点稳定性具体发生了什么变化。

#### 2.3 必须理解的坐标约定

- 图像左上角是原点 `(0, 0)`；
- `u` 或 `x_pixel` 向右增大；
- `v` 或 `y_pixel` 向下增大；
- 像素坐标只表示目标在图像中的位置，**不是机器人世界坐标，也不是米制距离**；
- 若要把像素位置转换成场地坐标或机器人坐标，需要相机标定、几何关系或其他测量信息，本周不要求实现。

**完成标准：**

- [ ] 输出图中有轮廓/矩形、中心点和坐标；
- [ ] 结果文件能正常打开；
- [ ] 至少有两组参数对比；
- [ ] 能说明一个误检案例和一个漏检或定位偏差案例；
- [ ] 能解释像素坐标与真实世界坐标的区别。

**截图要求：**

1. 原图与标注图对比；
2. 参数 A / 参数 B 的检测结果对比；
3. README 中的参数记录与现象分析。

### 任务 3：ROS2 发布目标位置并完成订阅验证（30 分）

**要做什么**：把视觉检测结果通过 ROS2 话题发出去，再由另一个节点接收并打印。为了降低新手环境差异，本周允许先使用固定测试坐标验证通信，再接入任务 1 的实际检测结果；最终验收必须能发布实际检测结果。

#### 3.1 消息设计

新建一个 `ament_cmake` 类型的接口包，定义消息 `TargetPosition.msg`，字段固定如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `bool detected` | `bool` | 本帧是否检测到目标 |
| `float32 u` | `float32` | 目标中心的图像横坐标（像素） |
| `float32 v` | `float32` | 目标中心的图像纵坐标（像素） |
| `float32 area` | `float32` | 目标轮廓面积（像素平方，近似值） |

> 当 `detected=false` 时，`u`、`v`、`area` 应使用约定的默认值（例如 0），并以 `detected` 字段判断该帧是否有效。不能把“没检测到目标”误当成目标位于图像左上角。

#### 3.2 节点要求

- **发布节点**：将检测结果发布到 `/target_position`；使用固定频率或逐张处理测试图片均可，但必须清楚说明数据来源；
- **订阅节点**：订阅 `/target_position`，打印 `detected / u / v / area`；
- 话题名和消息类型必须一致；
- 至少连续发布 10 条消息，订阅端能正确接收；
- 最终版本要把任务 1 的检测输出接入发布节点，而不是只发布写死的坐标。

#### 3.3 建议实施步骤

1. 创建接口包并定义 `TargetPosition.msg`；
2. 在 `package.xml` 和 `CMakeLists.txt` 中声明消息生成与运行依赖；
3. 编译并使用 `ros2 interface show` 检查消息字段；
4. 写发布节点与订阅节点；
5. 先用固定数据验证通信；
6. 再将视觉检测得到的 `detected / u / v / area` 接入发布端；
7. 使用 `ros2 topic info` 和 `ros2 topic echo` 检查话题。

**完成标准：**

- [ ] `ros2 interface show <接口包名>/msg/TargetPosition` 能显示 4 个字段；
- [ ] 发布节点和订阅节点可以同时运行；
- [ ] `/target_position` 类型与消息定义一致；
- [ ] 至少 10 条消息能被订阅端接收；
- [ ] 发布数据来自视觉检测流程，并正确表达未检测到目标的情况；
- [ ] 能解释为什么 `u、v` 不能直接当成机器人运动指令。

**截图要求：**

1. `ros2 interface show` 输出；
2. 发布端与订阅端同时运行的分屏截图；
3. `ros2 topic info /target_position` 输出；
4. 一次实际检测结果对应的消息输出。

## 七、常见问题（FAQ）

**Q1：`ros2 interface show` 找不到自定义消息。**  
A：检查接口包是否按要求配置消息生成依赖；重新编译目标包，并在新终端 source 工作空间的 `install/setup.bash`。

**Q2：发布者和订阅者都在运行，但收不到消息。**  
A：检查话题名、消息类型、发布端日志和 `ros2 topic info /target_position`。两端必须使用同一套已编译的接口定义。

**Q3：颜色分割把背景也检测出来了。**  
A：这属于颜色规则的局限。检查 HSV 阈值、光照、背景颜色和面积过滤；不要只为一张图调参，然后宣称算法对所有场景都有效。

**Q4：为什么中心点有时跳动？**  
A：候选轮廓可能在不同帧之间切换，边缘噪声和遮挡也会改变轮廓。先查看 mask 和轮廓，再分析筛选规则；本周不要求实现跟踪算法。

**Q5：可以把像素坐标直接发给底盘控制吗？**  
A：不可以。像素坐标描述目标在图像中的位置，不能直接等同于场地坐标或机器人坐标。后续需要标定和坐标转换，并由控制模块决定如何运动。

**Q6：没有摄像头怎么办？**  
A：可以使用静态图片完成任务，但必须在 README 标注数据来源。ROS2 发布节点仍需把实际检测结果发出去，可以按约定逐张处理图片；实时摄像头属于加分项。

## 九、下周预告

**第 3 周：摄像头实时输入与鲁棒性测试。**

下一步会把静态图片换成连续图像流，逐步理解：

```text
摄像头 → 连续帧 → 目标检测 → 中心点 / 置信信息
                         ↓
                  可视化与数据发布
```

后续再逐步接触相机标定、目标检测模型（如 YOLO）、多目标处理与坐标转换。当前阶段不要求提前训练模型，先确保基础链路可靠。

> **最后说一句**：视觉组的核心不只是“框出一个物体”，而是稳定地产生可信的数据，并清楚说明这些数据从哪里来、代表什么、有什么局限。第 2 周把检测与通信连起来，就是从单个脚本走向机器人系统的第一步。
