## 任务 1：颜色目标检测
- **输入**：静态测试图片（足球场景图，共 3 张，来源：微博@阿森纳足球俱乐部）。
- **目标特征**：足球（提取球体表面的白色区域，排除阴影、草地及球员）。
- **HSV 阈值设置**：`lower_white = [0, 0, 120]`，`upper_white = [180, 40, 255]`。
  - *解释*：白色的色相（H）和饱和度（S）极低，因此将 H 全包（0~180），S 上限设为 40 以过滤掉彩色背景。亮度（V）下限设为 120，能有效包容处于阴影或暗处的白色球皮。
- **处理步骤**：
  1. 将 BGR 图像转换为 HSV 色彩空间。
  2. 使用 `cv2.inRange` 提取白色生成初始二值掩膜。
  3. 形态学清理：先用 `5x5` 的核进行开运算（去草地反光噪点），再用 `7x7` 的核进行闭运算（填补球体上的黑色接缝）。
  4. 使用 `findContours` 提取外轮廓，并按面积从大到小排序。
  5. 遍历轮廓进行筛选：
     - **面积过滤**：剔除面积小于 1000 的噪点。
     - **形状过滤**：计算外接矩形的宽高比 `aspect_ratio`，仅保留在 `0.75 ~ 1.25` 之间的轮廓（近似正方形，符合足球的圆形特征，排除了细长的白线或白袜）。
  6. 对最终确认的目标，使用图像矩 `cv2.moments` 计算质心 `(u, v)` 作为中心点。
- **测试结果**：
  1. 最初未进行形状过滤，3 张图片，2 张成功输出坐标，1 张**误检**为背景白线与白袜。
  2. 调试后均成功，但框的精准度、完整度有待提高。

## 任务 2：可视化与参数对比
- **参数对比**：
   - **参数 A**（开运算核 `5x5`，闭运算核 `7x7`）：保持了球的边缘，但球体中心的一些黑色块没有被完全填平。
  - **参数 B**（全部增大到 `15x15` 或更大）：闭运算强行把球填成一个实心大圆；同时也将背景白色色块填实，导致**误检**。

## 任务 3：ROS2 通信
- **消息字段**：自定义 `TargetPosition.msg`，包含 `bool detected`，`float32 u`，`float32 v`，`float32 area`。
- **话题名称**：`/target_position`。
- **发布/订阅流程**：
  - 发布者节点（`publisher_node.py`）定时读取图片，执行上述视觉算法，将检测结果（是否检测到、中心坐标、面积）打包成消息发布。
  - 订阅者节点（`subscriber_node.py`）接收消息，并在终端打印。
  - 未检测到目标时，节点发送 `detected=False`，防止把 `(0,0)` 误认为目标位置。
- **数据接入**：视觉检测结果（`detected / u / v / area`）已真实接入 ROS2 消息，连续发布 10 帧以上，订阅端成功接收。

## 问题与解决过程
1. **问题**：在 WSL 里编译自定义消息时，报错找不到 `TargetPosition` 类型。
   **解决**：发现是 `CMakeLists.txt` 里漏写了 `rosidl_generate_interfaces`，补全并重新 `colcon build` 解决。同时，每次新开终端必须 `source install/setup.bash`。
2. **问题**：纯 OpenCV 检测时，总是框到球员的腿和白袜子。
   **解决**：进行形状过滤。

## 仍未解决的问题
目前的算法是基于静态图片的，如果换成真实摄像头连续视频流，画面运动模糊或光线剧烈变化时，HSV 的固定阈值可能会失效。下一步需要学习使用 ROS2 的 `cv_bridge` 接入摄像头视频流，并尝试结合形态学或卡尔曼滤波来平滑追踪。
