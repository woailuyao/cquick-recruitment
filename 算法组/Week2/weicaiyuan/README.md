## 任务 1：颜色目标检测

目标颜色：红色。

HSV 阈值：H[0-10] + [170-179]，S>144，V>66。

最小轮廓面积：500 像素。

中心点计算方法：因球体表面常有高光，直接求轮廓质心容易受边缘缺口影响而偏移。因此通过 `cv2.minEnclosingCircle` 求最小外接圆，以圆心作为坐标 (u, v)，面积用 πr² 估算，有效抵抗边缘毛刺。此外，引入核大小为 32 的椭圆核，先执行闭运算填补高光破洞，再执行开运算剔除地板反光噪点。

输入与输出：输入为本地测试图片，输出为目标中心像素坐标与面积；若未检测到目标，则输出 `detected = False`，坐标置 0。

## 任务 2：可视化与参数对比

可视化实现：在检测到的目标上绘制绿色外轮廓、橙色外接矩形、红色中心十字，左上角标注像素坐标与面积，左下角打上姓名和精确到秒的时间水印。未检测到目标时输出 NO TARGET DETECTED 字样。

参数对比与结果变化：
对比组 1（最小面积导致的漏检）：针对 img5 热气球，参数 A 设为 min_area=15000，未检测到目标（红色条纹连通域面积仅为 2961 px²，被当作噪点过滤）；参数 B 设为 min_area=100，成功检出（u=581.5, v=1204.5）。结论：固定较高面积阈值易导致远距离小目标漏检。
对比组 2（HSV 阈值导致的误检）：针对 img3 日落大海，参数 A 设为 h1max=10, smin=150，基本只框住太阳；参数 B 设为 h1max=25, smin=60，天空红橙色晚霞被大面积识别，发生严重误检。结论：纯颜色分割无法区分目标红和背景红。
对比组 3（形态学闭运算填补缺口）：针对 img4 板球特写，不加形态学时面积 408837，质心 u=651.9；加入闭运算后面积增至 427529，质心 u 偏移了约 24 像素。结论：闭运算成功填补高光内部空洞，但面积变化也会引起质心偏移。

误检/漏检及偏差案例：
误检（img3 日落）：天空橙红色与目标红色在 HSV 色域重叠，且“取最大面积轮廓”规则导致天空被错误选中。改进思路是引入圆度（Circularity）特征，太阳圆度高，晚霞圆度低。
漏检（img5 热气球）：气球条纹面积过小，被 min_area 机制误杀。需降低面积阈值或增加图像膨胀操作。
偏差（img4 板球）：球面高光反射导致阈值断档，轮廓边缘呈锯齿状缺口，质心偏向残缺的一侧。

像素坐标与真实世界坐标的区别：
像素坐标 (u, v) 的单位是像素，原点在图像左上角，v 轴向下。该坐标随相机分辨率、焦距、安装角度变化，绝对不等于实际的物理距离，不能直接作为机器人的运动指令。若要转换为世界坐标，必须经过相机内参标定、外参矩阵变换、地面平面假设及反投影计算。

## 任务 3：ROS2 通信

消息字段：TargetPosition 包含 `bool detected`（是否检测到目标）、`float32 u`（横坐标）、`float32 v`（纵坐标）、`float32 area`（轮廓面积）。约定当 detected 为 false 时，u、v、area 的数值均返回 0.0，避免误认为目标在左上角。

话题名：`/target_position`。

发布/订阅流程：
发布端（target_publisher）以 2Hz 固定频率运行，循环读取本地 img 目录下的测试图片。调用与任务 1 相同的检测函数处理图像，将结果直接填入 TargetPosition 消息并发布。
订阅端（target_subscriber）监听同一话题，每当收到新消息时，将 detected、u、v、area 四个字段解析并打印到终端。

实际检测结果接入与验证：
发布端代码没有使用写死的假坐标，完全将图片读取、颜色分割、轮廓筛选等检测流程接入。当读取到 img6 时，能正确计算并发布 False 以及全 0 的数据。使用 `ros2 interface show` 验证了接口包字段，运行后通过 `ros2 topic info` 确认 Publisher count 为 1，Subscription count 为 1。订阅端成功连续接收到了 20 条以上的消息，坐标数值与发布端日志完全对应。

## 问题与解决过程

记录问题一（图像处理）：初期调参时，红球内部因反光出现大量黑洞，且地板有零星噪点，单纯修改 HSV 无法兼顾暗部和亮部，且边缘毛刺导致中心点抖动。排查与解决：在代码中加入形态学处理，将 Kernel 尺寸调至 32 进行闭运算，强行填补了高光破洞；随后将中心点计算方法从传统的求轮廓质心改为最小外接圆算法，成功解决了边缘毛刺导致的中心点偏移问题。

记录问题二（环境与通信）：编译接口包后曾遇到终端找不到包及路径残留报错问题；另外在尝试使用 `ros2 param set` 动态修改参数时，终端提示 `Invalid access to undeclared parameter(s)`。排查与解决：通过清理 build 和 install 缓存并重新 source 解决了路径问题。参数修改报错是因为代码中未完整声明该 ROS2 参数，由于此报错并不影响本任务要求的基础消息通信与数据发布，故未将其作为核心阻碍。

## 仍未解决的问题

目前的固定参数无法完美适应所有光照。例如面对日落晚霞时，仅靠 HSV 阈值极难区分红色与橙红色。下一步打算尝试图像预处理（如直方图均衡化 CLAHE）或引入形状特征过滤（圆度计算），以提高算法在不同场景下的泛化能力，并解决 img3 这种大面积背景同色导致的严重误检。
