## 任务 1：颜色目标检测
- **目标颜色**：蓝色
- **HSV 阈值上下界**：下限 [90, 50, 50]，上限 [130, 255, 255]
- **最小轮廓面积**：500
- **中心点计算方法**：利用 `cv2.boundingRect` 计算目标外接矩形的中心点，即 `u = x + w/2`，`v = y + h/2`。
- **多个候选目标选择规则**：遍历所有轮廓，过滤掉面积小于 500 的噪点，保留面积最大的第一个轮廓作为最终输出目标。
- **测试图片结果**：测试了 3 张图片（包含深色背景、浅色背景、蓝色画作），代码均能稳定运行，并输出了中心点坐标 `(u, v)`。

## 任务 2：可视化与参数对比
- **可视化标注**：在原图上绘制了绿色的外接矩形、红色的中心点，并通过 `cv2.putText` 标注了具体的坐标 `u`、`v`。
- **参数对比及误检/漏检案例分析**：
  - **误检案例（如黑猫看海图）**：由于背景存在大面积的海蓝色，且颜色特征明显，算法把整个海面识别成了目标，导致外接矩形过大，中心点偏移。这说明仅靠颜色分割在复杂背景下容易发生误检。
  - **漏检/目标较小案例（如雪人光点图）**：目标虽然是蓝色，但面积较小，如果面积阈值设置过大就会被过滤掉。
- **像素坐标与真实世界坐标的区别**：像素坐标 `(u, v)` 描述的是目标在二维图像中的位置，单位是像素点。它不是真实世界中的物理距离（米）。若要将像素坐标转换成底盘能用的机器人坐标，需要进行相机标定和透视变换等几何转换，不能直接把 u、v 发给底盘控制。

## 任务 3：ROS2 通信
- **消息字段**：自定义了 `TargetPosition.msg`，包含 `bool detected`、`float32 u`、`float32 v`、`float32 area` 四个字段。
- **话题名**：`/target_position`
- **发布/订阅流程**：
  - **发布节点**：读取图片进行 HSV 颜色检测，将检测结果（是否检测到、坐标、面积）通过 `Publisher` 发布出去。如果没检测到，`detected` 设为 `False`，其余设为 `0.0`。
  - **订阅节点**：通过 `Subscriber` 订阅该话题，并在终端实时打印接收到的 `detected / u / v / area` 数据。
- **实际检测结果接入**：发布节点直接调用了任务 1 的 OpenCV 视觉代码，实现了从图像处理到 ROS2 通信的完整链路。
