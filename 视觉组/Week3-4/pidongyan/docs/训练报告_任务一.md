## 2. 训练（基线 v1）

| 参数 | 值 |
|---|---|
| 模型 | yolov8n.pt（COCO 预训练，nc 覆写为 1） |
| imgsz / epochs / batch / device | 640 / 50 / auto(=32) / CUDA:0 |
| 优化器 | `optimizer=auto` 实际选了 AdamW(lr=0.002)，**忽略了 lr0=0.01** |
| 环境 | Python 3.13.14 / torch 2.11.0+cu128 / ultralytics 8.4.203 / RTX 5060 Laptop 8GB |
| 耗时 | 50 epoch ≈ 93 s |

### 曲线诊断（`runs/detect/train/results.csv`）

1. **前 20 个 epoch 几乎没学到东西**：mAP50 长期在 0～0.02，
   第 3 轮 train/cls_loss 冲到 13.82，val/cls_loss 一度到 3853（AMP + 单类 + 正负样本极不平衡，
   早期输出极端置信度）。50 轮预算等于浪费了 40%。
2. **第 21 轮才起跳**（mAP50 0.006→0.13），26–27 轮到 0.548/0.608，之后在 0.20～0.52 反复震荡。
   val 只有 10 个正样本，是震荡与 P 值忽高忽低的主因。
3. **第 40 轮打印 `Closing dataloader mosaic` 后指标立刻稳定抬升**
   （0.386 → 0.571 → 0.700）。这是最强证据：`mosaic=1.0` 对「大球 + 大量空场」数据有害——
   拼图把球进一步缩小、空场拼接产生伪背景，前 40 轮一直在混乱标签里学。
4. best.pt 由 val 的 fitness（0.1·mAP50 + 0.9·mAP50-95）选出，不是 mAP50 最高的第 42 轮。

## 3. 结果

| 轮次 | 数据 | 训练参数 | split | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|---|---|---|
| v1 | `dataset/` | 考核基线 | val | 0.771 | 0.500 | 0.608 | 0.218 |
| v1 | `dataset/` | 考核基线 | **test** | 0.207 | 0.323 | **0.204** | 0.102 |
| v2 | `dataset/` | small_ball 预设 | test | 0.205 | 0.161 | **0.055** ❌ | 0.021 |
| v3 | `dataset_aug/` | **与 v1 完全相同的基线** | val 峰值 @ep17 | 0.704 | 0.800 | 0.734 | 0.183 |
| **v3（采用）** | `dataset_aug/` | **与 v1 完全相同的基线** | **test** | **0.664** | **0.677** | **0.613** | **0.212** |

**当时的结论是采用 v3**（2026-11-20 夜间双 seed 对照后正式权重已改为 v4，见第 8 节）：
test mAP50 **0.204 → 0.613（×3.0）**、Recall 0.323 → 0.677、
mAP50-95 0.102 → 0.212（×2.1）。因为 v3 与 v1 的超参**完全一致**，
这个提升可以干净地归因于「训练集里补进了 32–96 px 的小尺度球」，
而不是调参或测试集泄漏。v2 作为失败记录保留，不采用。

> best.pt 一律由 **val** 选出，test 只在训练结束后评估一次；
> 未用 test 指标挑 checkpoint、未用 test 结果反调超参、未把 test 片段挪进 train（避免测试集泄漏）。
> 三轮完整参数与指标见 `logs/train_runs.csv`、`runs/detect/<name>/train_args.md`。

`eval_cases.py`（conf=0.25, IoU=0.5）在 test 上的匹配统计：

| 轮次 | 正确 TP | 误检 FP | 漏检 FN |
|---|---|---|---|
| v1 | 3 | 4 | **28** |
| v3 | **26** | **35** | **5** |

v3 把漏检从 28 压到 5，但误检从 4 涨到 35（集中在少数几张图，
多为背景里的地球仪图案、栏杆与设备，见第 4 节）——这是尺度增强的代价，
也是下一步要补「类球干扰物负样本」的原因。

## 4. 误检 / 漏检案例

以下以**正式采用的 v3** 为准（绿=正确 TP，黄=误检 FP，红=漏检 FN）。

**案例 A · 漏检（FN）** — `docs/cases/case_v3_FN_far_small_ball.jpg`（f000120）
- 现象：红框内足球约 80 px，紧贴白色围挡；整帧明显过曝，球糊成灰白团，与背景对比度极低，v3 没给框。
- 原因：极端光照 + 球贴围挡，纹理与轮廓同时退化。v3 只剩 5 个漏检，基本都属于这一类难例。

**案例 B · 误检（FP）** — `docs/cases/case_v3_FP_globe_and_railings.jpg`（f000750）
- 现象：同一帧里 v3 **正确检出了足球**（绿框），但同时给出 3 个误检黄框：
  ① 蓝色地球仪图案（FP 0.22）；② 栏杆 / 推车设备区（**FP 0.60，高置信**）；
  ③ 右侧白色设备与栏杆。
- 原因：单类检测器只学「圆形 + 斑块」，缺「非球圆形物」负样本；尺度增强让模型对小圆形区域
  更敏感，误检随之增多（v1 4 个 → v3 35 个）。**0.60 的高置信误检靠调 conf 阈值压不掉**，
  只能补负样本数据。

**对比（v1 基线，问题诊断用）**：
- `docs/cases/case_FN_far_small_ball.jpg`：v1 在同样的 82 px 球上完全漏检（28 个漏检之一）。
- `docs/cases/case_FP_globe_pattern.jpg`：v1 以 0.47 置信度把地球仪当球，真球反而漏检。
- 同一帧 f000750 在 v1 是「真球漏检 + 1 个误检」，在 v3 是「真球检出 + 3 个误检」，
  很直观地体现了「召回换误检」的取舍。

（更多案例见 `check_out/eval_cases/cases_summary.csv`，按「漏检优先 / 目标越小越前」排序。）

## 5. 改进尝试与结论（如实记录三次实验）

### v2：只调超参 —— **失败，不采用**

| 改动 | 基线 | v2 | 当时的依据 |
|---|---|---|---|
| imgsz | 640 | 960 | 想让小球保留更多像素 |
| mosaic / erasing | 1.0 / 0.4 | 0.0 / 0.0 | 基线第 40 轮关 mosaic 后 mAP 跳升 |
| epochs / patience | 50 / 30 | 120 / 40 | 前 20 轮白跑，等效训练量不足 |
| optimizer / lr0 | auto(AdamW 0.002) | SGD 0.01 | 显式优化器 lr0 才生效 |
| warmup / cos_lr / scale | 3 / False / 0.5 | 5 / True / 0.6 | 抑制早期爆炸、增加尺度抖动 |

结果：**test mAP50 从 0.204 掉到 0.055**，且 80 轮就早停（best @ep40）。
查 `runs/detect/train_v2/results.csv` 发现 **val 峰值只有 0.336**（基线 0.700），
val/cls_loss 长期在 4～19（基线后期 1.7～2.6）→ **是训练本身崩了，不是 test 泛化差**。

原因：
1. `mosaic=0` 拿掉了 215 张小数据集**唯一的强正则**。基线前 40 轮虽乱，但 mosaic
   把 4 图拼接 + 随机缩放，等效放大了样本多样性；关掉后模型迅速过拟合。
   基线「关 mosaic 后跳升」只能说明**训练后期**该收，不能说明**全程**关掉更好。
2. SGD lr0=0.01 对 batch=14 的小数据偏大，val mAP 在 0 / 0.28 / 0.34 之间反复横跳。

**更根本的认识（写进报告的教训）**：
> 提高 imgsz 会把 train 和 test **一起**放大，**相对尺度差不变**
> （640 下 85px vs 41px，960 下 127px vs 62px，都是约 2:1）。
> 调超参无法凭空制造小目标样本 —— 模型没见过 80px 的球，换优化器也认不出来。
> 真正的解药是**让训练集里出现这个尺度的球**。

### v3：制造小尺度训练样本（数据增强，唯一变量是数据）

`tools/make_small_ball_aug.py` 只用 train 自己的图片，**不碰 val/test、不碰 test 片段**：

- 把 `dataset/` 完整复制到 `dataset_aug/`（正式划分原样保留，v1 随时可复现）；
- 对 train 每张含球图按 s∈[0.40,0.65] 整图缩小 → 球变小；
  背景用**同图强模糊版**（色调一致、原球被糊掉），缩小图随机放入；
- 同步换算 YOLO 标签，缩小后 <20px 的球丢弃；
- 生成 169 张增强图，train 215→384 张，**86 个球框落在 32–96 px 档**，
  增强样本框宽中位 **91.7 px**（test 是 82.5 px），尺度鸿沟被填上；
- 生成 `config/data_aug.yaml`，然后**沿用 v1 的全部基线超参**训练，
  这样 v1 / v3 只有一个变量，结论干净。

```bash
python tools/make_small_ball_aug.py                              # 生成 dataset_aug + data_aug.yaml
python tools/train_yolo.py                                       # v1 基线
python tools/train_yolo.py --preset small_ball --name train_v2    # v2（失败记录，保留备查）
python tools/train_yolo.py --data config/data_aug.yaml --name train_v3  # v3
python tools/train_yolo.py --eval-only --model runs/detect/train_v3/weights/best.pt --name train_v3
```

> `dataset_aug/` 里的增强图与原图同源，**不要再对它跑 `split_dataset.py`**
> （重新划分会让增强图落进 val/test 造成泄漏）。val/test 是原样复制，指标可直接对比。
> 第一版有拼接痕迹的增强数据**未删除**，按用户要求整体移到
> `dataset_aug_rejected/`（910 个文件 / 70 MB）保留备查；生成脚本已改为**只写不删**。

所有非基线参数会自动写到 `runs/detect/<name>/train_args.md`，
各轮指标追加到 `logs/train_runs.csv`，README 直接抄这两处即可。

## 6. 局限与下一步计划

1. **增强图不是真实拍摄**：v3 用「整图缩小 + 同图模糊背景」造出小球，仍有清晰/模糊的
   过渡带。它把漏检从 28 压到 5，但最稳妥的做法仍是**另拍一段真实远距视频**
   （必须是新的独立片段，绝不能动已划为 test 的 ball_run05），标注后加入 train 重新划分。
2. **类球干扰成了主要短板**：v3 误检从 4 涨到 35，且出现 0.60 的高置信误检。
   补含地球仪、圆形标志、栏杆圆环、推车设备的**空标签负样本帧**，
   或现场把 `--conf` 从 0.25 提到 0.4 左右压低置信误检。
3. **val 太小且分布偏**：只有 10 个球、都在画面顶边被裁切；v3 虽然 ep17 就到了 0.734，
   但 ep20 又掉回 0.30，best.pt 选择仍不稳。后续可增加独立验证片段，但不要拿 test 当 val。
4. **光照 / 遮挡**：v3 剩余的 5 个漏检都是强过曝或球贴白色围挡；已有 ball_run07
   开关灯片段覆盖部分光照变化，仍缺强逆光与半遮挡样本。
5. **mAP50-95 仍偏低**（0.212）：小球定位框本身就难精确，报告里如实写并配合案例分析，
   不要只挑 mAP50 好看的数字。

## 8. v4：类球干扰负样本 + 双 seed 对照（2026-11-20 夜间补做）

### 8.1 做法（唯一变量是数据，超参一律不动）

`tools/make_negative_samples.py` 从 `frames_pool_markers/` 的 **11 个无球视频段**
（marker_run01~05 / pose_A·A2·B·C / field_check*）等间隔抽 **40 张**，
写成**空标签**负样本，构建 `dataset_aug2/`（train 424，val/test 原样复制），
配置 `config/data_aug2.yaml`。这些帧里本来就有蓝色地球仪、栏杆圆环、
设备箱扣、白色圆形台面等类球干扰物 —— **不需要补拍、不需要相机**。

刻意**不用模型筛球**：v3 在这些帧上的高置信误检正是要保留的 hard negative，
用模型筛会把药倒掉。已目视抽查 marker_run04b / pose_C / field_check 三组代表帧，均确认无球。

### 8.2 结果（关键不是 0.995，是方差）

| 轮次 | 数据 | seed | test P/R/mAP50/mAP50-95 | val 峰值 | conf=0.25 案例统计 |
|---|---|---|---|---|---|
| v1 基线 | dataset | 0 | 0.207 / 0.323 / **0.204** / 0.102 | 0.700 | 正确3 / 误检4 / 漏检28 |
| v2 调超参 | dataset | 0 | 0.205 / 0.161 / **0.055** / 0.021 | 0.336 | — |
| v3 | dataset_aug | 0 | 0.664 / 0.677 / **0.613** / 0.212 | 0.734 | 正确26 / 误检35 / 漏检5 |
| v3 | dataset_aug | **1** | 0.181 / 0.387 / **0.136** / 0.042 | 0.578 | — |
| **v4** | dataset_aug2 | **0** | 1.000 / 0.999 / **0.995** / 0.499 | **0.895** | **正确30 / 误检0 / 漏检1** |
| v4 | dataset_aug2 | **1** | 0.582 / 0.613 / **0.613** / 0.273 | **0.875** | 正确13 / 误检5 / 漏检18 |

**结论（写报告请照这个口径，别只挑 0.995）**：

1. **50 epoch / 215 张的小数据集训练方差极大**：同一份 v3 数据，seed 从 0 换到 1，
   test mAP50 从 0.613 掉到 **0.136**（4.5 倍）。因此 v3 单次 0.613 不能当成稳定结论，
   第 3 节的 v3 数字必须配合本节一起看。
2. **负样本的作用主要是稳定 + 压误检**：v4 两个 seed 的 val 峰值 0.895 / 0.875
   （v3 是 0.734 / 0.578），波动从 ±0.11 降到 ±0.014；seed=0 那版误检 35→0、漏检 5→1。
   但 seed=1 在固定 conf=0.25 下仍有 18 个漏检，说明**置信度校准仍随种子波动**，
   不能宣称「v4 全面稳定优于 v3」。
3. **正式权重选 `best_train_v4.pt`（seed=0）**：它是实测误检 0 / 漏检 1 的一版，
   val 峰值也最高，最适合 20 号现场实时演示。v3 权重原样保留，
   随时可用 `--model best_train_v3.pt` 回退。
4. test 集未泄漏：核对过 `dataset_aug2/images/test` 与 `dataset/images/test`
   的文件名、图片内容哈希、标签哈希三者完全一致，train 里无 test 同名图片。
