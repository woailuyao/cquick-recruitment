### 误检与漏检分析

**误检案例 1 · 胶带卷（录屏中可见）**
场地边放置的一卷白色胶带被误判为足球（置信度约 0.6）。胶带卷的圆形轮廓、白色外观与
足球在低分辨率下高度相似，属于典型的“形状 + 颜色”双重混淆。这类同形状物体的误检
需要靠补充负样本重训来解决，单纯提高阈值会连带牺牲远端小球的召回。

**误检案例 2 · 场地弧线**
中圈/禁区弧线的局部曲率与足球接近，在低置信度阈值（约 0.25–0.45）下会被框成球，置信度通常
在 0.5 左右。提高阈值到 0.6 可抑制，但会牺牲远端小球的召回——这正是 precision / recall 的权衡，
本系统取 **0.6** 作为工作点。

**误检案例 3 · 天花板悬挂装饰**
实验室天花板挂有圆形星球装饰物，被误判为足球（置信度约 0.7）。原因是训练数据全部为地面视角，
画面中从未出现该类物体，模型对“高对比圆形物体”存在过拟合。改进方向：补充负样本图像重训。

**漏检案例 · 远端小球**
球距相机 8 m 以上时在图像中仅 15–25 像素，置信度降至 0.3 以下，低于 0.6 阈值被丢弃。
实时演示中画面顶部的 `raw=` 字段会显示该帧的原始置信度（即使低于阈值），可直观看到
“模型看见了但没达到阈值”的现象。

### 工程处理（抑制抖动与误检）

| 手段    | 参数                 | 作用                     |
| ----- | ------------------ | ---------------------- |
| 置信度阈值 | `--conf 0.6`       | 抑制弧线类低置信度误检            |
| 连续帧确认 | `--min-hits 3`     | 同一目标连续 3 帧命中才显示，消除单帧闪烁 |
| 宽高比约束 | `--max-aspect 1.8` | 剔除被框成扁长条的弧线            |
| 框坐标平滑 | `--smooth 0.6`     | 指数平滑，画面更稳              |

> 备注：曾尝试“屏蔽画面上部区域”来排除天花板装饰，但该假设在相机俯仰变化或远处小球
> 接近地平线时不成立，属于不可靠的硬编码，已弃用。

### 处理链路

```
相机 V4L2（MJPG 1280×720, 20fps）
  → 逐帧送入 YOLOv8n（imgsz 640 / 320）
  → 输出 ball 的 x1,y1,x2,y2 与置信度
```

### 相机外参

| 项目   | 数值     | 获取方式                           |
| ---- | ------ | ------------------------------ |
| 光心高度 | 0.75 m | 卷尺量地面到镜头中心（桌面 75 cm + 相机离桌面高度） |
| 俯仰角  | 21°    | 由两个已知距离的地面参考点反推                |

**外参校验过程**：

1. 在地上以相机正下方为起点，贴 2.0 m 和 4.0 m 两个参考点；
2. 先按估算填俯角 20°，程序算出两点距离 1.13 m / 1.65 m，明显偏小；
3. 按「地面距离 ≈ 高度 / tan(俯角)」反推，当时实际俯角约 9°；
4. 相机重新摆放后角度改变，最终演示按 21° 运行；此时 2.0 m 参考点算出 1.999 m，
   4.0 m 参考点算出 3.66 m（远点误差约 0.35 m，主要来自胶带点位置与远距离射线的敏感性）。

### 像素到地面的投影

`ground_projection.py`：

1. 用内参和畸变系数去畸变，得到归一化坐标；
2. 用 `K⁻¹` 还原相机坐标系下的射线方向；
3. 通过外参旋转到载体坐标系，与地面平面 Z = 0 求交；
4. 交点在合理范围外或射线接近水平时判为无效。

工具在画面上叠加地面网格，并实时显示点击点的米制坐标，用于验证投影精度。

### 地图匹配与位姿求解

`pose_solver.py`：

1. 取两个同类标志，与地图中同类两点配对，用「间距 + 方向差」枚举候选位姿；
2. 每个候选把全部观测点变换到地图系，统计落在容差内的内点数和残差；
3. 取内点最多、残差最小的候选，用 Kabsch 最小二乘做刚体配准精修；
4. 若另一候选的内点数与最优相当、但位置或朝向相差很大，判为 `ambiguous`；
5. 内点不足判 `insufficient_markers`，残差过大判 `high_residual`，这两种情况都不输出位姿。

合成数据自测：给定真值 (1.2, 0.4, 30°)，反解误差 0.000 m / 0.00°。

## 问题与解决过程

**问题**：相机在虚拟机中能打开，但 `cap.read()` 永远返回 False，报
`global cap_v4l.cpp:1050 tryIoctl VIDEOIO(V4L2:/dev/video0): select() timeout`。

**排查**：

1. `lsusb` 能看到 `0bda:5844`，`/dev/video0` 存在，说明设备已传入虚拟机；
2. `v4l2-ctl --list-formats-ext` 显示默认协商 YUYV 1280×720；
3. VirtualBox 日志显示该设备挂在 EHCI（USB 2.0）上，YUYV 720p 需约 442 Mbps，
   超过 USB 2.0 等时传输带宽。

**解决**：显式指定 `CAP_PROP_FOURCC = MJPG` 并走 `CAP_V4L2` 后端，带宽需求降到几十 Mbps，
720p 正常出帧。

**其他踩坑**：

- 虚拟机 GUI 多次僵死（OpenCV Qt 窗口 + Wayland 软件渲染），改为宿主机录屏、`nohup` 后台训练；
- Ultralytics 权重下载被墙，改用 hf-mirror 镜像获取 `yolov8n.pt`。
