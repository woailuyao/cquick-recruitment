任务 1：颜色目标检测
我选红色作为要识别的颜色。设置了HSV的颜色范围，最小轮廓面积设为300。用轮廓矩算目标的中心点，如果遇到特殊情况会做简单判断防止程序报错。如果有好几个目标，就选面积最大那一个。

程序运行过程：读取图片，把图片转为HSV格式，生成掩膜图片，做简单的降噪处理，找出物体轮廓，过滤掉太小的噪点轮廓，算出目标中心点。找不到目标的时候，终端会打印没检测到目标。

测试了三张图片：清楚的红色物体可以算出中心点u=240，v=180；物体比较小也可以识别出来；图片里没有红色就提示没检测到。
会出问题的情况：光线变化大就容易识别不到；背景有红色东西就会认错物体。

任务 2：可视化与参数对比
把找到的物体轮廓、中心点还有坐标数字画到图片上，保存图片。找不到目标图片上也会写上没检测到目标。

做了两组参数对比：
1. 最小轮廓面积：调到300的时候，小噪点会被过滤，识别比较稳；调到50，很多背景小点会被当成目标，识别出错。
2. 形态学处理：打开这个功能，图片噪声少，物体轮廓完整；关掉之后，图上很多噪点，轮廓碎碎的。

误检情况：背景有红色就会认错；漏检情况：光线变暗，识别不到红色物体。
像素坐标只是图片上面的位置，不能直接拿来控制机器人，要另外做标定转换。

任务 3：ROS2 通信
自己建了消息 TargetPosition.msg，里面包含是否检测到目标detected，坐标u、v，轮廓面积area。话题名字叫 /target_position。没检测到目标的时候u、v、area全部填0。

发布节点定时往外发模拟出来的坐标数据；订阅节点接收消息，把收到的内容打印出来。现在是写死的测试坐标，后面可以接上前面图片检测出来的真实数据。

操作步骤：进到工作空间，编译代码，刷新环境。一个终端跑发布节点，再开一个终端刷新环境跑订阅节点，可以收到十几条消息。也用命令看过自定义消息和话题信息。
图片上拿到的坐标不能直接控制机器人，需要转换。

问题与解决过程
1. 一开始在WSL里面装ROS2，试了很多次，老是网络超时，安装包损坏装不成功。后面改用虚拟机装Ubuntu系统，才把ROS2装上。
2. 新开终端运行程序提示找不到包，后来知道每开新终端都要执行source刷新环境。
3. 写发布节点的时候漏写一行创建发布器的代码，程序报错，补上代码重新编译就好了。
4. 计算中心点的时候遇到过程序报错，加了判断，避免除以0。
