## 一、串口四参数

串口没有时钟线。数据一位一位过去，两边得先约好同一套规矩，不然接收端根本不知道隔多久该读一下。

- **波特率**：每秒多少 bit。定成 115200，就是每秒 115200 个 bit，一位只占 1/115200 ≈ 8.68 µs。这个数一错，后面全乱。
- **数据位**：8 位，正好装一个字节，发 `#001P1500T1000!` 这种 ASCII 字符串刚好。
- **停止位**：1 位。帧尾把线拉回空闲高电平，接收端才敢确认这一帧收全了。
- **校验位**：N，不用。省时间，而且它只能发现错、纠不了错；实际上靠协议里的 `#` 和 `!` 判断帧边界。

合起来就是 **8-N-1**（8 数据位、无校验、1 停止位）。再加上帧头那 1 位起始位，一个字节在线上占 **1+8+0+1=10 位**，115200 下约 86.8 µs。

波特率不一致的话，运气好是报帧错误、什么都收不到；运气差是收到了，但全是乱码。后一种更麻烦：乱码里万一凑出一个像样的 `#` 开头，舵机可能就去执行一条我没想发的指令。原因放第三节。

## 三、为什么波特率不一致就一定会乱码

每位的时间 = 1/波特率。115200 时一位约 8.68 µs，9600 时一位约 104 µs，差了 12 倍。

串口是异步的，两边没有共享时钟线，接收端只能靠起始位那个下降沿对齐。它把这一刻当成第 0 位，然后按**自己的**波特率往下数，在每个 bit 的中点采样。中点到两边沿都最远，最不容易读错。节拍一致的时候采样点永远落在每一位中间，一路稳到最后，8-N-1 就是这么工作的。

节拍不一致就完了。采样点每往后一位就偏一点，而且偏差会累积，偏到后来踩到相邻位、甚至踩到下一个字节的起始位，读出来的 0/1 跟发送端就没关系了，这就是乱码；连帧结构都对不上时，芯片直接报帧错误（framing error），整帧扔掉。

具体数字：发送端 115200、接收端 9600，接收端以为一位有 104 µs，发送端一整个字节在它眼里只值自己的一位，那串快速跳变被当成一格里的抖动；反过来 9600 发给 115200 的接收端，它会在对方一位里采十几次，读到一串重复值。

## 四、把 `#001P1500T1000!` 逐段拆开

这条指令不是「# + ID + 数字」那种松散格式，是**严格等长切字段**的：

| 段 | 内容 | 含义 | 备注 |
| --- | --- | --- | --- |
| `#` | 起始符 | 一条指令开始 | 每帧必带 |
| `001` | ID | 1 号舵机 | 固定 3 位 |
| `P` | 指令码 | 写目标位置 | 大小写敏感 |
| `1500` | 目标 PWM | 1500 = 中立位 | 固定 4 位，500–2500 |
| `T` | 时间引导符 | 后面接动作时间 | 字段名 |
| `1000` | 时间 | 1000 ms 内走完 | 固定 4 位，ms |
| `!` | 结束符 | 指令结束 | 每帧必带 |

读成人话：**「喂 1 号，去 1500（中立位），用 1000 毫秒转过去。」** 照这个格式我自己写两条：

```text
#001P1500T1500!    // 1 号舵机转到中立位，用 1.5 秒
#003PULK!          // 3 号舵机卸力
```

**为什么位数一个都不能省**：解析器不认逗号也不认空格，它靠**位数**切字段。见 `#` 就往后抓 3 个字符当 ID，抓到 `P` 再抓 4 个当 PWM，抓到 `T` 再抓 4 个当时间。ID 少写一位（`#1P...`），它会把 `1P1` 当 ID，整句串位；`500` 不写成 `0500`，`T` 就被当成 PWM 的第 4 位；时间不满 4 位，`!` 会被当成数字。少一格，后面全往后挪一格。

指令表是同一个骨架，`#` + 3 位 ID + 指令码 +（可选参数）+ `!`：

| 指令 | 作用 | 有数值参数吗 |
| --- | --- | --- |
| `#001P1500T1000!` | 控制角度 | 有（P 和 T） |
| `#001PID!` | 读 ID | 无 |
| `#001PRAD!` | 读当前位置 | 无 |
| `#001PULR!` | 恢复扭力（动之前必须先发） | 无 |
| `#001PULK!` | 卸力（安全下电必发） | 无 |

下周实操顺序：**读 ID → PULR → 写角度 P → PRAD → PULK**。PULK 放最后不是走形式，卸力后舵机不出力，不会堵转憋着电流发热，舵机多半是这么烧的。

## 五、单线半双工、共地、电平不匹配

**① 收发共用一根线（单线半双工）**：普通串口有 TX、RX 两根线，一边发一边收；总线舵机为省线把收发合成**一根信号线**，控制器和所有舵机的信号脚都挂上去。

- **自己发的自己也会听到**：发出去的 `#001P1500T1000!` 顺着线回到自己的接收端。我猜控制器在发送期间把接收屏蔽了、发完再打开（待验证）。
- **同一时刻只能有一个设备说话**：一个拉高、一个拉低，线上就是谁都读不懂的电平，两边都硬还会互相灌电流。
- **多舵机不打架靠 ID**：每条指令带 3 位 ID 等于点名，舵机平时闭嘴，被叫到才回。所以 ID 绝不能重复，两个 001 会同时回话，总线立刻乱。

**② GND 必须连**：「高」「低」是**相对 GND 的电位差**。地不连在一起，两边 0V 基准不同，判断高低的门限就偏了，表现是读不到、读到随机值，或者平时能通、一上电机就丢包。所以 USB 转 TTL、24 路控制器、舵机电源，信号可以分开走，**地必须连成一片**；舵机大电流我单独供一路（5–8.4V），GND 也和控制器共地。

**③ 5V 和 3.3V 不能直连**：控制器这侧是 5V TTL，上位机和单片机常是 3.3V 的 IO。5V 直接怼进去超过它的耐压（约 3.3V+0.3V），电流从内部保护二极管灌进去，**烧的是 3.3V 那一侧**，5V 那头毫发无伤。稳妥做法是加分压或 level shifter；反过来 3.3V 发给 5V 器件多半能认成高电平，但余量小。
