## 任务 1：自定义 BallPos 消息 + 发布/订阅

用 ament_cmake 建了个接口包 `week2_ball`，`msg/BallPos.msg` 里三个字段：`int32 id`、`float32 x`、`float32 y`。比标准 `String` 多带了 id，因为三个球要能分清谁是谁。代码在 `src/week2_ball/`。

自定义消息最容易漏的固定就三处：`package.xml` 的 `rosidl_default_generators` 等依赖、`CMakeLists.txt` 里的 `rosidl_generate_interfaces`、还有最后要注册成 rosidl 接口包。少一处编译就不生成接口。所以我编译完先 `ros2 interface show week2_ball/msg/BallPos`，能打出字段再往下走（`01_interface_show.png`）。

发布端脚本 `ball_publisher`，每个周期连发 3 条消息（id 1/2/3，坐标就是细则给的 (2.0, 3.0)、(5.5, 8.0)、(9.0, 4.0)），2 Hz，日志打「发球: id=…, x=…, y=…」。订阅端 `ball_subscriber` 收同一个话题，日志打「收球: id=…, x=…, y=…」。两边一起跑见 `01_发布订阅分屏.png`。

`ros2 topic info /ball_pos` 打出来是 Type: week2_ball/msg/BallPos，Publisher count: 1，Subscription count: 1，和预期的对得上（`01_话题信息.png`）。

改参数的实验是把发布频率从 2 Hz 改成 5 Hz，也就是定时器周期 0.5 s → 0.2 s。两张截图当两次运行来比：`01_发布订阅分屏.png`（2 Hz）里每轮三条的起始间隔约 0.5 s，5 Hz 后的 `01_改频率后输出.png` 里变成约 0.2 s，订阅端刷屏明显变快，但每个周期还是 id 1/2/3 各一条。

后来我把频率做成了节点参数（`declare_parameter('freq', 2.0)`，默认还是 2 Hz），改频率不用动代码：`ros2 param set /ball_publisher freq 5.0` 运行中立刻生效，日志打「发布频率已改成 5.0 Hz」，订阅端刷屏随即变快。参数回调里挡了非法值，`ros2 param set /ball_publisher freq -1.0` 会被直接拒掉（`freq 必须大于 0`）。

还有个环境问题，新开终端每行前面都在刷这句：

```text
bash: /home/wang/ros2_ws/install/setup.bash: No such file or directory
```

原因是 `~/.bashrc` 里那行 source 在终端一打开就执行了，可当时 install 目录还没生成，或者路径对不上，于是先报这一句，后面的命令照样能跑。解决办法：进到 `~/ros2_ws` 里 `colcon build`，再 `source install/setup.bash`，用 `ros2 interface show week2_ball/msg/BallPos` 确认字段出得来，然后才启动节点。

## 任务 2：订阅 ball_pos，用 Twist 闭环走到三个坐标

节点名 `turtle_navigator`，脚本 `turtle_nav.py`。没按固定时间硬发速度，走的是闭环：

- 订阅 `/turtle1/pose`，每个周期都拿当前的 (x, y, θ)；
- 先原地把 θ 对准目标方位角，再往前走；
- 前进速度随剩余距离减小，快到了自己就慢下来；
- 距离小于阈值就判定到点。

这里的麻烦是消息一条一条来：三个球的坐标分三条到达，所以我在回调里用字典按 id 存坐标，攒满 3 个才让乌龟出发。这样顺序一定是 1 → 2 → 3，不会拿着半张地图乱跑。

这一项里实际用了一次服务调用，路径跑花的时候清屏：

```bash
ros2 service call /clear std_srvs/srv/Empty
```

它必须有响应、只调一次就结束，所以是服务不是话题。话题是发出去就不管、后面一直流；`/clear` 得等 turtlesim 把轨迹擦掉、回我一个结果，是一次性的请求—响应。

## 三种通信方式对比

| 通信方式 | 模型 | 特点 | 足球机器人典型场景 |
|---|---|---|---|
| **话题 Topic** | 发布者 → 订阅者，多对多 | 单向、持续流、发完不管，不保证一定有人收 | 视觉节点持续广播球的位置；战术层持续广播速度指令 |
| **服务 Service** | 客户端 → 服务端，一对一 | 请求—响应，有返回值，调一次就结束 | 清屏 `/clear`；问一句「当前比分多少」拿回一个结果 |
| **动作 Action** | 客户端 → 服务端，跑长任务 | 有目标、有进度反馈、可中途取消 | 「走到点 (9.0, 4.0)」，路上报进度，跑偏了随时取消 |

记法就一句：要一直流用话题，要一个答案用服务，要干一件耗时长又能中途取消的事用动作。

## 差速三公式

- `v = (vL + vR) / 2`：车体前进速度是左右轮的平均。两边一样快走直线，一边快一边慢就带着转。
- `ω = (vR − vL) / L`：角速度来自左右轮的速度差，L 是轮距。差越大转得越急；vR = vL 时 ω = 0，正好是一直走。
- `r = v / ω`：转弯半径是线速度除以角速度。r 越大弯越大，ω 趋近 0 时 r 趋于无穷，又回到直线。
