## 任务 1：颜色目标检测
- **目标颜色**：绿色（基于测试图片中万花筒的底色以及真实足球上的绿色纹理）。
- **HSV 阈值上下界**：下限 `[25, 30, 30]`，上限 `[100, 255, 255]`。
- **最小轮廓面积**：50。
- **中心点计算方法**：使用 `cv2.moments` 计算轮廓矩，处理了面积或 `m00` 为 0 的异常情况。若检测到多个候选目标，代码会按面积排序，最终选择面积最大的轮廓作为唯一目标。
- **测试图片结果**：
  - `1.jpg`：成功检测并输出中心点及面积。
  - `2.jpg`：成功检测，输出坐标与面积。
  - `3.jpg`：成功检测并输出中心点及面积。
- **算法失效情况分析**：
  1. 当环境光照剧烈变化、目标反光严重时，HSV 的 H 值可能发生偏移，导致无法生成完整的 Mask。
  2. 当背景存在与目标相似的颜色（例如背景有大片草地），或者目标被严重遮挡时，会导致误检或漏检。

## 任务 2：可视化与参数对比
- **可视化**：代码在图像上绘制了目标的绿色轮廓、红色中心点，并标注了 `u=..., v=...` 的坐标文本。如果未检测到目标，会输出 `No target` 警告。处理后的结果已保存为 `annotated_*.jpg`。
- **参数对比实验**：
  - **实验 A（默认参数）**：最小面积阈值设为 `50`。此时三张测试图均能成功框选出目标。
  - **实验 B（极端参数）**：将最小面积阈值调大至 `1000000` 后重新编译运行。现象：三张图片全部提示“未检测到目标”，发生严重漏检。**结论**：由于目标的轮廓像素面积达不到 100 万，被作为噪声过滤掉了，说明面积阈值不可设置得过大。
- **坐标概念理解**：像素坐标 `(u,v)` 以图像左上角为原点，向右为 u 轴，向下为 v 轴。像素坐标只表示目标在二维图像中的相对位置，**绝不能直接等同于机器人的真实世界坐标或米制距离**，后续必须经过相机标定和坐标系转换。

## 任务 3：ROS2 通信
- **消息字段**：`bool detected`, `float32 u`, `float32 v`, `float32 area`。
- **话题名**：`/target_position`。
- **发布/订阅流程**：发布节点 `detect_target.py` 读取静态测试图，经 OpenCV 处理后，将真实检测结果发布至话题；订阅节点 `target_subscriber.py` 持续监听并打印。当 `detected=False` 时，坐标和面积数据均为 `0.0`，严格遵循了消息约定。
- **工程化防坑设计（加分项）**：代码使用了基于 `__file__` 的相对路径动态定位（`Path(__file__).resolve().parents[3]`），无论工程被移动到哪台电脑的哪个目录下，只要保证 `images` 文件夹与 `src` 文件夹处于同级目录，均可直接编译运行，无需修改任何绝对路径。

## 问题与解决过程
- **真实遇到的问题**：最初在 Windows 挂载盘符（`/mnt/c/`）下执行 `colcon build` 时，由于跨文件系统的权限管理差异，引发了 `rosidl_generate_interfaces` 列表越界报错，导致自定义消息无法生成。
